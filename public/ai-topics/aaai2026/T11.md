# T11 金融AI与决策 调研报告

> 调研范围：金融领域基础模型（Kronos）、股权研究报告生成（FinRpt）、金融术语适应（TermGPT）、投资组合智能体平台（PortfolioPilot）、LLM时间顺序理解与金融回测（Chronology）。
> 调研时间：2026-08-07。外部文献均标注真实 arXiv ID / DOI，检索来源为 arXiv API 与 Crossref。

---

## 一、主题概览与研究热点

本主题 5 篇 AAAI 2026 收藏论文横跨金融 AI 的四条主线：

1. **金融时序基础模型（Time Series Foundation Model, TSFM）**：Kronos 把 LLM 的 tokenizer + 自回归预训练范式搬到 K 线数据上，在 120 亿条 K 线记录上预训练，主打零样本预测、波动率预测与合成数据生成。对应外部热点：TimeGPT、Chronos、Moirai、Lag-Llama、TimesFM 之后，金融专用 TSFM（FinCast、LENS、DELPHYNE）正快速涌现。
2. **LLM 报告生成与文档智能（Report Generation）**：FinRpt 首次形式化"股权研究报告生成（ERR Generation）"任务，配套数据集构建流水线、11 指标评估系统与多智能体框架 FinRpt-Gen。对应外部热点：Financial Statement Analysis with LLMs、Template-Based Financial Report Generation、FinReportBench。
3. **金融/法律领域术语与表示（Terminology & Representation）**：TermGPT 用多层对比微调（句子级 + token 级）缓解 LLM 嵌入空间的各向异性（isotropy）问题，并构建监管文件来源的金融术语数据集。对应外部热点：domain-adaptive post-training、对比学习领域适配、FinEval/FinBen 中的术语判别任务。
4. **智能体平台与时间理解（Agentic Platform & Chronology）**：PortfolioPilot 用自然语言生成可回测的 TypeScript 投资组合算法；Chronology 研究 LLM 的时间顺序理解与前视偏差（look-ahead bias）。对应外部热点：FinMem/FinAgent/FinCon/TradingAgents 等 LLM 交易智能体、look-ahead bias 审计（Look-Ahead-Bench、BacktestBench）、"Alpha 幻觉"批评。

**跨方向的热点信号（2025-2026）**：
- **前视偏差成为金融 LLM 研究的第一公理问题**：从 Assessing Look-Ahead Bias（2309.17322）到 PiT-Inference 的遗忘式去偏（2512.06607）、Look-Ahead-Bench（2601.13770）、BacktestBench（2605.17937），以及 Alpha Illusion（2605.16895）与 Benchmarks Are Not Validation（2607.28840）两篇"打假"论文，社区正在用体系化审计取代单一 Sharpe 报告。
- **LLM 智能体从"讲故事"转向"受约束的可执行工程"**：StockBench（2510.02209）用真实市场信号做污染规避评测；QuantEval（2601.08689）、FINESSE-Bench 把回测代码正确性纳入评估。
- **金融时序基础模型竞争白热化**：Kronos 之后 FinCast（2508.19609）、LENS（2408.10111）、DELPHYNE（2506.06288）等不断刷新零样本金融时序榜单。
- **多智能体投资委员会范式**：AlphaAgents（2508.11152）、MASS（2505.10278）、FinDebate、Macro Economists in the Machine（2606.08283）等把"分析师团队+经济讨论"抽象为可回测的多智能体系统。

## 二、收藏论文精读（含创新点/不足）

### 2.1 精读（Machine Learning VII · 论文 47 · Kronos: A Foundation Model for the Language of Financial Markets）
- arXiv: 2508.02739（v1，2025-08-02），作者 Yu Shi, Zongliang Fu, Shuo Chen, Bohan Zhao, Wei Xu, Changshui Zhang, Jian Li，代码公开（github.com/shiyu-coder/Kronos）。
- **核心创新点（1-3 点）**：
  1. 提出面向 K 线（OHLCV candlestick）的专用 tokenizer，把连续市场信息离散化为 token 序列，同时保留价格动态与交易活跃度模式，这是首个"把 K 线当语言"的规模化金融 TSFM；
  2. 在 45 家全球交易所、120 亿条 K 线记录上做自回归预训练，实现跨市场、跨资产的时序表示；
  3. 除价格预测外，显式覆盖波动率预测与合成 K 线生成两类被现有 TSFM 忽视的下游任务，在 RankIC、MAE、生成保真度上相对领先 TSFM（如 TimeGPT/Moirai 系）与经典基线分别提升 93%/87%、降低 9% MAE、提升 22%。
- **不足/空白/可改进之处**：
  1. **前视偏差与数据集构造细节未充分讨论**：跨市场语料的公司行动/复权处理、停牌与退市样本、幸存者偏差均未展开；tokenizer 的量化粒度对长尾波动的影响未做敏感性分析。
  2. **合成 K 线生成仅报告分布保真度（如统计矩/ACF）**，未做"生成数据→下游训练/回测"的闭环验证，即合成数据能否真正提升小样本市场（如 A 股）的预测。
  3. 预训练 120 亿条记录对多数机构不可复现；未公开蒸馏/持续预训练路线，零样本评测集中在欧美市场，中文 A 股/可转债等新兴市场覆盖不足。
  4. 与文本模态（新闻/公告）的融合缺失——对比 ChatTime（2412.11376）等图文时序模型，纯价格自回归的上限受限于弱有效市场假设。
- **精读结论**：Kronos 是"金融 TSFM = tokenizer + 自回归"路线的代表，其空白恰好是（a）新兴市场/小样本市场的领域适配与合成数据闭环、（b）防前视偏差的严谨评测、（c）新闻文本×K 线的多模态融合——三者均可作为后续 idea 的起点。

### 2.2 精读（Application Domains II · 论文 24 · TermGPT: Multi-Level Contrastive Fine-Tuning for Terminology Adaptation in Legal and Financial Domains）
- arXiv: 2511.09854（v2），作者 Yidan Sun, Mengying Zhu, Feiyue Chen, Yangyang Wu, Xiaolei Dan, Mengyuan Yang, Xiaolin Zheng, Shenglin Ben。
- **核心创新点**：
  1. 指出 LLM 嵌入空间的各向异性（isotropy）导致领域术语判别力差，是法律判决预测、金融风险分析失效的根源之一；
  2. 构造句子图（sentence graph）以刻画语义与结构关系，并据此生成"语义一致但可判别"的正负样本（上下文+拓扑线索）；
  3. 提出句子级+token 级的多层对比学习，同时增强全局上下文理解与细粒度术语判别；并构建首个来自官方监管文件的金融术语数据集。
- **不足/空白/可改进之处**：
  1. 英文摘要与中文摘要描述的版本不完全一致（中文版还提到 TermBench 六语言基准、文档级对比、合同分析/合规检查等下游），说明论文仍处于迭代中、评测口径不统一，术语数据集规模与划分未披露；
  2. 对比学习收益主要体现为嵌入空间指标，**缺乏与 RAG 检索、下游分类任务收益的端到端因果证明**——术语嵌入更"规整"是否真能带来检索精度/合规分类的增益未量化；
  3. 正负样本生成依赖图拓扑先验，当领域图稀疏（长尾监管条款）时样本质量退化；未与 LLM 驱动的难负例挖掘（hard negative mining）比较；
  4. 未讨论不同语言（中/英）术语的对齐与跨语言迁移，也未评测微调后是否保留通用能力（catastrophic forgetting 只字未提）。
- **精读结论**：TermGPT 把"isotropy 修复"作为金融术语适应的核心机制，这在领域嵌入社区是一个经典但重提的热点；其空白在于把术语表示收益转译为可量化的端到端金融任务收益（检索/合规/风控），这正是可执行的实验方向。

### 2.3 精读（Application Domains I · 论文 57 · FinRpt: Dataset, Evaluation System and LLM-based Multi-agent Framework for Equity Research Report Generation）
- arXiv: 2511.07322（v3），作者 Song Jin, Shuqi Li, Shukun Zhang, Rui Yan。
- **核心创新点**：
  1. 首次形式化"股权研究报告（Equity Research Report, ERR）生成"任务，填补 LLM 金融应用中的空白；
  2. 提出 7 种金融数据类型融合的数据集构建流水线，自动化产出高质量 ERR 数据集（可训练+可评测）；
  3. 建立含 11 个指标的 ERR 综合评估系统，并训练多智能体框架 FinRpt-Gen（SFT + 强化学习）。
- **不足/空白/可改进之处**：
  1. **评估指标多为文本/结构相似度与事实核对，未接入"报告中的数值预测是否与后续股价一致"这种经济有效性指标**——一份"文笔好但判断错"的报告会被 11 指标高估；
  2. 数据构建流水线依赖历史披露文件，若训练/评测切分未做 point-in-time 处理，报告生成会泄露未来信息（与 2.4 Chronology 的前视偏差问题同源）；
  3. 多智能体框架的"agent"角色设计与分工细节、RL 的奖励函数来源未在摘要中交代，可复现性存疑；代码与数据声称公开但未给链接；
  4. 未涉及中文 A 股报告（中文报告的行话、合规口径与美股不同），也未把报告生成与投资决策（信号→仓位）打通。
- **精读结论**：FinRpt 是"LLM 写研究报告"这条新赛道的基础设施工作。其最大空白是**把报告质量评价从"文本质量"升级为"事实锚定 + 点即时时序正确 + 决策有效性"三位一体**，这与 Chronology 的前视偏差主题天然互补。

### 2.4 精读（AAAI Emerging Trends in AI · 论文 183 · Do Large Language Models (LLMs) Understand Chronology? (Student Abstract)）
- arXiv: 2511.14214（v2），作者 Pattaraphon Kenny Wongchamcharoen, Paul Glasserman（哥伦比亚大学）。
- **核心创新点**：
  1. 把"LLM 是否理解时间顺序"分解为三类可测任务：乱序事件排序、条件排序（先过滤后排序）、基于多时间线交集的年代错误（anachronism）检测；
  2. 用"模型已知的事件"构造测试集，确保测的是预训练内部知识上的时间理解而非事实性；
  3. 跨 GPT-4.1 / GPT-5（hybrid-reasoning）/ Claude 3.7 Sonnet（含/不含 Extended Thinking）系统评测，发现：随序列增长 exact-match 率快速下降而秩相关保持高位（局部有序、全局时间线不一致）；推理模型 + 测试时扩展推理显著改善（GPT-5 高推理预算可达全长度完美排序）。
- **不足/空白/可改进之处**：
  1. 仅测"事件相对顺序"，未测**绝对时间戳/时区的钟表时间认知**、与日历/财报季的锚定，而这恰是金融回测中"我用的数据到 t 日为止"的关键；
  2. 事件均为已知历史事件，未覆盖**训练窗口外的近期金融事件**，因此无法直接刻画"回测期与训练窗口重叠"这一真实场景（测试的是记忆排序而非时序推理）；
  3. 样本量小、任务以英文为主，未做金融术语场景（如财报发布日期、分红除权日、限售解禁日）的专项评测；
  4. 给出现象（推理预算帮助排序）但未给出可操作的去偏方法——这是后续 idea 的直接落点。
- **精读结论**：Chronology 把"前视偏差审计"推向更底层：即便模型对事件"都知道"，它在时间线上也会搞乱顺序。这把"用 LLM 做金融预测必须防前视偏差"从工程告诫变成了可量化评测的学科问题，是生成"时序正确、污染可审计"评测基准的最佳理论支撑。

### 2.5 通读（AAAI Emerging Trends in AI · 论文 284 · PortfolioPilot: An Agentic Platform for Financial Portfolio Management Algorithm Development and Evaluation）
- DOI: 10.1609/aaai.v40i48.42396（AAAI-26 会议论文，2026-03-14），作者 Jared Chan Xu Yang, Haokai Ma, Yunshan Ma。
- **核心创新点**：开源智能体平台，用户用自然语言描述目标，系统经 Anthropic Claude API 动态合成可执行的 TypeScript 投资组合算法，在前端带安全校验运行，集成实时回测（历史行情）、经典优化（Markowitz/LSTM/ARIMA）与交互可视化，让无编程能力的金融从业者也能快速实验。
- **不足/空白/可改进之处**：
  1. 摘要中未见**防前视偏差/数据泄漏的系统级保障**（生成代码若引用未来数据、用未来因子回测，结果无效），而这恰是本主题其他论文的核心关切；
  2. 生成代码的**正确性验证**只提到"安全校验"（防注入），未提"逻辑正确性"（回测引擎是否与策略意图一致）、未提复现性与可审计日志；
  3. 经典算法库（Markowitz/LSTM/ARIMA）较浅，未接入现代因子模型/RL/TSFM（如 Kronos）；TypeScript 而非 Python 也限制了与主流 quant 生态（Qlib/FinRL）的衔接；
  4. 未涉及合规（用户画像与适当性匹配）、市场环境影响（容量/滑点）等真实部署约束。
- **通读结论**：PortfolioPilot 代表"NL→可回测算法"的智能体平台方向，工程价值明确，但离严谨量化研究还有系统性差距（防泄漏回测、逻辑校验、与 TSFM/RL 生态打通）。可与其差异化：把"自然语言生成策略 + 防前视静态检查 + 严谨回测审计"做成一个可复现的评测与研究框架。

## 三、外部前沿文献综述（含真实引用）

### 3.1 金融大语言模型（Financial LLM）与领域适配
- **综述与基础**：Li et al., *A Survey of Large Language Models in Finance (FinLLMs)*（arXiv:2402.02315）；Xie et al., *PIXIU: A Large Language Model, Instruction Data and Evaluation Benchmark for Finance*（arXiv:2306.05443）——首个金融指令微调 LLaMA（FinMA）与 9 数据集评测基准。
- **开源金融 LLM**：Yang et al., *FinGPT: Open-Source Financial Large Language Models*（arXiv:2306.06031）；Zhang et al., *FinGPT: Democratizing Internet-scale Data for Financial LLMs*（arXiv:2307.10485）；Araci, *FinBERT: A Pretrained Language Model for Financial Communications*（arXiv:2006.08097）。
- **领域适配方法论**：Gao et al., *Demystifying Domain-adaptive Post-training for Financial LLMs (FINDAP)*（arXiv:2501.04961）——系统研究金融域持续预训练+指令微调的联合训练配方；*SNFinLLM: Systematic and Nuanced Financial Domain Adaptation of Chinese LLMs*（arXiv:2408.02302）。
- **金融评测基准**：FinBen（arXiv:2402.12659）、FinEval（arXiv:2308.09975）、FinEval-KR（arXiv:2506.21591）、MME-Finance 多模态基准（arXiv:2411.03314）、Plutus 低资源希腊语金融（arXiv:2502.18772）、Evaluation and Benchmarking Suite for Financial LLMs and Agents（arXiv:2602.19073）、FINESSE-Bench（arXiv:2605.15482）、QuantEval（arXiv:2601.08689）。
- **系统级视角**：*Benchmarks Are Not Validation: A System-Level View of Financial LLM Applications*（arXiv:2607.28840）——批判"仅凭 benchmark 分数批准金融 LLM 上线"，要求数据/检索/智能体行为/治理/实现五层验证；*The Alpha Illusion*（arXiv:2605.16895）——直指 FinCon/FinMem/TradingAgents/FinAgent/FLAG-Trader 的 Sharpe 报告不可作为部署证据。这两篇是本主题报告类/智能体类 idea 的"评审红线"。

### 3.2 时间序列基础模型与金融 TSFM
- **通用 TSFM 家族**：TimeGPT-1（arXiv:2310.03589）；Chronos（arXiv:2403.07815）；Lag-Llama（arXiv:2310.08278）；TimesFM（arXiv:2310.10688）；Moirai（arXiv:2402.02592）与 Moirai-MoE（arXiv:2410.10469）；Timer-S1 十亿级串行扩展（arXiv:2603.04791）；ChatTime 数值-文本多模态 TSFM（arXiv:2412.11376）；Time-LLM 用 LLM 重编程做时序预测（arXiv:2310.01728）。
- **金融专用 TSFM**：Kronos（收藏论文，arXiv:2508.02739）；FinCast（arXiv:2508.19609）；LENS（arXiv:2408.10111）；DELPHYNE（arXiv:2506.06288）；*Advancing Financial Engineering with Foundation Models*（arXiv:2507.18577）综述了金融工程中 FM 的进展与挑战。
- **关键空白**：现有金融 TSFM 均以欧美市场为主、以价格自回归为主，跨市场小样本适配、合成数据闭环验证、与文本事件融合仍稀缺。

### 3.3 金融情感/事件/NER 与新闻驱动预测
- **情感**：Instruct-FinGPT 金融情感指令微调（arXiv:2306.12659）；*Enhancing Financial Sentiment Analysis via Retrieval Augmented LLMs*（arXiv:2310.04027）；中文细粒度金融情感（arXiv:2306.14096）；*Reasoning or Overthinking: Evaluating LLMs on Financial Sentiment Analysis*（arXiv:2506.04574）——发现过度推理反而伤害金融情感精度，与 Chronology 的"推理预算"结论形成张力。
- **事件/因子**：*Structured Event Representation and Stock Return Predictability (SER)*（arXiv:2512.19484）——用 LLM 抽取结构化事件做截面收益预测且可解释；Doc2EDAG 中文金融事件抽取（arXiv:1904.07535）；CausalStock 新闻驱动因果发现（arXiv:2411.06391）；LLMFactor 顺序知识引导提示抽因子（arXiv:2406.10811）；Ploutos 可解释金融 LLM 股价预测（arXiv:2403.00782）。
- **NER**：FiNER-ORD 金融 NER 数据集（arXiv:2302.11157）。
- **前视偏差在新闻信号中的实证**：*Assessing Look-Ahead Bias in Stock Return Predictions Generated By GPT Sentiment Analysis*（arXiv:2309.17322）——首次量化 LLM 情感策略的 look-ahead 与 distraction 两种偏差及其剥离方法。

### 3.4 LLM 交易智能体与多智能体系统
- **主流智能体**：FinMem 分层记忆交易智能体（arXiv:2311.13743）；FinAgent 多模态工具增强交易智能体（arXiv:2402.18485）；FinCon 概念口头强化多智能体（arXiv:2407.06567）；TradingAgents 多智能体交易框架（arXiv:2412.20138）；FLAG-Trader 梯度 RL 融合（arXiv:2502.11433）；LLM 交易智能体综述（arXiv:2408.06361）。
- **评测与"打假"**：StockBench 防污染真实市场评测（arXiv:2510.02209）；BacktestBench 自动化策略回测评测（arXiv:2605.17937）；*Summoning the Oracle to Slay It: Mitigating Look-Ahead Bias in Financial Backtesting with LLMs*（arXiv:2605.24564）；Market-Bench（arXiv:2512.12264）；Alpha Illusion（arXiv:2605.16895）。

## 四、研究 Idea（≥10个，完整实验方案）

> 硬件设定：4× NVIDIA L40（48GB×4 = 192GB）。全参微调 7B-13B（FSDP/DeepSpeed）；LoRA/QLoRA 可到 30B-70B；推理与数据合成可并行。
> API：DeepSeek V4 Flash（合成/抽取/常规生成）、DeepSeek V4 Pro（高难推理/评测）、Kimi K2.6（报告/长文生成）、Kimi K3（慎用）。

### Idea 1 · PiT-AuditBench：点即时刻金融 LLM 污染审计与时间理解评测基准
- **Idea 标题**：PiT-AuditBench：面向金融回测的 LLM 时序污染审计基准（PiT-AuditBench: A Point-in-Time Contamination and Chronology Audit Benchmark for Financial LLMs）
- **一句话简介**：构建"训练窗口重叠度可知、前视偏差可测"的金融时序审计基准，量化 LLM 在真实金融任务（排序/条件排序/事件时间戳）上的时间理解与记忆污染程度。
- **动机与现有不足**：Chronology 论文（AAAI Emerging Trends in AI · 论文 183）证明 LLM 对已知事件也会乱序，但只用"已知历史事件"，未覆盖训练窗口外的近期金融事件、绝对时间戳与财报/除权/解禁等金融日历锚点；Look-Ahead-Bench（2601.13770）与 StockBench（2510.02209）强调污染规避评测但未把"时间顺序理解能力"作为核心构造块；现有金融评测大多对切分期的 point-in-time 属性不做保证。
- **核心创新点**：(1) 把 Chronology 的三类任务（排序/条件排序/年代错误检测）落到金融事件实体（财报日、分红除权、限售解禁、宏观数据发布）并加入**绝对日期锚定与金融日历约束**；(2) 构造"训练窗口 overlap 已知"的事件集（按发布年度分成 LLM 训练窗口内/外两层），区分"记忆排序"与"时序推理"；(3) 输出一个标准化的 look-ahead risk score，可挂接到任何金融 LLM 管线。
- **方法概要**：从 SEC/交易所/开源财经 API 收集事件（公司行动、财报、宏观发布），构造 (a) 乱序排序集，(b) 条件排序集，(c) 多时间线交叉年代错误集，(d) 绝对时间戳问答题；用已知 cutoff 的开源模型（Llama-3.1-8B、Qwen2.5-7B、DeepSeek-V3）与 API 模型（GPT-4.1/DeepSeek V4 Pro/Claude）评测 exact-match、Kendall τ、时间误差；输出 look-ahead score = 训练窗口内样本上的超额记忆度。管线：数据收集→去重→人工+LLM 双重标注→评测→score 计算。
- **数据集与基线**：自建 PiT-AuditBench（~20k 事件，2023-2026 事件覆盖训练窗口内外）；对比基线：Chronology 原任务集（arXiv:2511.14214）、Look-Ahead-Bench（arXiv:2601.13770）、ExAnte（arXiv:2505.19533）。模型基线：Qwen2.5-7B、Llama-3.1-8B、GPT-4.1、DeepSeek V4 Pro。
- **评测指标**：主指标 look-ahead risk score（污染可测度）+ 时间排序 exact-match/τ；消融：绝对时间戳 MAE、金融日历约束违反率、不同训练窗口 overlap 水平下的分数梯度；回测严谨性：所有分数在"训练窗口内/外"分层报告。
- **算力与训练方案**：无需训练大模型；仅推理评测（7B 级 4×L40 并行 1-2 GPU·天；API 模型按量调用）。如需蒸馏打分器，LoRA 微调 7B 打分器约 1-2 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 批量抽取事件实体与时间属性；DeepSeek V4 Pro 作为排序答案的判分器（LLM-as-judge）并与规则计分交叉验证；Kimi K2.6 生成长格式金融事件描述用于构造难样本。
- **投稿目标会议与优先级**：ACL 2027 / AAAI 2027（benchmark 型）；**高**。
- **可行性与风险**：数据获取（SEC/交易所 API）可行；主要风险是"训练窗口 overlap"对闭源 API 不可精确已知，需用开源 cutoff 模型做代理+敏感性分析；风险中低。

### Idea 2 · ChronoRL：面向金融时序推理的测试时推理预算分配（test-time reasoning budget allocation）
- **Idea 标题**：ChronoRL：按任务难度自适应分配测试时推理预算以修复 LLM 金融时间理解（ChronoRL: Difficulty-Adaptive Test-Time Reasoning Budget Allocation for Financial Chronology Understanding）
- **一句话简介**：训练一个轻量"复杂度路由"模型，按事件序列长度/条件数/时间线交叉度动态决定 LLM 是否启用扩展推理（reasoning effort），在保证时序正确率的同时控制 API/推理成本。
- **动机与现有不足**：Chronology 论文发现推理模型+扩展推理显著改善排序，但全量开启推理成本高且 *Reasoning or Overthinking*（2506.04574）显示过度推理反而损害金融情感精度——"该想多久"没有策略；现有方案要么固定 effort，要么全部放弃推理。
- **核心创新点**：(1) 首个把"测试时推理预算"作为金融时序任务的**可学习决策**；(2) 路由信号不是表面难度而是"Chronology 复杂度特征"（序列长度、实体重叠、条件数、时间线数），并用强化学习按"正确率-成本"奖励优化；(3) 跨模型可迁移（路由学习输入特征，模型可换）。
- **方法概要**：基于 Idea 1 的 PiT-AuditBench 子集构造训练数据：对每个样本计算复杂度特征，运行多档 effort（low/medium/high）记录正确率与 token 成本；训练一个小型路由（XGBoost/小型 transformer），或直接 RL（策略 = 选 effort 档）最大化 正确率 − λ×成本；推理时：路由→选档→调 LLM→验证。基线：固定 high effort、固定 low effort、随机。
- **数据集与基线**：PiT-AuditBench + Chronology 原数据集；基线为固定 effort 策略与贪心策略。
- **评测指标**：主指标 帕累托曲线下面积（正确率×成本，AUC），时序 exact-match 在目标成本预算内；消融：各复杂度档的单独正确率、路由迁移性（在 GPT-4.1 学到的路由用于 DeepSeek 是否有效）。
- **算力与训练方案**：路由模型极小（<1 GPU·天）；数据收集需调用 API 多档评测（预算可控）；无大模型训练。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 多档推理样本生成；Kimi K2.6 生成难样本；DeepSeek V4 Flash 做低成本批量预筛选。
- **投稿目标会议与优先级**：ACL 2027 / NeurIPS 2026（推理效率方向）；**中-高**。
- **可行性与风险**：主要风险是"推理预算收益"是否足够稳定（Chronology 显示 GPT-5 高 effort 才完美）；需在 2-3 个模型家族上验证路由迁移性；风险中等。

### Idea 3 · FinAlign：把术语表示收益转译为端到端金融任务收益的对比微调框架
- **Idea 标题**：FinAlign：可证明术语表示收益的金融 RAG/合规对比微调框架（FinAlign: End-to-End Verifiable Contrastive Fine-Tuning for Financial Terminology, Retrieval, and Compliance）
- **一句话简介**：以 TermGPT 的 isotropy 修复为基础，把"术语判别"改造为"检索召回 + 合规分类 + 下游金融任务"可量化验证的三阶段对比微调。
- **动机与现有不足**：TermGPT（AAAI Application Domains II · 论文 24）证明多层对比微调改善术语判别，但只报嵌入指标，未证明 RAG 检索/合规分类/风控任务的端到端收益；且难负例依赖图拓扑，长尾监管条款退化。医学（CardioEmbed 2511.10930）与专利（PatenTEB 2510.22264）已有"领域嵌入+下游任务"基准范式，金融缺失。
- **核心创新点**：(1) 构造**金融术语难负例挖掘**——用 DeepSeek 生成"仅一词之差/语义极易混淆"的监管条款负样本，代替纯图拓扑；(2) 三阶段训练：MLM 域继续预训练 → 术语级+句子级对比（TermGPT 式）→ 用 RAG 检索与合规分类任务联合精调，让表示收益"可见"于任务；(3) 提供金融领域嵌入+下游任务联合基准（对标 CardioEmbed/PatenTEB 范式）。
- **方法概要**：数据：监管文件（SEC 规则、上交所/深交所规则、中文银保监文件）+ 金融公告；流程：文本清洗→术语/条款标注→DeepSeek 生成混淆负例→句子图构建（可选）→训练 7B embed/LLM（LoRA/QLoRA）→下游评估（检索 recall@k、合规二元分类、合同条款相似检索）。评测对比：原始模型、TermGPT 式、FinAlign 式。
- **数据集与基线**：自建 FinAlign-Bench（监管条款检索 + 合规分类，中英双语）；公开基线与数据：FinEval（2308.09975）、FinBen（2402.12659）、FiNER-ORD（2302.11157）；模型基线：Qwen2.5-7B、bge-m3、TermGPT 复现版。
- **评测指标**：主指标 检索 Recall@10 / nDCG + 合规分类 F1；消融：isotropy 分数（IC≈1 方向方差）、难负例 vs 图拓扑负例增益、下游任务相对上游任务收益的"可证明性"（任务指标与嵌入指标的斯皮尔曼相关）。
- **算力与训练方案**：QLoRA 微调 7B（4×L40，FSDP 分片），约 2-3 GPU·天/模型；数据合成靠 API 并行。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 批量生成混淆负例与监管条款改写；DeepSeek V4 Pro 做术语判别 LLM-as-judge；Kimi K2.6 生成中文合规问答对。
- **投稿目标会议与优先级**：ACL 2027 / EMNLP 2027 / ACL-FinNLP；**高**。
- **可行性与风险**：数据标注量可控（监管条款公开可得）；最大风险是"任务收益 vs 嵌入收益解耦"难做干净归因，需设计对照组；风险中等。

### Idea 4 · Kronos-CN：面向中国市场的金融 K 线基础模型（含合成数据闭环）
- **Idea 标题**：Kronos-CN：面向 A 股/港股/可转债的多市场 K 线基础模型与合成数据闭环（Kronos-CN: A Multi-Market Candlestick Foundation Model for Chinese Markets with Synthetic-Data-in-the-Loop）
- **一句话简介**：以 Kronos 为蓝本，预训练面向中国市场的 K 线 TSFM，并验证"合成 K 线→小样本市场训练→真实收益提升"的闭环。
- **动机与现有不足**：Kronos（AAAI Machine Learning VII · 论文 47）的语料集中于欧美交易所，未覆盖 A 股（涨跌停、T+1、停牌、复权、退市制度差异大）与可转债；其合成数据生成只报分布保真度，未做"合成数据→下游训练/回测"闭环；FinCast（2508.19609）与 LENS（2408.10111）同样缺中国市场细粒度处理。
- **核心创新点**：(1) 首个以 A 股/港股/可转债为主语料的 K 线 TSFM 预训练（涨跌停、停牌、前/后复权、T+1 规则的 tokenizer 感知）；(2) 设计**合成数据闭环评测**：用 Kronos-CN 生成合成 K 线→在数据稀疏的小票/新板块微调→比较回测 RankIC/换手率是否改善，证明生成保真度转化为下游收益；(3) 显式处理幸存者偏差与退市样本，做防前视复权。
- **方法概要**：数据：tushare/baostock/东方财富导出的全 A 股+港股+可转债日线/分钟线（先做分钟线可行性验证，日线为主），前/后复权双版本，剔除停牌；tokenizer：Kronos 式分位数 tokenizer + 涨跌停/一字板标记；预训练：自回归 next-token，7B 级（LoRA 起步）或 1-3B 全参；下游：价格 RankIC、波动率 MAE、合成数据→微调→回测闭环。回测严谨性：无前视复权、交易成本+滑点、T+1 约束、涨跌停不可成交约束。
- **数据集与基线**：自建 Kronos-CN 语料（2020-2026，数千只股票）；评测集：CSI300/中证500 成分、可转债样本；基线：Kronos 原版（2508.02739）、TimeGPT（2310.03589）、Chronos（2403.07815）、Moirai（2402.02592）零样本/微调版本。
- **评测指标**：主指标 RankIC（价格预测）与波动率 MAE、合成数据保真度（分布矩/ACF/收益分布）+ **合成数据闭环收益（微调后 RankIC 增量）**；消融：复权方式、涨跌停标记、退市样本剔除的影响。
- **算力与训练方案**：1-3B 全参（4×L40 FSDP）预训练 2-4 GPU·周；7B QLoRA 版本 1-2 GPU·周；合成数据生成并行推理。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 生成"市场制度描述→合成数据校验"的文档；DeepSeek V4 Pro 做回测报告总结与异常检测；本 idea 主体是纯模型训练，API 为辅助。
- **投稿目标会议与优先级**：ICML 2027 / NeurIPS 2026（基础模型）；**高**。
- **可行性与风险**：最大风险是**中国市场制度差异导致 TSFM 收益不如预期**（涨跌停使分布高度截断）；缓解：先跑 1-3B 小模型 + 单行业验证；数据获取（tushare 权限）是工程风险；风险中高。

### Idea 5 · NewsCast：点即时刻新闻事件 × K 线的多模态金融预测模型
- **Idea 标题**：NewsCast：防前视的"新闻事件 × K 线"多模态金融预测模型（NewsCast: Look-Ahead-Free Multimodal Fusion of News Events and Candlesticks）
- **一句话简介**：把 LLM 抽取的点即时刻新闻事件表示与 K 线 token 序列在时间轴对齐后联合预测收益与波动率，严格隔离新闻发布时间与交易时点。
- **动机与现有不足**：Kronos 纯价格自回归、无文本；M2VN（2510.20699）融合新闻与波动率但用 Time Machine GPT 做点即时刻 LLM，未公开且依赖收费 API；SER（2512.19484）用 LLM 抽取事件做截面预测但未做多模态时序融合；ChatTime（2412.11376）做数值-文本融合但面向通用 TSFM 非金融事件。前视偏差在新闻信号中已被实证（2309.17322），多数融合模型不设新闻-交易时间墙。
- **核心创新点**：(1) 显式的时间墙设计：新闻按发布时间(UTC)进入特征，交易信号只能使用 t 时刻前发布的新闻；(2) 事件级表示（谁-何时-何地-何事件）与 K 线 token 级表示在共享时间轴上融合（对齐注意/交叉注意力）；(3) 用开源 LLM 做点即时刻事件抽取，避免对收费 Time Machine GPT 的依赖，全程可复现。
- **方法概要**：数据：美股（Reuters/新闻 API 时间戳）+ A 股新闻；pipeline：新闻→LLM 事件抽取（结构化事件：公司/时间/事件类型/数值）→事件嵌入（LLM encoder，仅用发布时间前的模型版本）→与 Kronos-CN/Kronos 的 K 线 token 对齐→联合 transformer 预测下期收益/波动率。前视审计：在时间墙上随机"泄露"一组新闻作对照实验。
- **数据集与基线**：自建新闻-K线对齐数据集（公开新闻源 + tushare/Quandl 行情）；基线：Kronos（2508.02739）、M2VN（2510.20699）复现、SER（2512.19484）、纯事件因子模型。
- **评测指标**：主指标 RankIC/波动率 MAE + **前视对照（时间墙泄露 vs 不泄露的分数差）**；消融：事件结构表示 vs 朴素文本嵌入、对齐方式、新闻时效窗口。
- **算力与训练方案**：LLM 事件抽取用 API（DeepSeek Flash）批量处理；融合模型 1-3B（4×L40）2-4 GPU·天；K 线 encoder 可复用 Kronos-CN 预训练权重。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 大规模点即时刻事件抽取（这是本 idea 的 API 核心）；Kimi K2.6 生成新闻-事件的难样例；DeepSeek V4 Pro 做事件抽取质量 LLM-as-judge。
- **投稿目标会议与优先级**：ACL 2027 / EMNLP 2026-2027 / IJCAI 2027；**高**。

### Idea 6 · QuantCoder：自然语言→可回测量化策略代码的智能体平台（含防前视静态检查与回测审计）
- **Idea 标题**：QuantCoder：带防前视静态检查与回测审计的 NL→量化策略代码智能体平台（QuantCoder: An Agentic NL-to-Quant-Strategy Platform with Look-Ahead Static Checks and Backtest Auditing）
- **一句话简介**：在 PortfolioPilot 思路上扩展出"生成代码 + 防前视静态分析 + 严谨回测审计 + 可复现报告"的量化策略生成平台，解决"会写代码但写错/漏防泄漏"的问题。
- **动机与现有不足**：PortfolioPilot（AAAI Emerging Trends in AI · 论文 284）只做"安全校验（防注入）"而无**逻辑正确性与防前视校验**；BacktestBench（2605.17937）证明 LLM 生成的回测代码错误率高；Alpha Illusion（2605.16895）指出 Sharpe 报告≠部署证据。生成型量化策略平台亟需"生成正确且无泄漏代码"的系统保障。
- **核心创新点**：(1) **防前视静态检查器**：AST/数据流分析检测未来数据引用（如用未来收益率、用 t+1 收盘做 t 决策）、幸存者偏差（用全量股票池 vs 存活池）；(2) **回测审计模块**：交易成本/滑点/T+1/停牌涨跌停约束 + 与前视检查结果的交叉验证；(3) 智能体闭环：生成→静态检查→回测→失败反馈→重生成（LLM 修复），产出带审计日志的可复现报告。
- **方法概要**：平台 = 策略 DSL（Python 子集）/ 向量化算子库 + 静态分析器（自定义 AST visitor + 污染传播分析：标注"未来信息源"并追踪其流向）+ 回测引擎（开卷）/ 事件驱动回测 + 审计报告生成器。智能体：DeepSeek/Kimi 生成代码→静态检查返回错误类别→LLM 自修复（≤3 轮）→最终回测。评测集：BacktestBench 式"已知泄漏 bug 注入"测试集 + 人工标注策略。
- **数据集与基线**：BacktestBench（2605.17937）与自建 QuantBugSuite（注入 10 类常见泄漏/逻辑 bug）；基线：直接生成（无检查）、纯静态检查（无 LLM 修复）、PortfolioPilot 式安全校验。
- **评测指标**：主指标 无泄漏代码生成率（BugSuite 上泄漏检出率/修复率）+ 生成代码在回测引擎上的收益一致性（代码意图 vs 回测结果）；消融：LLM 修复轮数、检查器假阳性率、不同基座模型。
- **算力与训练方案**：无需大模型训练；代码生成/修复走 API（预算可控）；静态分析器轻量本地跑；4×L40 仅用于并行推理多个候选策略。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 生成策略代码候选；Kimi K2.6 做长策略文档与审计报告生成；DeepSeek V4 Pro 做"代码-意图对齐"判分（LLM-as-judge）。
- **投稿目标会议与优先级**：ICML 2027（工具/Agent）/ AAAI 2027 Demo；**中**。
- **可行性与风险**：主要风险是**静态分析对"隐性未来信息"（如调用外部 API 取未来数据）检测不完整**；需明确定义受支持数据源白名单并做污染传播；风险中。

### Idea 7 · FinRpt-Ground：事实锚定与决策有效的股权研究报告生成
- **Idea 标题**：FinRpt-Ground：点即时刻事实锚定 + 数值一致性验证的股权研究报告生成（FinRpt-Ground: Fact-Grounded and Decision-Effective Equity Research Report Generation）
- **一句话简介**：在 FinRpt 基础上把报告生成改造成"检索点即时刻披露 → 生成 → 数值一致性与决策有效性验证 → 重写"的闭环，报告评价从文本指标升级为"事实锚定 + 数值一致性 + 预测校准"。
- **动机与现有不足**：FinRpt（AAAI Application Domains I · 论文 57）的 11 指标偏文本质量，未接经济有效性；*Financial Statement Analysis with LLMs*（2407.17866）证明 LLM 财报分析预测强，但未与报告生成打通；FAITH（2508.05201）与 Deficiency（2311.15548）证明金融 LLM 幻觉严重，报告生成最怕"编数字"。Point-in-Time RAG（2605.31201）展示了点即时刻检索可行性。
- **核心创新点**：(1) **点即时刻检索**：只让报告引用报告日之前已披露的财报/公告（时间墙），杜绝"未来财报数字"进入报告；(2) **数值一致性验证器**：对生成的每个财务数字做来源追踪（claim→原始披露单元格），检出幻觉并触发重写；(3) **决策有效性指标**：报告的评级/目标价与后续实际收益的校准（rank-IC、命中率），把评价从"写得好"升级为"说得对"。
- **方法概要**：pipeline：股票×时间点→检索点即时刻披露（财报/公告/研报）→多智能体（数据抽取/财务分析/行文/合规）分步生成→数值验证器（对齐 + 来源追踪）→合规检查（免责声明/风险提示）→最终报告+审计。训练：基于 FinRpt 数据集 SFT + 用验证器信号做 RL（奖励 = 事实性 + 数值一致性 + 决策有效性）。
- **数据集与基线**：FinRpt（2511.07322）、自建中文 A 股报告集（研报公开数据）；基线：FinRpt-Gen（2511.07322）、直接 RAG 生成、Template-Based 报告生成（2504.14233）。
- **评测指标**：主指标 数值幻觉率（来源可追踪率）+ 决策有效性（评级校准、目标价 IC）；消融：11 文本指标（与 FinRpt 对齐）、点即时刻 vs 全量检索的影响、RL 奖励各项贡献。回测严谨性：训练/评测时间切分不重叠。
- **算力与训练方案**：7B 级 SFT+RL（4×L40，FSDP）3-6 GPU·周；验证器可独立训练（NLI 式数字对齐模型）2-3 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 批量抽取披露数字与生成草稿；Kimi K2.6 生成长报告/行文润色；DeepSeek V4 Pro 做"数值-来源对齐"判分与最终事实性 judge。
- **投稿目标会议与优先级**：ACL 2027 / ACL-FinNLP / EMNLP 2026；**高**。
- **可行性与风险**：最大风险是**数值验证器的召回/精度权衡**（漏检幻觉比误报更严重）；需引入人工标注的幻觉测试集；披露数据的点即时刻可得性是数据工程重点；风险中高。

### Idea 8 · MarketSim-Eval：用市场仿真检验 LLM 投资智能体的行为一致性与制度稳健性
- **Idea 标题**：MarketSim-Eval：市场仿真驱动的 LLM 投资智能体行为评测（MarketSim-Eval: Market-Simulation-Based Behavioral Evaluation of LLM Investment Agents）
- **一句话简介**：在可控的多智能体市场仿真环境中系统评测 LLM 投资智能体的策略一致性、制度适应性与回测稳健性，回答"换市场环境后智能体是否还言行一致"。

- **数据集与基线**：MarketSim-Bench 自建；基线智能体：FinMem（2311.13743）、FinAgent（2402.18485）、FLAG-Trader（2502.11433）复现版；对比人类标注行为。
- **评测指标**：主指标 行为一致性分数（规则遵守率）+ 制度迁移鲁棒性（不同制度下收益-风险变化）；消融：有无显式规则提示、推理预算、多智能体 vs 单智能体。
- **算力与训练方案**：无大模型训练；仿真+API 推理为主（4×L40 并行多智能体推理），数 GPU·周。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 作为市场仿真中的交易智能体（大批量决策）；DeepSeek V4 Pro 做行为审计 LLM-as-judge；Kimi K2.6 生成仿真场景剧本。
- **投稿目标会议与优先级**：AAMAS 2027 / ICML 2027 / NeurIPS 2026（智能体评测）；**中-高**。
- **可行性与风险**：主要风险是**仿真与真实市场差异大，结论外推受限**；应明确定位为"行为评测"而非"收益预测"；风险中等。

### Idea 9 · FinFactCheck：面向金融数字与表格的幻觉检测与可溯源验证器
- **Idea 标题**：FinFactCheck：金融表格/数字幻觉检测与可溯源验证器（FinFactCheck: Traceable Fact-Checking and Numerical Verification for Financial LLM Outputs）
- **一句话简介**：构建一个通用的金融"数值-来源"验证器模型与基准，可插拔到报告生成、QA、RAG 任何 LLM 管线，把幻觉检测从文本层下沉到数字层。
- **动机与现有不足**：FAITH（2508.05201）做了表格幻觉评估但止于检测分类；Fighting Numerical Hallucinations（2605.31064）偏工程编译技巧；Deaf 于*Deficiency of LLMs in Finance*（2311.15548）指出现有 LLM 在金融数字上系统性失败。缺少一个"检测+定位+溯源+修复"的端到端验证器。
- **核心创新点**：(1) 把验证建模为**数字级 claim-证据对齐**（不只是文段级别），输出"数字→表格单元格→披露来源"的三级溯源；(2) 训练一个专用验证模型（比对 LLM 输出与点即时刻证据，含数字抽取/对齐/矛盾判定），可离线打分；(3) 验证器可作为 RL 奖励函数（与 Idea 7 协同但独立可复用）。
- **方法概要**：数据：公开财报（SEC XBRL、A股披露）+ 合成的含错报告（DeepSeek 注入 10 类数字错误：抄错、单位错、时期错、四舍五入错、来源张冠李戴）；验证器 = 检索（数字+上下文）→ 抽取（所有数字 claim）→ 对齐（与证据单元格匹配）→ 判定（一致/矛盾/无法验证）；评测在含错注入与真实 RAG 输出上。输出可插拔 API。
- **数据集与基线**：自建 FinFactBench（含错注入 + 人工标注）；基线：FAITH（2508.05201）、通用 NLI 验证器、GPT-4o/DeepSeek 零样本验证、InfoLoss/信息论方法（2512.03107 的 92% 降幻觉方法）。
- **评测指标**：主指标 数字级精确率/召回率/F1（幻觉检出）+ 溯源准确率；消融：不同错误类型、不同证据噪声、检索窗口大小。
- **算力与训练方案**：验证器 7B（LoRA）1-2 GPU·天；数据合成用 API 并行。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 大规模合成含错报告与抽取数字；Kimi K2.6 生成自然化错误注入；DeepSeek V4 Pro 做零样本验证基线与一致性 judge。
- **投稿目标会议与优先级**：ACL 2027 / EMNLP 2026；**高**。
- **可行性与风险**：最大风险是**数字对齐在表格异构（XBRL/PDF 文本/图片）下召回低**；先用结构化 XBRL 保证基础集，再扩展非结构化；风险中等。

### Idea 10 · RiskChat：面向合规与风控的可解释金融对话智能体（监管问答+适当性）
- **Idea 标题**：RiskChat：监管条款增强的可解释金融合规/风控对话智能体（RiskChat: Regulation-Anchored, Explainable Compliance and Risk Conversational Agent）

- **投稿目标会议与优先级**：ACL 2027 / ACL-FinNLP / EMNLP 2026；**中**。

### Idea 11 · Chrono-Aug：为金融时序模型注入时间线先验的数据增强与自监督
- **Idea 标题**：Chrono-Aug：时间线一致的金融序列自监督数据增强（Chrono-Aug: Chronology-Consistent Self-Supervised Augmentation for Financial Sequence Models）
- **一句话简介**：在预训练阶段引入"事件时间线"自监督目标（排序/时距/周期性），让 TSFM/LLM 学到金融时间线先验，从源头缓解前视与乱序问题。
- **动机与现有不足**：Chronology 证明 LLM 全局时间线不一致；现有 TSFM 预训练只有 next-token，未显式教模型"事件在时间线上如何组织"；Synthetic Preference Data 增强时间理解的思路（2510.03955，面向视频）尚未迁移到金融时序。
- **核心创新点**：(1) 新增三类时序自监督：时间线排序预测、相对时距预测（如"事件A比B早多少天"）、周期/日历锚定（财报季、除权日模式）；(2) 与 next-token 目标联合训练（多任务），不改变推理接口；(3) 迁移性：该自监督可加在任何 TSFM/金融 LLM 预训练之上。
- **方法概要**：在 Kronos-CN（Idea 4）预训练流程中增加时间线头：输入 K 线段+事件标记→预测 (a) 事件段乱序后的正确排序（对比/分类），(b) 事件对相对时距（回归），(c) 周期性锚定（分类）；loss 加权联合；下游评测排序与预测。实验对比：有/无 Chrono-Aug 的预训练在 Idea 1 基准与 RankIC 上的表现。
- **数据集与基线**：Kronos-CN 语料 + PiT-AuditBench（Idea 1）；基线：无 Chrono-Aug 的 Kronos 式预训练、TimeGPT/Chronos。
- **评测指标**：主指标 时间线排序准确率（Idea 1 评测）+ RankIC 保持/提升；消融：各自监督目标单独贡献、权重灵敏度。
- **算力与训练方案**：在 Idea 4 的 1-3B 预训练上叠加（增加 ~10-20% 算力，4×L40 2-4 GPU·周）。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 生成带时间戳的事件描述与难排序样本，构造自监督数据的"语义增强"变体。
- **投稿目标会议与优先级**：ICML 2027 / NeurIPS 2026；**中**。
- **可行性与风险**：主要风险是**新增自监督目标可能干扰 next-token 主线**（负迁移）；需认真调权重与消融；风险中。

### Idea 12 · FinAgent-RLHF：以"回测收益-风险"与事实性为奖励的金融智能体强化学习
- **Idea 标题**：FinAgent-RLHF：融合回测信号与事实性奖励的金融决策智能体对齐（FinAgent-RLHF: Aligning Financial Decision Agents with Backtest-Validated and Factual Rewards）
- **一句话简介**：用"严格回测的风险调整收益 + 输出事实性 + 行为一致性"组成的奖励函数，对 LLM 交易/投顾智能体做 RL 对齐，使智能体既会赚钱（可验证口径下）又讲真话。
- **动机与现有不足**：FinRpt-Gen 的 RL 与 FLAG-Trader（2502.11433）的梯度 RL 奖励多为"文本质量/信号"；FinRL-DeepSeek（2502.07393）做风险敏感 RL 但未对齐事实性；Alpha Illusion 强调"回报必须可验证"。缺少把**可验证回测信号**作为奖励源的对齐方法。
- **核心创新点**：(1) 奖励 = λ1×回测风险调整收益（严格约束：成本/滑点/T+1/无前视）+ λ2×事实性（Idea 9 验证器得分）+ λ3×行为一致性（Idea 8 规则遵守）；(2) 用 GRPO/PPO 在多环境（市场状态采样）训练；(3) 输出对齐后智能体的"可验证归因"（钱从哪来、是否靠泄漏）。
- **方法概要**：环境：MarketSim（Idea 8）+ 真实历史数据回测器（开卷）；奖励计算闭环：动作→成交→下期收益（经成本修正）→奖励；训练：7B 基座（Qwen2.5-7B/DeepSeek 蒸馏小模型），GRPO，4×L40；评测：对齐前后在 StockBench 风格防污染评测 + 行为审计（Idea 8）。
- **数据集与基线**：StockBench（2510.02209）、自建 A 股评测期；基线：SFT 智能体、无事实性奖励的 RL、FinMem/FinAgent 复现。
- **评测指标**：主指标 可验证风险调整收益（Sharpe/Calmar，防污染口径）+ 事实性分数（Idea 9）+ 行为一致性；消融：奖励权重、训练步数。
- **算力与训练方案**：7B GRPO（4×L40 FSDP）3-6 GPU·周；环境仿真与奖励计算与训练解耦（预生成 episode）。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 生成多样市场状态训练轨迹与决策理由；DeepSeek V4 Pro 做奖励信号的判分（事实性/一致性 judge）；Kimi K2.6 生成长程决策复盘文档。
- **投稿目标会议与优先级**：NeurIPS 2026 / ICML 2027；**高**。
- **可行性与风险**：最大风险是**回测奖励方差大、易过拟合到特定市场状态**；需多市场状态采样 + 严格的 hold-out 期 + 防止 reward hacking（用验证器交叉约束）；风险中高。

### Idea 13 · CrossLingTerm：跨语言金融术语对齐与多语言合规检索
- **Idea 标题**：CrossLingTerm：中英金融术语对齐与跨语言合规检索（CrossLingTerm: Cross-Lingual Financial Terminology Alignment and Multilingual Compliance Retrieval）
- **一句话简介**：构建中英监管/研报术语对齐数据集与跨语言术语嵌入，解决"中文条款搜不到英文对照/术语翻译不一致"导致的合规与检索失败。
- **动机与现有不足**：TermGPT 的 TermBench 声称覆盖六种语言但评测未披露细节；Dólares or Dollars（2402.07405）发现金融 LLM 跨语言能力不均衡；金融领域的跨语言术语对齐检索（类似 Wikipedia 实体对齐）缺失。
- **核心创新点**：(1) 首个中英金融监管术语对齐数据集（条款级+术语级，含译法一致性标注）；(2) 跨语言对比微调：用对齐术语对做跨语言难负例对比训练，嵌入空间对齐后跨语言检索无需翻译；(3) 评测：跨语言监管检索（中文查询→英文条款）与术语一致性。
- **方法概要**：数据：证监会/交易所中文规则 + SEC/交易所英文规则按主题对齐，术语对抽取（DeepSeek 辅助+人工抽查）；训练：双语 embed 模型（Qwen 多语言/ bge-m3 微调）对比学习；评测：跨语言 Recall@k、术语一致性（同义不同译检出）。
- **数据集与基线**：自建 RegAlign-ZHEN；基线：bge-m3、mE5、通用翻译后检索（MT+检索）。
- **评测指标**：主指标 跨语言检索 Recall@10/nDCG + 术语对齐 F1；消融：有无跨语言对比训练、负例类型。
- **算力与训练方案**：embed 模型 LoRA 微调（4×L40）1-2 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 术语对抽取与译法候选生成；Kimi K2.6 生成中文合规长文；DeepSeek V4 Pro 做术语一致性 LLM-as-judge。
- **投稿目标会议与优先级**：ACL 2027 / EMNLP 2026；**中**。
- **可行性与风险**：主要风险是**中英监管文件并非逐条对应**，对齐标注难（需人工审核子集）；风险中等。

## 五、综述性结论与投稿策略

### 5.1 结论

1. **前视偏差是金融 AI 的第一公理问题**。从 Chronology（收藏论文 183）到 Look-Ahead-Bench、BacktestBench、Alpha Illusion、FINSABER，2025-2026 社区共识是：任何金融 LLM 成果若不报告点即时刻数据、训练窗口 overlap 与防污染回测，其"收益"都不可信。**本主题 5 篇收藏论文中，Chronology、PortfolioPilot、FinRpt 都直接相关，Kronos 也隐含此问题**——把"时序正确+污染可审计"做成方法论基础设施是最高杠杆的选题。
2. **金融 TSFM 处于"欧美价格自回归"垄断、中国市场与多模态融合空缺**。Kronos 之后，A 股制度感知的 K 线基础模型（Idea 4）、新闻×K 线防前视融合（Idea 5）、时序自监督增强（Idea 11）都是可填补的空白。
3. **报告生成从"写得好"转向"说得对、说得可追溯"**。FinRpt 的 11 指标缺经济有效性；事实锚定+数值验证+决策有效性（Idea 7）+ 可插拔验证器（Idea 9）构成完整补全。
4. **术语/表示工作必须端到端证明收益**。TermGPT 类工作的软肋是"嵌入指标≠任务指标"；用 RAG/合规/跨语言任务闭环（Idea 3、13）来证明价值，比单报 isotropy 更有说服力。
5. **智能体工作必须通过"行为审计+可验证回测"双闸门**。以 Alpha Illusion / Benchmarks Are Not Validation 为红线，量化智能体的提交应配套行为评测（Idea 8）与 RL 对齐（Idea 12）。

### 5.2 投稿策略建议

- **主打一条主线做深**：建议以"防前视偏差的金融时序基础模型 + 严谨回测"为主打（Idea 4/5/11 与 Idea 1/2 的审计基建），它们互相支撑且与 3 篇收藏论文（Kronos、Chronology、PortfolioPilot）直接呼应，novelty 论证最顺。
- **首选 NeurIPS 2026（9 月截稿）**：Idea 4（Kronos-CN）、Idea 5（NewsCast）、Idea 12（FinAgent-RLHF）贴合基础模型/RL 口味；Idea 1（审计基准）可作附赠评测基建。
- **ACL 2027 / ACL-FinNLP**：Idea 3（FinAlign）、Idea 7（FinRpt-Ground）、Idea 9（FinFactCheck）、Idea 13（CrossLingTerm）是 NLP 顶会友好的"任务+数据+模型"完整闭环。
- **ICML 2027 / AAMAS 2027**：Idea 6（QuantCoder 工具）、Idea 8（MarketSim 评测）、Idea 11（Chrono-Aug）。
- **风险对冲**：4×L40 约束下，优先落地"推理为主"的审计/评测类 idea（1、2、6、8）作为保底产出；预训练类（4、5、11）用小模型 1-3B 先行验证再扩展。
- **评审红线自检**：每篇投稿都应在 method 里含"防前视/点即时刻切分/成本与制度约束/训练窗口 overlap 审计"一节，主动回应 Alpha Illusion 式质疑，这本身就是加分项。
