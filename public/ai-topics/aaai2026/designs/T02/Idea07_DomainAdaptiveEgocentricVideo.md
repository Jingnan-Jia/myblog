# 实验设计书：领域自适应第一人称视频理解（Domain-Adaptive Egocentric Video Understanding）

> 主题：T02 视频理解与视频多模态大模型 ｜ 优先级：高 ｜ 目标会议：CVPR 2027 或 EgoCross Challenge @ EgoVis 2027

## 0. 摘要

EgoCross（Computer Vision V·论文77）表明通用与专用模型在跨域第一人称视频问答上域外泛化均差；领先方案 OmniEgo-R2（arXiv:2605.24481）靠"每域单独 SFT + 路由"获得第二，但需大量目标域数据、不做联合/自适应训练。本工作提出 **领域共享 + 领域专属双 LoRA** 架构：共享 LoRA 学习通用第一人称结构（手部交互、运动视差），专属 LoRA 学习域内视觉语法（手术器械纹理、工业设备、动物视角运动学）；配合**域自适应 GRPO**（对难域——手术/极端运动——加大探索与奖励缩放）与**合成目标域数据**（DeepSeek 生成域内描述与 QA + 风格增强）。四域混合训练，按域路由到专属 LoRA。预期贡献：(1) 首个面向 EgoCross 四域的联合域自适应方法；(2) 在 EgoCross 官方测试上超越 OmniEgo-R2 开源方案；(3) 双 LoRA 的域共享/专属分工分析。

## 1. 研究背景与动机

### 1.1 问题定义

给定第一人称视频与四类域（手术、工业、极限运动、动物视角），模型需完成预测/识别/定位/计数四类任务。挑战：(a) 域间视觉语法差异大（手术器械 vs 动物镜头），单模型难兼顾；(b) 各域标注数据稀缺；(c) 联合训练易互相干扰（灾难性遗忘/负迁移）。

### 1.2 相关工作不足

- **基准+试点**：EgoCross（Computer Vision V·论文77）只有微调/RL 试点，无成套方法。
- **领先方案弱项**：OmniEgo-R2（arXiv:2605.24481）每域单独 SFT + 路由推理，需大量目标域数据、无跨域知识共享、无自适应训练；EgoCross Challenge 2026 官方技术报告（arXiv:2608.04589）确认方法空白。
- **多域共享方法缺位**：EgoExo4D（arXiv:2311.18259）是多视角技能学习（第一/第三人称同步）而非跨域泛化；EgoExoLearn 聚焦程序活动。
- **空白**：共享+专属参数化 + 域自适应 RL + 合成目标域数据的联合框架。

### 1.3 为什么是现在、为什么你的环境

- **时机**：EgoCross Challenge 2026 已办一届、官方评测就绪；域自适应视频理解是 EgoVis 2027 热门赛道。
- **环境契合**：双 LoRA（rank 32×2）+ GRPO ≈ 10-14 GPU·天在 4×L40 内可行；合成数据 DeepSeek 离线生成成本可控。

## 2. 研究目标与可验证假设

- **H1（双 LoRA 优于单 LoRA）**：共享+专属双 LoRA 在四域平均上优于单一 LoRA 与每域独立微调。
  *成立时的可观测结果*：EgoCross O.Avg 提升 ≥2 点；难域（手术/极端运动）提升显著。
- **H2（域路由有效）**：按域路由到专属 LoRA 比"全域共享一套参数"更优。
  *成立时的可观测结果*：路由消融版 O.Avg 最高。
- **H3（域自适应 GRPO 增益）**：对难域加大探索与奖励缩放提升难域准确率且不伤易域。
  *成立时的可观测结果*：难域提升 ≥3 点、易域不掉点。
- **H4（合成数据有效）**：合成目标域数据作为冷启动/预热显著降低对真实目标域数据的依赖。
  *成立时的可观测结果*：仅 50% 真实目标域数据 + 合成数据 ≈ 全量真实数据效果。

## 3. 总体方法设计

### 3.1 数据流水线

1. **语料**：EgoCross 四域（手术/工业/极限运动/动物视角，~1000 QA）+ EgoExo4D + EgoSchema。
2. **合成目标域数据（DeepSeek V4 Pro）**：对每域生成域内描述与 QA——手术（器械名/操作步骤/无菌区），工业（装配/安全动作），极限运动（动作序列/身体姿态），动物视角（行为/运动）。约束：不使用受保护或非公开影像内容，仅用公开许可素材的域风格描述。
3. **风格增强**：对合成数据做域风格图像增强（色彩/纹理/运动模糊匹配域特性）。
4. **过滤**：双 LLM（DeepSeek V4 Pro + Kimi K2.6）验证 QA 合法性与域内真实性；人工抽检 5%。预期 **每域 ~3K、合计 ~12K**。

### 3.2 模型/算法设计

- **基座**：Qwen2.5-VL-7B。
- **共享 LoRA（rank 32）+ 专属 LoRA×4（rank 32）**：共享 LoRA 全量激活；输入按域标签路由激活对应专属 LoRA（MoE 式软路由，路由权重由轻量 router 输出，训练时以域标签为硬监督、推理时由 router 预测）。
- **域自适应 GRPO**：奖励 `r_d = s_d · r_correct`，其中 s_d 为域奖励缩放系数（难域 1.5、易域 1.0，按难域=手术/极端运动设置）；探索温度对难域提高（rollout 温度 1.0 vs 0.8）。
- **训练目标**：SFT（四域混合，域标签条件化）+ GRPO（域自适应奖励）。
- **防遗忘**：EWC 式正则（对共享 LoRA 施加 Fisher 加权约束，系数 0.1）。
- **超参初值**：lr 1e-5（SFT）/1e-6（GRPO）；batch 16；8 rollout/组；3 epoch。

### 3.3 训练流程
- Stage 0：合成数据冷启动预热（仅合成数据，2-3 天）；Stage 1：SFT 混合（真实+合成，4 天）；Stage 2：GRPO 域自适应（4-5 天）。
- 2 卡训练 + 2 卡 rollout/评测并行。

### 3.4 推理与评测流程
- 推理：router 预测域 → 激活共享+对应专属 LoRA → 作答；temperature=0。
- 评测：EgoCross 官方 O.Avg（四域）+ 各域准确率 + OpenQA/CloseQA。

## 6. 实验矩阵

- **A（主实验）**：完整（共享+专属 LoRA + 域自适应 GRPO + 合成预热）。
- **B1（架构消融）**：单 LoRA / 共享+专属（硬路由）/（软路由）。
- **B2（训练消融）**：纯 SFT / SFT+GRPO（统一奖励）/ SFT+GRPO（域自适应）。
- **B3（数据消融）**：无合成 / 50% 合成 / 全合成；EWC 有/无。
- **C（鲁棒性）**：路由噪声（oracle vs 预测）、合成数据污染、域不平衡。
- **D（泛化性）**：EgoSchema 零样本；训练域子集 → 评测全域（迁移实验）。

## 7. 评测协议

- 指标：EgoCross O.Avg、四域各自 accuracy、OpenQA/CloseQA、路由准确率、遗忘率（训练后 EgoSchema Δ）。
- 3 种子 mean±std；bootstrap p<0.05；逐域报告。

## 8. 算力与资源计划（4×L40）

- 阶段 GPU·天：预热 3 + SFT 4 + GRPO 5 + 评测 2 = **≈13 GPU·天**（预算 11-15）。
- 存储：模型 + 视频缓存 400GB。
- API：DeepSeek V4 Pro 合成四域 QA ≈ 700 万 token；Kimi K2.6 域内 judge ≈ 250 万 token；成本 ≈ **$300-650**。
