# 实验设计书：Idea 8 Verify-FP — 约束验证闭环的 LLM + 扩散楼层平面图生成（可迭代修正）

> 对应调研报告 Idea 8。在 HouseTune 两阶段基础上加"约束图 + 可微验证器 + 失败回灌"闭环，让生成可验证、可重试。

## 0. 摘要

Verify-FP 把"LLM 提议 → 扩散落地"升级为"LLM 提议 → 扩散落地 → 验证器校验 → 失败报告回灌 → LLM 修订 + 局部重生成"的闭环，精确满足面积、连通、朝向、规范等硬约束。创新点：形式化约束图（房间-邻接-面积-朝向）作条件输入；可微验证器（连通性可达矩阵、面积偏差、规范检查）输出结构化 JSON 失败报告；失败时 LLM 据报告修改布局、扩散对受限区域做 inpainting 式局部重生成（至多 K 轮）。条件扩散 ~300M（4×L40，约 3–4 GPU·天）+ 验证器规则引擎，总预算约 5 GPU·天。验证器与 LLM 修订为推理期 API 成本。

## 1. 研究背景与动机

### 1.1 问题定义

输入自然语言需求（"三室两厅，主卧朝南，面积 20m²，客厅与阳台连通"）→ 输出满足约束的矢量平面图（房间多边形、墙、门、窗）。硬约束集 $\mathcal{C}$（邻接、面积、连通、朝向、建筑规范）必须被验证与满足，失败可重试。

### 1.2 相关工作不足

- 收藏论文（Computer Vision XIII · 论文 102 · HouseTune: Two-Stage Floorplan Generation with LLM Assistance）的 DNPP 只能"精修"LLM 初稿，结构性错误（通道不通、面积冲突、房间数不符）无法修复，无验证反馈闭环。
- `HouseDiffusion`（arXiv:2211.13287）无条件控制；`LayoutGPT`（arXiv:2305.15393）无几何保证；`FloorPlan-DeepSeek`（DOI:10.52842/conf.ecaade.2025.2.175）证明 LLM 直接生成平面图可行但不精确。
- 图条件扩散（DOI:10.1109/ivcnz67716.2025.11281849）与 inpainting 平面图（DOI:10.1016/j.autcon.2026.107037）分别提供图条件与局部重生成基础，但无人组合成"可验证闭环"。

### 1.3 为什么是现在、为什么你的环境适合做

- 约束验证 + LLM 反馈的"验证-修正"范式是生成式 CAD/建筑 AI 的通用方法论，2025–2026 正在成型；HouseTune 提供直接上界。
- 环境适配：条件扩散 300M 是 4×L40 轻松负载；验证器为规则引擎零训练；LLM 修订用 API（推理期成本）。

## 2. 研究目标与可验证假设

1. **H1（约束满足率显著提升）**：闭环后硬约束满足率（连通性/面积偏差/规范违反）比 HouseTune 提升 ≥20 个点，且 K=3 轮内收敛。
   - 观测：RPLAN/HouseTune 协议评测集上的约束审计。
2. **H2（反馈回灌必要）**：移除"失败报告回灌 LLM"后，迭代退化为随机重采样，提升消失。
   - 观测：消融（无反馈 vs 有反馈）。
3. **H3（局部重生成优于整体重采样）**：对受限区域 inpainting 重生成比全图重采样约束满足率高、且不破坏已满足区域。
   - 观测：面积偏差/连通性与"非受限区域 IoU 保持度"对比。
4. **H4（约束图条件有用）**：把需求解析为约束图作条件输入比纯文本条件提高面积命中率（±5% 误差内）。
   - 观测：约束编码方式消融。

## 3. 总体方法设计

### 3.1 数据流水线（含 API prompt 思路）

1. **基础数据**：RPLAN 平面图 + 建筑标注（公开数据集）→ 解析为 (房间多边形, 墙, 门, 窗) + 邻接图。HouseTune 风格文本需求由标注自动生成。
2. **约束图重标注**：对每图自动抽取约束集 $\mathcal{C}$：房间数、面积区间、邻接对、朝向、连通性（可达）。约 60K 张。
3. **需求文本多样化（Kimi K2.6）**：由约束集生成多样化自然语言需求（60K 条），用于训练条件扩散的文本/约束双编码与 LLM 提议阶段。
4. **失败样本挖掘**：用预训练扩散/LLM 提议对 60K 需求生成初始平面图，验证器打标失败类型（房间数错/通道断/面积冲突/规范违反），构造"需求→失败报告→修订后真值"的闭环训练对（20K 条）。

### 3.2 模型/算法设计

**Stage1 LLM 提议（DeepSeek V4 Pro，CoT）**：输入需求 → 输出 Layout-Init（房间框 + 邻接 + 相对尺寸）。prompt 模板（中文注释）：

```
你是建筑平面图规划师。给定用户需求与约束集 C（房间数/面积/邻接/朝向/规范），
按 CoT 输出：1) 房间拓扑（邻接图）；2) 初始布局（房间矩形 + 位置关系）；
3) 候选门/窗位置。输出 JSON。不得违反 C 中的硬约束。
```

**Stage2 约束图条件扩散（~300M，HouseDiffusion 骨干改造）**：
- 条件编码：约束图 $G_C$ 经 GNN/Transformer 编码成条件 token；与噪声向量拼接进 denoiser。
- 双流：房间多边形离散坐标 + 房间属性连续向量联合去噪（HouseDiffusion 式）。
- inpainting 变体：对需重生成区域做局部条件去噪（遮罩区域重采样），参考 DOI:10.1016/j.autcon.2026.107037。

**验证器（规则引擎，可微可选）**：
- 连通性：房间/通道可达矩阵 BFS，输出断点对列表。
- 面积偏差：每个房间目标面积 vs 实际面积。
- 朝向/规范：门窗对齐、通道最小宽度（如 1.2m）、消防通道、房间日照朝向。
- 输出结构化 JSON 失败报告（失败类型 + 涉及房间 + 建议）。

**闭环迭代**：
$$\text{Layout}_{k+1}=\text{Denoise}\big(\text{LLMRevise}(\text{Layout}_k, \text{Report}_k)\big),\quad k=1..K,\ K=3$$
LLMRevise：把失败报告翻译为"修改动作"（改房间框/加通道/换朝向）；扩散只对报告涉及区域重生成。早停：验证器通过或相似度 < 阈值。

### 3.3 训练流程

- 条件扩散：4×L40 DP，global batch 64，25K 步，lr 3e-4 cosine，约 3–4 GPU·天。
- LLM 提议/修订：API 推理，无需训练（可选：用 20K 闭环对做 LoRA 偏好微调 1 GPU·天）。
- 验证器：规则引擎，零训练。

### 3.4 推理与评测流程

输入需求 → LLM 提议 → 扩散落地 → 验证器 → （失败）LLM 修订 + 局部重生成 → 循环至 K 轮 → 输出最终平面图 + 验证报告。批量评测：1K 需求 × {K=0,1,3}，记录约束满足率、结构指标、轮数分布。

统一口径：同一 1K 评测需求、同一约束审计脚本（连通性/面积/规范）、同一结构指标实现（IoU/JSD）。

## 6. 实验矩阵

- **A（主实验）**：Verify-FP vs 全基线（约束满足率 + 结构指标 + 用户需求命中率）。
- **B（消融）**：验证器反馈有无；约束编码方式（文本 vs 约束图 vs 拼接）；K 轮数（0/1/3/5）；局部重生成 vs 整体重采样；LLM 修订 LoRA 有无。
- **C（鲁棒性）**：极端需求（10 房间、不规则地块）；矛盾约束（用户要求冲突）；规范子集（消防通道等）压力测试。
- **D（泛化性）**：跨数据集（RPLAN → 外部平面图）；不同 LLM 提议者（V4 Pro vs K2.6）。

## 7. 评测协议

- 指标：约束满足率（连通性 100% 目标、面积偏差 ≤5% 房间占比、规范违反数 0 目标）；IoU/JSD（结构）；需求命中率（属性匹配）；平均迭代轮数。
- 统计：3 种子；二项检验（满足率，n=1K）；报告 95% CI；消融报 Δ。

## 10. 风险与备选方案

| 风险 | 等级 | 缓解 |
|---|---|---|
| 验证器规则覆盖不全 | 中高 | 可扩展规则 DSL + 定期审计新增规范 |
| 迭代发散/震荡 | 中高 | 限 K=3 + 相似度早停 + 约束满足率单调监控 |
| 扩散能力够不上约束 | 中高 | 数据中强化难约束样本（失败挖掘） |
| LLM 修订"阳奉阴违" | 中 | 修订必须作用于约束图实体（结构化动作）而非自由文本 |
| RPLAN 偏规整、域窄 | 中 | 跨数据集泛化实验 + 不规则地块压力测试 |
