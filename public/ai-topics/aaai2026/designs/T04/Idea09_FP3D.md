# 实验设计书：Idea 9 FP-3D — 文本→平面图→3D 室内场景的一致级联生成与空间合理性评测

> 对应调研报告 Idea 9。以平面图为可验证中间锚，2D/3D 几何显式对齐；提出"可居住性"评测协议。

## 0. 摘要

FP-3D 把"文本→平面图"延伸为"文本→约束平面图→结构化 3D 室内场景"的一致级联：Stage1 复用 Idea 8 的约束闭环生成满足需求的平面图；Stage2 用 2D 扩散（HouseCrafter 类，arXiv:2406.20077）从平面图多视角渲染提升为 3DGS 网格，LLM 负责家具清单与布局语义，3D 网络负责几何-外观。提出可居住性评测协议（面积利用率、通行宽度、家具碰撞、采光朝向 + 人类评审）。总预算约 6–8 GPU·天，属长周期工作。

## 1. 研究背景与动机

### 1.1 问题定义

输入文本需求 → 输出 (满足约束的平面图, 对应 3D 室内场景)（网格/高斯 + 家具布局），要求 2D/3D 几何一致、空间可居住（碰撞可通行、采光合理、面积利用率高）。

### 1.2 相关工作不足

- 收藏论文（Computer Vision XIII · 论文 102 · HouseTune: Two-Stage Floorplan Generation with LLM Assistance）只停在 2D 平面图。
- `HouseCrafter`（arXiv:2406.20077）做平面图→3D 但无文本条件与约束控制；`SPATIALGEN`（arXiv:2509.14981）做布局引导 3D 生成但布局来自模型内部，2D/3D 不一致。
- 无"端到端文本→满足约束的 3D 房间 + 2D/3D 一致"方案。

### 1.3 为什么是现在、为什么你的环境适合做

- 2D 扩散（HouseCrafter）与 3DGS 优化成熟；3D-FRONT（arXiv:2011.09127）提供带语义家具的室内数据；LLM 可低成本生成家具清单。
- 环境适配：Stage2 2D 扩散 LoRA（~1B）+ 每场景 3DGS 优化分钟级，均落在 4×L40 预算内。

## 2. 研究目标与可验证假设

1. **H1（中间锚保一致）**：有平面图中间锚的 2D/3D 几何一致性（墙/家具 IoU、投影误差）显著优于无锚端到端方案。
   - 观测：3D-FRONT 子集上墙 IoU 提升 ≥0.15、投影点距误差降 ≥30%。
2. **H2（分层生成优于端到端）**：先几何后外观的分层流水线比端到端生成碰撞率低、可居住指标更好。
   - 观测：家具碰撞率与通行宽度指标对比。
3. **H3（LLM 家具规划有贡献）**：LLM 生成的家具清单/布局语义提升家具类别覆盖率与摆放合理性（人类评审 +12 分）。
   - 观测：消融（无 LLM vs 有 LLM）。
4. **H4（可居住性评测可区分方法）**：可居住性指标与人类"可居住度"评分显著相关（|r|>0.7）。
   - 观测：200 场景人工评分相关性分析。

## 3. 总体方法设计

### 3.1 数据流水线（含 API prompt 思路）

1. **Stage1 平面图**：复用 Idea 8 的约束闭环（LLM CoT 提议 + 扩散落地 + 验证器），产出 5K 个满足约束的平面图（训练用 3D-FRONT 的平面图+3D 配对，推理用文本需求）。
2. **家具清单与布局（DeepSeek V4 Pro）**：输入平面图房间划分 + 户型 → LLM 输出家具清单（类别、数量、尺寸）与布局语义（贴墙/居中/朝向）。prompt 含房间尺寸约束与通行宽度硬约束。
3. **3D 数据构造**：3D-FRONT 提供 (平面图, 3D 场景, 家具 mesh)。渲染多视角图（每场景 32 视角）作为 2D 扩散监督；家具 mesh 保留作布局真值。
4. **多样化房间描述（Kimi K2.6）**：生成 20K 条多样化需求文本（风格/预算/使用者），用于条件训练。

### 3.2 模型/算法设计

**Stage1（复用 Idea 8）**：LLM + 约束扩散出平面图。

**Stage2（2D 扩散 LoRA + 3DGS）**：
1. **平面图条件 2D 扩散**（HouseCrafter 骨干 + LoRA rank 64）：输入平面图线稿/语义分割图 → 输出多视角室内 RGB（相机位姿由平面图坐标反投影给定）。
2. **3DGS 场景构建**：多视角 RGB + 深度估计 → 3DGS 初始化 → 每场景可微渲染优化（分钟级）。家具 mesh 从 3D-FRONT 库按 LLM 清单检索，按布局语义放置并做碰撞规避。
3. **2D-3D 一致性**：投影一致性损失 $\mathcal{L}_\text{proj}=\sum_{\pi}\|P_\pi(\text{3D})-I_\pi\|$（家具占用体素投影 vs 2D 分割），约束级联误差。

**可居住性评测器（规则 + 可计算）**：
- 面积利用率 = 家具占用体积 / 房间体积。
- 通行宽度：通道最窄宽度（≥0.9m 达标）。
- 家具碰撞率：mesh 重叠体积占比。
- 采光朝向：窗朝向与房间用途匹配度。

**超参数**：2D 扩散 LoRA lr 1e-4，24K 步；3DGS 优化 lr 1e-3，2K 步/场景。

### 3.3 训练流程

- Stage2a 2D 扩散 LoRA：4×L40 DP，global batch 32，24K 步，约 3 GPU·天。
- Stage2b 每场景 3DGS 优化：并行 4 卡 × 数分钟/场景；5K 场景 ≈ 2 GPU·天。
- Stage1 复用 Idea 8 checkpoint（若独立训练 +3 GPU·天）。

### 3.4 推理与评测流程

文本需求 → Stage1 平面图 → LLM 家具规划 → Stage2 2D 扩散多视角 → 3DGS 构建 + 家具放置 → 渲染俯视图/透视 → 可居住性评测器打分 + Kimi 空间合理性评审 → 输出 JSON 报告。批量流水线自动化。

## 6. 实验矩阵

- **A（主实验）**：FP-3D vs 基线（2D/3D 一致性 + 可居住性 + 渲染质量 PSNR/FID）。
- **B（消融）**：中间锚有无；结构化分层 vs 端到端；LLM 家具规划有无；投影一致性损失有无。
- **C（鲁棒性）**：不规则地块；大户型（10+ 房间）；家具库外类别。
- **D（泛化性）**：跨数据集（3D-FRONT → 其他室内）；不同需求风格。

## 7. 评测协议

- 指标：墙/家具 IoU、投影点距误差（2D/3D 一致）；面积利用率、通行宽度达标率、碰撞率、采光匹配（可居住性）；PSNR/FID（渲染质量）；人类可居住度评分（5 人 × 200 场景）。
- 统计：3 种子；均值±std；人类评分报 ICC（组内相关）；相关性报 Pearson + 95% CI。

## 10. 风险与备选方案

| 风险 | 等级 | 缓解 |
|---|---|---|
| 级联误差累积（LLM→平面图→3D 任一环失败放大） | 高 | 逐级评测 + 人工可检视中间产物 + 投影一致性损失 |
| 2D→3D 几何漂移 | 中高 | 平面图中间锚 + 投影一致性 + 深度监督 |
| 家具类别多样性不足 | 中 | 3D-FRONT 预置类别库起步；检索增强 |
| 可居住性评测争议 | 中 | 规则文档化 + 人类评分验证（H4） |
| 工程量大 | 中高 | 每级独立里程碑；先做 200 场景端到端 demo 再扩量 |
