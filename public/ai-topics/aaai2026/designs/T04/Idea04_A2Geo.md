# 实验设计书：Idea 4 A2Geo — 语言 Agent 交互式跨视角目标地理定位（Ask-Select-Verify 闭环）

> 对应调研报告 Idea 4。视觉定位模块为被调用的"工具"，LLM（DeepSeek V4 Pro）为决策编排者，Kimi K2.6 为独立验证者。

## 0. 摘要

A2Geo 把 MoPT 这类"LLM 只当提示源"升级为"LLM 当决策者"的 agentic 闭环：UAV 持续提问 → 视觉定位模块生成候选（语言/框/点多模态）→ LLM 结合卫星上下文与地理常识验证 → 不满足则请求新视角/新提示 → 循环直至输出坐标。创新点：任务拆解 + 工具调用（ReAct 式，arXiv:2210.03629）、多模态候选互相验证 + 可解释二元判断、主动视角请求策略。视觉模块训练与 MoP-UAV（Computer Vision XII · 论文 67）同量级（2–4 GPU·天），planner 走 prompt 工程 + 轻量偏好微调（可选 QLoRA 1–2 GPU·天）。总预算约 5–8 GPU·天，API 为主要运行时成本。

## 1. 研究背景与动机

### 1.1 问题定义

输入：UAV 视角图像（或视频帧）+ 多模态提示（自然语言描述、目标框、点击点）+ 卫星地图服务。输出：目标的地理坐标（经纬度）与置信度。系统需在单轮定位失败时，通过"询问-验证-再询问"的闭环利用地理常识（如"湖泊东侧桥下"）与主动视角选择收敛到正确位置。

### 1.2 相关工作不足

- 收藏论文（Computer Vision XII · 论文 67 · Learning Better UAV-Based Cross-View Object Geo-Localization from Multi-Modal Prompts: MoP-UAV Benchmark and MoPT Framework）首次引入语言/框/点提示，但 LLM 只做初始提示源，**无推理循环**；定位失败无法二次约束。
- 判别式单轮方法：`VAGeo`（arXiv:2501.07194）、`MOGeo`（arXiv:2603.13843）、`Recurrent CVGL`（arXiv:2509.12757）、`Anchor-free CVGL`（arXiv:2509.25623）全部单轮，无验证与视角决策。
- 缺"感知 + LLM agent 闭环 + 主动视角"的完整系统；这是收藏论文明确预告的方向。

### 1.3 为什么是现在、为什么你的环境适合做

- Agent 工具调用（ReAct）与多模态 LLM API 成熟；跨视角定位网络（MoPT 类）已有开源基线。DeepSeek V4 Pro/Kimi K2.6 可作为低成本、可并行的 planner/verifier。
- 环境适配：视觉模块训练量小（2–4 GPU·天）；planner 无需大训练；主要成本是 API 推理，正好在预算内。

## 2. 研究目标与可验证假设

1. **H1（闭环优于单轮）**：带 Ask-Select-Verify 循环的 A2Geo 端到端成功率比单轮 MoPT + LLM 提示高 ≥8 个点。
   - 观测：MoP-UAV 评测集上成功率 62% → ≥70%。
2. **H2（地理常识验证有效）**：LLM 用卫星上下文 + POI 文本做"是不是这里"的二元验证，能拒绝单轮误检（误接受率降 ≥30%）。
   - 观测：双 LLM（V4 Pro + K2.6）一致性投票后误接受率显著下降。
3. **H3（主动视角有增益）**：允许请求新视角时，≤50m 命中率 +5 个点，且平均轮数 ≤3。
   - 观测：多轮协议（自建 MoP-UAV 多视角变体）对比单轮。
4. **H4（提示改写有用）**：Kimi 把模糊语言提示改写为可检索表述，使候选生成 Top-k 召回 +10%。
   - 观测：改写前后召回对比。

## 3. 总体方法设计

### 3.1 数据流水线（含 API 提示/合成）

1. **视觉模块训练数据**：MoP-UAV（Computer Vision XII · 论文 67）语言/框/点提示对；MOGeo（arXiv:2603.13843）图像对；补 CVGlobal 风格检索数据（公开多地点 UAV-卫星对，若可得）。
2. **Agent 评测数据**：自建 500 个任务（从 MoP-UAV 扩展）：每个任务 = {UAV 图, 初始提示（语言/框/点）, 卫星地图瓦片集, GT 坐标, 可请求的新视角候选集（预渲染不同高度/朝向）}。
3. **提示工程数据**：DeepSeek V4 Pro 生成 2K 条"模糊→可检索"改写对；Kimi K2.6 生成"失败归因"文本（定位失败原因分类：遮挡/视角差/歧义）。
4. **POI 上下文**：用公开 OSM 数据为卫星瓦片附加 POI 文本（名称+类型+相对方位描述）。

### 3.2 模型/算法设计

**系统架构（ReAct 式工具调用循环，arXiv:2210.03629）**：
- **工具1 视觉定位模块**（复现 MoPT 网络，双塔 + 交叉注意力，作为被调用工具）：输入 UAV 图 + 提示 → 输出候选 (坐标, 置信度, 特征)。
- **工具2 卫星上下文检索**：候选位置 → 裁剪卫星瓦片 256² + 附近 POI 文本。
- **工具3 视角请求**：返回可请求的新视角候选（高度/朝向变化的预渲染 UAV 图）。
- **LLM Planner（DeepSeek V4 Pro）**：循环执行 — 解析提示 → 调用工具1 → 若有验证证据调用工具2 → 二元判断"是不是这里"+ 理由 → 置信不足则调用工具3 → 输出最终坐标。
- **独立 Verifier（Kimi K2.6）**：对 LLM 判断做独立验证，双模型一致性投票（硬约束：视觉模块置信度 < 阈值时禁止接受）。
- **状态/预算**：限定最大轮数 4、token 预算 8K/任务。

**训练**：视觉模块按 MoPT 训练协议（跨视角对比损失 + RefCOCOg 预训练）。Planner：零样本 prompt 为主；可选轻量偏好微调（用 500 任务中成功/失败轨迹构造偏好对，QLoRA 微调 7B 开源 VLM，rank 32）。

### 3.3 训练流程

- 视觉模块：4×L40 DP，global batch 128，2–4 GPU·天（与 MoPT 同量级）。
- Planner 偏好微调（可选）：QLoRA 1–2 GPU·天。
- 其余为推理期成本。

### 3.4 推理与评测流程

对 500 任务逐任务运行 agent 循环（API 调用），记录每轮动作/置信度/最终输出；离线计算命中率与轮数；双 LLM 投票做验证。评测脚本并行调用 API（限速 20 req/s）。

## 5. 基线复现

| 基线 | 官方代码 | 说明 |
|---|---|---|
| MoPT（论文67 框架） | 官方（若开源） | 单轮判别式 + LLM 提示变体 |
| VAGeo（arXiv:2501.07194） | 官方仓库 | 单轮 |
| MOGeo（arXiv:2603.13843） | 官方仓库 | 单轮 |
| Fine-Grained CVGL（arXiv:2308.16906） | 官方仓库 | 单轮 + 语言提示变体 |
| A2Geo 无验证循环 | 本工作 | 消融中间体 |
| 随机视角基线 | 本工作 | 主动策略 vs 随机请求 |

统一口径：同一 500 任务、同一命中半径定义（≤50m/≤100m）、同一轮数上限 4。

## 6. 实验矩阵

- **A（主实验）**：A2Geo vs 全基线（成功率/≤50m/≤100m/平均轮数/API 成本）。
- **B（消融）**：无验证循环 vs 有；单提示 vs 主动多视角；双 LLM 投票 vs 单模型；视觉置信度硬约束阈值（0.3/0.5/0.7）；planner 微调有无。
- **C（鲁棒性）**：提示噪声（拼写错误/歧义指代）；夜间/季节子集；极端视角差。
- **D（泛化性）**：跨基准（MoP-UAV → MOGeo 交叉评测）；不同 LLM（V4 Pro vs K2.6 各作 planner）。

## 7. 评测协议

- 指标：端到端成功率（输出坐标被验证模块接受且 ≤50m）；≤50m/≤100m 命中率；平均轮数；误接受率（验证说"是"但实际错）；API token 成本/任务。
- 统计：3 种子（agent 随机性固定）；报告均值±std；成功率做二项检验（n=500）；双 LLM 一致率。

## 10. 风险与备选方案

| 风险 | 等级 | 缓解 |
|---|---|---|
| LLM 幻觉式验证（说"是"其实不是） | 高 | 视觉置信度硬约束 + 双 LLM 一致性投票 |
| Agent 循环开销大/发散 | 中高 | 限轮 4 + token 预算 + 相似度早停 |
| 基准缺多轮/主动视角协议 | 中高 | 自建 500 任务多视角变体（MoP-UAV 扩展） |
| MoP-UAV 数据未开源 | 中 | 用 MOGeo + 自建子集替代 |
| API 评测成本超预算 | 低 | 缓存 + 抽样验证（100 任务子集） |
