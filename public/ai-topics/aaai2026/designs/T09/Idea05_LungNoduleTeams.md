# 实验设计书：肺结节协作多智能体的记忆进化与可复现评测协议（LungNoduleTeams）

> 对应调研报告「六、研究 Idea」Idea 5｜肺结节协作多智能体的记忆进化与可复现评测协议。主题：T09 医疗AI与AI for Science。硬件：4×L40（192GB）。API：DeepSeek V4 Flash/Pro、Kimi K2.6。优先级：中高。

## 0. 摘要（3-5 句）

本研究把 LungNoduleAgent 的"检测→描述→推理"流水线升级为**可审计的协作决策系统** LungNoduleTeams：每个诊断结论附带"检测框、分割掩膜、知识库引文、置信度"四元组证据流；检测/描述/推理三 agent 分歧时由 LLM 仲裁器结合病理知识库裁决并记录理由；离线把误判病例提炼成经验条目写回知识库实现记忆进化；并推出基于 LIDC-IDRI 全划分 + 报告级/结节级双轨指标的**可复现评测协议**。主指标为恶性分类 AUC/F1、结节级 Dice、证据完备率与医生一致性 κ。预算约 3–4 GPU·天 + API 调用。

## 1. 研究背景与动机

### 1.1 问题定义

专病医疗多智能体（肺结节）由检测器、区域描述模型、推理医生 agent 协作诊断，核心问题：(a) agent 间只是"流水线拼装"，无分歧仲裁与证据链，错误无护栏地传播（检测假阴直接进入诊断）；(b) 评测依赖私有多中心数据，不可复现；(c) 无记忆——相同误判会重复发生。目标：加入证据流、仲裁、记忆进化与统一评测协议，使系统可审计、可复现、可增量改进。

### 1.2 相关工作不足

- **（Multiagent Systems·论文 57·LungNoduleAgent: A Collaborative Multi-Agent System for Precision Diagnosis of Lung Nodules）DOI:10.1609/aaai.v40i35.40225**：三段流水线 + 知识库，但无分歧仲裁、无证据链、私有数据不可复现。
- **Evo-MedAgent [arXiv:2604.14475]**：记忆+反思+自我进化，但面向通用医学且不针对肺结节；**AgentRx [arXiv:2605.10286]**：医疗 agent 标准评测基准，但非专病。
- **MedAgent-Pro [arXiv:2503.18968]**：证据化多模态工作流，但文档检索而非图谱；**TeamMedAgents [arXiv:2508.08115]**：团队协作理论，无记忆进化。
- **空白**：专病肺结节 + 证据四元组 + 分歧仲裁 + 记忆进化 + 开源评测协议的组合。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：LungNoduleAgent（2026）刚建立专病范式，Evo-MedAgent/AgentRx 刚提出记忆与评测方向，把两者落到肺结节专病并补仲裁是 2026 窗口。
- **环境匹配**：检测/分割用公开预训练权重少量微调（1–2 天）；7B 描述模型 LoRA 1 天；LLM agent 走 API；LIDC-IDRI 公开可获；4×L40 足够。

## 2. 研究目标与可验证假设

1. **H1（证据流提升可审计性）**：四元组证据流使错误可追溯、可修正，证据完备率显著高于无证据版本。*成立时的可观测结果*：证据完备率 ≥90%；因可追溯修正而提升的端到端 AUC ≥0.01。
2. **H2（仲裁优于多数投票）**：LLM 仲裁器对分歧的裁决准确率高于多数投票。*成立时的可观测结果*：仲裁正确率 > 多数投票 ≥8pt（人工标注 200 例仲裁质量）。
3. **H3（记忆进化带来增量改进）**：把误判案例写回知识库后，第二轮同类误判率下降。*成立时的可观测结果*：记忆库构建后同类别误判率下降 ≥15%（相对）。
4. **H4（评测协议可复现）**：LIDC-IDRI 全划分 + 双轨指标协议在不同运行下稳定。*成立时的可观测结果*：5 折交叉验证主要指标 3 种子波动 ≤2pt。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据流水线

1. **LIDC-IDRI 划分**：按患者切 5 折；每折结节级/报告级双轨：结节级（检测框+分割 mask+恶性度 1–5）；报告级（为每例生成结构化诊断报告文本，标注 finding 实体）。
2. **多中心模拟**：如无真多中心数据，用 LIDC 内部按扫描设备/采集协议分组模拟域偏移（声明为代理指标）。
3. **知识库构建（离线）**：RadLex 术语 + Fleischner 指南摘要 + 从 PubMed 检索的肺结节综述/指南文献摘要（DeepSeek V4 Flash 生成条目化摘要 + 引文）。
4. **经验记忆库（evaluated memory）**：训练/验证期把"检测错、描述错、推理错"的案例由 LLM 复盘生成经验条目（格式：`{"scenario":..., "signal":..., "rule":..., "source_case":...}`）写回知识库，在线检索注入。
5. **脱敏**：不使用任何真实患者身份信息；LIDC 为去标识公开数据。

### 3.2 方法设计（模块拆解）

1. **Nodule Spotter（检测）**：YOLOv8 或 3D CNN（公开预训练），对 LIDC 微调；输出结节框 + 置信度。
2. **分割**：nnU-Net（2D/3D），在 LIDC 结节 mask 上微调；输出分割掩膜（供四元组）。
3. **区域描述（7B VLM）**：Qwen2.5-VL-7B / LLaVA-Med LoRA rank 16；输入结节裁剪图 + 上下文，输出区域描述（位置、边缘、密度、大小）。
4. **推理医生 agent（DeepSeek V4 Pro）**：多 agent 辩论（3 个不同角色的医生 prompt）→ 分歧仲裁器：LLM-as-judge 结合知识库引文裁决，输出 `{"malignancy":"low|intermediate|high", "reasoning":"...", "evidence_ids":[...], "confidence":...}`。
5. **证据四元组**：每个结论 `(bbox, mask, citation_id, confidence)` 绑定；证据完备率 = 有完整四元组支撑的结论占比。
6. **记忆进化（离线，非在线训练）**：每一折结束后用 DeepSeek V4 Pro 复盘误判→经验条目→写库；下一折检索注入（不污染测试折——严格按折隔离）。

### 3.3 训练流程

- 检测/分割微调：YOLO/nnU-Net，AdamW，lr 1e-4，各自 1–2 天（LIDC 规模）。
- 描述 VLM LoRA：20k 结节裁剪样本 ×2 epoch ≈ 1 天。
- 推理 agent：零微调（API 驱动）。
- 记忆进化：无梯度更新，纯知识库操作。

### 3.4 评测流程

- 结节级：检测 AP/Dice、恶性分类 AUC/F1。
- 报告级：报告 BLEU-4、结构化 finding 匹配。
- 系统级：证据完备率、仲裁一致性（与多数投票对比）、记忆增量。
- 临床：与放射科医生诊断一致性 Cohen's κ（双医生盲评 100 例）。

## 4. 数据集细节

### 4.1 来源、许可与伦理合规
- **LIDC-IDRI**：TCIA 公开去标识数据，免申请，需遵守 TCIA 条款并在论文致谢标注源。
- 可申请的多中心 CT（如有）：需 IRB + 数据共享协议（DPA）；本文默认以 LIDC 5 折 + 域偏移模拟替代。
- 伦理：回顾性公开数据；不涉及活体患者互动；输出仅供学术评测，不构成临床建议；论文声明"辅助诊断研究、未经临床验证"。

### 4.2 划分与预处理
- 患者级 5 折（nodule 分层保证各折恶性/良性比例相近）。
- 预处理：CT 重采样 + 窗位窗宽（肺窗）；结节裁剪以 mask bbox 为中心加边距；报告文本规范化。

## 5. 基线复现

| 基线 | 获取方式 | 复现要点 |
|---|---|---|
| LungNoduleAgent [DOI:10.1609/aaai.v40i35.40225] | 官方数字或按论文复现 | 三段流水线（无仲裁/记忆） |
| MedAgent-Pro [arXiv:2503.18968] | 公开流程复现 | 文档检索工作流 |
| MedAgents [arXiv:2311.10537] | 公开代码 | 多角色零样本 |
| 单模型 Qwen2.5-VL / GPT-4o | API/权重 | 端到端诊断 |
| 纯检测+分类管线（无 LLM） | 复现 | 结构化基线 |

- **统一口径**：同一 5 折划分、同一报告模板、同一知识库快照（静态）用于无记忆基线；统计 3 种子均值±std。
- **预期指标表**（占位）：恶性 AUC LungNoduleAgent ~0.90→本方法 ~0.92；证据完备率 无=0→仲裁后 ~0.9；κ 医生一致性 ~0.6–0.7。

## 6. 实验矩阵

- **A 主实验**：LungNoduleTeams vs 全部基线（AUC/F1/Dice/BLEU/证据完备率）。
- **B 消融**：B1 无仲裁（多数投票）；B2 无记忆（静态知识库）；B3 无证据流（报告生成与判定耦合）；B4 描述 agent 换成更强/更弱 VLM；B5 知识库大小（1k/5k/10k 条目）。
- **C 鲁棒性**：C1 检测器假阴注入（模拟漏检）；C2 域偏移（按设备分组外推）；C3 节点描述噪声。
- **D 记忆进化**：D1 多轮迭代误判率曲线；D2 记忆条目质量人工评估 200 条；D3 记忆检索的精度。

## 7. 评测协议

- **主指标**：恶性分类 AUC、结节级 Dice、证据完备率、医生一致性 κ。
- **次指标**：检测 AP、报告 BLEU-4、仲裁正确率、记忆增量（同类误判率下降）。
- **临床指标**：双医生盲评 κ + 与金标准（LIDC 众包标注）一致率。
- **显著性**：5 折 × 3 种子配对 t 检验 p<0.05；AUC 用 DeLong；报告均值±std。
- 评测协议与划分文件开源（HF + GitHub）。

## 10. 风险与备选方案

| 风险 | 影响 | 备选方案 |
|---|---|---|
| 多中心数据不可得 | 中 | LIDC 5 折 + 设备/协议域偏移模拟（声明代理）；结论相应收敛 |
| 仲裁器过度依赖 API 能力 | 中 | 人工抽检 200 例仲裁质量门控；若 V4 Pro 不足用 Kimi K2.6 或双模型仲裁 |
| 检测假阴传播 | 高 | 证据流 + 护栏：检测低置信时不进推理，标记"需复核" |
| 记忆进化提升不显著 | 中 | 更激进地提炼规则；扩大记忆库；若仍低则如实报告并转为分析性贡献 |
| 评测协议稳定性差 | 中 | 固定划分 + 3 种子 + 固定知识库快照；波动 >2pt 时先排查 prompt 随机性 |
| 数据合规 | 低 | LIDC 公开去标识；多中心若不可得不启用；论文声明辅助诊断边界 |
