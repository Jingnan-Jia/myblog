# 实验设计书：证据可追溯的药物发现多智能体 RAG（DrugTraceRAG）

> 对应调研报告「六、研究 Idea」Idea 6｜证据可追溯的药物发现多智能体 RAG。主题：T09 医疗AI与AI for Science。硬件：4×L40（192GB）。API：DeepSeek V4 Flash/Pro、Kimi K2.6。优先级：高。

## 0. 摘要（3-5 句）

本研究提出 DrugTraceRAG：在 CLADD 的药物发现 RAG 智能体之上加入**"声明—证据—来源"三级审计与跨源矛盾消解**，让每个答案句都能回溯到分子/蛋白实体及其来源文献（DOI）与检索分数。系统免微调，把 PubChem/UniProt/PDB/PubMed/ChEMBL 检索封装成可验证工具调用，用 DeepSeek V4 Flash 做证据抽取与实体归一化、V4 Pro 做矛盾仲裁与最终生成、Kimi K2.6 做长文献融合，评测闭环要求每句可回溯到 ≥1 来源。零模型训练，预算约 2 GPU·天 + API 成本。

## 1. 研究背景与动机

### 1.1 问题定义

药物发现问答（ADMET 性质、药物重定位、靶点关联）中，RAG 智能体常给出"看似有据、实则错引"的答案：检索文献与答案内容不匹配（实体归因失败），且多源（实验/综述/专利）矛盾时无仲裁。目标：构建输出**可审计证据链**的智能体——每个答案句附带 (实体, 来源 DOI, 检索分数)，矛盾时显式仲裁并标注，人工可复核。

### 1.2 相关工作不足

- **（Application Domains I·论文 63·RAG-Enhanced Collaborative LLM Agents for Drug Discovery）arXiv:2502.17506 / DOI:10.1609/aaai.v40i1.37020（CLADD）**：多 agent + RAG + 免微调，但证据不可追溯、多源整合靠提示拼装、无结构化冲突消解。
- **Deceptive Grounding [arXiv:2607.09349]**：证明临床 RAG 实体归因不可靠——直接支撑"引用级校验"的必要性。
- **AssayBench [arXiv:2605.10876]**：提出 assay 级自动评测，但未解决证据追溯；**AgentDrug [arXiv:2410.13147]**、**ToolMol [arXiv:2605.12784]**：agentic 分子工具，无证据审计。
- **空白**：药物发现领域"声明→证据→来源"三级审计 + 跨源矛盾消解 + 每句可回溯评测闭环的组合。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：CLADD 已证明免微调可行，Deceptive Grounding 刚暴露归因漏洞，AssayBench 刚提出自动评测——补"证据审计 + 矛盾消解 + 可回溯评测"是 2026 可信 agent 窗口。
- **环境匹配**：零训练，全公开 API；4×L40 只跑本地嵌入 + 并行推理；成本低、风险低，适合高优先级快速产出。

## 2. 研究目标与可验证假设

1. **H1（引用可回溯）**：答案句引用覆盖率（每句→来源可回溯比例）显著高于普通 RAG 与 CLADD。*成立时的可观测结果*：引用覆盖率 ≥90%，普通 RAG ≤50%。
2. **H2（引用准确）**：回溯到的来源确实支持该句（人工复核），引用准确率 ≥85%。*成立时的可观测结果*：200 条人工复核引用准确率 ≥85%。
3. **H3（矛盾消解有效）**：多源矛盾时仲裁结果正确率高于"取首个来源"与多数投票。*成立时的可观测结果*：矛盾消解正确率 ≥80%，比"取首源"高 ≥10pt。
4. **H4（免微调即可用）**：无需领域微调即在多任务（ADMET/重定位/靶点关联）上超过通用 LLM。*成立时的可观测结果*：三任务平均正确率超 DeepSeek 直接推理 ≥10pt。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据流水线

1. **任务集构建**：
   - ADMET：MoleculeNet 子集（BBB、CYP、hERG 等，取有公开数据的分类/回归任务）；
   - 药物重定位：DrugBank 中已报道的重新定位案例（公开列表）做检索问答；
   - 靶点关联：从 ChEMBL/UniProt 抽取"分子—靶点—疾病"三元组生成 QA。
   - 每任务约 500–1000 题；答案由领域专家（药学背景）标注或从权威来源摘录（标注来源）。
2. **工具层**：封装 PubChem（分子结构/性质）、UniProt（蛋白）、PDB（结构）、PubMed（文献）、ChEMBL（活性数据）公开 REST API；输出统一 `ToolResult{source_type, id, doi, snippet, score}` 格式。
3. **证据抽取（DeepSeek V4 Flash 批量）**：对检索到的 snippets 抽取"实体 → 声明 → 证据"三元组，输出 JSON：`{"entity":"hERG", "claim":"XX 抑制 hERG", "evidence":"...", "doi":"10.xxxx", "score":0.93}`。
4. **矛盾标注**：同一实体多源冲突时，由 V4 Pro 按证据类型优先级（实验数据 > 权威数据库 > 综述 > 专利）+ 时效仲裁，输出 `{"conflict":true, "winner":"source_id", "reason":"..."}`。
5. **脱敏与版权**：不引入私有数据库；PubMed 摘要按条款使用（引用保留 DOI）；本地不缓存整库，只缓存检索结果（短期）。

### 3.2 方法设计（模块拆解）

1. **管线**：问题解析（提取分子/蛋白实体，LLM）→ 多源并行检索（工具层）→ 实体归一化（ChEBI/UniProt ID 统一）→ 证据抽取 → 矛盾仲裁（规则+LLM）→ 生成带引用答案（每句内嵌 [doi:xxx]）。
2. **三级证据对象**：`Answer{ sentence → Claim{entity, predicate, value} → Evidence{source, doi, score} }`；评测时逐句解析。
3. **引用完整性校验器**：生成后跑一个"每句是否 ≥1 来源 + 来源是否支持句意"的校验（DeepSeek V4 Pro + 规则），不通过则回溯修正。
4. **RAG 组件**：本地 biomedical embedding（如 PubMedBERT 类模型）做检索融合 + 稀疏检索（BM25）混合；4×L40 跑嵌入缓存与并行推理。

### 3.3 训练流程

- **零模型训练**。全部为 API + 开源 RAG 流水线。可选：用少量开发集调 prompt/检索权重（非梯度）。

### 3.4 评测流程

- 自动：答案正确率（专家标注 + LLM-as-judge 对齐）、引用覆盖率、引用准确率、矛盾消解正确率、检索 nDCG。
- 人工：200 条专家复核（引用支持性、事实正确性）。
- 端到端：任务正确率对比基线。

## 4. 数据集细节

### 4.1 来源、许可与伦理合规
- MoleculeNet（DeepChem）、DrugBank（学术许可，重定位案例需遵守其许可证）、ChEMBL（CC BY-SA）、UniProt/PubChem/PubMed（公开 API 条款）。
- 伦理：无患者数据；药物发现输出不得用作医疗建议；论文声明"非临床用途"。
- 版权：引用以 DOI 呈现；不复制整篇文献。

### 4.2 划分与预处理
- 按任务划分 train/dev/test（开发集 100 题调 prompt，测试 300–500 题只评一次）。
- 实体归一化映射表构建（分子名→InChI/Canonical SMILES→ChEBI；蛋白→UniProt ID）。

## 5. 基线复现

| 基线 | 获取方式 | 复现要点 |
|---|---|---|
| CLADD [arXiv:2502.17506] | 按论文/官方流程复现 | 多 agent RAG（无审计） |
| AgentDrug [arXiv:2410.13147] | 官方代码（如有） | 零样本分子编辑 |
| ToolMol [arXiv:2605.12784] | 官方代码（如有） | 进化 agentic 框架 |
| 普通 RAG | 本系统去掉审计/仲裁 | 消融对照 |
| 通用 LLM 直接推理 | DeepSeek V4 Pro / GPT-4o API | 无检索 |

- **统一口径**：同一任务集、同一检索库快照（时间戳固定）、同一解码参数；报告 3 种子均值±std。
- **预期指标表**（占位）：引用覆盖率 普通 RAG ~50% → CLADD ~65% → 本方法 ~90%；引用准确率 ≥85%；矛盾消解 ≥80%。

## 6. 实验矩阵

- **A 主实验**：DrugTraceRAG vs 基线（3 任务 × 指标）。
- **B 消融**：B1 无审计（去掉三级校验）；B2 无矛盾消解（取首源）；B3 无工具层（纯文本检索）；B4 证据抽取用 Flash vs Pro；B5 检索融合（BM25 vs dense vs 混合）。
- **C 鲁棒性**：C1 实体归一化错误注入；C2 检索库版本变化；C3 长问句（多实体）。
- **D 泛化**：D1 跨任务（训练集在 ADMET，测重定位/靶点）；D2 用 Kimi K2.6 作生成器 vs DeepSeek V4 Pro；D3 引用缺失时回退策略。

## 7. 评测协议

- **主指标**：答案正确率、引用覆盖率、引用准确率、矛盾消解正确率。
- **次指标**：检索 nDCG@10、实体 F1、回退触发率。
- **人工**：200 条专家复核（引用支持性 5 级 + 事实性），双专家 κ。
- **显著性**：3 种子配对检验 p<0.05；比例差异用 McNemar；报告均值±std。

## 10. 风险与备选方案

| 风险 | 影响 | 备选方案 |
|---|---|---|
| 引用可回溯但内容错（残余幻觉） | 高 | 引用完整性校验器 + 专家抽检门控；不通过则拒绝生成该句 |
| 矛盾仲裁规则过拟合 | 中 | 在开发集上校准证据类型优先级；消融 B2 对比 |
| 外部 API 限流/变更 | 中 | 工具层抽象 + 缓存；限流退避重试；备用数据库镜像 |
| 任务答案标注成本高 | 中 | 从权威来源自动摘录 + 专家复核 30% |
| 免微调效果弱 | 低 | 若某任务不行，加小规模 LoRA（4×L40 可做）但不改变主卖点 |
| 数据合规 | 低 | 全公开 API；遵守各库条款；引用保留 DOI |
