# 实验设计书：DecodeSig —— 基于解码行为的黑盒 LLM 成员推理（概率轨迹 / 拒绝行为 / 长度分布）

## 0. 摘要

本实验设计书提出用自回归解码的"逐 token 概率轨迹、拒绝行为、长度分布"三类新特征做黑盒 LLM 成员推理（MIA），替代/补充 AAAI 2026 收藏论文 IMIA（Philosophy and Ethics of AI · 论文 75 · Privacy Leaks by Adversaries: Adversarial Iterations for Membership Inference Attack）的对抗迭代特征。核心创新：① 三类解码行为特征（逐 token 概率方差/跃迁、拒绝/回避模式、长度与熵分布），均只需黑盒 top-k 输出；② 特征级集成：与困惑度基线互补的 MIA 增强；③ 评估对 DP-SFT 训练与输出扰动防护的鲁棒性（回应强 MIA 边界讨论 arXiv:2505.18773）。全程无模型训练，本地 Qwen2.5-7B/14B 采样 + 商用 API，总预算 ≈2 GPU·天，投稿目标 CCS 2026 / NeurIPS 2026。

## 1. 研究背景与动机

### 1.1 问题定义

威胁模型：黑盒——攻击者只能向目标 LLM 发送 prompt、读取 top-k token 概率（或仅文本响应），无法访问权重/logits 全量/嵌入。攻击目标：判断某条文本是否属于目标模型的训练数据（成员 vs 非成员）。

与 IMIA 的差异：IMIA 用"生成目标样本对抗样本所需迭代次数"作特征，每次样本要跑完整对抗攻击（开销大）；本设计只用**一次正常解码的输出行为**（逐 token 概率、拒绝与否、长度统计），零对抗攻击成本。科学问题：解码轨迹中"对成员的自信-犹豫模式、拒绝回避模式、长度偏好"是否携带可判别的成员信息？

### 1.2 相关工作不足

- **（Philosophy and Ethics of AI · 论文 75 · IMIA）**：对抗迭代次数特征，黑白盒均有效、对 DP 训练也有攻击性；但开销大、特征单一、未验证生成模型大模型。
- **Semantic MIA（arXiv:2406.10218）**：语义特征，依赖语义嵌入与重写查询。
- **EM-MIAs（arXiv:2412.17249）**：集成方法，仍需多次扰动。
- **Min-K% / 困惑度类**：基于困惑度阈值，对过度训练/记忆模型区分弱。
- **Automatic Calibration（arXiv:2505.03392）**：校准协议，可借鉴到特征校准。
- **强 MIA 边界（arXiv:2505.18773）**：讨论强 MIA 极限与防护；本设计用其"对防护鲁棒性"讨论作为对照。
- **空白**：解码轨迹（top-k 概率序列/拒绝模式/长度统计）作为黑盒 MIA 特征未被系统利用。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：MIA 特征从"静态困惑度"走向"行为动态"（IMIA 的迭代次数、MrM 的响应重建）——解码行为是这一趋势的又一候选；黑盒 top-k 是 API 常见暴露面。
- **环境**：无训练，本地 Qwen2.5-7B/14B 采样 2 万样本 × 128 token ≈1.5 GPU·天；DeepSeek V4 Flash 作目标之一（黑盒）+ 生成 prompt 集，Kimi K2.6 做辅助脚本/报告。
- **合规**：WikiText/PILE/PubMed 公开语料构造成员/非成员划分，无真实隐私数据。

## 2. 研究目标与可验证假设

1. **H1（解码特征可判别）**：三类解码行为特征对成员/非成员的区分 AUC ≥ 0.70（单独），集成后 ≥ 0.80。
   - 成立时可观测结果：概率轨迹（方差/跃迁）单独 AUC ≥ 0.65；集成特征 AUC ≥ 0.80。
2. **H2（与困惑度互补）**：解码特征与困惑度基线互补——集成后优于任一单类（增量 ≥ 3% AUC）。
   - 成立时可观测结果：困惑度 + 解码特征集成 AUC 显著高于困惑度单独（配对检验 p<0.05）。
3. **H3（对防护鲁棒）**：输出加噪 / 截断防护下，解码特征衰减小于困惑度特征。
   - 成立时可观测结果：加噪/截断后解码特征 AUC 下降 ≤ 0.05，困惑度下降 ≥ 0.1。
4. **H4（免对抗开销）**：解码特征方法单样本成本（一次解码）显著低于 IMIA（完整对抗攻击），且达到可比 AUC。
   - 成立时可观测结果：单样本查询数 = 1（vs IMIA 数十次）；AUC 差距 ≤ 0.05。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/对抗样本流水线

1. **成员/非成员构造**：WikiText-103、PILE 子集、PubMed 各取 5000 成员文本（用于训练对应模型的数据）与 5000 非成员（同域未见文本）；3 种子划分。
2. **采样协议**：固定 prompt 集（文本前缀 32 token）→ 让目标模型续写 128 token；解码参数固定（temperature=1.0，top-p=0.95）并做敏感性分析（temperature∈{0.7,1.0,1.5}）。
3. **目标模型**：本地 Qwen2.5-7B/14B（在 WikiText/PILE/PubMed 上 SFT 构造"已知成员"受害者，或直接用其公开训练分布近似）+ DeepSeek V4 Flash（API 黑盒）。
4. **数量**：每模型 2 万样本（1 万成员 + 1 万非成员）采样。

### 3.2 攻击/算法设计

- **特征 1：概率轨迹（逐 token）**：记录 top-k（k=10）概率序列 p_t：
  - 均值/方差/最大跃迁 |p_t − p_{t-1}|、中位数、top-1 置信度序列的自相关；
  - 成员样本更可能呈现"整段自信、少数犹豫峰"的模式。
- **特征 2：拒绝/回避行为**：是否出现拒绝模板（"I can't"/"I'm not sure"/空响应）；拒绝发生位置；对成员的复述倾向（响应与 prompt 的重复率）。
- **特征 3：长度与熵分布**：响应长度、逐 token 熵、KL 于 uniform、终止概率分布。
- **集成**：逻辑回归/梯度提升（LightGBM）融合 3 类特征 + 困惑度；用影子模型/校准集（参考 arXiv:2505.03392）选择阈值。
- **判定**：对每个目标样本输出成员概率；统计判定（双阈值高低风险带）。

### 3.3 训练/注入流程

- 无模型训练；仅"受害者模型 SFT 构造已知成员分布"（Qwen2.5-7B 在 WikiText 子集 SFT 2 epoch，LoRA）≈0.5 GPU·天（可选，用于严格成员标签）。

### 3.4 评测与防御对照流程

- 对照：Min-K% 风格（若可用）或困惑度阈值基线、语义 MIA（arXiv:2406.10218）改造、IMIA（对抗迭代，复现收藏论文口径）。
- 防御对照：① 输出加噪（Kimi 重写扰动）；② token 截断（截到 60%）；③ DP-SFT 训练（可选，DP-SGD 微调受害者模型）。
- 评估：AUC / TPR@低FPR（1%）/ 查询预算 / 特征重要性（SHAP）。

## 5. 基线复现

| 基线 | 出处 | 复现步骤 | 预期指标（Qwen2.5-7B, WikiText） |
|---|---|---|---|
| 困惑度阈值 | 经典 | per-token NLL 平均阈值 | AUC ≈0.6–0.7 |
| Min-K% 风格 | arXiv:2406.10218 同类 | 取最小 k% 概率平均 | AUC 略高于困惑度 |
| 语义 MIA | arXiv:2406.10218 | 语义嵌入 + 重写 | AUC 中上，查询多次 |
| IMIA | 收藏 Philo · 75 | 对抗迭代次数 | AUC 高但开销大 |
| 本设计（DecodeSig） | — | 三类解码特征 + 集成 | AUC ≥ 0.80，单样本查询 |

统一口径：同一成员/非成员划分、同一采样协议、同一 AUC 评测脚本；IMIA 复现时限定同一查询预算档。

## 6. 实验矩阵

- **A（主实验）**：DecodeSig vs 4 基线 × 3 模型 → AUC/TPR@1%FPR。
- **B（特征消融）**：单类特征 vs 两类 vs 三类集成 + SHAP 重要性。
- **C（解码参数敏感性）**：temperature/top-p × AUC → 稳健性。
- **D（防护鲁棒）**：加噪/截断/DP-SFT × AUC 衰减（H3）。
- **E（跨语料）**：WikiText/PILE/PubMed × AUC → 通用性。
- **F（效率对比）**：单样本查询数 vs IMIA → 开销表（H4）。

## 7. 评测协议

- 主指标：AUC、TPR@FPR=1%、查询预算（每样本平均 API 调用）、特征重要性。
- 统计：3 种子；AUC 差异用 DeLong 检验（α=0.05）；解码参数敏感性报告区间。
- 判定：双阈值高低风险带，报告校准曲线。

## 8. 算力与资源计划

- 本地：Qwen2.5-7B/14B 采样 2 万样本 × 128 token ≈1.5 GPU·天；可选 SFT 构造受害者 ≈0.5 GPU·天。
- API：DeepSeek V4 Flash 作为目标之一 + 生成 prompt 集 ≈30 万 token；Kimi K2.6 辅助脚本与报告 ≈10 万 token。
- 存储：采样轨迹 < 30GB（JSONL）。
- 总预算 ≈2 GPU·天。

## 10. 风险与备选方案

| 风险 | 概率 | 影响 | 备选方案 |
|---|---|---|---|
| 解码行为特征被后端解码参数（temperature/重排序）干扰 | 中 | 高 | 固定解码参数 + 敏感性分析（C）；报告无 logits 时只用文本特征的退化 |
| top-k 不可用时（纯文本 API） | 中 | 中 | 只用文本侧特征（长度/拒绝/重复率），报告该子集性能 |
| 成员标签近似不严（SFT 分布 vs 真实训练） | 中 | 中 | 严格 SFT 构造已知成员受害者 + 报告两种口径 |
| 集成特征过度拟合 | 低 | 中 | 影子模型/交叉验证选特征；特征数量限制 |
