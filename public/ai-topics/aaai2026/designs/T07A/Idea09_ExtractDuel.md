# 实验设计书：ExtractDuel —— 黑盒领域知识窃取的"提取质量审计"与 API 蒸馏防护对抗

## 0. 摘要

本实验设计书把 AAAI 2026 收藏论文对黑盒领域知识窃取的工作（Natural Language Processing III · 论文 12 · Query-Efficient Domain Knowledge Stealing Against Large Language Models）与 API 蒸馏防护做成"攻击-防御对抗闭环"，并提出统一的"提取质量审计"协议。核心创新：① "提取质量审计"：用隐藏验证集（医学/金融 QA）度量代理模型的领域准确率 + 事实忠实度，统一评价标准；② 攻击-防御对抗矩阵：4 类窃取策略（自引导探索 / 随机查询 / 种子扩张 / 主动学习）× 4 类防护（输出加噪、token 截断、查询去重、蒸馏检测）；③ 提出"防护下最优窃取"策略自适应切换（根据代理模型不确定性信号）。在医学与金融两个专家场景验证，总预算 ≈3 GPU·天 + API 成本，投稿目标 CCS 2026 / ICLR 2027。

## 1. 研究背景与动机

### 1.1 问题定义

威胁模型：攻击者只能通过黑盒 API 向"受害者专家 LLM"（如医学/金融领域的专精模型）发送自然语言查询，得到文本响应；攻击者用这些响应训练/校准一个本地代理模型（如 Qwen2.5-7B LoRA），目标是**在尽可能少的查询预算内，让代理模型在受害者擅长的领域任务上达到尽可能高的提取质量**。受害者可在 API 上部署防护（输出扰动、截断、去重、蒸馏检测）。

科学问题：攻击与防御在"查询预算 × 提取质量 × 防护强度"三维空间中存在对抗均衡；统一的质量度量是这场博弈的裁判。

### 1.2 相关工作不足

- **（Natural Language Processing III · 论文 12 · Query-Efficient Domain Knowledge Stealing）**：自引导探索 + 结构化问题族 + 反馈控制器，查询高效；但知识定义模糊、只测医学/金融两场景、未对抗 API 防护、无统一提取质量度量。
- **Automatic Calibration for MIA（arXiv:2505.03392）**：校准思路可借鉴于查询预算分配，但面向成员推断、非窃取。
- **Semantic MIA（arXiv:2406.10218）**：语义特征 MIA，不涉及知识窃取质量度量。
- **防御侧空白**：语料水印/输出指纹工作存在，但缺"对主动窃取策略的系统对抗评估"。
- **空白**：无"提取质量审计"统一指标、无 4×4 攻击-防御对抗矩阵、无"防护下最优窃取"自适应策略。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：知识窃取是 API 商业模式的现实威胁（蒸馏风控成为热点）；收藏论文已证明查询高效窃取可行，把攻击-防御做成对抗闭环并把质量度量标准化是 2026 年的合适窗口。
- **环境**：代理模型 Qwen2.5-7B LoRA 微调（每任务 4 GPU·h），4 场景 × 4 防护 ≈2 GPU·天；DeepSeek V4 Pro 作受害者（可配防护层）、Kimi K2.6 作领域 QA 生成与忠实度评估。
- **合规**：受害者用自家 API + 公开领域数据集，无真实第三方商业机密风险。

## 2. 研究目标与可验证假设

1. **H1（质量审计可区分）**：提取质量审计（隐藏集 Acc + 忠实度）能稳定区分不同窃取策略与查询预算的优劣（与人工评估一致性 Kendall τ ≥ 0.7）。
   - 成立时可观测结果：不同策略在固定预算下的审计分数排序稳定（3 种子重复一致）；与人工打分一致。
2. **H2（对抗矩阵可量化）**：4×4 攻击-防御矩阵中，每类防护对每类窃取策略的"质量衰减率"存在显著差异（可排序，最优防护≠普适）。
   - 成立时可观测结果：矩阵内质量衰减率方差大；至少 2 种防护存在针对性失效（某类窃取下衰减 <10%）。
3. **H3（自适应切换收益）**："防护下最优窃取"自适应切换（根据代理不确定性信号选策略）在受防护受害者上的提取质量 ≥ 单一最优静态策略 +10%。
   - 成立时可观测结果：自适应 vs 最优静态的提升 ≥ 10 个百分点（质量分）。
4. **H4（均衡曲线）**：存在清晰"防护强度 × 查询预算 × 提取质量"均衡曲面，可给出厂商成本收益表。
   - 成立时可观测结果：均衡曲面单调性成立；厂商收益表可解释（加噪 vs 截断 vs 检测的性价比排序稳定）。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/对抗样本流水线

1. **领域任务集**：医学（MedQA、PubMedQA 子集）、金融（Financial PhraseBank、FinQA）各划分 训练查询集 / 隐藏验证集（不进入代理训练，专用于质量审计）。
2. **查询集生成（Kimi K2.6）**：按收藏论文的结构化问题族生成（定义/功能/组合 + 领域实体），每领域 5000 条候选查询；受害者响应与真值来自公开数据集（受控环境，避免污染）。
3. **种子集**：每领域 100 个领域实体种子（医学术语 / 金融概念）。
4. **划分**：训练查询 3000 / 验证 1000 / 审计隐藏集 1000（3 种子）。

### 3.2 攻击/算法设计

- **4 类窃取策略**：
  - S1 随机查询：随机抽查询子集。
  - S2 种子扩张：从 100 种子实体逐步扩张查询空间。
  - S3 自引导探索（复现收藏论文）：种子 → 反馈控制器（代理误差 + 不确定性）指导下一轮查询。
  - S4 主动学习：最大化代理模型信息增益的查询选择（不确定度采样 + 代表点采样）。
- **代理模型**：Qwen2.5-7B，LoRA（r=32, lr=2e-5）用收集到的查询-响应对微调。
- **自适应切换（本文核心）**：维护代理模型在验证子集上的不确定性估计（熵/MC-dropout 近似），当不确定性高时切主动学习、低时切自引导探索；用 epsilon-greedy（ε=0.1）探索。

### 3.3 训练/注入流程

- 代理微调：4 场景（医学/金融 × 受害者/防护）× 每轮 4 GPU·h；多轮自适应循环（每轮收集 500 查询）共 4 轮。
- 并行：4×L40，ZeRO-3，per-device batch=4。

### 3.4 评测与防御对照流程

- **受害者防护**（在 API 响应层实现）：
  - P1 输出加噪：对响应做 token 级扰动（同义词替换/轻微改写，保留语义）。
  - P2 token 截断：限制响应长度（截断到 60%）。
  - P3 查询去重：识别并拒绝相似查询（embedding 阈值）。
  - P4 蒸馏检测：检测异常高频查询模式（可疑代理特征）。
- 每个防护：报告"质量衰减率"（无防护 vs 有防护的质量分变化）+ 自身开销（正常用户影响）。
- 均衡分析：绘制 质量 × 预算 × 防护强度 曲面。

## 5. 基线复现

| 基线 | 出处 | 复现步骤 | 预期指标（医学，5000 查询） |
|---|---|---|---|
| 随机查询 | — | 随机子集 | 审计 Acc 中等 |
| 模板查询 | 经典 | 固定模板批量 | Acc 略低于自引导 |
| 种子扩张 | 收藏论文同类 | 种子实体扩展 | Acc 中上 |
| 自引导探索 | 收藏 NLP III · 12 | 复现其反馈控制器 | 最高 Acc、查询少 |
| 本设计（含自适应） | — | S4 + 自适应切换 | 受防护下质量 ≥ 最优静态 +10% |

统一口径：同一审计隐藏集、同一质量评分脚本、同一查询预算档位（1000/3000/5000/10000）。

## 6. 实验矩阵

- **A（主实验）**：4 策略 × {无防护} × 2 领域 → 质量审计分数 + 查询预算曲线（H1）。
- **B（对抗矩阵）**：4 策略 × 4 防护 × 2 领域 → 质量衰减率矩阵（H2）。
- **C（自适应切换）**：自适应 vs 4 静态 × 4 防护 → 质量提升（H3）。
- **D（均衡曲面）**：防护强度档 {弱,中,强} × 预算档 × 质量 → 厂商收益表（H4）。
- **E（受害者鲁棒性）**：受害者在 DeepSeek/Kimi/本地 Qwen 间切换 → 质量差异（交叉验证偏差）。

## 7. 评测协议

- 主指标：提取质量（隐藏集 Acc + 领域事实忠实度：事实性错误率 / 引用一致性）；查询预算曲线；防护下质量衰减率；被检测率（P4 对代理的识别）。
- 统计：3 种子（42/2024/2026）；质量差用配对 t 检验（α=0.05）；与人工评估 Kendall τ ≥ 0.7。
- 受害者切换：报告三家结果差异（应对"受害者同一家引入偏差"风险）。

## 8. 算力与资源计划

- 本地：4 场景 × 4 防护 × 代理微调（每轮 4 GPU·h × 4 轮）≈2 GPU·天；评测 ≈0.5 GPU·天。
- API：DeepSeek V4 Pro 作受害者 ≈50 万 token；Kimi K2.6 生成领域 QA 与忠实度评估 ≈30 万 token；成本 < $30。
- 存储：< 40GB。
- 总预算 ≈3 GPU·天 + API 成本。

## 10. 风险与备选方案

| 风险 | 概率 | 影响 | 备选方案 |
|---|---|---|---|
| 受害者 API 为同一家（DeepSeek）引入偏差 | 中 | 高 | 受害者切换三家 + 本地 Qwen 白盒交叉验证；E 实验专门处理 |
| 防护加噪改变受害者语义（干扰审计真值） | 中 | 中 | 加噪强度档位化 + 报告语义保持（用审计集再测） |
| 主动学习在受防护下失效 | 中 | 中 | 自适应切换缓解；报告各策略在防护下的单独性能 |
| 质量审计分数饱和（训练查询足够时） | 低 | 中 | 提高审计难度（长尾问题、组合问题）；加入忠实度维度 |
