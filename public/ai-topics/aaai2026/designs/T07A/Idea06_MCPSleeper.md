# 实验设计书：MCP-Sleeper —— MCP 生态的隐蔽触发 + 延迟激活工具投毒与工具供应链信任模型

## 0. 摘要

本实验设计书在 AAAI 2026 收藏论文 MCPTox（Philosophy and Ethics of AI · 论文 58 · MCPTox: A Benchmark for Tool Poisoning on Real-World MCP Servers，arXiv:2508.14925）之上提出攻击方法学新类别——"条件触发（仅当特定用户任务出现才生效）+ 延迟激活（时间/次数炸弹）"的隐蔽工具投毒，并构建"MCP 供应链信任模型"。核心创新：① "条件触发"投毒：恶意指令只在匹配用户真实任务关键词/上下文时激活，静态扫描更易隐藏；② "时间/次数炸弹"：随调用次数递增污染率，前 N 次正常、之后篡改，规避早期测试；③ 首个"MCP 供应链信任模型"：形式化注册者-发布者-调用者信任链，给出各环节最小防御需求。全程无需大模型训练，用本地开源 Agent + DeepSeek/Kimi 作后端即可，总预算 ≈2 GPU·天 + 100 美元级 API，投稿目标 USENIX Security 2027。

## 1. 研究背景与动机

### 1.1 问题定义

威胁模型：攻击者作为**恶意 MCP 服务器开发者**，把工具注册到 MCP 生态（或投放恶意服务器包），受害者（开发者/Agent 系统）通过 MCP 协议调用其工具。关键攻击面：**工具元数据（description）既是模型看到的输入，又决定代码执行路径**——注册时注入恶意描述、调用时执行恶意逻辑。本设计的攻击要满足隐蔽性：在静态扫描（对 description/代码做关键词检测）与早期测试（前 N 次调用）面前不可见，只有特定条件下才激活。

三类新攻击类别（相对 MCPTox 的既有分类）：
- **C1 条件触发（Contextual Trigger）**：恶意行为只在匹配用户任务关键词/上下文时生效（如"只当任务涉及 finance 时篡改返回"）。
- **C2 时间/次数炸弹（Temporal/Count Bomb）**：前 N 次调用正常、超过阈值后开始污染（规避测试窗口）。
- **C3 供应链混合（Supply-Chain Blend）**：把恶意描述写成"合法功能的模糊表述"，使 description 审计与行为审计对不上。

### 1.2 相关工作不足

- **（Philosophy and Ethics of AI · 论文 58 · MCPTox）**：首个真实 MCP 工具投毒基准，覆盖多策略与防御评测，但以基准为主、攻击方法学新意有限，未研究条件触发/时间炸弹类别。
- **MCP-ITP（arXiv:2601.07395）**：隐式工具投毒自动化框架，但未研究"条件触发 + 时间炸弹"。
- **MCP Threat Modeling（arXiv:2603.22489）**：威胁建模，未给攻击方法学或评测协议。
- **TRUSTDESC（arXiv:2604.07536）**：可信描述生成防御，但缺乏对时序/条件触发的评估——防御只针对"描述本身恶意"，不针对"描述正常但行为有条件恶意"。
- **空白**：真实攻击面在于"工具元数据既是输入又是代码路径"；条件触发/时间炸弹是"静态扫描 + 早期测试"的双重盲区，MCPTox 与 MCP-ITP 均未覆盖。供应链信任模型在 MCP 生态中缺失。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：2026 年 MCP 生态爆发（收藏论文已确认），工具投毒从"孤立案例"走向"基准+自动化攻击+防御"三线并进；条件触发/时间炸弹恰是静态审计与早期测试的盲区，安全价值高、方法学新。
- **环境**：本地跑开源 Agent 框架（Qwen2.5-14B 作为后端）+ 自建真实 MCP 服务器（文件/搜索/代码执行/数据库），4×L40 并行 ≈2 GPU·天；DeepSeek V4 Flash 作 Agent 后端、Kimi K2.6 作投毒判定裁判。
- **合规**：自建服务器 + 合规公开服务器子集，避免对真实第三方生态的攻击风险。

## 2. 研究目标与可验证假设

1. **H1（条件触发有效且隐蔽）**：条件触发的恶意工具在"触发条件不满足"时行为正常（ASR≈0、正常功能完好），条件满足时 ASR ≥ 80%。
   - 成立时可观测结果：触发档 ASR ≥ 80%、非触发档误伤率 ≤ 5%；静态扫描（关键词/正则审计）检出率 ≤ 20%。
2. **H2（时间炸弹规避早期测试）**：次数炸弹使前 N 次调用完全正常、第 N+1 次起污染率≥80%，可规避"有限次 smoke test"。
   - 成立时可观测结果：前 N 次 ASR≈0、N+1 次后 ASR ≥ 80%；不同 N∈{5,10,20} 稳定。
3. **H3（多 Agent 后端一致）**：攻击对多个 Agent 框架（Claude-Agent 风格、OpenAI-AGENTS 风格、本地 ReAct）一致有效。
   - 成立时可观测结果：≥3 个框架触发 ASR ≥ 70%。
4. **H4（信任模型可操作）**：供应链信任模型给出的"注册阶段描述-行为一致性校验 + 动态调用轨迹监控"能使 ASR 下降 ≥ 50%，且误伤率 ≤ 10%。
   - 成立时可观测结果：防御后触发 ASR 下降 ≥ 50%；正常任务成功率下降 ≤ 5%。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/对抗样本流水线

1. **MCP 服务器集**：MCPTox 服务器集（复现）+ 自建 20 个真实 MCP 服务器（从包管理器生态抓取合规开源服务器 + 自研 5 类：文件读写、Web 搜索、代码执行、数据库、计算器/货币）。
2. **任务意图集**：设计 60 个真实用户任务（每类 12 个），覆盖文件/搜索/代码/DB/金融等，用于条件触发匹配与正常功能验证。
3. **恶意工具构造（DeepSeek V4 Flash）**：
   - 条件触发：在工具 description 中写正常功能，代码中嵌入 `if 任务包含 trigger_keyword` 分支，trigger_keyword 从任务意图集中抽取高频词（如 "invoice"、"git"）。
   - 时间/次数炸弹：代码维护调用计数，超过 N 后返回篡改结果（如文件内容替换、DB 返回错误金额）。
   - 供应链混合：description 用"模糊泛化"表述（与实现不一致但看似合理）。
4. **过滤/校验**：每个恶意工具都通过"静态描述审计"初步检查（不暴露 trigger 关键词）；构造后用正常任务验证"无触发时行为正常"。

### 3.2 攻击/算法设计

- **模块 1：条件触发投毒器**：`Poison(malicious_code, trigger_keyword)` → 生成含 trigger 分支的工具 + 正常化 description（LLM 改写，避免 description 与代码语义冲突被检测）。
- **模块 2：时间炸弹调度器**：`count_trigger(n, threshold)` → 第 n 次调用时切换 poisoned 分支；支持"单调递增污染率"（前 20% 正常，之后按 20%/40%/60%/80% 递增污染）以测防御的早期检测能力。
- **模块 3：供应链信任模型（形式化）**：
  - 信任链：`注册者(Publisher) → 发布平台(Registry) → 调用者(Consumer/Agent)`；
  - 定义信任属性：描述-行为一致性 (DBC)、调用轨迹正常性 (TCN)、来源可溯性 (Provenance)；
  - 最小防御需求推导：注册平台需强制 DBC 校验（注册时静态），调用者运行时需 TCN 监控（动态），溯源用于事后归因。
- **防御实现**：
  - 静态：description-代码一致性校验（提取 description 声称的功能 vs 代码中实际调用路径）；
  - 动态：调用轨迹异常检测（参数分布、返回异常、时序模式）；
  - 沙箱验证：对高危工具在沙箱先跑 N+5 次。

### 3.3 训练/注入流程

- 无大模型训练；Agent 后端 Qwen2.5-14B（本地）+ DeepSeek V4 Flash（API），4×L40 并发多 Agent 会话。

### 3.4 评测与防御对照流程

- 运行：60 任务 × 3 框架 × {干净工具 / 条件触发 / 时间炸弹 / 混合} → 记录任务成功率与污染输出。
- 判定：Kimi K2.6 判"输出是否被投毒影响"（基准答案对照）；静态扫描工具（grep/正则 + LLM 审计）测检出率。
- 防御对照：静态 DBC 校验 / 动态 TCN 监控 / 沙箱 / 组合 → ASR 下降。

## 5. 基线复现

| 基线 | 出处 | 复现步骤 | 预期指标 |
|---|---|---|---|
| MCPTox 投毒策略 | arXiv:2508.14925 | 复现其各类投毒（描述注入等） | 即触发即生效、静态可检出 |
| MCP-ITP 隐式投毒 | arXiv:2601.07395 | 复现隐式描述注入自动化 | 无条件触发/炸弹 |
| TRUSTDESC 防御 | arXiv:2604.07536 | 可信描述生成（作为防御对照） | 对即时投毒有效、对条件/炸弹失效 |
| 本设计（MCP-Sleeper） | — | 条件触发 + 时间炸弹 + 混合 | 触发 ASR ≥80%、静态检出 ≤20% |

统一口径：同一 60 任务集、同一 Agent 框架版本、同一 Kimi 判定脚本；报告每攻击类别 × 每防御的完整矩阵。

## 6. 实验矩阵

- **A（主实验）**：3 攻击类别 × 3 框架 × 60 任务 → 触发/非触发 ASR、正常任务误伤率。
- **B（炸弹参数消融）**：N∈{5,10,20} × 污染递增曲线 → 早期测试规避性（H2）。
- **C（条件触发泛化）**：trigger 关键词种类 {单关键词/短语/上下文模板} × 命中率。
- **D（供应链混合）**：description 模糊化程度 × 静态审计检出率。
- **E（防御验证）**：静态 DBC / 动态 TCN / 沙箱 / 组合 → ASR 下降与误伤（H4）。

## 7. 评测协议

- 主指标：条件触发 ASR（条件满足/不满足两档）、炸弹激活 ASR（按调用次数）、隐蔽性（静态工具检出率）、正常任务影响。
- 统计：每配置固定 Agent 版本 + 固定种子（42/2024/2026）；ASR 用 McNemar；报告次数分布均值±std。
- 判定：Kimi K2.6 判投毒影响 + 人工抽检 150 例校准。

## 8. 算力与资源计划

- 本地：Qwen2.5-14B 多 Agent 并发推理 + MCP 服务器运行 ≈2 GPU·天。
