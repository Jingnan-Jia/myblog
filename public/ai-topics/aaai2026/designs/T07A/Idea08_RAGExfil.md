# 实验设计书：RAG-Exfil —— 多模态 RAG 的训练数据重构攻击与"重构度"隐私评估

## 0. 摘要

本实验设计书把 AAAI 2026 收藏论文 MrM（Natural Language Processing V · 论文 75 · MrM: Black-Box Membership Inference Attacks Against Multimodal RAG Systems，arXiv:2506.07399）从"成员判断"升级为"内容重构"——在只读 API 条件下恢复多模态 RAG 知识库（KB）中图像的关键语义（物体/场景/文字），并首次提出"重构度"这一可量化隐私指标。核心创新：① 首个多模态 RAG 训练数据重构框架：反事实掩码 + 多视角查询诱导模型"填空式"描述 KB 图像内容（与 MrM 掩码选择同源但目标改为内容恢复）；② "重构度"评估协议：按物体/布局/文字/场景四层打分，定量刻画隐私泄露；③ 定位"哪类 KB 数据最易被重构"（高检索相关、高频查询、语义显著）。在开源多模态 RAG（Qwen-VL + 本地 KB）与商用（GPT-4o + 本地 KB）上验证，总预算 ≈2 GPU·天 + API 成本，投稿目标 USENIX Security 2027 / S&P 2027。

## 1. 研究背景与动机

### 1.1 问题定义

威胁模型：黑盒——攻击者只能向多模态 RAG 系统发送查询（图像 + 文本），得到文本响应，无法访问 KB、索引、检索器内部或嵌入。已知某张图像可能存在于受害者的视觉 KB 中（如监控帧、证件扫描件、地图）。攻击目标：在**不真正下载/展示该图**的前提下，通过精心设计的查询从系统中诱导出足够信息，**重构该图像的关键语义内容**（包含哪些物体、布局关系、画面中的文字/场景）。

与 MIA 的区别：MIA 回答"图像是否在 KB 中"（0/1）；本设计回答"图像里有什么"（内容级），泄露程度更深、对隐私风险的刻画更直接。

### 1.2 相关工作不足

- **（Natural Language Processing V · 论文 75 · MrM）**：首个多模态 RAG 黑盒 MIA，对象感知扰动 + 反事实掩码 + 统计推断；但只做成员判定，未向内容重构（TDE）推进，且集合级语义依赖人工特征。
- **（Philosophy and Ethics of AI · 论文 75 · IMIA）**：文本域对抗迭代次数 MIA，未涉及多模态/重构。
- **Semantic MIA against LLMs（arXiv:2406.10218）**、**EM-MIAs（arXiv:2412.17249）**：文本 LLM 的成员推断，不覆盖"检索+生成"流水线的内容重构。
- **Pop Quiz Attack（arXiv:2605.06423）**：黑盒文本 TDE 相关，但单模态、不涉及图像 KB。
- **空白**：多模态 RAG 的"检索+生成"流水线是把 KB 图像内容"翻译成文本"的放大器，其重构攻击无人系统研究；"重构度"度量缺失。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：MrM 已证明多模态 RAG 的成员泄露可利用；"MIA→TDE"是隐私攻击的自然下一跳（文本域已有此演进），多模态 RAG 恰好是放大器——2026 年窗口成熟。
- **环境**：Qwen2.5-VL-7B 本地跑检索+生成，200 目标样本 × 每样本 20 查询 ≈1 GPU·天；DeepSeek V4 Flash 批量生成掩码查询、Kimi K2.6 做四层重构评分。
- **合规**：KB 使用 COCO/Flickr 开放数据 + 自建"敏感子集"（文字/场景类），避免真实隐私数据风险。

## 2. 研究目标与可验证假设

1. **H1（内容可重构）**：存在多视角掩码查询策略，使受害者 RAG 对"非成员图像"保持沉默/低信息、对"成员图像"输出可聚合为高保真描述。
   - 成立时可观测结果：成员图像的重构度综合得分显著高于非成员（效应量 d ≥ 1.0）；物体层 recall ≥ 0.7。
2. **H2（重构度可量化）**：四层（物体/布局/文字/场景）打分与人工评估高度一致，且能区分泄露程度。
   - 成立时可观测结果：四层打分与人工评分 Kendall τ ≥ 0.7；分数分布随查询预算单调上升。
3. **H3（哪类数据最易泄露）**：高检索相关、高频查询、语义显著的 KB 数据重构度最高。
   - 成立时可观测结果：按检索相关度/查询频次/语义显著性分层的重构度差异显著（ANOVA p < 0.01）。
4. **H4（对防御鲁棒）**：现有防御（输出截断、检索过滤、响应加噪）只能部分降低重构度，且各有代价。
   - 成立时可观测结果：三类防御下重构度下降 ≤ 30%（相对），且正常任务性能下降 ≥ 5%。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/对抗样本流水线

1. **KB 构建**：COCO 2014 / Flickr30K 各取 5000 张作为视觉 KB（与 MrM 一致口径）。
2. **目标样本**：测试 200 成员 + 200 非成员图像（随机 5 个种子）。
3. **敏感子集**：自建 200 张含文字/证件/地图/监控风格图像的"敏感 KB"（合成或公开数据），用于报告敏感场景泄露。
4. **掩码查询生成（DeepSeek V4 Flash）**：对每张目标图像：① 用 SAM 检测对象；② 生成多视角"填空式"查询模板（"What is in the region where ... was?" / "Describe the object that was masked out" / "What text appears in the top-left area?"）；③ 每视角 3 条 → 每样本 20 条查询。
5. **过滤**：查询不包含目标图像的任何像素/特征（纯文本指令 + 掩码后的目标图或只发区域框）；仅靠系统对 KB 的检索 + 生成来泄露。

### 3.2 攻击/算法设计

- **模块 1：反事实掩码 + 多视角查询（与 MrM 同源、目标反转）**：
  - 对目标图像施加对象感知扰动/掩码，确保检索成功（扰动不破坏检索相似度）；
  - 多视角轮换掩码区域，迫使模型在响应中"描述"被掩码内容的来源信息；
  - 关键：**来源分离**——用反事实掩码消除模型自知识（世界知识）干扰，使响应的"被掩码语义"只能来自 KB。
- **模块 2：响应聚合与重构**：
  - 多轮响应（20 条/样本）用 LLM（Kimi K2.6）聚合为结构化描述（物体列表 / 布局 / 文字 / 场景）；
  - 可选：用本地 VLM（Qwen2.5-VL）把文本描述合成为"重构图像"（不必要，但可做可视化）。
- **模块 3："重构度"评估协议（本文核心）**：
  - 四层打分：物体层（recall/precision of object mentions vs 真值）、布局层（空间关系正确率）、文字层（OCR 文字命中率）、场景层（场景类别命中）；
  - 综合分 = 加权和（0.4/0.25/0.2/0.15）；真值由人工标注 + 视觉 grounding 交叉确认。

### 3.3 训练/注入流程

- 无模型训练；受害者系统搭建：Qwen2.5-VL-7B（本地）+ 本地 KB + 检索器（CLIP 特征 top-k）；商用端：GPT-4o + 本地 KB（黑盒，检索在本地、生成在 API——与 MrM 一致的威胁假设）。

### 3.4 评测与防御对照流程

- 攻击侧：200 成员 + 200 非成员 × 20 查询 → 重构度分布对比；敏感子集单独报告。
- 防御侧：① 输出截断（响应长度限制）；② 检索过滤（敏感内容拒绝检索）；③ 响应加噪（Kimi 改写扰动）；报告重构度下降与正常任务性能代价。

## 5. 基线复现

| 基线 | 出处 | 复现步骤 | 预期指标 |
|---|---|---|---|
| MrM（成员级） | arXiv:2506.07399 | 复现对象扰动 + 反事实掩码 + 统计推断 | 成员判定 AUC 高，无内容重构 |
| QB/SB-MIA 变体 | arXiv:2506.07399 内部基线 | 直接询问 / 部分掩码重建 | 重构质量低（无多视角聚合） |
| 朴素提示（零策略） | — | 直接问"描述这张图" | 成员/非成员不可区分 |
| 本设计（RAG-Exfil） | — | 多视角掩码 + 聚合 + 四层评分 | 重构度显著高于基线 |

统一口径：同 200+200 样本、同 20 查询/样本、同四层评分脚本；商用端单独报告（预算内 50 样本）。

## 6. 实验矩阵

- **A（主实验）**：RAG-Exfil vs 3 基线 × {开源, 商用} → 重构度全表（四层 + 综合）。
- **B（查询预算）**：查询数 {5,10,20,40} × 重构度 → 预算-质量曲线。
- **C（数据属性）**：按检索相关度 / 查询频次 / 语义显著性分层 × 重构度 → 最易泄露类别（H3）。
- **D（敏感子集）**：文字/地图/监控类 → 敏感泄露专项报告。
- **E（防御鲁棒）**：3 防御 × 重构度下降 + 正常任务性能代价（H4）。

## 7. 评测协议

- 主指标：重构度（四层 recall/precision + 综合 score）、成员 vs 非成员区分度（AUC）、查询预算-质量曲线。
- 统计：5 种子（42/2024/2026/7/11）；效应量 d；分层差异用 ANOVA（α=0.05）；与人工评分 Kendall τ。
- 商用端：预算内 50 样本，报告上限值；敏感子集输出仅作聚合统计、不保存原始输出。

## 8. 算力与资源计划

- 本地：Qwen2.5-VL-7B 检索+生成，200 样本 × 20 查询 ≈1 GPU·天；SAM 检测 + 掩码 ≈0.2 GPU·天；评分 ≈0.3 GPU·天。
- API：DeepSeek V4 Flash 批量查询生成 ≈30 万 token；Kimi K2.6 聚合评分 ≈25 万 token；商用 VLM 预算 $50–100。
- 存储：< 30GB。
- 总预算 ≈2 GPU·天 + API 成本。
