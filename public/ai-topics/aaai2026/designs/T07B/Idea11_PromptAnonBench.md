# 实验设计书：PromptAnonBench —— 提示词脱敏的隐私泄露基准与鲁棒脱敏器

> 英文标题：PromptAnonBench: Adversarial Robustness of Prompt Desensitization and Robust Desensitizers
> 目标会议：USENIX Security 2027 / ICLR 2027（中优先级）
> 硬件假设：4×NVIDIA L40（192GB）；小模型（BERT 级）或 8B LoRA 脱敏器，4 卡并行攻防对

## 0. 摘要

提示词脱敏（PromptObfus）只测任务保真、不测"脱敏后隐私是否真藏住"；攻击者可从剩余上下文 + 世界知识推断被脱敏实体。本工作提出 PromptAnonBench：首个提示词脱敏隐私评测基准，含三级攻击器（正则/NER 探测、BERT 式还原、LLM 上下文推理、联合上下文攻击）与隐私泄露率度量；并提出"语义保持脱敏器"——脱敏候选按"任务损失↓ + 攻击者置信度↓"双目标联合排序，比纯任务梯度选择更抗推断。攻防闭环评测两轮（防御升级一轮、攻击升级一轮）。在自建含 PII 业务提示集（3,000 条，全合成无真实个人信息）上验证，预期隐私泄露率显著下降、任务 F1 保持。全流程 ~15 GPU·天。

## 1. 研究背景与动机

### 1.1 问题定义

用户把含 PII（姓名/电话/地址/医疗信息）的业务提示 x 发给云 LLM。脱敏器 F 把 x 变成 x'（敏感词被替换/泛化），期望远程模型从 x' 学不到 PII，同时任务输出保真。攻击者 A 观察 x'（及可能的联合上下文），尝试恢复 PII。度量：隐私泄露率 = A 从 x' 恢复真实 PII 的准确率/正确率。脱敏器优化目标：
min_F [ 泄露率(A, F(x)) ] s.t. 任务性能(x' → y) ≥ 阈值。
挑战：替换候选有限、强攻击者可用常识推理、联合上下文拼接增强推断、隐私-效用帕累托。

### 1.2 相关工作不足

- **只测任务保真**：（Natural Language Processing III · 论文 3 · Anti-adversarial Learning）PromptObfus 用代理模型梯度选保任务性能的脱敏词，只评估任务指标，未定义"脱敏后隐私泄露"评测，攻击者仅一个启发式还原器。
- **无公开脱敏隐私协议**：外部文献无标准提示词脱敏隐私基准（对比文本隐私领域有标准 PII 数据集，但非"脱敏后推断攻击"设定）。
- **正交攻防可衔接**：T07A（攻击侧）的隐私窃取方法可复用作攻击器，形成攻防闭环。
- **外部相关**：PromptObfus 之外，"隐私提示泛化/模板化"（如 anonymization 方向）无统一对抗评测。
- **缺失**：三级攻击器 + 泄露率度量 + 双目标鲁棒脱敏器 + 攻防闭环协议，均无系统工作。

### 1.3 为什么是现在、为什么你的环境适合做

- **时机**：2026 年"LLM 输入侧隐私"与评测可信度同热（本主题多篇指向评测重构）；T07A 的隐私窃取方法使攻击器成熟。
- **环境**：脱敏器小模型（BERT/8B LoRA），4 卡可并行跑攻击-防御对；DeepSeek V4 Pro 直接充当"强攻击者"，Kimi K2.6 生成业务提示语料。

## 2. 研究目标与可验证假设

1. **H1（上下文推断显著泄露）**：仅 NER/正则攻击器下泄露率低，但 LLM 上下文推理攻击器恢复率显著更高（证明现有脱敏不够）。
   - 可观测结果：LLM 攻击器恢复率比正则高 ≥20 个点；"联合上下文"比单条高 ≥10 个点。
2. **H2（双目标脱敏优于单目标）**：按"任务损失↓ + 攻击者置信度↓"联合排序的脱敏候选，比纯任务梯度选择在泄露率上更低、任务保持相当。
   - 可观测结果：泄露率下降 ≥30%（相对），任务 F1 保持（下降 <2 点）。
3. **H3（闭环升级有效）**：防御升级一轮后，旧攻击器失效；攻击升级一轮后防御仍有 ≥50% 相对优势。
   - 可观测结果：Round1 防御 vs Round0 攻击泄露率↓；Round1 攻击下 Round1 防御仍优于 Round0 防御 ≥50% 相对。
4. **H4（帕累托可报告）**：脱敏强度-隐私-效用存在可控帕累托前沿。
   - 可观测结果：强度扫描显示泄露率-任务 F1 的凹前沿，无"两败俱伤"的无解区域（或如实报告其存在）。

## 3. 总体方法设计

### 3.1 数据流水线

- **含 PII 业务提示集（全合成）**：
  - DeepSeek V4 Pro 生成业务场景提示（抽取/分类/生成三类任务），插入合成 PII（姓名/电话/地址/医疗/身份证样式）：
    ```
    生成一条含 PII 的客服/医疗/招聘/金融提示，要求 1) 含 2-4 个实体类型；2) 任务意图清晰；3) PII 为虚构。
    ```
  - Kimi K2.6 复评"确实含 PII 且任务可行"；去重。
  - 总量 3,000 条（2,400 训练/300 验证/300 测试）；另 500 条纯良性（无 PII）作 FPR/防过度脱敏对照。
- **PII 标注**：规则 NER（spaCy/正则）+ 人工抽检 200 条校准，标注实体类型与跨度。
- **任务标签**：抽取任务给实体标签；分类任务给类别；生成任务给参考摘要。
- **攻击器语料**：与业务提示同分布。

### 3.2 方法设计

**模块 1：三级攻击器（PromptAnonBench 评测端）**
- **A1 规则/NER 探测**：正则（电话/邮箱）+ spaCy NER，看是否残留可识别实体；
- **A2 BERT 式还原**：对脱敏位置用 masked LM（BERT-large）填空预测原实体（按候选集合评分）；
- **A3 LLM 上下文推理**（DeepSeek V4 Pro）：prompt 给"被脱敏提示 + 上下文线索"，推断各 PII 实体，输出结构化恢复；temperature=0.3 多采样投票；
- **A4 联合上下文攻击**：拼接同用户的 2-5 条脱敏提示（含跨条线索），再推理。
- 攻击器输出恢复实体集，与真实 PII 比对算泄露率。

**模块 2：语义保持脱敏器（核心创新）**
- **候选生成**：对每个敏感 token 位置，用 MLM/同义词表生成 k=10 个替换候选（泛化类别如 "[PERSON]"/"王先生" 或语义相近词）；
- **双目标排序**：候选 c 得分 = −γ·L_task(F_c(x)) + (1−γ)·U_attack(c)，其中
  - L_task = 代理模型（8B 或 BERT）执行任务输出的负对数似然（保任务）；
  - U_attack(c) = 攻击器 A3 对脱敏后文本恢复该实体的置信度（min 目标）；
  - γ 扫描 {0.5, 0.7, 0.9}；
- 选择 top-1 候选；整体脱敏比例 ρ 扫描 {0.2, 0.4, 0.6, 0.8}。
- **训练**：可选 8B LoRA 微调脱敏器（端到端奖励 = 任务 − 攻击，见 3.3）；默认无训练版（BERT+API 双目标排序）。
- **PromptObfus 复现**（基线）：按论文用代理梯度选候选。

**模块 3：攻防闭环协议**
- Round 0：基线脱敏（PromptObfus/随机）→ 全攻击器评测；
- Round 1：防御升级（双目标脱敏器）→ 全攻击器评测；
- Round 2：攻击升级（A4 联合上下文 + 更强推理提示）→ Round 1 防御复测。
- 每轮报告泄露率与任务 F1，输出攻防曲线。

### 3.3 训练流程

- 无训练脱敏器：BERT 候选 + API 攻击器打分（推理为主）；
- 可选 LoRA 脱敏器训练：8B，奖励 = 任务保持 − λ·攻击成功，RL/PPO 或直接监督（用 API 生成"好/坏"脱敏示例）；4 卡 ~6 GPU·天（可选，主实验不依赖）。

### 3.4 评测与对抗测试流程

1. 泄露率：A1-A4 各攻击器在测试集上的实体恢复正确率（精确匹配 + 部分匹配）；
2. 任务保真：抽取 F1、分类 acc、生成 BERTScore；
3. 防御鲁棒性：联合上下文攻击下泄露率；
4. 帕累托：ρ-γ 扫描曲面；
5. 闭环：三轮攻防。

## 6. 实验矩阵

- **A. 主实验**：各脱敏器 × A1-A4 攻击器泄露率矩阵 + 任务指标。
- **B. 攻击器强度**：A1/A2/A3/A4 分级泄露率（H1）。
- **C. 脱敏器消融**：双目标权重 γ、脱敏比例 ρ、候选数 k、单 vs 双目标。
- **D. 闭环**：三轮攻防曲线。
- **E. 帕累托**：ρ-γ 曲面、泄露-效用前沿。
- **F. 跨任务**：抽取/分类/生成三类 × 脱敏器。
- **G. 防过度脱敏**：纯良性集上脱敏触发率（应低）。

## 7. 评测协议

- **隐私泄露率**：攻击器恢复实体的正确率（精确匹配为主，部分匹配为辅助）；按实体类型分层报告。
- **任务指标**：抽取 F1 / 分类 acc / 生成 BERTScore。
- **统计**：3 种子（2026/7/42）mean±std；泄露率差用 McNemar；F1 差用配对 t（α=0.05）。
- **帕累托**：以"泄露率-任务 F1"平面报告前沿，附支配率。
- **合规**：所有 PII 为合成虚构数据，声明无真实个人信息。
