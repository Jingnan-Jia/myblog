# 实验设计书：Idea 10 物理一致的安全场景生成与闭环失效验证（Physics-Consistent Adversarial Scenario Generation with Closed-Loop Failure Validation）

> 主题 T01 自动驾驶感知与端到端驾驶 · 12 个 idea 之一 · 优先级：高（ICLR 2027 / IEEE T-IV）

## 0. 摘要

安全场景生成（Any2Critical/ScenGE）以「碰撞率」为单一指标可被轻易刷分（把对手设计得足够激进即可），且无物理可行性校验、无闭环失效复验。本工作建立「RAG 场景检索 → LLM 元描述 → 约束流匹配生成（CCFM 风格）→ 物理一致性过滤 → 闭环失效验证 → 失败归因 → 回灌难例库」的完整链路：对抗轨迹必须满足运动学/动力学可行（过滤传送式碰撞），生成场景在模拟器中跑基线 planner 只有真实暴露特定失败类别才计入有效，并用「覆盖度 × 真实性 × 失效归因」三维场景有效性度量替代单一碰撞率。预期有效失效暴露率较 Any2Critical 提升 ≥2 倍。贡献：(1) 首个物理一致性过滤 + 闭环失效验证的完整生成链路；(2) 替代碰撞率的场景有效性度量。

## 1. 研究背景与动机

### 1.1 问题定义

给定任意真实世界场景上下文（地图、背景车辆、天气），生成对抗场景（他车轨迹/行为），要求：(a) 场景物理可行（车辆动力学可实现，非传送式碰撞）；(b) 能真实暴露基线 planner 的特定失败类别（被追尾、乱变道碰撞、路口抢行）；(c) 有效性度量不依赖单一碰撞率。

### 1.2 相关工作不足

- Any2Critical（Philosophy and Ethics of AI · 论文 24）RAG 生成、平均碰撞率 89.69%，但碰撞率可刷分、RAG 静态检索、无物理可行性与闭环失效验证（报告 3.4 精读空白）。
- ScenGE（Special Track on AI for Social Impact I · 论文 82）LLM 元场景 + 对抗协作图，代码级控制，但背景车优化仍偏启发式、无物理一致性显式校验。
- DiffScene（AAAI 2025，DOI 10.1609/aaai.v39i8.32951）、SAFE-SIM（arXiv 2401.00391）、Versatile Behavior Diffusion（arXiv 2404.02524）证明扩散生成对抗行为有效，但均未闭环失效归因。
- CCFM: Collision-Constrained Flow Matching（arXiv 2607.04451）刚提出碰撞约束流匹配，说明「约束生成」是 2026 新热点，尚无完整闭环链路。
- 空白：生成 → 物理校验 → 闭环评估的完整链路（调研报告 §3.4 心得）。

### 1.3 为什么是现在、为什么你的环境适合

- 现在是：约束生成（CCFM）与 LLM 场景推理（Any2Critical/ScenGE）都刚出现，把它们缝合进闭环验证是窗口期；政策对可验证安全测试是刚需（呼应哲学伦理板块）。
- 环境适合：生成器 <500M + 模拟器批量并发，4×L40 流水线可跑（2 卡生成 + 2 卡闭环复验）；CARLA 并发实例可横向扩展；无需大型预训练。

## 2. 研究目标与可验证假设

- **H1（物理过滤必要）**：物理一致性过滤显著剔除「传送式碰撞」，提升有效失效暴露率。
  - 可观测结果：过滤后「传送式碰撞」占比从 ~40% 降到 <5%；有效失效暴露率相对不过滤 +≥50%。
- **H2（闭环复验必要）**：生成场景只有经模拟器闭环复验暴露特定失败类别才有效。
  - 可观测结果：仅「碰撞」的生成场景有 ~30% 在闭环复验中不构成真实失败（误报）；加入复验后有效性提升。
- **H3（度量替代碰撞率）**：三维度量（覆盖度×真实性×失效归因）比单一碰撞率更抗刷分。
  - 可观测结果：把基线 planner 换成更激进策略时，碰撞率仍高但三维有效性显著下降；三维度量与「真实暴露失败类别数」相关系数更高。
- **H4（RAG 库规模）**：RAG 库增大 → 覆盖度提升且有效性不降。
  - 可观测结果：库 500→5000 时覆盖度 +30%、真实性不降（多样性-真实性 Pareto 前沿可度量）。

## 3. 总体方法设计

### 3.1 数据流水线

- 场景来源：nuScenes/Argoverse 场景基底（地图、背景车、初始条件）+ NHTSA-5K 式事故库（自建：从公开事故报告/碰撞模板整理，Any2Critical 同源思路）。
- RAG 检索：给定目标失败类别（如「被追尾」），从事故库检索最相关模板（语义 embedding 检索）；LLM 元场景推理（沿用 ScenGE 元描述思路）生成场景参数（背景车位置/速度/意图、天气）。
- 轨迹生成：CCFM 风格碰撞约束流匹配生成对抗他车轨迹（碰撞时间约束 + 运动学约束）。
- 物理一致性过滤：
  - 运动学可行：速度曲线满足 $|a| \le a_{max}=4m/s^2$、加加速度约束、转向率 $|\dot\theta|\le 30°/s$。
  - 动力学可行：横向加速度与曲率一致性检查。
  - 行为合理性：给对抗车加「反应延迟」（人类驾驶员反应 0.8–1.5s）防「读心级」突然规避。
  - 过滤阈值放宽度设为超参（实验 H 中做 Pareto 消融）。
- 闭环失效验证：生成场景在 CARLA 中跑基线 planner（SparseDrive/本环境自训 planner），记录碰撞/违规/僵局事件 + 场景 trace。
- 失败归因：用 Idea 1 critic + LLM 归因报告（从轨迹+视频判断失败类别与责任主体：SDV 过错/他车过错/环境）。
- 回灌难例库：归因正确的失败场景回灌 RAG 库（飞轮）。
- LLM 角色（DeepSeek V4 Pro / Kimi K2.6）：事故库检索重排序、元场景推理、失效归因报告（结构化 JSON）。
- 数量预期：RAG 库初始 1k 模板；每轮生成 1 万候选 → 物理过滤后 3k → 闭环复验 3k → 有效 600 回灌；3 轮迭代后库达 3k+。

### 3.2 模型/算法设计

- 生成器：约束流匹配（CCFM 风格，<500M）或扩散行为生成（VBD 风格）二选一，按复现难易选 VBD 官方实现（arXiv 2404.02524）。
- 物理过滤器：显式规则检查器（运动学/动力学不等式），不训练。
- 有效性度量：
  - 覆盖度 = 生成场景在失败类别空间（碰撞类型 × 场景拓扑 × 天气）的多样性覆盖比例。
  - 真实性 = 物理过滤通过率 + 行为合理性得分（LLM 评分 + 运动学指标）。
  - 失效归因 = 归因正确的失败 / 总失败（由闭环复验真值判定）。
  - 综合 $S = w_c C + w_t T + w_a A$，$w_c=w_t=w_a=1/3$；报告三维分量。
- 基线 planner：SparseDrive（200M，本环境训练）作为被测对象；可切换（实验 F）。

### 3.3 训练流程

- 无大模型重训练（主要工程是流水线）；生成器若有需微调（VBD 条件微调）则 3–5 GPU·天。
- 流水线调度：GPU0-1 生成 + 过滤；GPU2-3 并行开 4 个 CARLA 实例做闭环复验（CPU 受限时用 2 实例 + 更长耗时）。
- 轮次迭代：3 轮，每轮 1 万候选。

### 3.4 推理与评测流程

- 每轮：检索 → 生成 → 过滤 → 复验 → 归因 → 回灌 → 统计三维度量。
- 评测对比：与 Any2Critical/ScenGE 机制基线在「有效失效暴露率、碰撞率、真实性、覆盖度」四维对比。

## 4. 数据集细节

- nuScenes / Argoverse 2 场景基底：作为初始场景（地图 + 背景车辆采样）。
- 自建 NHTSA-5K 风格事故库：从公开事故碰撞模板整理 1k 条（按碰撞类别、拓扑、天气分类）；文中说明构建过程（不涉及版权数据）。

## 6. 实验矩阵

- **A. 主实验**：完整链路 vs 基线。目的：验证 H1/H2。预期：有效失效暴露率 ≥0.4。
- **B. 物理过滤器阈值消融**：严格/中等/宽松。目的：多样性-真实性 Pareto。预期：中等阈值平衡，报告 Pareto 前沿。
- **C. 闭环复验必要性**：无复验（仅几何判定）vs 有复验。目的：验证 H2。预期：无复验误报率 ~30%。
- **D. RAG 库规模**：{500, 1k, 3k}。目的：验证 H4。预期：覆盖度上升、真实性不降。
- **E. 失效归因消融**：LLM 归因 vs 规则归因 vs 无归因。预期：LLM 归因 A 分量最高。
- **F. 跨 planner**：被测对象 = SparseDrive / OpenDriveVLA 轨迹头 / 保守规则 planner。预期：保守 planner 失败类别不同，链路通用。
- **G. 飞轮回灌**：3 轮迭代有效性变化。预期：回灌后有效失效暴露率单调上升。
- **H. 度量抗刷分检验**：更换激进 baseline 策略对比碰撞率 vs 三维度。目的：验证 H3。

## 7. 评测协议

- 指标：有效失效暴露率（归因正确失败 / 总生成）、碰撞率、物理可行通过率、覆盖度、真实性、误报率。
- 均值±方差：3 个场景 seed（CARLA 随机化固定）；显著性用 bootstrap（有效性分布偏态）。
- 固定：CARLA 版本、seed、500 上下文集合、失败类别 taxonomy。
- 可复现：公开 RAG 库构建流程、过滤器代码、归因 schema、评测脚本。

## 8. 算力与资源计划

- 生成 + 过滤：3 轮 × 1 万候选 ≈ 3 GPU·天（2 卡）。
- 闭环复验：3 轮 × 3k 场景 × 每场景 ~1 分钟 / 4 实例并行 ≈ 4–6 天（CPU 并行，GPU 少用）。
- 生成器微调（如 VBD 条件）：≈ 3 GPU·天。
- 合计 GPU 约 6–9 GPU·天 + CPU 复验 4–6 天（可压缩）；存储 ≈ 500GB（场景 trace + 视频）。
- API：检索重排序 + 归因报告 ≈ 6M token ≈ $10。

## 10. 风险与备选方案

| 风险 | 概率 | 影响 | 预案 |
|---|---|---|---|
| 模拟器闭环复验吞吐低 | 中 | 高 | 并发批次 + 预过滤难例（先几何碰撞判定再上模拟器）+ 降采样复验帧率 |
| 物理过滤器误伤多样场景 | 中 | 中 | Pareto 消融（实验 B）公开 trade-off；对真实但激进的「危险行为」用行为合理性软约束而非硬过滤 |
| 归因 LLM 不准确 | 中 | 中 | 与 Idea 1 critic 交叉验证；规则兜底（几何时序证据判定责任） |
| 有效失效暴露率偏低 | 中 | 中 | 检索更难模板 + 增强对抗强度（约束范围内） + 多轮回灌 |
