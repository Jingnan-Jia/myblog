# 实验设计书：Idea 7 鱼眼球面占据：几何对齐的跨域鲁棒宽视场感知（Fisheye Spherical Occupancy: Geometry-Aligned Cross-Domain Robust Wide-FOV Perception）

> 主题 T01 自动驾驶感知与端到端驾驶 · 12 个 idea 之一 · 优先级：中（ICRA 2027）

## 0. 摘要

现有鱼眼 3D 感知只在合成数据上验证 3DOD（Fisheye3DOD），真实鱼眼占据预测无基准；BEV 类方法假设针孔几何，强畸变下深度误差大。本工作把 SPSC 稀疏占据与球面坐标表示结合：用等距球面-深度双表示 token 化体素，建立合成（CARLA 鱼眼）→ 真实（nuScenes/WoodScape 鱼眼）的几何对齐自监督（轨迹一致性约束，无需配对），并做鱼眼-针孔混合阵列训练提升鲁棒性。预期合成-真实 gap 较直接在鱼眼上跑 SPSC 减半、球面/笛卡尔占据 mIoU 与 3DOD AP 双提升。贡献：(1) 首个球面坐标稀疏占据框架；(2) 无配对的合成-真实几何对齐；(3) 混合阵列鲁棒性协议。

## 1. 研究背景与动机

### 1.1 问题定义

鱼眼相机视场角可达 190°+，强径向畸变使针孔 BEV 投影假设失效。要求：在鱼眼输入下直接预测 3D 占据（球面-笛卡尔双表示），并跨越合成（CARLA）→ 真实（nuScenes/WoodScape）域保持精度。

### 1.2 相关工作不足

- Fisheye3DOD（Computer Vision V · 论文 13）只做 3DOD、只在 CARLA 合成数据验证，无真实数据泛化、未扩展到占据/融合。
- 现有 BEV/占据方法（SPSC、OccFormer 类）假设针孔几何，鱼眼强畸变下深度误差大。
- 鱼眼综述（Surround-View Fisheye Camera Perception for Automated Driving，IEEE T-ITS 2023，DOI 10.1109/tits.2023.3235057）指出球面表示是鱼眼 3D 感知的关键几何范式。
- 空白：真实鱼眼占据无基准、合成-真实鸿沟无解决方案。

### 1.3 为什么是现在、为什么你的环境适合

- 现在是：CARLA 可大规模合成鱼眼数据（Fisheye3DOD 已证明可行性）；nuScenes 含鱼眼环视相机（CAM_FISH* 不一定有，需用其全景相机的球面投影数据或 WoodScape 提供真实鱼眼）。
- 环境适合：骨干 <300M，合成预训练 80k（3 GPU·天）+ 真实微调 40k（2 GPU·天），4×L40 轻松；无大模型负担，主要工作量在数据组装。

## 2. 研究目标与可验证假设

- **H1（球面表示有效）**：球面坐标 token 化的稀疏占据在鱼眼输入上显著优于笛卡尔假设的基线。
  - 可观测结果：合成数据上球面 mIoU 相对「SPSC 直接跑鱼眼」+≥8 点；3DOD AP +≥5 点。
- **H2（几何对齐跨域）**：无配对的轨迹一致性自监督显著缩小合成-真实 gap。
  - 可观测结果：真实微调后 mIoU 相对「只合成预训练→真实直接测」提升 ≥10 点；gap（真实 − 合成）减半。
- **H3（混合阵列鲁棒）**：鱼眼-针孔混合训练提升在部分相机失配（阵列异构）下的鲁棒性。
  - 可观测结果：混合阵列训练在异构评测下 mIoU 保持率 +10 点。
- **H4（双表示可迁移）**：球面表示可作为中间表征，输出可微映射回笛卡尔体素供下游规划消费。
  - 可观测结果：球面→笛卡尔可微映射引入的 mIoU 损失 <2 点；供下游占据规划器使用不阻塞。

## 3. 总体方法设计

### 3.1 数据流水线

- 合成数据（CARLA）：沿用 Fisheye3DOD 合成管线，或自建 CARLA 鱼眼采集（190° 等距投影相机 + 占据真值来自 CARLA 语义渲染/标注）。目标 5k 帧（多天气、多路口、多时刻）。
- 真实数据：nuScenes 全景相机序列（若可投到鱼眼球面投影）或 WoodScape（真实鱼眼，标注为 2D 检测为主，占据需弱标注）；WoodScape 提供鱼眼内参 + 畸变模型。
- 无配对几何对齐（自监督）：同一车辆在鱼眼与针孔视图同时观测 → 「轨迹一致性」：3D 点在两个视图的球面/针孔重投影应一致 → 构造跨视图几何一致损失（无需逐像素配对）。
- 混合阵列：把鱼眼相机与针孔相机混排训练（比例 1:1），模拟异构环视。
- LLM 用法（DeepSeek V4 Pro）：生成「鱼眼场景描述与畸变问题报告」（近景畸变、边缘拉伸、遮挡），辅助标注优先级与难例采样；生成合成场景变体提示词（天气/光照/障碍组合）驱动 CARLA 渲染。
- 数量预期：合成 5k 帧、真实 2k 帧（WoodScape/nuScenes 鱼眼子集）、混合阵列增广 4k 帧。

### 3.2 模型/算法设计

- 骨干：SPSC 稀疏占据（渐进剪枝 + 序列化），输入分支改为**球面特征编码器**。
- 球面坐标表示：体素在球面参数化（等距 $(r, \theta, \phi)$）+ 深度通道双表示；query 位置编码用球面坐标而非笛卡尔。球面→笛卡尔可微映射 $\Phi: (r,\theta,\phi)\to(x,y,z)$ 作为输出头最后的网格化层（保持可微）。
- 深度一致性损失：$L_{depth} = \|\hat d_{fisheye} - d_{depth_proj}\|_1$（鱼眼深度 = 从球面射线与 3D 占据边缘交点反投影），缓解鱼眼深度歧义。
- 跨视图几何一致（对齐）：$L_{align} = \sum_{p \in 3D} \|\Pi_{fish}(p) - \Pi_{pinhole}(p)\|_1$（3D 点在鱼眼/针孔投影一致），自监督无需配对。
- 主损失：占据语义 mIoU（focal+dice）+ $L_{depth} + \lambda_{al} L_{align}$，$\lambda_{al}=0.3$。
- 超参初值：球面网格 128×64×16（r,θ,φ）、query 数 300、序列化长度 1024、d_model 256。

### 3.3 训练流程

- 阶段 1（合成预训练）：80k step，lr 3e-4，cosine，warmup 2k，batch 8/卡 × 4，DDP（<300M），3 GPU·天。
- 阶段 2（真实微调）：40k step，lr 1e-4，数据 = 真实 + 20% 合成（防遗忘），2 GPU·天。
- 阶段 3（混合阵列微调）：20k step，lr 5e-5，鱼眼+针孔混合，1 GPU·天（可选）。

### 3.4 推理与评测流程

- 推理：鱼眼图像 → 球面特征 → 稀疏占据头 → 双表示输出（球面 + 笛卡尔）。
- 评测：合成测试集（CARLA 留出场景）、真实测试集（WoodScape/nuScenes 鱼眼子集）分别测球面/笛卡尔 mIoU 与 3DOD AP；报告合成-真实 gap。
- 跨域协议：合成训练→真实直接测（gap 基线）vs 加对齐 vs 加微调，逐步分解每个环节的 gap 减少。

## 4. 数据集细节

- CARLA（合成）：0.9.x，自采 5k 帧鱼眼（190° 等距）+ 占据真值；或复用 Fisheye3DOD 数据（许可需向作者确认）。
- WoodScape（真实鱼眼）：https://www.waves.utoronto.ca/；CC 许可需确认；提供多鱼眼相机（190°）与 2D 检测/语义分割标注（占据需自标弱监督）。
- nuScenes（全景相机投球面）：CC BY-NC-SA 4.0；全景相机可重投影为等距球面视图作为真实鱼眼替代。
- 划分：合成 5k（4k 训练 / 500 验证 / 500 测试）；真实 2k（1.6k 训练 / 400 测试）。

## 6. 实验矩阵

- **A. 主实验**：球面稀疏占据全管线 vs 基线。目的：验证 H1。预期：合成 mIoU +8 点、AP +5 点。
- **B. 坐标表示消融**：球面 / 笛卡尔 / 球面-深度双表示。目的：隔离几何范式贡献。预期：双表示最优。
- **C. 对齐损失消融**：无对齐 / 对齐 / 对齐+微调。目的：验证 H2。预期：gap 逐级减半。
- **D. 混合阵列消融**：纯鱼眼 / 纯针孔 / 混合（1:1）。目的：验证 H3。预期：混合在异构评测最稳。
- **E. 深度一致性消融**：±L_depth。预期：鱼眼深度歧义缓解 mIoU +2 点。
- **F. 合成数据规模**：{2k, 5k, 10k}。预期：规模增大 gap 下降但边际递减。
- **G. 可微映射验证**：球面→笛卡尔映射的 mIoU 损失 + 下游占据 planner 兼容性。目的：验证 H4。

## 7. 评测协议

- 指标：球面/笛卡尔 mIoU、3DOD AP（moderate）、合成-真实 gap（= |真实 − 合成| mIoU）、退化鲁棒性（异构阵列 mIoU 保持率）。
- 均值±方差：3 seeds；显著性配对 t-test。
- 固定：合成渲染 seed、测试帧集、评测脚本版本。
- 可复现：公开 CARLA 采集配置、WoodScape 预处理、config/权重。

## 8. 算力与资源计划

- 合成数据采集/渲染：CARLA 5k 帧 ≈ 2–3 天（CPU 渲染可并行）。
- 训练：80k + 40k + 20k ≈ 6 GPU·天。
- 评测：两域 × 两表示 ≈ 1 GPU·天。
- 合计 ≈ 7 GPU·天 + 渲染时间；存储 ≈ 250GB。
- API：场景描述/变体 prompt ≈ 2M token ≈ $3。
