# 实验设计书：RiskChat：监管条款增强的可解释金融合规/风控对话智能体

> 所属主题：T11 金融AI与决策 ｜ 文件：Idea10_RiskChat.md
> 关联收藏论文：Application Domains II · 论文 24（TermGPT，术语嵌入）；依赖 Idea03 嵌入与 Idea09 验证器

## 0. 摘要

RiskChat 是一个面向金融合规问答与适当性匹配的**可解释对话智能体**：每条回答附"条款来源 + 推理链（条款→事实→推断）"，并内置过期条款识别与用户适当性匹配。它把 TermGPT 的术语表示能力、Idea 9 的验证器与 RAG 结合成产品级闭环。知识库为结构化监管条款（SEC 规则、中证/银保监/证监会条文，含生效/修订日期）。核心贡献：(1) 条款级来源锚定 RAG（回答必须引具体条款 + 生效日期）；(2) 适当性引擎（用户风险画像 → 产品风险等级匹配，对标监管适当性规则）；(3) 可解释三步推理链，供合规人员复核。评测集 RegComplianceQA 含人工标注的条款引用 ground-truth 与过期条款陷阱。

## 1. 研究背景与动机

### 1.1 问题定义

输入：用户问题 Q（合规咨询 / 适当性 / 风控意图）+ 用户画像 P（风险承受能力、投资经验、资产规模）。输出：回答 A（含引用的条款 C 与生效日期）、推理链（条款→事实→推断）、适当性结论。评测：回答正确率、引用真实率（条款存在且正确）、过期条款检出率、适当性匹配准确率、解释质量。

### 1.2 相关工作不足

- **TermGPT（AAAI Application Domains II · 论文 24）**：只改表示不产出合规产品，未做条款级来源锚定；
- **PortfolioPilot（AAAI Emerging Trends in AI · 论文 284）**：NL→算法平台，无适当性匹配与条款引用；
- **TRIDENT（arXiv:2507.21134）**：评测金融安全但未给可解释性方案与条款锚定；
- **通用 RAG**：常混淆条款、编造出处、无生效日期版本管理；Corrective RAG（2604.01733）改进检索但非条款级锚定；
- **TermGPT 表示 + Naive RAG**：表示好但无过期条款识别与推理链。

### 1.3 为什么是现在、为什么你的环境适合做

监管对"金融 AI 必须可解释、可溯源"的要求收紧；监管文本公开结构化可得；TermGPT 刚证明领域表示收益但缺产品闭环。环境优势：(1) 7B QLoRA + 检索器 2-3 GPU·天可训练；(2) 条款版本管理是纯数据工程；(3) 与 Idea 3（术语嵌入）、Idea 9（验证器）模块复用。

## 2. 研究目标与可验证假设

| # | 假设 | 成立时的可观测结果 |
|---|------|---------------------|
| H1 | 条款级来源锚定 RAG 显著降低编造出处 | 引用真实率（条款存在且正确）比通用 RAG 高 ≥20 个点 |
| H2 | 过期条款识别有效 | 过期条款陷阱样本的检出率 >85% |
| H3 | 适当性引擎匹配准确 | 适当性匹配准确率 >85%（人工标注 ground-truth） |
| H4 | TermGPT 式术语嵌入提升条款检索 | 术语嵌入检索器的条款命中率高于通用嵌入 ≥5 个点 |

第一验证实验：在 500 条人工合规问答上跑"通用 RAG vs 条款锚定 RAG"对照，测引用真实率（H1），1 周出结果。

## 3. 总体方法设计

### 3.1 数据流水线

- **条款知识库**：SEC 规则（Regulation S-K/S-T 等，含发布/修订日期）、中证/证监会/银保监办法（中文，含生效日期）；条款块化 + 编号 + 版本时间戳 + 主题标签；
- **合规问答对生成**（DeepSeek V4 Flash + Kimi K2.6）：按"问题-条款-答案"模板生成，覆盖：条款咨询、适当性（产品风险等级 vs 用户画像）、风险提示；每条含 ground-truth 条款引用与生效日期；
- **过期条款陷阱**：人工构造"问当前有效规则，模型若引 2019 年旧版即错"的样本 + LLM 生成变体；
- **用户画像场景**（Kimi K2.6）：不同风险承受/经验/资产组合的画像描述；
- **清洗与去泄漏**：条款版本只取评测日之前生效版本；问答构造日期记录；评测与训练按日期切分；
- **数量**：条款 ~30k 块（中英）；训练问答 ~20k；评测 RegComplianceQA 人工 2,000（含过期陷阱 400 + 适当性 600）。

### 3.2 方法设计

- **意图分类**：合规咨询 / 适当性 / 风控三分类（小模型）；
- **条款检索**：TermGPT 式术语嵌入（复用 Idea 3 权重）或 bge-m3 + 关键词混合，检索 top-k（k=8）条款，按"主题匹配 + 生效日期 ≤ 当前"过滤；
- **生成**：7B LLM（QLoRA 微调），指令要求输出 JSON：{answer, citations:[{clause_id, effective_date, quote}], reasoning_chain:[条款→事实→推断], suitability_verdict}；
- **验证器**（复用 Idea 9）：校验 citations 真实存在 + 引文与条款内容一致 + 生效日期正确；失败触发重写（≤2 轮）；
- **适当性引擎**：规则表（产品风险等级 R1-R5 × 用户画像匹配规则，对标监管适当性办法）+ LLM 落盘结论；
- **可解释性**：三步链结构化输出 + 合规复核界面（人工可审）；
- **防泄漏**：检索与生成只用生效日期 ≤ 当前的条款；过期陷阱刻意考验版本管理。

### 3.3 训练流程

- 检索：bge-m3 冻结 / 或 Idea 3 的术语嵌入微调；
- 生成模型：7B QLoRA（r=16, α=32, lr=2e-5），SFT 2 epochs，4×L40 FSDP，2-3 GPU·天；
- 适当性引擎：规则表（可解释、无需训练）+ LLM 校验。

### 3.4 回测与评测流程

- **评测协议**：RegComplianceQA 全量（2,000）；指标：回答正确率（答案与 ground-truth 语义一致，Pro judge + 人工复核 200）、引用真实率、过期检出率、适当性准确率、解释可用性（三步链完整 + 无矛盾）；
- **防泄漏**：条款版本快照；问答构造日期晚于条款生效；评测 200 条人工复核 κ≥0.85；
- **插拔消融**：有无验证器、有无术语嵌入、有无过期过滤。

## 5. 基线复现

| 基线 | 类型 | 复现方式 | 预期指标 |
|---|---|---|---|
| 通用 RAG（bge-m3 + LLM） | 朴素 | https://github.com/FlagOpen/FlagEmbedding | 正确率/引用真实率 |
| Corrective RAG | 增强检索 | arXiv:2604.01733 复现 | 同上 |
| 零样本 DeepSeek | 无检索 | 直接回答 | 同上 |
| TermGPT 表示 + Naive RAG | 表示增强 | arXiv:2511.09854 嵌入 + 朴素检索 | 同上 |
| RiskChat（无验证器） | 消融 | 本设计去验证器 | 引用真实率（预期降） |
| RiskChat（完整） | 本方法 | 本设计 | 全部指标 |

**统一口径**：同一评测集、同一 judge（Pro + 人工复核）、同一检索知识库版本。

## 6. 实验矩阵

- **A 主实验**：RiskChat vs 基线（正确率 / 引用真实率 / 过期检出 / 适当性准确率）；
- **B 检索器消融**：通用嵌入 vs 术语嵌入 vs 关键词（H4）；
- **C 验证器消融**：有无验证器 + 重写轮数（H1）；
- **D 过期条款专项**：陷阱样本检出率 + 版本管理正确性（H2）；
- **E 适当性消融**：规则表 vs 纯 LLM vs 无画像；
- **F 意图分类消融** + 跨语言（中/英子集）；
- **G 稳健性**：条款版本扰动、种子、检索 top-k。

## 7. 评测协议

- **指标**：回答正确率（语义一致）、引用真实率（条款存在且内容一致）、过期条款检出率、适当性匹配准确率、推理链完整率；
- **统计**：3 种子 mean±std；模型间 McNemar/paired 检验；人工复核 200 条 κ 报告；
- **无前视**：条款版本快照 + 日期切分；评测不接触训练问答。

## 8. 算力与资源计划

| 阶段 | 资源 | 量 |
|---|---|---|
| 条款知识库构建 | CPU | 2 人·周 |
| 问答对生成 | API（Flash + Kimi） | 约 8,000 万 token |
| 生成模型 SFT | 4×L40 | 8-12 GPU·天（2-3 天） |
| 检索 + 评测 | 4×L40 + API（Pro judge） | 2-3 GPU·天 |
| 存储 | 条款 + 问答 + checkpoint | <300GB |
| 总计 | 4×L40 | 约 10-16 GPU·天 |

**API 成本**：Flash 问答生成约 6,000 万 token；Kimi 长解释/画像约 1,000 万；Pro judge 约 1,500 万。估算 $400-1,000（按当期定价核算）。

## 10. 风险与备选方案

| 风险 | 等级 | 缓解/备选 |
|---|---|---|
| 监管文本时效性与版本管理（条款频繁修订） | 高 | 版本时间戳为数据一等公民；过期过滤强制开启；陷阱样本专项评测 |
| 免责/责任问题 | 中 | 定位"辅助合规"；输出免责声明；合规复核界面人工闭环 |
| 引用真实率提升有限（H1 弱） | 中 | 加强验证器重写闭环 + 检索 top-k 调参；主结论收缩为"可解释性 + 版本管理" |
| 适当性规则标准化难 | 中 | 以公开监管办法为蓝本建立规则表；规则透明可审 |
| 跨语言一致（中/英） | 中 | 分语言子集训练与评测；翻译一致性消融 |
