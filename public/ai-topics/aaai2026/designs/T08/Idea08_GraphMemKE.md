# 实验设计书：Idea 8 可扩展的多跳编辑图记忆（GraphMemKE）

## 0. 摘要
本项目提出 GraphMemKE：用"编辑即图节点更新"的动态图记忆 + 图游走计划 + LLM 推理验证，替代 ALEX 的静态聚簇与 MeLLo 的线性存储。编辑流经 LLM 抽取为带时间戳的三元组建图，新旧事实以证据强度裁决冲突；检索 = 查询实体子图展开（BFS/PPR 变体）；生成 = 游走路径 + LLM 逐跳验证。在 MQuAKE/MQuAKE-CF 上对照 MeLLo/GMeLLo/CLEVER-CKE/ALEX/CaKE，把"编辑规模伸缩性"作为一等指标（1/10/100/1000 条编辑下的精度、延迟、内存）。无大模型训练（API 为主），约 2–4 GPU·天，投稿 ACL 2027 / EMNLP 2026。

## 1. 研究背景与动机
### 1.1 问题定义
多跳知识编辑需要让模型在收到编辑流（不断新增/修改/删除事实）后，多跳推理答案保持更新。外部记忆式编辑（MeLLo 线性存储、ALEX 层次聚簇）在编辑数增大时检索退化；参数编辑（CaKE 电路感知）需微调、编辑爆炸。问题：设计一种"动态、有结构、可验证"的外部记忆，让编辑规模增长时精度不塌、检索可控。

### 1.2 相关工作不足
- ALEX（NLP IV · 论文 105 · ALEX:A Light Editing-knowledge Extractor）聚簇静态、无编辑冲突仲裁、复杂度分析理想化（O(K+N/C) 假设簇均匀）。
- MeLLo（arXiv:2305.14795）线性存储，检索复杂度随编辑数线性退化。
- GMeLLo（arXiv:2408.15903）、CLEVER-CKE（arXiv:2407.10275）静态 KG，无编辑冲突与时序。
- CaKE（arXiv:2503.16356）电路感知需参数微调；Reason-KE（arXiv:2509.01468）推理链对齐，抗干扰但无动态图。
- 知识编辑综述（arXiv:2401.01286）指出"动态、可验证外部记忆"仍是空白。

### 1.3 为什么是现在、为什么你的环境适合做
- 证据：外部记忆式编辑 2024–2025 成为主流（GMeLLo/CLEVER-CKE/CaKE/Reason-KE），但动态图记忆仍空白；ALEX（AAAI 2026）证明层次化方向正确但静态。
- 环境：本方法全走 DeepSeek API（图构建/仲裁/推理）+ 4×L40 生成评测，无训练负担；Kimi 做多跳 judge，成本可控。

## 2. 研究目标与可验证假设
- H1（动态图优于静态存储）：编辑数 100–1000 时 GraphMemKE 的 MultiHop-ACC 显著高于 MeLLo/ALEX。成立时观测：1000 条编辑时 MultiHop-ACC 领先 ≥ +10 个点。
- H2（冲突仲裁有效）：同实体新旧事实冲突时，证据强度仲裁能选对最新/最强事实。成立时观测：冲突集上仲裁正确率 ≥85%。
- H3（游走计划可验证）：图游走 + LLM 逐跳验证的推理正确率高于无游走计划的直接检索拼接。成立时观测：HopWise-ACC 提升 ≥ +5 个点。
- H4（伸缩性）：编辑 1→1000 条，精度下降 <5 个点，检索延迟亚线性增长。成立时观测：1000 条时 MultiHop-ACC ≥ 10 条时 −5 点以内。

## 3. 总体方法设计
### 3.1 语料/数据流水线
1. 编辑流：MQuAKE 官方编辑（arXiv:2305.14795）+ DeepSeek 生成干扰编辑（同实体矛盾事实、无关事实各半），1000 条带时间戳。
2. 三元组抽取（DeepSeek V4 Pro）：prompt `Extract (head, relation, tail) triples with confidence from the new fact`，构建动态图节点/边。
3. 冲突仲裁：新旧事实对同 (h,r) 时，用证据强度（来源可信度、时间戳、一致性 judge）裁决；记录被覆盖版本供 Revoke 类评测。
4. 验证问题：DeepSeek 按 MQuAKE 模式生成多跳问题 + 分步答案，人工抽检 100 条。

### 3.2 方法设计
- 动态图记忆：邻接表 + 时间戳 + 版本指针；节点 = 实体，边 = 关系（带 validity 窗口）。
- 冲突解决：score = λ1·timestamp + λ2·evidence_strength(judge) + λ3·consistency(与已知图一致性)，取最高；λ 初值 0.4/0.4/0.2。
- 检索 = 查询实体子图展开：BFS 深度 d=2 或 PPR（对照 HippoRAG 思想，arXiv:2405.14831）取 top-k 子图节点/边；候选事实携带时间戳与版本。
- 生成 = 游走计划 + 验证：检索子图 → DeepSeek 生成"推理路径计划"（哪些实体-关系链）→ 逐跳用 LLM 验证每个 hop 是否有证据 → 汇聚答案。
- 伸缩性机制：图分片（按实体前缀分桶）+ 内存 LRU；1000 条编辑时仅加载相关分片。
- 超参数初值：BFS 深度 d=2、top-k 子图节点 50、PPR α=0.85、λ=0.4/0.4/0.2。

### 3.3 训练流程
- 无大模型训练（API 为主）。
- 可选：7B 推理游走策略 LoRA 微调（学习"何时停止展开/何时验证"），2 GPU·天。
- 4×L40 用于 MQuAKE 生成评测（vLLM 并行）。

### 3.4 评测流程
- MQuAKE/MQuAKE-CF 官方评测：MultiHop-ACC、HopWise-ACC。
- 伸缩性评测：编辑数 1/10/100/1000 下精度、推理延迟、内存占用曲线。
- 冲突评测：仲裁正确率（人工 100 条抽检）。
- 图构建质量：LLM 抽取三元组准确率（人工审计 100 条）。

## 6. 实验矩阵
- A（主实验）：GraphMemKE vs 基线，MQuAKE + MQuAKE-CF × 编辑数 100/1000。
- B（消融）：冲突仲裁策略（时间戳/证据强度/一致性/组合）；游走深度 d；PPR vs BFS；是否逐跳验证；可选游走策略 LoRA。
- C（鲁棒性）：编辑冲突密度（10/50%）；事实噪声（20% 错误三元组）；编辑风暴（单轮 100 条）。
- D（泛化性）：跨生成器；编辑时序乱序；图分片对伸缩性的影响。

## 7. 评测协议
- 多跳指标：MultiHop-ACC、HopWise-ACC（MQuAKE 官方）。
- 伸缩指标：精度-编辑数曲线、检索延迟（中位数）、内存峰值。
- 冲突指标：仲裁正确率、人工 100 条 κ。
- 图质量：LLM 抽取三元组准确率（人工 100 条）。
- 统计：3 种子；均值±std；配对 bootstrap p<0.05。

## 8. 算力与资源计划
- 4×L40：生成评测 ≈ 1–2 GPU·天；可选游走策略 LoRA 2 GPU·天；消融 ≈ 1 GPU·天；合计 2–4 GPU·天（不含可选训练）。
- 存储：图 + 编辑流 <10GB。
- API：图构建 + 仲裁 + 推理（DeepSeek）≈ 200–400 美元；多跳 judge（Kimi K2.6）≈ 100–200 美元；合计 ≤ 600 美元。

## 10. 风险与备选方案
| 风险 | 等级 | 对策 |
|---|---|---|
| LLM 抽取三元组质量不稳 | 高 | 小规模图（100 编辑）人工审计设质量阈值；低于阈值换更强 prompt |
| 冲突仲裁复杂度高 | 中 | 先用时间戳+一致性两因子简化，再增证据强度 |
| 1000 编辑下检索退化 | 中 | 图分片 + LRU；如仍退化则降为 500 编辑并在论文明确伸缩上界 |
| 基线代码获取困难 | 中 | 预注册链接；无法获取则按论文重实现并标注 |
