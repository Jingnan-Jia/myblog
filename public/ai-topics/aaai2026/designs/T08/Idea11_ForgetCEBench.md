# 实验设计书：Idea 11 学习型基数估计的多表遗忘评测协议（ForgetCE-Bench）

## 0. 摘要
本项目构建 ForgetCE-Bench：为 CEP 类学习型基数估计（CE）遗忘方法建立标准化评测协议，覆盖行删除、域删除、表间级联删除三类删除任务，补齐"删除目标精确性与隐私泄露"指标。在 IMDb/TPC-H（NeuroCard/FACE 架构）上，对 CEP、全量重训、随机参数掩码、无遗忘（直接保留）四类方法统一评测：删除后 Q-error、遗忘精确性、保留集性能、计算开销、删除比率敏感性。规模小（单卡可训）、4×L40 轻松并行多配置，约 3–5 GPU·天，投稿 ICDE 2027 / VLDB 2027。

## 1. 研究背景与动机
### 1.1 问题定义
学习型 CE 模型（NeuroCard/FACE 学多表连接基数分布）在使用中面临数据删除需求（隐私合规、用户删号、过期数据清理）。删除后若模型仍"记得"被删数据则造成隐私泄露；若粗暴重训则开销巨大。CEP 提出剪枝式遗忘，但社区缺乏统一评测协议：指标只报 Q-error 与开销，缺少"删除目标精确性"（被删数据对估计的影响是否真正消除）与隐私/归因指标，导致方法间无法公平对比。

### 1.2 相关工作不足
- CEP（ML III · 论文 33 · Forgetting by Pruning: Data Deletion in Join Cardinality Estimation）只报 Q-error 与开销，缺遗忘精确性/隐私类指标；仅 NeuroCard/FACE 两架构。
- 机器遗忘综述（arXiv:2209.02299）批评领域缺乏统一评估与隐私度量。
- DB 社区无跨方法可比基准；各论文自定删除任务，无法复现对比。

### 1.3 为什么是现在、为什么你的环境适合做
- 证据：CEP（AAAI 2026）刚定义 CE 遗忘问题；数据合规（GDPR 删除权）驱动"数据库级遗忘"需求上升；DB 社区（ICDE/VLDB）对"评测协议 + 隐私指标"类资源论文接受度高。
- 环境：NeuroCard/FACE 为小模型（MLP/autoregressive，单卡可训）；4×L40 可并行跑全部方法 × 删除配置；无需 API 或少量 API（DeepSeek 生成删除后查询集与说明文档）。

## 2. 研究目标与可验证假设
- H1（三类任务可区分）：三类删除任务（行/域/表间级联）的遗忘难度显著不同，级联最难。成立时观测：同方法下级联删除 Q-error 显著高于行删除。
- H2（遗忘精确性可测）：提出的遗忘精确性指标能区分"真遗忘"与"假遗忘"（随机掩码看似降低对删除数据的依赖）。成立时观测：CEP 在遗忘精确性上显著高于随机掩码。
- H3（精确性与精度平衡）：遗忘精确性提升伴随保留集性能小幅下降，CEP 的 Pareto 前沿优于全量重训与随机掩码。成立时观测：保留集 Q-error 与遗忘精确性的二维图 CEP 占优。
- H4（代价优势）：CEP 开销 < 全量重训 10%，且高删除率下 Q-error 不劣于全量重训。成立时观测：开销 ≤ 重训 5%，删除 70% 时 Q-error 与重训差 <5%。

## 3. 总体方法设计
### 3.1 语料/数据流水线
1. 数据：IMDb（official join benchmark 变体）、TPC-H（scale factor 1–10）——与 NeuroCard/FACE/CEP 同口径。
2. 删除任务构造：三类 × 删除比率 {10%, 30%, 50%, 70%}：行删除（按谓词删元组）、域删除（删除某属性值域）、表间级联删除（删除触发连接表元组）。
3. 删除后查询集：DeepSeek 生成删除相关查询（命中被删数据的查询）与保留数据查询；保留查询用于测保留集性能。
4. 归因验证说明：DeepSeek 生成"被删数据对哪些查询估计影响"的说明文本供评测文档化。

### 3.2 方法设计
- 方法集合：CEP（arXiv:2511.20293 复现：分布敏感性剪枝 + 域剪枝）、全量重训（上界）、随机参数掩码（近遗忘基线）、无遗忘（直接保留、下界）、Fisher 信息掩码（近似遗忘可选）。
- 指标定义：
  - 删除后 Q-error：对被删数据相关查询，模型估计基数/真实基数的误差（标准 q-error）。
  - 遗忘精确性（Forgetting Precision）：被删数据影响估计的残留度 = |估计(删除后) − 估计(删除前完整模型)| 的差异，或对被删查询"是否回到未训练状态"的度量（与 membership inference 对齐）。
  - 保留集性能：保留查询的 Q-error。
  - 开销：训练/微调/遗忘执行时间 vs 全量重训时间。
- 统一评测脚本输出指标矩阵（方法 × 删除任务 × 删除比率）。
- 超参数初值：删除比率 {10,30,50,70}%、剪枝阈值按 CEP 论文、bootstrap 1000。

### 3.3 训练流程
- NeuroCard/FACE：单卡训练（~1–2 小时/模型），4×L40 并行跑 4 方法 × 3 任务 × 4 比率 = 48 配置，约 2–3 GPU·天。
- CEP 复现：按论文实现剪枝（半连接删除结果算敏感度 + 域剪枝）。
- 无需 API 训练；API 仅用于查询集生成与文档化。

### 3.4 评测流程
- 全矩阵：删除后 Q-error、遗忘精确性、保留集性能、开销（vs 重训时间）、删除比率敏感性曲线。
- 隐私对照：把遗忘精确性与 membership inference 攻击成功率对齐（参考机器遗忘综述 arXiv:2209.02299 建议）。

## 4. 数据集细节
| 数据集 | 来源 | 许可 | 用途 |

## 5. 基线复现
| 基线 | 官方代码 | 预期 Q-error（删除 50%，IMDb，粗估） |
|---|---|---|
| 全量重训 | NeuroCard / FACE 官方代码库（CEP 论文标注） | ~5–15（上界） |
| CEP | arXiv:2511.20293（自实现） | ~6–18 |
| 随机参数掩码 | 自实现 | ~8–20 |
| 无遗忘（直接保留） | 自实现 | ~20–50（下界） |
| ForgetCE-Bench 评测协议 | 本项目 | 输出统一矩阵 |
- 复现步骤：NeuroCard/FACE 官方训练脚本；CEP 按论文实现剪枝算子。
- 统一口径：同一数据版本、同一查询集、同一 Q-error 定义、同一硬件（L40）。

## 6. 实验矩阵
- A（主实验）：4 方法 × 3 删除任务 × 4 比率，输出全指标矩阵。
- B（消融）：删除比率敏感性；剪枝阈值；Fisher 掩码 vs CEP；级联删除深度。
- C（鲁棒性）：查询分布偏移；数据分布偏斜（长尾）；TPC-H 不同 scale factor。
- D（泛化性）：架构（NeuroCard vs FACE）；扩展到第三方 CE 模型（如果可获取）。

## 7. 评测协议
- Q-error：P50/P90/P95 分位 + 均值。
- 遗忘精确性：对被删查询估计变化度量（归一化到 [0,1]）+ membership inference AUC。
- 保留集性能：保留查询 Q-error。
- 开销：方法耗时 / 全量重训耗时。
- 统计：5 个随机种子（数据采样）；均值±std；配对 bootstrap p<0.05；报告删除比率-精度曲线。

## 8. 算力与资源计划
- 4×L40：48 配置主实验 2–3 GPU·天；消融 + 泛化 1–2 GPU·天；合计 3–5 GPU·天。
- 存储：数据 + 模型 <50GB。
- API：DeepSeek 生成删除后查询集与说明 ≈ 50–100 美元；Kimi 文档/结果审查 ≈ 20–50 美元；合计 ≤ 150 美元。
