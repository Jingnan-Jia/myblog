# 实验设计书：Idea 7 证据充分性感知的 RALM 拒绝与校准（EvidenceGate）

## 0. 摘要
本项目提出 EvidenceGate：显式建模"检索到的证据是否足以支撑答案"，训练一个小型证据充分性校验器，把 RALM 的拒绝/回答决策从置信度启发式升级为"证据充分性门控"。构造四态训练数据（证据充分/不足/矛盾/缺失），训练 DeBERTa/Qwen2.5-0.5B 级校验器回归证据充分性；生成阶段两分支（回答 vs 拒绝）由门控裁决，并与拒绝后训练/DPO 联合优化。在自建四态集 + NQ/TriviaQA + RGB 子集上，对照 RALM 直接作答、refusal post-training、Self-RAG、LogProb 阈值弃权，主指标为回答准确率 + 拒绝正确率 + 校准 ECE。约 4–6 GPU·天，投稿 EMNLP 2026 / NeurIPS 2026。

## 1. 研究背景与动机
### 1.1 问题定义
检索增强模型（RALM）理想行为：检索到充分证据就作答，否则拒绝。实际存在两类缺陷：①过度拒绝——检索全不相关时，RALM 仍拒绝本可答对的问题（参数化知识可答）；②过度自信——证据不充分也自信作答。现有拒绝机制依赖 logprob 启发式，没有显式建模"证据充分性"这一中间量。问题：如何量化证据充分性，并用它做按需回答/拒绝的门控？

### 1.2 相关工作不足
- RALM 实证（NLP VI · 论文 77 · Do Retrieval Augmented Language Models Know When They Don't Know?）发现过度拒绝、拒绝与校准脱节，但其拒绝机制是启发式组合、不确定性估计仅 logprob 类。
- Self-RAG（arXiv:2310.11511）有反思 token 但不显式建模证据充分性。
- UQ 综述（arXiv:2412.05563）与 2026 ACL 综述（arXiv:2601.15690）指出不确定性应从诊断走向控制信号，中间缺"证据充分性"量化器。
- Double-Bench（NLP IV · 论文 30）描述过度自信但无修正机制；缺乏矛盾/无关证据诊断子集。

### 1.3 为什么是现在、为什么你的环境适合做
- 证据：可信 RAG / RALM 校准是 2026 热点（EMNLP/NeurIPS 投稿窗口）；"证据充分性作为控制信号"与 2026 ACL 综述观点（arXiv:2601.15690）完全同构；本主题 RALM 论文（arXiv:2509.01476）是直接上游。
- 环境：校验器为 0.5–1B 小模型单卡可训；7B RALM 仅 LoRA；4×L40 并行，成本低。

## 2. 研究目标与可验证假设
- H1（门控优于启发式）：EvidenceGate 门控在"该拒则拒/该答则答"上的拒绝正确率显著高于 logprob 阈值弃权。成立时观测：拒绝正确率（ACC_refuse）提升 ≥ +10 个点，同时回答准确率不降。
- H2（缓解过度拒绝）：门控下过度拒绝率（本可答对却被拒）显著下降。成立时观测：过度拒绝率下降 ≥ 30%（相对）。
- H3（校准改善）：EvidenceGate 后模型整体 ECE 显著低于直接作答 RALM。成立时观测：ECE 下降 ≥ 0.05。
- H4（蒸馏有效）：LLM-as-judge 蒸馏的小校验器与 judge 本身在四态分类上一致率 ≥90%。成立时观测：蒸馏校验器四态分类准确率 ≥90%，人工抽检 300 条 κ≥0.7。

## 3. 总体方法设计
### 3.1 语料/数据流水线
1. 四态训练集（DeepSeek V4 Pro 生成）：对 NQ/TriviaQA 已知问题构造：
   - 证据充分（正确证据段 + 正确答案）；
   - 证据不足（截断/弱化证据，答案无法完全支撑）；
   - 证据矛盾（Kimi K2.6 生成与正确答案相反的段落）；
   - 证据缺失（无证据）。
   每态 3000 条，共 1.2 万条；人工抽检 300 条。
2. 校验器标签：用 DeepSeek judge 给"该答/该拒 + 证据充分性打分 0–4"；双模型（V4 Pro + Kimi K2.6）一致才入训。
3. RGB 子集（arXiv:2309.01431）作为 OOD 评测；NQ/TriviaQA 未知问题（KB 外实体）作为"缺失证据"来源。
4. DPO 数据（可选）：门控决策 + 正确/错误回答对，用于联合优化。

### 3.2 方法设计
- 证据充分性打分器 g(evidence, question)：输入拼接 [CLS]证据[SEP]问题，输出标量 s∈[0,1]。模型：DeBERTa-v3-base 或 Qwen2.5-0.5B 回归头。
- 联合特征：s_gate = α·s + β·(模型内部不确定性，如 logprob 熵) + γ·(证据-答案对齐分，用冻结 7B 的交叉注意力/embedding 相似度)，α/β/γ 初值 0.5/0.3/0.2。
- 门控策略：s_gate ≥ τ 则回答，否则拒绝；τ 用验证集网格搜索（τ∈{0.3,…,0.7}）。
- 生成阶段两分支：回答分支 = 证据 + prompt 强制引用；拒绝分支 = 模板化拒绝（"证据不足，无法可靠作答"）。
- 联合优化：门控与 7B RALM LoRA 微调（含 DPO 可选）交替更新。
- 超参数初值：τ=0.5、batch 32、lr 校验器 2e-5 / 生成器 5e-5、LoRA r=16。

### 3.3 训练流程
- 校验器：单卡训练（DeBERTa-base ~2 小时 / Qwen2.5-0.5B ~0.5 GPU·天）。
- 7B RALM LoRA：在四态数据 + 拒绝后训练数据上，2–3 GPU·天（FSDP 2 卡）。
- 门控联合调优：用验证集选 τ；可选 DPO 1 轮。
- 并行：4×L40 上校验器、生成器 LoRA、评测并行。

### 3.4 评测流程
- 四态分类：校验器对四态数据的分类准确率。
- 端到端：NQ/TriviaQA（已知 + 未知问题混合）、RGB 子集；报告"该答答对率 / 该拒拒对率 / 过度拒绝率 / 过度自信率 / ECE"。
- 校准：期望校准误差 ECE（10-bin）、可靠性图。
- 消融：特征组合（只用 s / +logprob / +对齐分）、τ、蒸馏 vs 直接用 judge。

## 5. 基线复现
| 基线 | 官方代码 | 预期 ECE / 拒绝正确率（粗估） |
|---|---|---|
| RALM 直接作答 | bge-m3 + Qwen2.5-7B | ECE ~0.15–0.25 |
| refusal post-training | 自建（四态 + 拒绝数据 LoRA） | ECE ~0.12–0.2 |
| Self-RAG | github.com/AkariAsai/self-rag | ECE ~0.12–0.2 |
| LogProb 阈值弃权 | 自建 | ECE ~0.1–0.18 |
| EvidenceGate（本项目） | 自建 | ECE ~0.05–0.1，ACC_refuse ~0.7–0.8 |
- 复现步骤：Self-RAG 官方 repo；logprob 弃权按论文（arXiv:2509.01476）实现；refusal post-training 用同四态数据。
- 统一口径：同一检索器、同一生成器基座、同一评测脚本、同一 τ 选择流程。

## 6. 实验矩阵
- A（主实验）：EvidenceGate vs 基线，NQ/TriviaQA/RGB 全指标。
- B（消融）：特征组合；τ 灵敏度；校验器模型规模（DeBERTa-base vs 0.5B vs 1B）；蒸馏 vs 直接 judge。
- C（鲁棒性）：矛盾证据密度（0/30/60%）；检索质量扰动（加噪声段）；未知问题比例（10/50%）。
- D（泛化性）：跨生成器（7B→13B、Mistral-7B）；跨语言（中文四态变体）；跨领域（医疗 QA 子集可选）。

## 7. 评测协议
- 回答指标：准确率（已知问题子集）、EM/F1。
- 拒绝指标：拒绝正确率（该拒则拒）、过度拒绝率（该答被拒）、过度自信率（证据不足却答）。
- 校准指标：ECE（10-bin）、Brier score、可靠性图。
- 组合指标：综合质量分 = 该答答对率 + 该拒拒对率（参考 arXiv:2509.01476 的 balance）。
- 统计：3 种子；均值±std；配对 bootstrap p<0.05；人工 300 条 κ。

## 8. 算力与资源计划
- 4×L40：校验器 0.5–1 GPU·天；7B RALM LoRA 2–3 GPU·天；评测 + 消融 1–2 GPU·天；合计 4–6 GPU·天。
- 存储：四态数据 + 缓存 <30GB。
- API：四态生成 + judge ≈ 150–300 美元；Kimi 矛盾证据 + 交叉验证 ≈ 100–200 美元；合计 ≤ 500 美元。

## 10. 风险与备选方案
| 风险 | 等级 | 对策 |
|---|---|---|
| judge 偏差传播进训练信号 | 高 | 双模型 agreement 过滤低置信 + 人工抽检 300 条 |
| 门控 τ 敏感 | 中 | 网格搜索 + 验证集；报告 τ 灵敏度曲线 |
| 过度拒绝缓解不足 | 中 | 在特征中加入参数化知识置信（E∅ 自答分）平衡 |
