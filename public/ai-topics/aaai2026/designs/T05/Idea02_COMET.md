# 实验设计书：Idea 2 · COMET —— 可组合子空间正交 LoRA 专家

> Composable Subspace-Orthogonal PEFT Experts with Conflict-Aware Routing
> 目标会议：ICML 2027（中优先级）
> 硬件：4 × NVIDIA L40（192GB）｜API：DeepSeek V4 Flash/Pro、Kimi K2.6

---

## 0. 摘要

COMET 构建"可合并、可增减、可组合"的多任务 LoRA 专家平台：所有任务专家在共享子空间（联合 SVD 得到的共享 U 矩阵）内训练各自专属 V 分量，训练中施加正交性约束使合并冲突可证明减少；推理时用"适配分数 × 相互干扰"双信号的路由器动态选择专家子集。与 HotMoE（浅/深层混合路由）、TopicLoRA（主题对齐）、Sub-MoE（仅 MoE 侧子空间合并）相比，COMET 首次把子空间正交化引入 LoRA 专家组合，支持运行时增减专家与无损合并。以 LLaMA-3-8B 为基座、6 个任务专家并行训练，预计 15–25 GPU·天。

## 1. 研究背景与动机

### 1.1 问题定义

给定基座 f_θ 与 T 个任务 {τ_1..τ_T}，为每个任务训练一个 LoRA 专家 ΔW_t（A_t,B_t）。目标：
1. 单任务性能不低于独立 LoRA；
2. 多个专家可无损组合/合并（新增任务只加一个 V 分量）；
3. 推理时按输入选择最适专家子集，且子集间相互干扰最小。

核心矛盾：多专家在独立训练后直接合并（Task Arithmetic 式加权求和）会出现参数冲突导致掉点；现有方法（LoRA Hub/S-LoRA 等服务框架）只解决"同时服务多专家"，不解决"合并时的冲突控制"。

### 1.2 相关工作不足（收藏论文用「(Session·论文N·英文标题)」格式；外部文献保留真实 arXiv ID/DOI）

- **HotMoE**（NLP II·40）：浅层 expert-expert / 深层 token-expert 混合路由，但各专家独立训练无正交约束，合并仍有冲突；
- **TopicLoRA**（ML IX·52）：主题先验图对齐 MoE-LoRA 分配，路由在"专家"层面，未处理参数冲突；
- **Sub-MoE**（ML IV·86，arXiv:2506.23266）：MoE 侧联合 SVD 子空间合并（共享 U、合并 V），证实子空间对齐可减冲突，但未迁移到 LoRA 多任务组合、无路由；
- **Task Arithmetic**（arXiv:2212.04089）：加权合并多 LoRA 会互相抵消，缺冲突度量；
- **S-LoRA**（arXiv:2311.03285）：高并发 LoRA 服务框架，无冲突控制与组合能力。

空白：**共享子空间正交化的多 LoRA 组合 + 冲突感知路由**。

### 1.3 为什么是现在、为什么你的环境适合做

- 多任务 LoRA 平台是工业界刚需（S-LoRA 等现象级工作），且 Sub-MoE 刚证明子空间合并有效性，正交组合的 LoRA 侧版本是自然补位；
- 6 个任务专家各占 1 卡并行训练，4×L40 恰好匹配，无需更大集群；
- Kimi K2.6/DeepSeek V4 合成多任务指令对与任务描述嵌入，LLM-as-judge 评 MT-Bench，API 成本可控。

## 2. 研究目标与可验证假设（2-4 条，每条给出"成立时的可观测结果"）

- **H1（正交减冲突）**：共享子空间 + 正交约束使多专家合并的负迁移显著低于朴素合并。
  - 可观测结果：T=6 专家两两合并时，平均任务 acc 下降 <2pt（朴素 Task Arithmetic 式合并下降 >5pt）；合并对夹角（V_i^T V_j 的 Frobenius 内积）显著小于独立训练。
- **H2（冲突感知路由）**：加入"干扰度量"的路由优于仅任务相似度路由。
  - 可观测结果：路由后的加权 acc 高于仅相似度路由 ≥1.5pt；且被选中专家子集的重叠度（共同参数激活）低于基线。
- **H3（增量可扩展）**：新增第 T+1 个任务只需新增一个 V 分量，性能与重训所有专家相当。
  - 可观测结果：增量训练后 6→7 任务，平均 acc 与全量重训差距 ≤0.5pt，训练成本降低 ≥5/6。
- **H4（无损合并）**：在共享子空间内做加权合并（weighted sum of V）在适当权重下接近专家级选择的上限。
  - 可观测结果：合并模型在目标任务上 acc ≥ 专家级路由的 95%。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据流水线

**候选任务集（T=6）**：Code（MBPP 子集 5k）、Math（GSM8K 5k）、Medical（MedQA 3k，MQA 格式）、Finance（FinBen 取 3k 指令）、NLU（GLUE-SST2 转指令 5k）、Chat（Alpaca 8k）。总量 ~29k 指令对。

**API 合成（Kimi K2.6 / DeepSeek V4 Pro）**：
- 多任务指令对增强：对每任务用 prompt `请以{任务}的风格把以下输入改写为指令-响应对，保持原意` 合成 2× 变体（Flash 批量）；
- 任务描述嵌入：`请用 50 词描述{任务}的输入输出分布与常用指令模式` 生成任务描述文本，作为路由特征之一；
- 过滤规则：答案长度 <5 token 或 >512 token 的样本丢弃；LLM-as-judge（DeepSeek V4 Flash）对随机 5% 样本打质量分，平均分 <3/5 的批次重生成。

**数量**：每个任务 5k 条（4.9k 原数据 + 变体混合），共 30k 条；任务描述 6 条；变体 12k 条。

### 3.2 模型/算法设计（模块拆解、关键公式、超参数初值）

**共享子空间初始化**：
- 取基座各层 W0，对目标模块（q,v 投影层）拼接所有任务的初始化 A 矩阵做联合 SVD：把 T 个随机 A_t ∈ℝ^{r×d} 纵向拼接 → SVD → 共享 U（d×r，取前 r=32 主奇异方向）；
- 每个专家用 `ΔW_t = U · V_t^T` 参数化，其中 V_t ∈ℝ^{d×r} 是专属分量（对应 Sub-MoE 的"合并 V"思想，ML IV·86）。注意 U 共享、V_t 独立。

**训练损失**：

`L_t = CE(x,y; W0+U·V_t^T) + λ1·Σ_{j≠t} ‖V_t^T V_j‖_F² + λ2·L_align(V_t, U-shared)`

- 正交正则：Σ_{j≠t}‖V_t^T V_j‖_F² 显式压制专家间冲突（λ1=0.05）；
- 路由一致性正则：当路由器把样本分给专家 t，其损失中加权 λ2=0.01；
- 任务间共享约束：U 在训练中保持共享（全局更新，梯度取多专家平均）。

**冲突感知路由器**：
- 特征 x 经任务描述嵌入 + 输入文本 embedding（mean pooling）；
- 适配分数 s_t = <φ(x), e_t>（e_t 为任务描述 embedding）；
- 干扰度量 d_t = Σ_{j∈S\{t}} ‖V_j^T V_t‖_F（当前候选子集 S 内两两干扰）；
- 选择：`S* = argmax_{|S|≤3} Σ_{t∈S} s_t − γ·max interference`，贪心近似（γ=0.3）。

**推理组合**：
- 专家级路由：每 token 选 top-1 专家（复用 LoRA 分支）；
- 合并模式：`ΔW = Σ_t w_t U V_t^T`，权重 w_t 用适配分数 softmax 归一化（可选 task arithmetic 加权，arXiv:2212.04089）。

**超参数初值表**：r=32（共享子空间秩），lora_alpha=16，λ1=0.05，λ2=0.01，γ=0.3，|S|≤3，dropout=0.1。

### 3.3 训练流程（优化器/学习率/批次/调度/FSDP 或 QLoRA 并行方案）

- 每个任务专家 1 卡并行训练（QLoRA 4-bit NF4 量化基座，共享权重只读一次加载，显存 ~3×8GB/卡）；
- 优化器 AdamW，lr=2e-4，cosine 衰减，200 步 warm-up，epoch=3，seq_len 1024，per-gpu bs=8，grad_accum=4；
- U 的更新：每步取 6 个专家梯度平均，lr=5e-5（慢速共享空间）；
- 路由器的 1 卡训练：用合成任务特征+softmax 标签，lr=1e-4；每 1000 步在 MT-Bench 风格验证集上评估路由 acc；
- bf16 + gradient checkpointing。

### 3.4 推理与评测流程

- 推理：路由器对输入打分 → 选专家子集 S* → 专家级路由生成；可选合并模式；
- 评测：各任务官方验证集 acc（Code 用 pass@1 采样 50 次，Math 用 8 样本投票）；MT-Bench 用 LLM-as-judge（DeepSeek V4）打 1–10 分；
- 合并无损度：比较"专家级路由 acc" vs "合并权重 acc"。

## 6. 实验矩阵（A/B/C…：主实验、消融、鲁棒性、泛化性）

- **A（主实验）**：COMET 路由与合并模式 vs 6 条基线；
- **B（消融）**：
  - B1 去掉正交正则（λ1=0）；
  - B2 去掉干扰度量（仅相似度路由）；
  - B3 不共享 U（每个专家独立 SVD）＝退化到独立 LoRA + 冲突路由；
  - B4 共享子空间秩 r∈{8,16,32,64}；
  - B5 与 GateRA 式难度调制结合（IDEA 1 的模块）验证协同；
- **C（鲁棒性）**：任务数 T∈{3,6,9}；任务相似度配置（同域/跨域）；专家子集大小 |S|∈{1,2,3}；随机种子×3；
- **D（泛化性）**：基座换 DeepSeek-R1-Distill-7B；增加视觉语言任务（Qwen2.5-VL 侧，可选）；OOD 任务（未训练的新任务）上的零样本路由。

## 7. 评测协议（指标定义、均值±方差、显著性检验、随机种子）

- 指标：各任务 acc、平均 acc、负迁移量、合并无损度（=合并 acc/路由 acc）、正交度（平均‖V_i^T V_j‖_F）、路由 acc、新增专家训练成本（GPU·h）、MT-Bench 得分；
- 均值±方差：主实验 3 种子；显著性：配对 bootstrap p<0.05；
- 随机种子 {42,7,2026}；Code pass@1 用固定 seed 采样 50 次（temperature 0.2）。
