# 实验设计书：Idea 5 · LAPER —— 学习型注意力画像感知 KV 压缩

> Learned Attention-Profile-Aware KV Compression via Distilled Importance Scoring
> 目标会议：ICLR 2027（高优先级）
> 硬件：4 × NVIDIA L40（192GB）｜API：DeepSeek V4（可选，judge）

---

## 0. 摘要

LAPER 用一个从完整缓存注意力蒸馏出的轻量评分器（<10M 参数）替代手工启发式 KV 重要性打分，并联合（层、头、模态）自适应分配 KV 预算。评分器输入为"注意力统计 + 位置 + 模态标记 + token 嵌入"，输出重要性；预算分配网络用端到端损失（保留 acc + 内存惩罚）训练；部署时评分器前置运行，复用现有 evict/merge 策略，推理零额外权重开销。以 Qwen2.5-7B 训练、跨模型迁移到 Llama-3.1，覆盖 LongBench/RULER/多模态长上下文，预计 8–15 GPU·天。

## 1. 研究背景与动机

### 1.1 问题定义

KV cache 压缩的主流方法依赖启发式重要性评分：H2O 按注意力分数保留 Heavy Hitter（arXiv:2306.14048），SnapKV 用观测窗口注意力（arXiv:2404.14469），PyramidKV 做金字塔信息漏斗（arXiv:2406.02069），KeepKV 用 Electoral Votes 规则（NLP IV·67，arXiv:2504.09936）。这些启发式：
1. 不区分头部语义（HACK 的离线分类不可迁移，ML VII·3）；
2. 不感知模态（DAVID 的手工融合度量不迁移，ML III·9）；
3. 预算分配是统一的，未做（层、头、模态）非对称。

目标：训练一个**跨模型可迁移**的学习型评分器 + 非对称预算分配网络，替代手工启发式，且推理零额外权重开销。

### 1.2 相关工作不足（收藏论文用「(Session·论文N·英文标题)」格式；外部文献保留真实 arXiv ID/DOI）

- **H2O**（arXiv:2306.14048）：启发式重击 token 保留，无学习；
- **SnapKV**（arXiv:2404.14469）：观测窗口启发式；
- **PyramidKV**（arXiv:2406.02069）：金字塔启发式；
- **KeepKV**（NLP IV·67，arXiv:2504.09936）：合并式 + Electoral Votes 规则式评分，无学习、无头/层/模态非对称；
- **HACK**（ML VII·3，arXiv:2504.09261）：VAR 头部语义/结构分类，离线不可迁移；
- **DAVID**（ML III·9）：视觉-文本融合度量 + 阈值切换，手工规则；
- **CaM**（arXiv:2406.11430）：L2 范数注意力残差合并，无学习；
- **MInference**（arXiv:2407.02490）：长上下文 prefill 稀疏注意力，不解决 decode KV。

空白：**学习型评分器（蒸馏自全缓存 oracle）× 层/头/模态非对称预算 × 跨模型迁移** 的结合。

### 1.3 为什么是现在、为什么你的环境适合做

- 7B 模型单卡即可运行，3 卡并行收集数据、1 卡训练评分器，算力需求低（8–15 GPU·天），与本环境完美匹配；
- Qwen2.5-7B / Qwen2.5-VL-7B（arXiv:2412.15115 / 2502.13923）与 Llama-3.1 均开放可得；
- 社区已有完整 KV 压缩评测工具（KV 压缩综合基准，DOI:10.18653/v1/2024.findings-emnlp.266），可复现基线。

## 2. 研究目标与可验证假设（2-4 条，每条给出"成立时的可观测结果"）

- **H1（评分器有效性）**：学习型评分器的重要性预测与 oracle 一致，优于启发式。
  - 可观测结果：评分器与 oracle 的 top-k 重叠度（IoU/Jaccard）> 0.8，显著高于 H2O/SnapKV 的启发式评分；同压缩率下保留 acc 更高。
- **H2（非对称预算增益）**：层/头/模态自适应预算分配优于统一预算。
  - 可观测结果：在 10%/20%/50% 压缩率下，非对称预算的 acc 保持率比统一预算高 ≥1.5pt。
- **H3（跨模型迁移）**：在 Qwen2.5 上训练的评分器迁移到 Llama-3.1 仍有收益。
  - 可观测结果：零样本迁移（Qwen→Llama）在 20% 压缩率下 acc 保持率 ≥ 在 Qwen 上表现的 90%（即迁移损失 ≤10%）。
- **H4（端到端收益）**：评分器开销被 KV 节省抵消，推理吞吐提升。
  - 可观测结果：在 batch=1、长上下文（16k）下，LAPER 吞吐 ≥ 全缓存；在 batch≥8 下吞吐提升 ≥30%（相对全缓存）；评分器前向开销 <5% 推理时间。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据流水线

**数据收集**：
- 文本：LongBench（arXiv:2308.14508）长文档 QA + RULER（arXiv:2404.06654）长上下文合成检索；
- 多模态：Qwen2.5-VL-7B 在长视频 QA（Video-MME 风格，用 Video-MME 公开子集）与长图 VQA 上收集；
- 每条样本：跑完整缓存前向，记录每层每头每 token 的注意力权重、位置、模态标记、token 嵌入。

**oracle 标签**：
- oracle 重要性 = per-head 注意力残差累积（对下游 token 的注意力贡献）；实现：对一段长输入，逐步解码，统计每个 KV 位置被后续 token 注意的总量；
- 备选 oracle：训练一个小型"keep 真值"——用 keep 后解码的 logits 与全缓存 logits 的 KL 作为保真度信号。

**过滤**：样本长度 ≥8k token 才有价值（否则压缩无意义）；模态样本按 1:1 与文本配比。

**数量**：文本 3k 条 + 多模态 1.5k 条 = 4.5k 训练样本（每样本含完整注意力统计）。

### 3.2 模型/算法设计（模块拆解、关键公式、超参数初值）

**评分器**（<10M 参数）：
- 输入特征：`[head 注意力熵, head 均值注意力, 位置 index, 模态标记 one-hot, 层号, token 嵌入(取 mean-pooled hidden)]`；
- 结构：MLP（input ~128 → hidden 256 → 1）或轻量 2 层 Transformer（hidden 128）；
- 输出：重要性分数 s∈[0,1]；
- 训练损失：`L = BCE(s, oracle_keep_label) + λ·L_budget`，其中 L_budget 为 top-k 稀疏约束（软 top-k 惩罚：鼓励 k 个保留位置分数高、其余低）。

**非对称预算分配网络**：
- 输入：(层号、头号、模态标记、全局注意力模式统计)；
- 输出：该（层,头）的预算比例 π∈[0,1]^K（softmax 归一化到总预算 B）；
- 训练损失：`L = -log P(acc | budget π) + α·max(0, Σπ - B)²`（端到端可微，用直通估计）；α=1.0。

**部署**：
- 评分器前置：给定输入 token 流，逐段打分 → 决定 evict（保留 top-k）或 merge（复用 KeepKV 的零扰动合并，NLP IV·67）；
- 预算按 π 分配到各（层,头）；多模态标记区分视觉/文本 token；
- 零额外推理权重：评分器只在 prefill 阶段运行一次（KV 决策），decode 不再调用。

**超参数初值表**：评分器 hidden 256，λ=0.5，α=1.0，总预算 B∈{0.1,0.2,0.5}，k 由预算导出，模态标记维度 2。

### 3.3 训练流程（优化器/学习率/批次/调度/FSDP 或 QLoRA 并行方案）

- 数据收集：3 卡并行（1 卡/模型：Qwen2.5-7B、Qwen2.5-VL-7B、Llama-3.1-8B）跑完整缓存前向 3 天；
- 评分器训练：1 卡，AdamW，lr=1e-4，bs=64，~10k 步，1–2 天；
- 预算网络训练：与评分器联合，先训评分器冻结，再训预算网络 2k 步；
- 混合精度 bf16；无 FSDP（单卡即可）。

### 3.4 推理与评测流程

- 评测：文本 LongBench/RULER；多模态 Video-MME 子集/长图 VQA；跨模型：训练于 Qwen2.5 → 测 Llama-3.1（零样本）与 → 测 Qwen2.5-VL；
- 指标：各压缩率（10%/20%/50%）下 acc 保持率、评分器-oracle 一致性、迁移损失、内存/吞吐收益、训练样本效率；
- 对比上界：全缓存；对比基线：H2O、SnapKV、PyramidKV、KeepKV、DAVID、HACK。

## 6. 实验矩阵（A/B/C…：主实验、消融、鲁棒性、泛化性）

- **A（主实验）**：LAPER vs 7 条基线，三个压缩率 × 三种输入类型（文本/多模态/跨模型）；
- **B（消融）**：
  - B1 去掉预算网络（统一预算）→ 纯评分器；
  - B2 去掉模态标记；
  - B3 去掉位置/层号特征；
  - B4 评分器 vs oracle 直接用于部署（oracle 上界）；
  - B5 evict vs merge 后端策略；
  - B6 训练数据规模 {1k,2k,4.5k}；
- **C（鲁棒性）**：输入分布扰动（加长/缩短）；压缩率连续变化 {5%,10%,20%,50%}；不同 seed；
- **D（泛化性）**：跨模型（Qwen→Llama，Qwen→Qwen2.5-VL 多模态）；超长上下文 32k/64k（评分器输入稀疏采样控制开销）；训练样本效率曲线。

## 7. 评测协议（指标定义、均值±方差、显著性检验、随机种子）

- 指标：acc 保持率（各压缩率相对全缓存）、oracle 一致性（top-k IoU）、迁移损失（=1 − 目标模型保持率/源模型保持率）、吞吐（token/s）、峰值内存、评分器前向开销占比、训练样本效率；
- 主实验 3 seed；均值±方差；配对 bootstrap p<0.05；
- 随机种子 {42,7,2026}；生成 greedy。
