# 实验设计书：Idea 3｜在线自适应的工具调用图与安全感知路由

> OnlineTool: Online Adaptive Tool-Invocation Graph with Safety-Aware Routing
> 资源假设：4× NVIDIA L40（192GB）；DeepSeek V4 Flash/Pro、Kimi K2.6 API。

## 0. 摘要
AutoTool 用离线静态"工具使用惯性图"旁路逐步骤 LLM 推理、降本最高 30%，但图不随任务与工具集演化、冷启动失效，且无视工具特权差异（过度使用高特权工具）与注入攻击（工具库可被污染）。本工作提出 OnlineTool：把静态图升级为在线可更新、带最小特权约束、冷启动语义引导、注入防御的混合路由。执行中动态更新工具-工具转移概率与参数模板，新工具以语义嵌入自动冷启动入图；图高置信时旁路 LLM，低置信或涉敏工具时回退 LLM + 沙箱校验。预计无大训练（可选 7B LoRA 5 GPU·天），任务完成率持平 ReAct 的同时推理 token 降 30–40%，高特权工具使用率显著下降。

## 1. 研究背景与动机

### 1.1 问题定义
LLM agent 的每一步工具调用都要经过 LLM 推理，成本高且不可预测。AutoTool（Natural Language Processing II·论文 46·AutoTool，arXiv:2511.14650）提出用有向图（节点=工具，边=转移概率）编码统计惯性，用图遍历替代逐步骤 LLM 选择。但现实部署中：①工具集动态变化（新工具上线、旧工具废弃）；②冷启动无历史轨迹；③任务分布漂移使静态图误导；④不同工具有不同特权/风险等级，agent 倾向过度使用高特权工具（ToolPrivBench）；⑤工具库本身可被注入污染（ToolHijacker）。问题定义为：**设计一个随任务执行在线演化、兼顾安全约束、可冷启动的工具路由器，在保证任务完成率的同时最小化推理成本与特权工具使用**。

### 1.2 相关工作不足
- 静态图失效场景：AutoTool 图离线构建，冷启动与工具集动态更新场景未覆盖。
- 无安全维度：AutoTool、ToolLLM（arXiv:2307.16789）均未建模特权与注入；ToolPrivBench（arXiv:2606.20023）显示主流 agent 系统性地过度特权；ToolHijacker（arXiv:2504.19793）证明工具库注入可劫持选择。
- 效率-安全权衡未量化：LLMCert-T（arXiv:2510.03992）给了选择安全性统计上界，但未与图路由结合。

### 1.3 为什么是现在、为什么你的环境适合做
在线更新需要大量低成本 rollout 支撑统计学习，DeepSeek V4 Flash 的廉价 token 正好满足；4×L40 足够承载本地 7B 回退模型与沙箱验证；安全评测已有公开对抗样本（ToolHijacker/ToolPrivBench 的方法可复现）。本 idea 是"统计结构 + 最小 LLM 调用 + 安全约束"三者合成的直接落地。

## 2. 研究目标与可验证假设
1. **H1（在线图优于静态图）**：在线更新使任务完成率随会话数递增，静态图平台期。
   - 成立时观测：10 会话后在线图完成率超过静态图 ≥5 个点；新工具注入后无需重训即被使用。
2. **H2（图-LLM 混合降本不降质）**：高置信图旁路 + 低置信 LLM 回退，完成任务率持平 ReAct，token 降 ≥30%。
   - 成立时观测：ToolBench/BFCL 上完成率差 ≤2 点，token 降幅达标。
3. **H3（最小特权约束有效）**：路由加特权约束后，高特权工具使用率显著下降而完成率不降。
   - 成立时观测：高特权工具使用率降 ≥30%，任务完成率差 ≤2 点。
4. **H4（注入防御）**：对工具库注入恶意描述时，安全模块检测率高且路由不选被污染工具。
   - 成立时观测：注入样本上检出率 ≥0.8，选择被污染工具的次数趋近 0。

## 3. 总体方法设计

### 3.1 数据/轨迹采集流水线
- **初始图构建**：ToolBench（arXiv:2307.16789）官方指令集 + 自采 30K agent 轨迹。轨迹由 DeepSeek V4 Pro 以 ReAct 风格采样（每任务 ≤15 步，含工具名、参数、结果摘要、成功标志）。用 V4 Flash 批量再采样 20K 条补充长尾工具对。
- **prompt 思路（轨迹采样）**：
  ```
  你是工具调用 agent。给定任务与工具列表，逐步输出 (工具名, 参数)。若上一步失败，给出修复动作。
  记录每步：调用链 (tool_i→tool_j)、耗时、结果 ok/fail。
  ```
- **冷启动新工具**：新工具 API 描述（OpenAPI）经 V4 Pro 生成一句话摘要，用 Kimi K2.6 算语义 embedding，与现有节点算相似度入图，初始转移概率均匀。
- **数量**：30K+20K=50K 条轨迹，覆盖 ToolBench 20K 指令 + 自采 10K 长尾。

### 3.2 系统/算法设计
- **图结构**：有向加权图 `G=(V,E,W)`，V=工具节点，E=转移边，W=转移概率 + 参数模板（频率统计的 top 参数值分布）。每节点带 `priv_level`（高/中/低，规则引擎从 OpenAPI 的权限/写操作推断）+ `risk_tag`（写入型/支付型/只读型）。
- **在线更新**：每次执行成功后按 `W(v_i,v_j) ← (1−η)W + η·1` 更新，η=0.05；失败则反向衰减。用衰减窗口（指数加权，半衰期 100 步）保证分布漂移时快速遗忘；置信度 `conf = 最大出边概率 − 次大出边概率`。
- **路由决策**：每步 `score = max_out_weight`，若 `score ≥ θ_conf` 且目标工具非高特权 → 图直出（旁路 LLM）；否则回退 LLM（V4 Flash 或本地 7B）。涉敏工具（priv_level 高）强制走 LLM + 沙箱校验。
- **最小特权约束**：同功能候选集合内，路由目标加偏置项 `λ·(−priv_level)`，即同效低特权优先；备选打分 `r(t) = W·(1−priv_penalty)`，`priv_penalty ∈ {0, 0.15, 0.3}` 按风险级。
- **注入防御**：工具描述经敏感指令扫描（正则 + V4 Flash 分类）；异常描述（含 "ignore previous"/"always call" 等指令）隔离并标记，路由禁止选择。

### 3.3 训练流程
- **主流程无大训练**；图统计为在线计数。
- 可选回退模型：Qwen2.5-7B LoRA（r=16, lr=2e-5, batch=32, 1 epoch）在 20K 失败轨迹的"修复动作"上微调，5 GPU·天，用于低置信回退（对照 API 回退）。

### 3.4 推理与评测流程
- 评测环境：ToolBench 官方离线模拟器；BFCL（自建 HTTP 模拟服务）；tau-bench（arXiv:2406.12045）子集（含状态比对）。
- 单任务流程：任务→路由循环（图打分→置信判断→LLM 或图直出→执行→更新图→沙箱校验）→终态判定。
- 冷启动实验：模拟"新工具上线"（临时向 API 列表加入 20 个未在训练图中工具）。

## 4. 数据集/环境细节
- ToolBench：公开（arXiv:2307.16789），指令集 + 工具描述，离线模拟器可跑，许可宽松（学术）。
- BFCL：Berkeley 函数调用基准，公开。
- tau-bench 子集（arXiv:2406.12045）：零售/航空场景，含数据库状态比对，取 50 任务。
- 自采 30K 轨迹：仅记录文本，无专有数据。
- 沙箱：Docker 隔离，网络白名单，写操作限制。

## 5. 基线复现
| 基线 | 官方代码 | 复现要点 |
|---|---|---|
| AutoTool（arXiv:2511.14650） | 若开源按官方；否则按论文静态图重实现 | 静态图 + 参数级信息整合 |
| ReAct（自实现） | 通用 | V4 Flash 逐步调用 |
| ToolLLM（arXiv:2307.16789） | GitHub: OpenBMB/ToolBench | DFSDT + tool-retriever |
| ToolRAG（检索式） | GitHub: OpenBMB/ToolBench 分支 | 检索 top-k 工具注入上下文 |
| LLMCert-T（arXiv:2510.03992） | 复现其统计证书 | 仅作为安全性上界对照 |

统一口径：同 ToolBench 200 条指令子集 + BFCL 全量 + tau-bench 50 任务；max_steps=15；记录完成率、token 数、特权工具使用次数。
预期表：完成率 ReAct ~55%、AutoTool ~50%（省 30% token）、OnlineTool ~53% 且 token 再降 10–20%、高特权使用率降 30%+。

## 6. 实验矩阵
- **A. 主实验**：OnlineTool vs 五基线，三数据集。
- **B. 消融**：在线更新 vs 静态图；置信阈值 θ_conf∈{0.3,0.5,0.7}；安全约束有无；冷启动引导有无。
- **C. 鲁棒性**：任务分布漂移（注入 30% 新工具域任务）；工具描述被注入（H4）；长尾任务（出现次数<10 的工具）。
- **D. 成本-质量权衡**：不同回退策略（API/本地 7B/全部图直出）下的 Pareto 曲线。
- **E. 泛化**：tau-bench 新域冷启动（无历史轨迹）表现。

## 7. 评测协议
- 完成率 = 终态判定成功比例；token 成本 = 每任务推理 token（图直出记 0）；特权使用率 = 高特权工具调用/总调用。
- 均值±方差：5 seed；配对 t 检验 p<0.05；成本显著性用 bootstrap CI。
- 成本上限：每任务 max_steps=15、max LLM 调用 8；防震荡用衰减窗口 + 置信门槛。

## 8. 算力与资源计划
- 4×L40：可选 7B 回退 LoRA 5 GPU·天；rollout 评测（ToolBench/BFCL/tau-bench 沙箱并行）约 10 GPU·天。**总 ~15 GPU·天**。
- 存储：镜像 + 数据 <30GB。
- API 估算：V4 Flash 主选择/回退约 15M token ¥80–150；V4 Pro 初始轨迹 20K 条 ~5M token ¥150–400；Kimi K2.6 embedding 0.5M ¥30–60。总计 ~¥300–600。

## 9. 里程碑与时间线（单人 + 4 卡）
- W1：ToolBench/BFCL/tau-bench 环境搭建 + ReAct/ToolLLM 基线复现。
- W2：初始图构建（50K 轨迹采样）。
- W3：在线更新 + 置信路由实现，ToolBench 首跑。
- W4：安全模块（特权约束 + 注入扫描）+ H3/H4 实验。
- W5：漂移/冷启动鲁棒性 + 成本曲线。
- W6：写作 + 图表 + 复现核验。

## 10. 风险与备选方案
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 在线更新震荡 | 中 | 高 | 衰减窗口 + 置信门槛；更新限幅 η |
| 静态图基线复现困难（AutoTool 未开源） | 中 | 中 | 按论文重实现并标注差异；只对比可复现指标 |
| 安全模块复杂度高 | 高 | 中 | 先做"最小特权 + 注入检测"子集，沙箱仅对写操作启用 |
