# 实验设计书：Idea 2｜工具验证的反事实多智能体事实性裁决

> TVC: Tool-Verified Counterfactual Tests for Multi-Agent Factuality
> 资源假设：4× NVIDIA L40（192GB）；DeepSeek V4 Flash/Pro、Kimi K2.6 API。

## 0. 摘要
多智能体辩论（MAD）的共识只保证"一致"而非"正确"，MUG 用图像反事实测试识别幻觉 agent 却受限于可编辑图像域。本工作提出 TVC（Tool-Verified Counterfactual tests）：把"反事实测试"从图像推广到任意开放域，用**可执行工具**为反事实问题提供地面真值。流程为：论断抽取 → 反事实构造（改数值/日期/实体）→ Python REPL + Search API 执行给真值 → 向 N 个 agent 注入真假反事实 → 以正确率识别"幻觉 agent" → 用非幻觉子集加权裁决，并把裁决结果回写为"事实轨迹"记忆。全程零参数训练，只需 API 调用与单卡 7B judge 对照，预计 <5 GPU·天。在 GAIA/HotpotQA/FEVER 上验证事实性准确率与幻觉检出率。

## 1. 研究背景与动机

### 1.1 问题定义
多智能体裁决（multi-agent deliberation）在事实性问答、长文档校验中被广泛使用，但其共识判据存在系统性缺陷：所有 agent 可能共享同一错误先验，从而"集体一致地错"。我们定义问题为：**给定一个问题 Q，如何在多智能体回答中识别出"幻觉 agent"（系统性编造/错误 agent），并据此做加权裁决，使最终答案对齐可执行地面真值**。关键约束：反事实证据必须可验证，即对论断做改动后能用一个确定性的检查（代码断言/API 查询/检索比对）判定真假。

### 1.2 相关工作不足
- 反事实测试限图像域：MUG（Computer Vision V·论文 101·Multi-Agent Undercover Gaming）用图像编辑构造反事实，无法覆盖百科/代码/数据类开放域。
- 共识≠正确：MAD（arXiv:2305.14325）及其变体的共识机制只统计一致性；Problem Drift（arXiv:2502.19559）证明长辩论会偏离原问题。
- 工具真值未被用于多 agent 质检：ToolLLM/ToolBench（arXiv:2307.16789）证明工具可执行验证可行，但未衔接多智能体裁决；RuVerBench（arXiv:2606.29920）显示 agentic 场景的 rubric 验证本身不可靠，需要可执行锚点。

### 1.3 为什么是现在、为什么你的环境适合做
工具调用已商品化（Python REPL、搜索 API 均可低成本调用），使"反事实即检查"可自动化；DeepSeek V4 Flash 的低价可支撑大批量 agent 群体；本实验不需要大训练，硬件风险几乎为零，适合作为低算力高确定性成果快速产出。若做成含评测基准的版本，符合 AAAI 2027 综合口味。

## 2. 研究目标与可验证假设
1. **H1（工具反事实可识别幻觉 agent）**：注入真假反事实后，幻觉 agent 的正确率显著低于正常 agent。
   - 成立时观测：幻觉检出 F1 ≥ 0.7（对照随机 0.5）。
2. **H2（加权裁决优于投票）**：以非幻觉子集加权聚合的事实性准确率高于多数投票与单 agent。
   - 成立时观测：GAIA/HotpotQA 上加权裁决准确率 > MAD 投票 ≥3 个绝对点。
3. **H3（事实轨迹记忆增益）**：把裁决结果回写记忆，后续同类问题 agent 表现提升。
   - 成立时观测：复用事实轨迹后，热问题准确率提升 ≥5 点。
4. **H4（工具真值优于 LLM-judge）**：以工具执行为真值的反事实测试，其裁决可靠性高于纯 LLM-as-judge。
   - 成立时观测：对照 LLM-judge（arXiv:2504.17087 系 meta-judge）在同问题集上准确率更高。

## 3. 总体方法设计

### 3.1 数据/轨迹采集流水线
- **数据源**：GAIA（arXiv:2311.12983）验证集子集（200 题，可执行答案已知）；HotpotQA（100 题，检索可验证）；FEVER（100 题，证据可检索）。自采 2K 条"带可执行答案的 QA"：从维基百科 + 数学/日期/单位类模板构造，答案可由代码断言/API 校验。
- **流水线（LLM-as-teacher）**：
  1. 论断抽取：DeepSeek V4 Pro 从 Q 与参考答案抽取关键断言 `C = {c1..ck}`（数值/日期/实体/关系）。
  2. 反事实构造：对每个断言做扰动 `c' = perturb(c)`（数值±20%、日期改动、实体替换为同槽位实体），prompt：
     ```
     抽取断言中的可验证事实。生成 3 个反事实改写：①数值/日期改动；②实体替换；③否定式。
     每个改写必须是"可判定的"（可用代码/检索验证真伪）。
     ```
  3. 工具真值：Python REPL（sympy/requests）+ Search API 对 `c` 与 `c'` 求值，得 `gt ∈ {true,false}`；无法判定的样本丢弃，人工抽检 200 例。
  4. 构建测试集：`Q + {c:true}` 或 `Q + {c':false}` 随机注入，形成 4K 条带标签反事实测试。
- **数量**：2K 基础 QA × 每题 2 条反事实 = 4K 条。

### 3.2 系统/算法设计
- **Agent 群体**：N=5 个 agent（同后端不同温度/角色提示），默认 DeepSeek V4 Flash；对照实验用 7B 本地（Qwen2.5-7B）观察同质化影响。
- **卧底检测协议**：对每个问题，向各 agent 注入真假反事实各若干条（注入比例 p=50%，随机错开），统计每个 agent 在"已知真值"项上的答对率 `acc_a`，低于阈值 τ（如 0.6）者标记为幻觉 agent。
- **加权裁决**：`weight_a = acc_a / Σ acc_a`（仅非幻觉子集），最终答案 = 加权多数；与均匀投票对照。
- **事实轨迹回写**：裁决正确后，把 `(Q, 关键断言, 工具真值, 裁决结果)` 追加到记忆（KV + 语义索引），供后续问题检索参考（衔接 CA3Mem 记忆图方向）。
- **幻觉检出的理论保证**：若真实 agent 答对率 q>0.8、幻觉 agent 答对率 <0.5，注入 m≥6 条反事实时，按二项分布可将检出误差控制在 5% 内（χ² 检验判定偏离）。

### 3.3 训练流程
- **无需大训练**。可选：用 2K 反事实样例做 7B judge 的 LoRA 校准（评估偏差，5 GPU·天）——仅为对比，非主流程。
- 若做 DPO 校准：base=Qwen2.5-7B，LoRA r=16，lr=2e-5，batch=32，epochs=1，数据为"工具真值正确回答 vs 错误回答"偏好对。

### 3.4 推理与评测流程
- 工具环境：本机 sandbox Python REPL（denylist 禁网络写盘、限内存/超时）；Search API 用 V4 Pro 配置的 Web 检索；GAIA 已带工具验证脚本（官方）复用。
- 评测在 3 个任务上零样本跑：事实性准确率（相对工具真值）+ 幻觉检出 F1 + 加权 vs 投票对比 + 记忆复用。

## 4. 数据集/环境细节
- GAIA（arXiv:2311.12983）：公开，验证集含参考答案，取 200 题（Level 1–3 均匀）。
- HotpotQA：公开（CC BY 4.0），取 100 题，证据来自维基段落检索。
- FEVER：公开，取 100 题。
- 自采 2K：本团队生成，无版权问题；与三个官方集互斥。
- 沙箱：Python 3.11 + requests + sympy，容器化（Docker，网络仅白名单域名）。

## 5. 基线复现
| 基线 | 官方代码 | 复现要点 |
|---|---|---|
| MAD（arXiv:2305.14325） | GitHub: comet-2000/multi-agent-debate | 2-3 轮辩论 + 最终裁决 |
| 单 agent CoT + self-consistency | 自实现（V4 Pro/Flash） | temperature=0.7，采样 8 次多数 |
| LLM-as-judge（arXiv:2504.17087） | 自实现 meta-judge | V4 Pro 作裁判，无工具真值 |
| MUG 原协议（Computer Vision V·论文 101） | 若开源按原协议；否则仅在图像反事实子集对照 | 图像域单独测 |

统一口径：同 200 题 GAIA 子集、同 N=5 agent、同 max 步数/预算；报告准确率、F1、token 成本。
预期表：加权裁决 GAIA 准确率 60–70%（基线 MAD ~50–55%）；幻觉检出 F1 0.7+。

## 6. 实验矩阵
- **A. 主实验**：TVC 加权裁决 vs MAD vs 单 agent+SC vs LLM-judge，三数据集。
- **B. 消融**：注入比例 p∈{0.2,0.5,0.8}；agent 数 N∈{3,5,7}；加权 vs 投票 vs 仅非幻觉子集多数。
- **C. 鲁棒性**：反事实扰动类型（数值/实体/否定）分列；工具真值判定失败率的影响；同质 agent（同后端同提示）vs 异质。
- **D. 泛化性**：跨域迁移（FEVER 训练记忆 → GAIA 测试）；7B 本地后端对照。
- **E. 记忆复用**：事实轨迹热/冷问题的增益。

## 7. 评测协议
- 事实性准确率 = 最终答案与工具真值一致的比率；幻觉检出 = 标记 agent 中真幻觉的 Precision/Recall/F1（人工复核 200 例校准标签）。
- 均值±方差：每设置 5 个 seed（agent 温度/注入随机），配对 t 检验 p<0.05。
- 成本控制：每题 agent 调用 ≤10 次、反事实构造 ≤5 次、工具执行 ≤20 次；单题预算 $0.1 上限。

## 8. 算力与资源计划
- 4×L40：仅 7B judge 对照 LoRA（可选 5 GPU·天）；主要成本是 API + 单卡推理。**总 <5 GPU·天**。
- 存储：Docker 沙箱镜像 + 数据 <20GB。
- API 估算：V4 Flash agent 群体 4K 题 × 5 agent × 0.5K token ≈ 10M token，估 ¥50–100；V4 Pro 论断/反事实/裁判 5M token，估 ¥150–400；Kimi K2.6 长证据比对 2M token，估 ¥100–200。总计 ~¥400–800。

## 9. 里程碑与时间线（单人 + 4 卡）
- W1：数据构造（2K QA + 反事实生成 + 工具真值），人工抽检 200 例；基线 MAD/SC 复现。
- W2：卧底检测协议 + 加权裁决实现；GAIA 子集首跑。
- W3：消融矩阵 + FEVER/HotpotQA 全跑；幻觉检出人工复核。
- W4：事实轨迹记忆 + 记忆复用实验。
- W5：写作 + 图表 + 复现检查。

## 10. 风险与备选方案
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 反事实构造质量参差 | 中 | 中 | 人工抽检 200 + 工具真值优先；无法判定则丢弃 |
| 幻觉 agent 检出率低（H1 弱） | 中 | 中 | 增大注入比例 p、加二项检验判定；报告诚实边界 |
| LLM-judge 对照不显著 | 低 | 中 | 强调工具真值的可复核性（judge 不可复核）为卖点 |
| GAIA 题太难导致 agent 全错 | 中 | 高 | 按 Level 分层报告；加自采可执行 QA 兜底 |
