# 实验设计书：Idea 9｜非平稳环境下的智能体适应能力基准（自适应基准）

> EvoBench: An Adaptation-Centric Benchmark for LLM Agents under Non-Stationary Environments
> 资源假设：4× NVIDIA L40（192GB）；DeepSeek V4 Flash/Pro、Kimi K2.6 API。

## 0. 摘要
SoMe、AgentBench、tau-bench 等现有 agent 基准都是固定环境-固定工具-固定用户，无法度量 agent 在真实部署中"平台规则、工具接口、用户分布持续漂移"时的适应能力。本工作提出 EvoBench：①漂移引擎——在评测中途按脚本/LLM 调度器改变工具 schema（参数改名/新增废弃工具）、UI 布局、用户偏好分布；②适应指标套件——适应期成功率曲线下面积（AUC）、震荡度、漂移后恢复步数；③两模式——无记忆 vs 带记忆，量化记忆系统对适应的贡献。以 SoMe 8 类任务为基底重构动态版，另构建 3 域（WebArena 子集 / tau-bench 子集 / SoMe）× 4 种漂移类型 × 3 种强度。无需训练，成本在评测 rollout（4×L40 跑 WebArena 沙箱 8-12 GPU·天 + 社交/工具域走 API）。

## 1. 研究背景与动机

### 1.1 问题定义
LLM agent 在生产环境的接口（工具、UI、用户偏好）会随时间漂移：电商平台改 API 参数名、社交平台改推荐规则、用户群体偏好迁移。现有基准把评测快照固定，agent 只需记住"当前环境"，无需适应。问题定义为：**构建一个可复现的"环境漂移"评测协议与指标，量化 agent 的在线适应能力（适应速度、恢复代价、震荡程度），并分离"记忆系统对适应的贡献"**。

### 1.2 相关工作不足
- 静态快照：SoMe（Application Domains II·论文 62·SoMe，DOI 10.1609/aaai.v40i2.37113）真实但静态；AgentBench（arXiv:2308.03688）、tau-bench（arXiv:2406.12045）同样固定环境。
- 缺适应指标：现有基准无"漂移后恢复步数/适应 AUC"类指标。
- 记忆贡献未量化：MemGPT（arXiv:2310.08560）、CA3Mem（Computer Vision XII·论文 85）各有记忆机制，但无人系统评测"记忆对非平稳适应的增益"。

### 1.3 为什么是现在、为什么你的环境适合做
非平稳/持续适应是 agent 从 demo 走向生产的关键缺口，社区刚出现零星工作（漂移测试、持续 agent）但无标准基准；SoMe 数据池（916 万帖）已公开，可低成本重构；4×L40 足够跑 WebArena 沙箱并行评测；DeepSeek V4 Flash 低价支撑大 trial 数。基准型成果符合 NeurIPS D&B / ICLR D&B 及 AAAI 综合口味。

## 2. 研究目标与可验证假设
1. **H1（漂移可显著降低静态最优策略）**：无适应机制的 ReAct 类 agent 在漂移后成功率显著下降。
   - 成立时观测：漂移后成功率平均下降 ≥20 个绝对点（对照漂移前）。
2. **H2（适应指标可分离 agent 差异）**：适应 AUC 与恢复步数能区分不同 agent（ReAct vs 带记忆 agent vs 图路由）。
   - 成立时观测：三类 agent 的适应 AUC 排序稳定（5 域 × 3 强度下一致）。
3. **H3（记忆系统显著贡献适应）**：带记忆（MemGPT/CA3Mem 式）agent 的适应 AUC 高于无记忆基线 ≥15%。
   - 成立时观测：三域中带记忆 agent 恢复步数显著更短。
4. **H4（漂移强度可调且可复现）**：漂移强度注入后，成功率下降幅度与强度单调。
   - 成立时观测：3 强度×4 类型下下降幅度单调递增，且同 seed 重复一致。

## 3. 总体方法设计

### 3.1 数据/轨迹采集流水线
- **三域四漂移类型**：
  - WebArena 子集（50 任务）：UI 布局漂移（CSS/按钮位置）、工具 schema 漂移（表单字段改名）。
  - tau-bench 子集（50 任务）：工具 API 漂移（参数改名/废弃）、业务规则漂移（退货政策变化）。
  - SoMe（改造，8 类任务）：用户偏好分布漂移（话题权重迁移）、平台规则漂移（内容审核标准）、数据分布漂移（新热点出现）。
  - 每域 4 类漂移 × 3 强度（轻/中/重）。
- **漂移注入**：脚本化修改（WebArena/tau-bench 改页面与 API 定义）+ LLM 调度器（SoMe 偏好迁移由 V4 Pro 生成迁移剧本：`把话题 {A→B} 权重从 0.6→0.2，引入新话题 C`）。
- **评测轨迹**：每设置 10 任务 × 5 seed × 2 模式（无记忆/带记忆）= 每域 400 条轨迹；SoMe 域保留其帖池与标注查询。

### 3.2 系统/算法设计
- **评测 harness**：统一接口，agent 接入 = (观察, 动作) 循环；可插拔记忆模块（None / MemGPT 式文本记忆 / 感知-动作记忆）。
- **漂移引擎**：评测执行到 T_drift 步（如任务 50%）触发漂移；记录漂移前成功率窗口、漂移瞬间、漂移后窗口。
- **适应指标**：
  - 适应 AUC = 漂移后 200 步内成功率曲线积分；
  - 恢复步数 = 成功率回到漂移前 90% 水平的步数；
  - 震荡度 = 漂移后相邻窗口成功率的波动标准差；
  - 适应速率 = 前 50 步成功率斜率。
- **基线 agent**：ReAct（V4 Flash）、ReAct+MemGPT 记忆、带图路由（AutoTool 式）作为"结构适应"代理、无记忆单 agent 对照。

### 3.3 训练流程
- **无需训练**。所有 agent 为 API 后端 + 可选本地记忆推理。
- 若需对齐评测可配置性：固定 agent 提示模板，避免 prompt 差异混淆。

### 3.4 推理与评测流程
- 评测环境：WebArena Docker（4×L40 并行 8 实例）；tau-bench 本地模拟（含数据库比对）；SoMe 用其公开数据池 + 标注查询（API 调用评测）。
- 每任务流程：预热（漂移前）→ 漂移注入 → 漂移后继续 → 轨迹记录（步数、成功标志、token 数）。
- 输出：三域 × 4 类型 × 3 强度 × 2 模式的适应指标矩阵。

## 4. 数据集/环境细节
- SoMe（DOI 10.1609/aaai.v40i2.37113）：公开数据池 916 万帖/6591 用户 + 17869 标注查询；许可学术使用。
- WebArena（arXiv:2307.13854）：Apache-2.0，Docker。
- tau-bench（arXiv:2406.12045）：公开模拟器。
- 漂移剧本：本团队生成（脚本 + LLM），发布时开源漂移引擎。
- 划分：每域 50 任务（30 训练剧本构建 / 20 保持测试）。

## 5. 基线复现
| 基线 | 官方代码 | 复现要点 |
|---|---|---|
| ReAct | 自实现 | V4 Flash 逐步调用 |
| ReAct + MemGPT（arXiv:2310.08560） | GitHub: cpacker/MemGPT | 虚拟上下文记忆 |
| CA3Mem 式记忆 agent（Computer Vision XII·论文 85） | 若开源按官方 | 记忆图 + 联想检索（文本轨迹版） |
| AutoTool 式图路由（arXiv:2511.14650） | 自实现静态图 | 结构适应代理 |
| 无记忆单 agent（CoT） | 自实现 | 下限 |

统一口径：同 harness、同 agent 提示、同漂移剧本、同 seed；报告适应 AUC、恢复步数、震荡度、平均成功率。
预期表：漂移后 ReAct 成功率 −25 点；带记忆 agent 恢复步数短 40%+；图路由在 schema 漂移上适应最好、在偏好漂移上最差。

## 6. 实验矩阵
- **A. 主实验**：5 基线 × 三域，全漂移矩阵。
- **B. 消融**：漂移类型（4 类分列）；强度（3 档）；模式（无记忆/带记忆）。
- **C. 鲁棒性**：漂移时间点 T_drift 位置（25%/50%/75%）；seed 稳定性。
- **D. 泛化**：新 agent 接入（Kimi K2.6、V4 Pro）；跨域漂移剧本复用。
- **E. 诊断**：失败模式分类学（漂移后失败类型分布，呼应 SoMe 缺失败模式分类的空白）。

## 7. 评测协议
- 指标定义见 §3.2；均值±方差（5 seed）；组间差异 Mann-Whitney U 检验 p<0.05。
- 成功判定：WebArena 官方、tau-bench 状态比对、SoMe 标注查询匹配。
- 成本上限：每任务 ≤30 步、每域 ≤200 条轨迹、API 调用单任务预算 $0.2。

## 8. 算力与资源计划
- 4×L40：WebArena 沙箱评测 8-12 GPU·天（并行 8 实例）；tau-bench 本地 2 GPU·天；SoMe 走 API。
- 存储：Docker 镜像 + 轨迹数据 ~40GB。
- API 估算：V4 Flash agent 后端 ~15M token ¥80-150；V4 Pro 漂移剧本 ~2M ¥60-150；Kimi K2.6 记忆基线 ~5M ¥250-500。总计 ~¥400-800。

## 9. 里程碑与时间线（单人 + 4 卡）
- W1：SoMe 数据接入 + 三域 harness + 漂移引擎 v0（WebArena 脚本漂移）。
- W2：漂移剧本（V4 Pro）+ 指标实现；ReAct/无记忆基线跑通。
- W3：MemGPT/CA3Mem/AutoTool 基线接入；主实验 A。
- W4：消融 B + 漂移时间点鲁棒性。
- W5：诊断 E + 泛化 D。
- W6：写作 + 图表 + 发布（开源 harness + 剧本）。

## 10. 风险与备选方案
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 漂移设计过拟合特定评测 | 中 | 高 | 公开漂移引擎 + 多域交叉验证 + 社区共建接口 |
| 工程量大 | 高 | 高 | 先做社交域 MVP（SoMe 改造），再扩 2 域 |
| 漂移后全 agent 崩（无区分度） | 低 | 中 | 调漂移强度下限（轻档弱化）保证基线可恢复 |
| 指标受噪声干扰 | 中 | 中 | 长窗口平滑 + 多 seed；指标公式提前冻结 |
