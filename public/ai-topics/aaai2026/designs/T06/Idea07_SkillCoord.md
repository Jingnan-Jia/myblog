# 实验设计书：Idea 7｜技能基元驱动的多智能体上下文协调

> SkillCoord: Skill-Primitive-Driven In-Context Coordination for Multi-Agent RL
> 资源假设：4× NVIDIA L40（192GB）；DeepSeek V4 Flash/Pro、Kimi K2.6 API。

## 0. 摘要
MAICC 用"轨迹检索作上下文"实现去中心化多智能体协调，但整段轨迹检索会稀释细粒度任务信息，且中心化嵌入到去中心化的蒸馏存在误差、在线/离线记忆平衡靠启发式。本工作提出 SkillCoord：①把成功轨迹聚类为**团队技能基元**（短子目标 + 分工模式），检索对象从整轨迹降为基元；②用对比学习 + 蒸馏损失做中心化-去中心化一致性训练，减小近似误差；③基于混合效用（个体 + 团队回报）在线自调节记忆权重，替换启发式。在 Level-Based Foraging 与 SMAC v1/v2（含未见地图）上验证，MARL 网络 <1B 参数，4×L40 并行 8 环境采样，预计 5-8 GPU·天。目标在未见任务上的回报/胜率显著超过 MAICC 与 ICAL。

## 1. 研究背景与动机

### 1.1 问题定义
多智能体 RL（MARL）在未见过的任务/地图上快速协调（in-context coordination）是核心挑战：agent 需要在线读取团队经验决定"我该干什么、队友会干什么"。现有方法把整段历史轨迹作为上下文注入策略，但长轨迹中细粒度技能信息被稀释；同时去中心化策略是中心化学习的近似，两者差距在复杂环境放大。问题定义为：**如何用"团队技能基元"（可复用短片段）作为上下文，并校准中心化-去中心化差距，实现未见任务上的快速协调适应**。

### 1.2 相关工作不足
- 整轨迹检索稀释信息：MAICC（Machine Learning IV·论文 16·MAICC）用中心化嵌入 + 去中心化近似，轨迹检索作上下文，但检索粒度粗、蒸馏误差存在、在线/离线记忆平衡为启发式。
- 上下文对齐未解决分工：ICAL（in-context alignment learning）关注对齐但未显式建模"技能基元分工"。
- 通信剪枝与规划：Multiagent Systems·论文 3·Efficient Multiagent Planning via Shared Action Suggestions 用共享建议剪枝信念，但为经典 POMDP、未衔接 LLM agent，行动语义需人工。

### 1.3 为什么是现在、为什么你的环境适合做
上下文强化学习（in-context RL）与技能基元（skill/option）在单智能体 RL 已成熟，向多智能体迁移是未饱和前沿；SMAC v1/v2 与 LBF 是社区标准环境、开销小，4×L40 可并行大批量采样；本 idea 不依赖大模型训练，GPU 需求低，适合作为 MARL 方法论文稳定产出。MARL 团队（AAMAS/NeurIPS）对"记忆 + 上下文协调"高度关注。

## 2. 研究目标与可验证假设
1. **H1（技能基元优于整轨迹检索）**：基元检索的未见任务回报高于整轨迹检索。
   - 成立时观测：LBF 未见配置上回报提升 ≥15%；SMAC 未见地图胜率提升 ≥10 点。
2. **H2（一致性训练缩小差距）**：对比 + 蒸馏损失减小中心化-去中心化差距，未见任务泛化提升。
   - 成立时观测：去中心化/中心化回报比从 ~0.8 升至 ≥0.9；消融移除蒸馏损失后胜率回落。
3. **H3（混合效用自调节优于启发式）**：基于个体 + 团队回报的自调节记忆权重优于固定权重。
   - 成立时观测：长时任务（SMAC 复杂地图）回报提升 ≥10%，且权重自适应行为可解释。
4. **H4（跨未见地图快速适应）**：一次在线适应（≤100 步）后未见地图胜率快速爬升。
   - 成立时观测：未见地图前 100 步胜率斜率显著高于 MAICC。

## 3. 总体方法设计

### 3.1 数据/轨迹采集流水线
- **环境**：Level-Based Foraging（LBF，2-4 agent 网格协作取食）、SMAC v1（3m/8m/2s3z/2s_vs_1sc）、SMAC v2（未见图谱，官方 24 地图）。
- **成功轨迹收集**：预训练 QMIX/MAPPO 在训练地图上采样 200K 条成功片段（按 episode 拆成固定窗口子轨迹），存 `(观察序列, 联合动作, 回报, 子目标标签)`。
- **子目标标签**：行为聚类自动得到（见 3.2）；可选 LLM 语义标注（DeepSeek V4 Flash 把关键帧转写为"在收集金币/掩护输出"等自然语言基元名）作对照。
- **数量**：每环境 20K 成功轨迹 → 切片为 100K 窗口片段 → 聚类为 K=64 技能基元。

### 3.2 系统/算法设计
- **技能基元库**：对窗口片段做行为聚类（VQ-VAE 式离散码本 或 k-means 于行为特征），每基元 = `(子目标表示, 典型分工模式, 统计回报)`。检索：当前团队状态（去中心化局部观）→ 与基元的相似度打分 → Top-K 基元作为策略输入上下文。
- **中心化-去中心化架构**：
  - 中心化 Critic/编码器：输入全局态 + 检索上下文，输出价值与"共识表示" `z_t`。
  - 去中心化 Actor：输入局部观 + `z_t`（经共享嵌入）+ 检索基元，输出动作。
  - 一致性训练损失：`L_cross = L_distill(actor(a|o_i, z) || 中心化策略 π_cent) + L_contrast(z_i, z_j)`（同 episode agent 表示拉近，异 episode 推远）。
- **混合效用记忆权重**：在线维护两套记忆统计：个体效用 `u_ind(episode)` 与团队回报 `u_team(episode)`；权重 `w_t = softmax(β·(α_t·u_ind + (1−α_t)·u_team))`，`α_t` 由在线 meta-梯度（近期回报差分）自适应。
- **策略底座**：PPO（LBF）、QMIX（SMAC v1）、MAPPO（SMAC v2），网络 ~1M 参数（MLP + GRU），上下文注入 = 检索基元 embedding concat。

### 3.3 训练流程
- 预训练：QMIX/MAPPO 训练地图 500K 步（4 卡并行 8 env/卡，约 4 GPU·天）。
- 基元聚类：VQ-VAE 码本 64，1 卡 1 天。
- 一致性训练：冻结策略热启动，加 `L_cross`（λ_distill=0.1，λ_contrast=0.05）继续训练 300K 步（约 2 GPU·天）。
- 在线适应评测：未见地图上继续更新记忆权重与检索缓存（不更新网络权重），测前 100 步胜率。

### 3.4 推理与评测流程
- 评测：LBF 未见配置（新障碍/新大小）；SMAC v1 未见地图（train/test 分离）；SMAC v2 官方 test 24 地图全量。
- 每设置 10 个随机地图 × 5 seed；报告平均回报/胜率 + 前 100 步适应曲线。
- LLM 基元标注对照：用 V4 Flash 把聚类基元转写为自然语言名（提示：描述 5 帧关键帧中 agent 的角色与分工），验证语义标注是否提升检索质量（对照纯行为特征）。

## 6. 实验矩阵
- **A. 主实验**：SkillCoord vs 基线，LBF + SMAC v1/v2 未见任务。
- **B. 消融**：基元 vs 整轨迹检索；蒸馏损失有无；对比损失有无；混合效用自调节 vs 固定权重；K（基元数）∈{16,64,256}。
- **C. 鲁棒性**：agent 数变化（LBF 2→4）；部分可观测度（视野大小）；奖励噪声。
- **D. 泛化**：SMAC v2 跨种族未见地图；LLM 语义标注 vs 纯行为基元。
- **E. 训练数据量**：成功轨迹比例（10K/20K/40K）对基元质量影响。

## 7. 评测协议
- LBF：平均团队回报（归一化 0-1）；SMAC：win rate（官方判定）+ 平均回报。
- 适应速度：前 100 步胜率的线性斜率 + 达到 50% 胜率的步数。
- 均值±方差：10 地图 × 5 seed；Mann-Whitney U 检验 p<0.05（胜率非正态）。
- 成本上限：每评测 episode ≤2K 步、每环境 ≤20K 步评估。

## 8. 算力与资源计划
- 4×L40：预训练 4 + 聚类 1 + 一致性训练 2 + 评测/在线适应 1-2 ≈ **5-8 GPU·天**。
- 存储：轨迹/基元数据 ~50GB；SC2 环境镜像 ~5GB。
- API 估算：V4 Flash 基元语义标注 ~1M token ¥5-15（可选，极小成本）。

## 9. 里程碑与时间线（单人 + 4 卡）
