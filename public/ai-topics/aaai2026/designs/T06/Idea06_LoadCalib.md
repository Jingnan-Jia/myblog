# 实验设计书：Idea 6｜认知负载自适应的思维链合成与蒸馏

> LoadCalib: Cognitive-Load-Calibrated Chain-of-Thought Synthesis for Small Models
> 资源假设：4× NVIDIA L40（192GB）；DeepSeek V4 Flash/Pro、Kimi K2.6 API。

## 0. 摘要
MACoT 发现过多自我反思会伤害小模型，但最优反思密度是人工经验值、随样本难度漂移。本工作提出 LoadCalib：①训练轻量"难度感知负载预测器"把题目难度映射到反思密度档位；②用 RL（REINFORCE）训练 CoT 合成器，以"学生蒸馏后准确率"为奖励，自动校准长度/反思密度/步骤粒度；③提出"负载-收益曲线"作为跨模型可迁移的诊断工具。数据为 GSM8K/MATH/ASDiv（蒸馏）+ MMLU 子集（泛化）。预计 7B 学生 LoRA 多轮（每轮 3 GPU·天）+ 7B 合成器 LoRA（REINFORCE，8 GPU·天），总计约 30 GPU·天。目标学生 pass@1 显著超过 MACoT 与 R1-Distill，且负载-收益曲线揭示"小模型该配多少反思"的规律。

## 1. 研究背景与动机

### 1.1 问题定义
用小模型蒸馏大模型的 CoT 时，CoT 的"认知负载"（反思密度、步数粒度、长度）与样本难度不匹配会显著伤害性能：过浅则推理不足，过深则小模型承压出错（MACoT 的观察）。问题定义为：**如何为每个样本自动校准最适合目标小模型的 CoT 负载，使蒸馏后的准确率最大化**。核心是学习"难度 → 负载"的映射，并让负载选择随学生模型能力自适应。

### 1.2 相关工作不足
- 反思密度人工调参：MACoT（Multiagent Systems·论文 46·MACoT）用六类 agent 合成认知负载匹配 CoT，但最优反思密度为经验值，且依赖教师质量。
- 固定长 CoT 蒸馏：R1 系（长 CoT 直接蒸馏）对不同难度一刀切，小模型在简单题上浪费容量。
- 合成器无自校准：现有 CoT 合成（如大模型自蒸馏）不以"学生收益"为信号。

### 1.3 为什么是现在、为什么你的环境适合做
"以小模型为主"的蒸馏需求随 edge 部署爆发；RL 训练 CoT 生成器的技术（REINFORCE/GRPO）已成熟；4×L40 可同时并行训练 7B 学生与 7B 合成器；DeepSeek V4 Pro 可高质量生成多档 CoT 池。数据全部公开（GSM8K/MATH/ASDiv/MMLU）。

## 2. 研究目标与可验证假设
1. **H1（难度感知负载校准优于固定档位）**：难度自适应负载的蒸馏学生准确率高于任何单一固定档位。
   - 成立时观测：GSM8K/MATH 上自适应学生 pass@1 高于最佳固定档位 ≥2 点。
2. **H2（RL 合成的负载优于启发式）**：以学生收益为奖励的 RL 合成器胜过启发式档位匹配。
   - 成立时观测：RL 合成 CoT 的学生 pass@1 高于启发式档位 ≥1.5 点。
3. **H3（负载-收益曲线可迁移）**：在小模型上测得的"负载-收益"关系可预测另一规模小模型的最优负载档位。
   - 成立时观测：1.5B 预测的最优档位与实际最优档位一致（或 top-2 命中）。
4. **H4（不损害泛化）**：负载校准的蒸馏学生在 MMLU 子集上不劣于基线蒸馏。
   - 成立时观测：MMLU 子集准确率差 ≤1 点。

## 3. 总体方法设计

### 3.1 数据/轨迹采集流水线
- **CoT 候选池（LLM-as-teacher）**：对 GSM8K（train 7.4K）+ MATH（train 7.5K）+ ASDiv（2.3K）每题，用 DeepSeek V4 Pro 生成 5 档反思密度 CoT（档位 d∈{0,1,2,3,4}：0=无反思直答，1=单步检查，2=每 2 步一次反思，3=每步反思，4=过度反思冗余式）。prompt 模板：
  ```
  以 {档位 d} 的反思强度解答 {题目}。档位定义：{各档具体规则}。
  输出完整解题 CoT。
  ```
  每题每档 1 条，共 ~17K 题 × 5 = 85K 条 CoT。
- **难度标注**：DeepSeek V4 Pro 给每题 1-5 分难度标签（prompt 含 rubric），10K 题人工抽检 300 校准。
- **蒸馏评测信号**：学生模型在 5K 验证子集上逐题跑各档 CoT 得 `acc(d,x)`，构成训练信号。
- **数量**：85K 候选 CoT + 难度标签；学生蒸馏数据 = 每题选中档位 CoT，约 17K 条。

### 3.2 系统/算法设计
- **难度预测器**：BERT 级编码器（`bert-base` 类，参数 <200M）输入 = 题目文本 + 选项，输出难度回归 `ŷ ∈ [1,5]`；训练数据 = V4 Pro 难度标签 10K，MSE 损失，正则化让输出分档（映射到 5 档）。
- **负载选择**：`d*(x) = clip(round(w·ŷ(x)+b))`，w、b 由验证集扫描确定；RL 合成器替代该启发式。
- **RL CoT 合成器（REINFORCE）**：生成模型（Qwen2.5-7B，LoRA）输入 = 题目 + 难度标签，输出 CoT。奖励：
  `R = acc_student(coT) − λ·len_penalty(coT)`
  其中 `acc_student` = 学生（Qwen2.5-7B，固定权重）蒸馏该 CoT 后（LoRA 一 epoch）在验证集上的 pass@1 提升；`len_penalty` 抑制冗余。REINFORCE 基线修正：
  `∇J = E[ (R − b) · ∇log p_θ(coT|x) ]`，baseline b 为组内均值（group=8）。
- **负载-收益曲线**：横轴 = 反思密度档位，纵轴 = 学生 acc；对 3 个规模（1.5B/7B/14B）画出曲线，分析峰值位置与曲线陡度。

### 3.3 训练流程
- **难度预测器**：BERT 级，lr=2e-5，batch=64，epochs=3，1 卡即可，<0.5 GPU·天。
- **学生蒸馏**：Qwen2.5-7B LoRA（r=16，lr=2e-5，batch=32，1 epoch），每轮 3 GPU·天；共 4-6 轮（随 RL 合成器迭代）。
- **RL 合成器**：Qwen2.5-7B LoRA（r=16，lr=1e-6，group=8），REINFORCE 训练 8 GPU·天（4 卡并行 rollout）。
- 合计：难度预测 <1 + 学生蒸馏 12-18 + 合成器 8 ≈ **25-30 GPU·天**。

### 3.4 推理与评测流程
- 评测：学生 pass@1（GSM8K 测试 1319、MATH 500、ASDiv 测试）；MMLU 子集（8 个 STEM 任务）零样本泛化；负载-收益曲线跨规模对比。
- 对照 Kimi K2.6 长推理 CoT 与 R1 系蒸馏设置差异。

## 4. 数据集/环境细节
- GSM8K（arXiv，CC BY）train 7.4K/test 1.3K；MATH train/test；ASDiv train/test；MMLU 子集（公开）。
- 划分：CoT 池构建用 train 全量；RL 训练信号用 5K 验证子集；最终评估用官方 test 集，与训练严格分离。
- 教师与难度标签由 API 生成，无版权问题。

## 5. 基线复现
| 基线 | 官方代码 | 复现要点 |
|---|---|---|
| MACoT（Multiagent Systems·论文 46） | 若开源按官方；否则按描述重实现 | 六类 agent 合成认知匹配 CoT，微调 Qwen2.5-7B |
| 长 CoT 直接蒸馏 | 自实现（V4 Pro 长推理 → LoRA 学生） | 对应 R1 系蒸馏 |
| R1-Distill（DeepSeek-R1-Distill 系，公开） | HuggingFace 权重 | 直接对比学生能力 |
| 无反思 CoT | 自实现 | 档位 0 |
| 启发式档位匹配 | 自实现 | w,b 扫描替代 RL |

统一口径：同一学生底座 Qwen2.5-7B、同 LoRA 超参、同 test 集；报告 pass@1（温度 0）与 pass@8（自洽性）。
预期表：无反思 ~65% / 长 CoT ~78% / MACoT ~80% / LoadCalib 目标 82%+（GSM8K）；MATH500 相应提升。

## 6. 实验矩阵
- **A. 主实验**：LoadCalib（RL 合成）vs 各基线，GSM8K/MATH/ASDiv。
- **B. 消融**：难度预测器有无（随机负载 vs 预测负载）；RL vs 启发式档位；反思档位数（3/5/7）；长度惩罚 λ。
- **C. 学生规模**：1.5B/7B/14B 的负载-收益曲线与最优档位迁移。
- **D. 鲁棒性**：难度标签噪声（注入 10% 错误标签）；CoT 池教师质量（V4 Pro vs Flash 生成）。
- **E. 泛化**：MMLU 子集；训练未见题型的负载选择正确率。

## 7. 评测协议
- pass@1（greedy）与 pass@8（自洽性多数）；均值±方差（5 seed：学生微调种子）；学生 acc 噪声大 → 每组 3 次蒸馏取均值，bootstrap 95% CI。
- 显著性：Welch t 检验 p<0.05；RL 奖励稳定用固定种子 + 组内均值 baseline。
- 成本上限：RL 合成器 rollout 每代 ≤2000 条；学生蒸馏每轮 ≤1 epoch。

## 8. 算力与资源计划
- 4×L40：难度预测 0.5 + 学生蒸馏 12-18 + RL 合成器 8 + 评测 2 ≈ **25-30 GPU·天**（分 3 周）。
- 存储：CoT 池 85K 条（~2GB）+ 检查点 4×7B LoRA（~10GB）。
- API 估算：V4 Pro CoT 池 + 难度标签 ~40M token ¥1200–3000（主要成本）；V4 Flash 批量候选 ~10M ¥60–120；Kimi K2.6 长推理对照 2M ¥100–200。总计 ~¥1400–3300。

## 9. 里程碑与时间线（单人 + 4 卡）
- W1：CoT 池构建（V4 Pro 5 档 ×17K 题）+ 难度标注 + 抽检。
- W2：难度预测器训练 + 基线蒸馏（无反思/长 CoT/MACoT 重实现）。
- W3：启发式负载选择验证（H1）；学生蒸馏首轮。
- W4-5：RL 合成器（REINFORCE）训练 + 学生多轮迭代。
- W6：负载-收益曲线（3 规模）+ 泛化/鲁棒性。
- W7：写作 + 图表。
