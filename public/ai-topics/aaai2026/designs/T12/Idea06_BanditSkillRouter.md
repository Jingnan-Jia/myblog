# 实验设计书：Bandit-Skill-Router —— 长时序操作的上下文赌博机技能路由器

## 0. 摘要（3-5 句）
长时序 VLA/操作任务在技能边界处累积误差，现有 LLM 规划（SayCan/LLM-Planner 一族）把「下一个技能」交给提示词，既不维护探索-利用、也无执行反馈回路。Bandit-Skill-Router 把「下一个技能/原语」建模为上下文 bandit：臂 = 技能库（grasp/place/reorient/push…），上下文 = LLM 抽取的语言-视觉特征 + 上一步成败；用 UCB/汤普森采样在技能间探索，LLM 仅在「臂初始化」与「失败后臂重定义」时低频介入。预期把长时序任务成功率提升 10–20 个点，并给出「平均路由遗憾」这一可量化的路由质量指标。

## 1. 研究背景与动机

### 1.1 问题定义
- 输入：长时序操作任务（如 Meta-World/RLBench 的复合任务），任务由若干子技能组成；一个预训练技能库（VLA 或 Diffusion Policy 技能策略）。
- 决策环：每步选择技能 a∈A 执行，观察是否推进任务；目标是最小化到达终点的总代价与路由遗憾。
- 核心困难：技能选择依赖（语言上下文, 视觉状态, 历史成败），且初始技能集不完备（失败后需重定义臂）。

### 1.2 相关工作不足
- SayCan (arXiv:2204.01691)、LLM-Planner (arXiv:2212.04088)：LLM 提示词规划技能序列，无探索-利用、无执行反馈，失败不可自纠。
- Decision Transformer (arXiv:2106.01345)：序列建模规划，但假设离线数据充分、不支持在线技能重路由。
- Bandits Meet LLMs 综述（论文 77）、LLMP-UCB（arXiv:2604.05859）、多目标 prompt bandit（arXiv:2605.14553）：bandit 管理 LLM 选择可行，但全部在文本/推荐域，**操作技能路由无人做**。
- (Machine Learning V · 论文 82 · IndoorUAV) 的失败模式（卡在某子指令）正说明「分解后无路由反馈」的通病。
- 结论：**在线上下文 bandit 的技能路由 + LLM 臂管理在机器人操作上是空白**。

### 1.3 为什么是现在、为什么你的环境适合做
- 现在：预训练 VLA 技能库（OpenVLA/π0/Diffusion Policy）已可廉价微调；bandit×LLM 理论（LLMP-UCB）就绪。
- 环境：**仿真为主、真机可选**——Meta-World（arXiv:1910.10897）+ RLBench + SIMPLER（WidowX）；任务官方元数据提供技能划分，仿真可安全在线探索。

## 2. 研究目标与可验证假设（2-4 条）
1. **H1（bandit 路由优于 LLM-only）**：上下文 bandit 路由的任务成功率比 LLM 提示词路由高 ≥10 点。→ 可观测：长时序任务成功率对比。
2. **H2（反馈回路修复误差累积）**：加入「失败后臂重采样」，长时序成功率提升 ≥8 点。→ 可观测：有无反馈回路的消融。
3. **H3（低遗憾）**：平均路由遗憾收敛到最优 skill 的 20% 以内。→ 可观测：累积遗憾曲线。
4. **H4（LLM 低频化）**：API 调用比 LLM-only 路由降低 ≥10×，成功率不减。→ 可观测：成功率-调用次数帕累托。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/轨迹流水线
- **技能库构建**：用官方任务元数据把任务切成技能序列（如 Meta-World 的 pick→place→push）；每技能用预训练 VLA（OpenVLA 或 Diffusion Policy）微调到 85%+ 单技能成功率。
- **上下文特征**：LLM（DeepSeek V4 Flash）在任务开始时从「任务文本 + 首帧」抽取语言-视觉特征向量（32 维：目标/物/关系/空间词嵌入）；每步再拼接上一技能成败（成功/失败/停滞三态）与当前视觉 embedding。
- **臂定义**：初始臂集 = 该任务技能候选（LLM 给出，含描述）；失败后由 Kimi K2.6 分析失败原因并重定义臂（拆分/替换技能）。
- **Rollout 数据**：在线探索记录 (上下文, 臂选择, 结果, 步数)，用于离线回放训练可选的价值预测头。

### 3.2 方法设计（模块拆解、关键公式、超参数初值）
- **上下文 bandit**：
  - 奖励 r_t ∈ {+1 子技能成功推进, 0 无进展, −1 失败/停滞}。
  - UCB：`a* = argmax_a (μ̂_a(x) + c·√(ln N / n_a(x)))`，c=0.5；n_a(x) 为相似上下文近邻计数。
  - 汤普森采样（备选）：θ_a ~ N(μ̂_a, σ²_a)，按后验采样。
- **反馈回路**：子技能停滞（连续 T=5 步状态无变化）→ 触发「再采样」：先重试 1 次，仍失败则调用 Kimi 分析 + 臂重定义。
- **LLM 介入点**：①任务起始臂初始化（1 次）；②停滞后的臂重定义（低频，每任务 ≤3 次）。
- **路由遗憾**：`Regret = Σ_t (r_a* − r_{a_t})`，a* 由离线最优（官方任务序列 + 事后 oracle）估计。
- **超参数初值**：

| 超参 | 初值 |
|---|---|
| bandit | UCB（c=0.5）；Thompson 作对比 |
| 停滞阈值 T | 5 步 |
| 臂重定义调用 | ≤3 次/任务 |
| 技能策略 | OpenVLA LoRA 或 Diffusion Policy，单技能 ≥85% |
| 上下文特征 | 32 维 LLM 特征 + 16 维视觉 + 8 维成败 |
| 评测 rollout | 每任务 50 episode × 100 任务 |

### 3.3 训练流程（优化器/学习率/批次/并行；RL 训练资源估算）
- bandit 无需训练（在线学习）；技能策略预训练/微调占主要 GPU。
- 技能微调：OpenVLA 7B LoRA 每技能 500–1000 步，4 卡并行，约 2–4 GPU·天。
- 若加价值预测头：用回放数据离线训练（1 卡，小时级）。
- 总预算 **3–6 GPU·天**（仿真 rollout 在 CPU 池）。

### 3.4 评测流程
- Meta-World 10 复合任务 × RLBench 5 任务 × SIMPLER 4 任务（长时序版），成功率 + 平均路由遗憾 + 调用次数。
- 每任务 50 episode；3 次重复统计。

## 4. 环境/数据集细节
- **Meta-World**（arXiv:1910.10897）：开源，MT10 复合任务；MuJoCo 后端。
- **RLBench**：社区基准（软件），用其 5 个多阶段任务；以社区官方仓库为准。
- **SIMPLER**：WidowX 桌面仿真（软件，复现自 DiTEA/官方仓库）。
- 真机（可选加分）：WidowX 4 任务，用离线预采集历史做 bandit warm-start（真机不在线探索）。
- 许可：Meta-World/RLBench/SIMPLER 均为开源研究软件。

## 5. 基线复现
| 基线 | 出处 | 复现要点 |
|---|---|---|
| LLM-only 路由（提示词） | SayCan 思路 (arXiv:2204.01691)、LLM-Planner (arXiv:2212.04088) | 每步调用 LLM 选技能 |
| SayCan 复现 | arXiv:2204.01691 | 价值 + LLM 打分 |
| Decision Transformer | arXiv:2106.01345 | 离线序列建模 |
| 端到端 VLA | OpenVLA (arXiv:2406.09246) | 直接输出动作 |
- **预期指标表（长时序任务成功率，100 任务 × 50 ep）**：端到端 VLA ~35%、DT ~45%、LLM-only ~52%、**Ours 62–70%**；平均路由遗憾 Ours 收敛到 oracle 的 <20%。
- **统一口径**：技能划分一律用官方任务元数据；成功判据用环境回调；LLM 调用统计统一。

## 6. 实验矩阵
- **A 主实验**：Ours vs 基线。
- **B 路由消融**：bandit vs 纯 LLM 路由；UCB vs Thompson。
- **C 反馈消融**：有无停滞重采样；有无臂重定义。
- **D 臂规模**：臂数 3/5/8/12 的遗憾与成功率。
- **E 反馈延迟**：即时反馈 vs 延迟 1 步 vs 延迟 3 步。
- **F 失败恢复率**：注入 20% 技能随机失败后的恢复成功率。
- **G 跨任务泛化**：训练任务外的新任务 zero-shot 路由。

## 7. 评测协议
- **成功率**：环境回调二值成功 / episode 数；mean±std（3 次重复）。
- **平均路由遗憾**：按累计遗憾 / episode 报告；oracle 用官方序列 + 事后最优估计。
- **调用次数**：每任务 LLM API 调用数，与成功率构成帕累托。
- **统计**：配对 t-test（α=0.05，Bonferroni 校正）；3 次独立重复。

## 8. 算力与资源计划
- GPU：技能微调 2–4 + 主实验/消融 3–5 ≈ **6–9 GPU·天**；4 卡并行。
- 存储：<100GB。
- **API 成本**：臂初始化 + 失败分析为主，100 任务 × ≤4 次 ≈ 400 次调用 + LLM-only 基线对照 ≈ 1.5 万次；DeepSeek V4 Flash 约 $30，Kimi 约 $30；总 **≤$100**。

## 9. 里程碑与时间线（按周，单人+4 卡）
- W1–2：环境 + 技能库构建（Meta-World 先跑通）。
- W3–4：bandit 路由 + 上下文特征管线。
- W5：反馈回路（停滞检测 + 臂重定义）。
- W6：主实验 + 遗憾曲线。
- W7–8：消融（B–G）。
- W9：写作；W10：投稿（ICRA/CoRL）。

## 10. 风险与备选方案（表）
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 技能粒度敏感 | 中 | 中 | 统一用官方任务元数据；试 3 种粒度 |
| bandit 在线探索真机不安全 | 中 | 中 | 先仿真；真机用离线历史 warm-start + 保守探索 |
| LLM 上下文特征噪声大 | 中 | 中 | 特征仅作上下文，决策权在 bandit；置信度加权 |
| 技能库微调开销大 | 中 | 低 | 用 Diffusion Policy 轻量技能（每技能 <1 卡·天） |
