# 实验设计书：FailCheck —— 长时序 VLA/VLN 的失败感知恢复

## 0. 摘要（3-5 句）
IndoorUAV（Machine Learning V · 论文 82）等分解式 VLA/VLN agent 的典型失败是「卡在子指令反复执行」，且无检测与恢复机制，误差线性累积。FailCheck 在 VLA/VLN 执行回路外插入一个可插拔模块：轻量卡点检测器（小模型或低成本 LLM）在每子任务间隔判断「进行/达成/卡死」三态，卡死时触发 LLM 基于最近 K 帧与失败原因重写剩余子目标（重试/绕路/回退重来）。检测-修复与策略解耦，可叠加在任何 VLA/VLN 之上。预期把 IndoorUAV 级分解 agent 的 SR 提升 8–15 点，并给出「成功率-步数帕累托」与检测器精度的量化分析。

## 1. 研究背景与动机

### 1.1 问题定义
- 输入：一个分解式长时序 agent（LLM 把长指令拆成子目标序列，VLA 逐段执行）在连续环境（Habitat/仿真操作）中运行。
- 目标：实时检测「卡死/偏离/错误子目标」，并自动修复（重试、绕路、回退），使任务成功率上升、总步数不显著恶化。
- 约束：检测器要便宜（不能每步调用大模型）、修复要低频、模块对底层策略透明可替换。

### 1.2 相关工作不足
- (Machine Learning V · 论文 82 · IndoorUAV...)：失败模式即「卡在子指令不停执行」，论文明确无检测与纠错；所有方法 VLN SR<10%。
- ReAgent-V (arXiv:2506.01300)：reward 驱动的视频反思可提升多模态智能体，但面向视频问答/决策，**未用于机器人控制回路**。
- LLM 规划一族（LLM-Planner arXiv:2212.04088、SayCan arXiv:2204.01691）：单向「规划→执行」，无「执行-验证-再规划」闭环。
- 结论：**「轻量卡死检测 + LLM 子目标重规划」作为可插拔恢复模块，在 VLA/VLN 上没有系统方案**。

### 1.3 为什么是现在、为什么你的环境适合做
- 现在：低成本 LLM（DeepSeek V4 Flash）可做高频三态判定；小模型（0.5–1.5B）微调便宜；IndoorUAV 提供标准化失败测试场。
- 环境：**仿真**——IndoorUAV（Habitat）+ VLN-CE 对照 + 仿真操作（Meta-World 长时序）；可控注入故障（遮挡/光照）测鲁棒性；真机仅做「停止并求助人类」的保守恢复。

## 2. 研究目标与可验证假设（2-4 条）
1. **H1（SR 提升）**：叠加 FailCheck 后，分解式 agent 的 SR 提升 ≥8 点（IndoorUAV VLN）。→ 可观测：官方 test-unseen 评测。
2. **H2（检测器质量）**：检测器「卡死」判定的 precision/recall ≥0.8（人工标注 200 段）。→ 可观测：混淆矩阵与 F1。
3. **H3（代价可控）**：修复使总步数不劣化超过 10%，LLM 调用比「每步反思」低 10×。→ 可观测：步数分布 + 调用统计。
4. **H4（故障鲁棒性）**：注入遮挡/光照后 SR 衰减比无恢复版本小 50%。→ 可观测：鲁棒性评测表。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/轨迹流水线
- **复现底座**：IndoorUAV-Agent（GPT-4o 分解 + π0 VLA）+ 微调 π0；Meta-World 长时序任务（官方元数据分解）。
- **检测器训练数据**：从底座 rollout 中收集「子目标间隔」样本（观测序列 + 位姿轨迹 + 该段真值标签：进行/达成/卡死）；人工标注 2000 段（3 标注者多数）；正样本卡死占比 25%（欠采样过采样到 1:1）。
- **故障注入**：训练/评测期对 10% episode 注入（随机遮挡 2–5s、光照突变、子目标顺序打乱）。
- **修复样本**：记录卡死时刻最近 K=8 帧 + 失败原因（由 DeepSeek Flash 生成）→ 作为 Kimi 重规划的输入样例。

### 3.2 方法设计（模块拆解、关键公式、超参数初值）
- **检测器**：
  - 输入：最近 K=8 帧 RGBD 特征（预训练 VLA 编码器冻结）+ 位姿序列差分 + 当前子目标文本。
  - 输出：三态 logits；卡死定义：连续 T=10 步位姿变化 <0.05m 且偏航 <5°。
  - 模型：0.5–1.5B VLM LoRA（或轻量时序头），训练 5000 步。
- **卡死确认策略**：检测器连续两轮报「卡死」且置信度 >0.75 才触发修复（抑制误报）。
- **修复（LLM 重规划）**：Kimi K2.6 输入「最近 K 帧描述 + 失败原因 + 剩余子目标」，输出重规划（retry/绕路/回退重来三选一 + 新子目标序列）。每次修复 ≤2 轮。
- **接口**：`(state, subgoal_k, detector) → {continue, achieved, stuck}`；stuck 时 `repair(subgoal_{k..K}, frames)`。模块以 hook 形式注入执行回路。
- **超参数初值**：

| 超参 | 初值 |
|---|---|
| 检测器 | 1B VLM LoRA 或 0.5B 时序模型 |
| K（帧数） | 8 |
| 卡死阈值 | 连续 10 步 / 位姿 <0.05m |
| 确认策略 | 连续 2 轮 + 置信度 >0.75 |
| 修复轮次 | ≤2/任务 |
| 主策略 | π0 LoRA 微调（如 Idea 2 底座） |

### 3.3 训练流程（优化器/学习率/批次/并行；RL 训练资源估算）
- 检测器微调：1 卡 1 天；主策略微调：4 卡 3–5 天；修复模块无训练。
- 消融与统计：3 seed。总 **6–10 GPU·天**。
- rollout 在 CPU 池并行（Habitat/Meta-World headless）。

### 3.4 评测流程
- 官方 test-unseen SR；成功率-步数帕累托；检测器 F1（200 段人工标注）；修复触发率与成功修复率；API 调用频率与成本。
- 故障注入鲁棒性（遮挡/光照/顺序错乱）。

## 4. 环境/数据集细节
- **IndoorUAV**（Habitat，场景 1075 个）：官方数据集与评测协议（见 Idea 2 环境节）。
- **VLN-CE**（arXiv:2004.02857）：跨域对照（只评测、不训练）。
- **Meta-World**（arXiv:1910.10897）：长时序操作对照。
- 无真机恢复动作（真机仅「停止并求助人类」）。

## 5. 基线复现
| 基线 | 出处 | 复现要点 |
|---|---|---|
| 无恢复分解式 agent | (Machine Learning V · 论文 82) | IndoorUAV-Agent 复现 |
| 端到端 π0 | arXiv:2410.24164 | 无分解 |
| 每步反思（ReAgent-V 式） | arXiv:2506.01300 | 高成本对照 |
| NavGPTv2（社区复现） | 社区实现（若公开） | 规划式导航对照 |
| 规则式卡死重试 | 本项目 | 卡死只重试、不重规划 |
- **预期指标表（IndoorUAV VLN，官方口径）**：无恢复 7.3%、规则重试 ~10%、每步反思 ~12%（成本高）、**Ours 16–20%**；检测器 F1 ≥0.8；修复触发率 30–50% 中修复成功 >60%。
- **统一口径**：SR 2m 阈值；步数上限 400；调用统计一致。

## 6. 实验矩阵
- **A 主实验**：FailCheck vs 基线（IndoorUAV + Meta-World）。
- **B 检测器消融**：模型规模（0.5B/1B/LLM-API 直判）；确认策略（1 轮 vs 2 轮）；阈值。
- **C 修复消融**：retry-only / 绕路 / 回退 / 组合；修复轮次。
- **D 故障注入**：遮挡/光照/顺序错乱各 10% 的鲁棒性。
- **E 跨域**：IndoorUAV→VLN-CE；Meta-World 变体。
- **F 成本**：API 调用-成功率帕累托（与每步反思对比）。

## 7. 评测协议
- **SR**：官方 2m 阈值；mean±std（3 seed × 3 次采样）。
- **F1**：200 段人工标注的检测器 precision/recall。
- **修复成功率**：触发修复后是否最终成功到达。
- **步数**：成功 episode 的中位步数；帕累托前沿（成功率 vs 平均步数）。
- **显著性**：配对 t-test（α=0.05，Bonferroni 校正）。

## 8. 算力与资源计划
- GPU：检测器 1 + 主策略 3–5 + 消融 3–5 ≈ **7–11 GPU·天**（4×L40）。
- 存储：Habitat 场景 + 数据 + 检查点 ≈ 400GB。
- **API 成本**：检测用 Flash（高频，每子任务 1 次）约 5 万次 ≈ $30–50；Kimi 修复（低频，每任务 ≤2 次）≈ 2 万次 ≈ $60；每步反思基线另计。总 **≤$150**。

## 9. 里程碑与时间线（按周，单人+4 卡）
- W1–2：复现 IndoorUAV-Agent/π0 底座 + 故障注入框架。
- W3：检测器训练数据收集与标注。
- W4–5：检测器微调 + 主实验。
- W6：修复模块（Kimi 重规划）集成。
- W7–8：消融 + 鲁棒性 + 跨域。
- W9：写作；W10：投稿（CoRL/RSS）。

## 10. 风险与备选方案（表）
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 检测器误报导致无谓重规划 | 中 | 中 | 连续两轮确认 + 置信度阈值；误报样本回流重训 |
| 修复后仍失败 | 中 | 中 | 修复轮次上限 + 终局「停止并求助人类」 |
| 主策略底座表现差（SR 低） | 中 | 中 | 与 Idea 2 的 RL 底座合并（FailCheck 可叠加） |
| 真机恢复动作安全约束 | 确定 | 低 | 真机仅保守「停止+求助」 |
