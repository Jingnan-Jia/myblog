# 实验设计书：Align-By-Design —— LLM 环境设计师缩小人机目标状态分歧

## 0. 摘要（3-5 句）
GSD/HRGAD（Humans and AI · 论文 43）把「人类预期状态 vs 机器人实际状态」的分歧形式化并求最小环境修改集，但其搜索假设修改可枚举、代价已知，未利用语义知识。Align-By-Design 让 LLM 充当环境设计师：基于「人类指令语义 + 当前环境 + 机器人能力」生成候选修改（物体摆放/路标/感知提示）并输出代价估计，再用 GSD 可计算界作为排序与筛选的验证信号，形成「LLM 生成 + 形式验证」闭环。在 PDDL 规划基准与 MiniGrid 具身指令集双轨验证，目标是产出比枚举式 HRGAD 更低的修改代价、且人类满意度更高；本项目 GPU 需求≈0，是低成本保底 idea。

## 1. 研究背景与动机

### 1.1 问题定义
- 输入：人类指令（自然语言）、环境当前状态、机器人能力模型（可达状态集）。
- 目标：找到一组最小代价的环境修改（物体重新摆放、添加路标、感知提示），使机器人规划产生的实际达到状态与人类预期状态的分歧（GSD）最小。
- 难点：候选修改空间极大（组合爆炸）、代价语义化、修改需语义合理（不能违背人类意图）。

### 1.2 相关工作不足
- (Humans and AI · 论文 43 · Reducing Goal State Divergence with Environment Design)：GSD 指标与近似的最大/最小界推导好，但 HRGAD 搜索假设「环境修改可枚举、代价已知」，且仅规划级抽象、无真机可执行性、未与 LLM 协作。
- Eurekaverse (arXiv:2411.01775)：LLM 用代码生成环境课程（UED），但面向「提高任务难度」，不针对「人类预期 vs 机器人实际状态」分歧。
- MAPL (arXiv:2606.25398)：LLM 偏好建模人类语义，但无环境设计环节。
- Mitigating Goal Misgeneralization (arXiv:2507.03068)：UED/最小最大遗憾缓解目标错位，但目标由环境自动定义、非人类语义指令。
- 结论：**「LLM 语义化环境修改生成 × GSD 形式验证」无人做**。

### 1.3 为什么是现在、为什么你的环境适合做
- 现在：LLM 生成可执行环境代码（Eurekaverse 证明）；GSD 界可计算；规划器（PDDL）成熟。
- 环境：**纯规划/轻量仿真**——PDDL 规划基准（论文 43 同款）+ Gym-MiniGrid 人机协作指令集；无需训练、无需 GPU 集群，个人电脑即可跑。

## 2. 研究目标与可验证假设（2-4 条）
1. **H1（LLM 生成接近形式最优）**：LLM 生成的候选修改包含形式化 HRGAD 最优解的命中率 ≥60%。→ 可观测：在小基准上枚举比对。
2. **H2（GSD 下降）**：经验证筛选后的修改集使实际 GSD 下降 ≥ 随机修改的 2 倍。→ 可观测：重规划后 GSD 对比。
3. **H3（代价更低）**：LLM+验证的修改代价 ≤ 枚举式 HRGAD 的 80%。→ 可观测：修改代价统计。
4. **H4（人类满意度）**：用户对「修改合理性」评分（1–5）≥4。→ 可观测：20 人小规模用户研究。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/轨迹流水线
- **PDDL 域**：复现论文 43 的规划基准（含人类预期状态标注 + 可枚举候选修改）；新增「语义描述」注释（物体/关系/目标的人类语言说明）。
- **MiniGrid 指令集**：自建 50 条人机协作指令（如「把箱子放到门前但别挡住路」），每条附「人类预期状态」标注（由 3 名标注者一致确定）。
- **LLM 输入包**：人类指令 + 环境状态快照（结构化描述）+ 机器人能力列表 + GSD 界计算说明。
- **数据量**：PDDL 20 个实例 × 5 种指令变体 = 100 条；MiniGrid 50 条。

### 3.2 方法设计（模块拆解、关键公式、超参数初值）
- **LLM 候选生成**（DeepSeek V4 Pro）：输出「候选修改列表」，每项含：修改类型（摆放/路标/感知提示）、目标对象、新状态、**代价估计（$或归一化）**、理由。
- **GSD 界验证**：对每个候选，用论文 43 的近似界公式计算修改后的 GSD 上界 `Ĝ(M) = GSD_bound(env+M)`；同时用规划器（Fast Downward 类）重规划验证实际可达状态，计算实测 GSD。
- **筛选与排序**：`score(M) = ΔGSD实测 / cost(M)`，按得分取前 K 个（K=3）给用户/评估；若 GSD 未降则拒绝候选。
- **闭环**：LLM 生成 → 验证 → 拒绝/采纳 → 反馈给 LLM 再生成（迭代 2 轮）。
- **超参数初值**：K=3、迭代 ≤2 轮、代价归一化 [0,1]、GSD 阈值 0.1。

### 3.3 训练流程（优化器/学习率/批次/并行；RL 训练资源估算）
- 无模型训练；全流程为「LLM API + PDDL 规划器 + GSD 计算」在 CPU 上运行。
- GPU 预算 ≈ 0（可用多余卡并行跑规划器消融）。
- 全流程 100+50 条任务 × 每任务 ~10 次 LLM 调用 × 2 轮 ≈ 3000 次调用，数小时完成。

### 3.4 评测流程
- 重规划后实测 GSD 下降、修改代价、命中形式最优解比例。
- 20 人用户研究：对采纳的修改方案评「合理性/安全性/与意图一致性」（Likert 1–5）。
- 与 HRGAD 精确/近似求解、随机修改、纯 LLM（无验证）对比。

## 4. 环境/数据集细节
- **PDDL 规划基准**：论文 43 所用域（规划级，无物理引擎）；Fast Downward 等 PDDL 规划器为开源软件。
- **Gym-MiniGrid**：开源（BSD），具身式网格世界，可执行物体摆放/路径修改。
- 无真机（与论文 43 一致，真机 GSD 实测留 follow-up）。

## 5. 基线复现
| 基线 | 出处 | 复现要点 |
|---|---|---|
| HRGAD 精确/近似求解 | (Humans and AI · 论文 43) | 枚举式搜索 |
| 随机修改 | 本项目 | 随机候选 + 验证 |
| 纯 LLM（无验证） | 本项目 | 直接采纳 LLM 候选 |
| Eurekaverse（方法参照） | arXiv:2411.01775 | LLM 环境生成范式 |
- **预期指标表（PDDL 100 条）**：随机修改 GSD 下降 15%、HRGAD 精确 100%（枚举上界）、纯 LLM 无验证 60%、**Ours 85–95% 命中形式最优（H1）+ 代价 0.75×**。
- **统一口径**：GSD 用论文 43 公式与归一化；代价单位统一。

## 6. 实验矩阵
- **A 主实验**：Ours vs 基线（PDDL + MiniGrid 双轨）。
- **B 生成消融**：LLM 生成 vs 枚举 vs 随机；DeepSeek vs Kimi vs 组合。
- **C 验证消融**：有无 GSD 验证筛选；阈值敏感性。
- **D 规模**：候选数量、迭代轮数 {1,2,3}。
- **E 指令复杂性**：单目标 vs 多条件 vs 含否定指令。

## 7. 评测协议
- **GSD 下降**：ΔGSD = GSD(env) − GSD(env+M)，归一化。
- **代价**：sum(cost(M))，归一化单位。
- **命中率**：LLM 输出候选集中是否含形式最优解（枚举基准）。
- **用户研究**：20 人 × 20 条任务，Likert 均值 ± std；组间 ANOVA。

## 8. 算力与资源计划
- GPU：≈0（可选：并行规划器消融用 1–2 卡数小时）。存储 <10GB。
- **API 成本**：3000 次调用，DeepSeek V4 Pro 约 $60–90、Kimi K2.6 约 $50；总 **≤$150**。

## 9. 里程碑与时间线（按周，单人）
- W1：复现论文 43 基准 + HRGAD 求解器。
- W2：LLM 候选生成 + GSD 验证闭环。
- W3–4：PDDL 主实验 + 消融。
- W5：MiniGrid 具身版 + 用户研究。
- W6：写作；投稿（AAMAS/ICRA）。

## 10. 风险与备选方案（表）
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| GSD 真机不可实测 | 确定 | 中 | 明确只报规划基准（论文 43 同限）；真机列为 future |
| LLM 生成与形式最优差距大 | 中 | 高 | 验证筛选兜底 + 迭代 2 轮；量化差距并如实报告 |
| 无训练内容、新颖度依赖组合 | 中 | 中 | 强化「LLM×形式验证」闭环论证；加入用户研究实证 |
| 用户研究偏差 | 低 | 低 | 双盲 + 3 名标注者多数 |
