# 实验设计书：XEmb-SkillLib —— 跨形态 VLA 技能库的 bandit 路由器

## 0. 摘要（3-5 句）
DiTEA（Intelligent Robotics · 论文 30）在单形态内用 MoE 抗遗忘，但机械臂/移动/双机械臂/人形等多形态数据共享时的负迁移与遗忘仍未解决；FedVLA（arXiv:2508.02190）用双门控 MoE 却面向联邦隐私。XEmb-SkillLib 用「形态×技能」二维专家网格 + 训练期 bandit 路由：专家沿形态维与技能维稀疏激活、共享专家兜底，结构上隔离跨形态冲突；把「当前 batch 用哪些专家子集」建模为 bandit 选择，按各专家在验证子集的增益动态分配负载。两阶段（SFT + 少量 GRPO，奖励含跨形态保留率）在 4×L40 上给出可复现的 cross-embodiment 训练配方，对比 OpenVLA 动辄 64+ GPU 的用量。

## 1. 研究背景与动机

### 1.1 问题定义
- 输入：多形态演示数据（Open X-Embodiment 子集：BridgeV2 机械臂、DROID 移动操作、RT 类遥操 + 仿真双形态）。
- 目标：训练单一 7B VLA，在 E 个形态 × T 个技能的任务网格上：①各单元成功率不塌陷；②学新形态/新技能时不遗忘旧形态（低跨形态遗忘率）。
- 约束：4×L40（192GB）内可复现；专家分配需自适应数据分布。

### 1.2 相关工作不足
- (Intelligent Robotics · 论文 30 · DiTEA...)：Action MoE + 指令门控在单形态（WidowX/Franka）内抗遗忘，但跨形态共享时无隔离机制，且只训 4+8 个任务。
- FedVLA (arXiv:2508.02190)：双门控 MoE + 联邦聚合，面向隐私而非多形态数据不平衡。
- GR00T N1 (arXiv:2503.14734)：双系统人形 VLA，异构数据训练，但依赖大规模算力、非 4×L40 可复现配方。
- OpenVLA (arXiv:2406.09246)：开源 7B，官方训练需 64+ GPU；LoRA 微调可消费级但单形态。
- Bandits Meet LLMs 综述（论文 77）：bandit 可管理 LLM 微调资源分配（提示/数据/模块），但从未用于 MoE 专家路由。
- 结论：**「跨形态 2D MoE 网格 + 训练期 bandit 路由 + 低算力配方」无先例**。

### 1.3 为什么是现在、为什么你的环境适合做
- 现在：Open X-Embodiment（arXiv:2310.08864）公开多形态数据；MoE 抗遗忘被 DiTEA 证明；bandit×LLM 路由思想（论文 77）成熟。
- 环境：**离线/仿真**——OXE 子集 + robosuite/RLBench 双形态仿真；不涉及真机，可在 4×L40 上分阶段推进。

## 2. 研究目标与可验证假设（2-4 条）
1. **H1（2D 专家网格抗遗忘）**：相比单维 MoE（DiTEA 式），「形态×技能」网格把跨形态遗忘率降低 ≥50%。→ 可观测：逐形态保留率矩阵。
2. **H2（bandit 路由优于均匀路由）**：训练期 bandit 分配专家负载，验证集增益高于均匀分配 ≥15%。→ 可观测：SFT 过程验证曲线。
3. **H3（多形态共存）**：多形态联合训练的每形态 SR 不低于「单形态单独训练」的 85%。→ 可观测：形态级 SR。
4. **H4（算力可复现）**：全部训练在 4×L40 内 12–18 GPU·天完成。→ 可观测：资源日志。

## 3. 总体方法设计（详细到可复现）

### 3.1 数据/轨迹流水线
- **数据选择**：Open X-Embodiment 中 BridgeV2（WidowX 机械臂）、DROID（移动操作）、RT 类（双机械臂遥操）各抽 5–10K 条；仿真补充 robosuite 2 形态（单臂/双臂）× 3 技能 各 2K 条。
- **指令统一（API）**：DeepSeek V4 Flash 离线把各形态同一任务的语言描述改写为统一指令模板（「在 <形态> 上 <动作> <目标>」），消除形态噪声。
- **任务相似度图（API）**：Kimi K2.6 对任务文本构建相似度图，作为 bandit 路由先验（哪些专家可共享）。
- **数据量**：总计 ~24K 条；按形态×技能划分为 12 单元，每单元 ≥1K。

### 3.2 方法设计（模块拆解、关键公式、超参数初值）
- **形态×技能专家网格**：专家索引 (e_emb ∈ {机械臂, 移动, 双臂, 人形}, e_skill ∈ {pick, place, push, reorient, nav})，稀疏激活 top-2（每维各选 1）+ 1 个共享专家兜底；每专家为同构 DiT 动作 MLP。
- **训练期 bandit 路由**：
  - 臂 = (e_emb, e_skill) 组合（16 个候选子集）；上下文 = batch 的形态-技能分布向量。
  - 奖励 = 该专家子集在验证子集上的 `ΔSR`（每 500 步测一次）。
  - UCB 分配：`分配权重 = softmax(μ̂_e + c·√(ln N/n_e))`，c=0.3。
  - 每 batch 按权重采样专家子集；与 DiTEA 的负载均衡损失共用。
- **跨形态保留奖励（GRPO 阶段）**：`r = Σ_形态 SR_e + λ·retention_e`，retention = 新旧数据混合评测时的旧形态 SR。
- **负载均衡损失**：按动作序列长度归一化（DiTEA 式改进），λ_aux=0.01。
- **超参数初值**：

| 超参 | 初值 |
|---|---|
| 底座 | 7B VLA（视觉 DINOv2+SigLIP 冻结，语言 7B） |
| 专家网格 | 4 形态 × 5 技能 + 共享专家 |
| 稀疏激活 | top-2 + 共享 |
| SFT 步数 | 30–60K |
| GRPO 步数 | 3–6K |
| lr | 2e-5（SFT）/ 1e-5（GRPO） |
| bandit c | 0.3 |
| λ_aux / λ_retention | 0.01 / 0.5 |

### 3.3 训练流程（优化器/学习率/批次/并行；RL 训练资源估算）
- **SFT**：FSDP（7B 全参 + MoE 头），全局 batch 128（梯度累积），30–60K 步 ≈ 6–10 GPU·天。
- **GRPO**：每步 64 rollout，3–6K 步 ≈ 5–8 GPU·天；奖励含跨形态保留。
- 4×L40 全程；监控专家利用率（bandit 负载均衡）。
- 总 **12–18 GPU·天**（12 个 idea 中最重，仍在 4×L40 数周内）。
- 种子：主实验 3 seed。

### 3.4 评测流程
- 逐形态逐任务 SR（SIMPLER 机械臂口径 + robosuite 双形态 + OXE 保留子集）。
- 跨形态遗忘率：按「先训形态 A→加形态 B」时序测 A 回退。
- OOD 任务：未训练任务 zero-shot 专家路由。

## 4. 环境/数据集细节
- **Open X-Embodiment**（arXiv:2310.08864）：开源多形态数据集（GCS/网页），子集 BridgeV2/DROID/RT；许可遵循各数据源。
- **robosuite**（arXiv:2009.12293）：双形态仿真；**RLBench**：社区基准（软件）。
- **SIMPLER**：WidowX 仿真评测（软件）。
- 无真机；全部离线/仿真。

## 5. 基线复现
| 基线 | 出处 | 复现要点 |
|---|---|---|
| OpenVLA（多形态微调） | arXiv:2406.09246 | LoRA 全数据 |
| DiTEA（复现） | DOI:10.1609/aaai.v40i22.38902 | 单维 MoE |
| GR00T N1（公开子集复现） | arXiv:2503.14734 | 双系统 VLA |
| FedVLA（复现或方法参照） | arXiv:2508.02190 | 双门控 MoE |
| 均匀路由 MoE | 本项目 | 无 bandit |
- **预期指标表（形态级平均 SR）**：单形态单独 60%、多形态联合（均匀）40%、DiTEA 式 45%、**Ours 52–58%**；跨形态遗忘率 Ours ≤5% vs 均匀路由 ≥20%。
- **统一口径**：评测用固定 12 单元 × 50 episode；保留率用同一模型多次评估均值。

## 6. 实验矩阵
- **A 主实验**：Ours vs 基线。
- **B 路由消融**：bandit vs 均匀 vs 静态先验（Kimi 图）。
- **C 网格消融**：形态×技能 vs 单维 vs 全共享；共享专家比例 {10%,20%,30%}。
- **D 数据消融**：形态不平衡度 {均衡, 3:1, 10:1}。
- **E 遗忘**：先 A 后 B 的遗忘时序；增量加入第 4 形态。
- **F OOD**：未训练技能 zero-shot 路由成功率。

## 7. 评测协议
- **SR**：各单元环境回调二值成功；mean±std（3 seed）。
- **跨形态遗忘率**：retention 曲线（新形态加入前后旧形态 SR 回退百分比）。
- **专家利用率**：bandit 分配的负载均衡偏差（DiTEA 式）。
- **显著性**：配对 t-test（α=0.05，Bonferroni 校正）。

## 8. 算力与资源计划
- GPU：SFT 6–10 + GRPO 5–8 + 消融 4–6 ≈ **15–24 GPU·天**；4×L40 并行，3–4 周窗口。
- 存储：OXE 子集 + 检查点 ≈ 600GB（下载/清洗为最大工程量）。
- **API 成本**：指令统一 + 相似度图 ≈ 3000 次调用；DeepSeek V4 Flash 约 $20，Kimi K2.6 约 $20；总 **≤$60**（几乎纯训练成本）。

## 9. 里程碑与时间线（按周，单人+4 卡）
- W1–2：OXE 子集下载/清洗 + robosuite 双形态仿真数据。
- W3–4：专家网格 + FSDP 训练框架；bandit 路由实现。
- W5–8：SFT 主实验（30–60K 步，分阶段）；监控利用率。
- W9–10：GRPO 跨形态保留阶段。
- W11：消融 + OOD。
- W12–13：写作；投稿（ICRA/RSS）。

## 10. 风险与备选方案（表）
| 风险 | 概率 | 影响 | 缓解/备选 |
|---|---|---|---|
| 4×L40 上跨形态数据量不足致专家坍缩 | 中 | 高 | 负载均衡损失 + bandit 探索惩罚；减少专家数或先 2 形态 |
| OXE 下载/清洗工作量大 | 高 | 中 | 先只用 2–3 个公开子集（BridgeV2/DROID）；脚本化清洗 |
| 专家坍缩（大量样本路由到共享专家） | 中 | 中 | bandit 探索项 + 每专家最小分配保证 |
| GRPO 阶段不收敛 | 中 | 中 | 只训动作头 + 少量步数；奖励含保留项稳定化 |
