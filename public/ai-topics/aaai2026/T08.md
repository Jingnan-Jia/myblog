# T08 检索增强RAG与知识管理 调研报告

> 主题范围：文本图RAG、长上下文检索、KV级检索、多向量检索、文档RAG评测、知识编辑、数据集精炼、机器遗忘、LLM求解器选择。
> 共 11 篇 AAAI 2026 收藏论文。本报告按子方向分组梳理，精读 5 篇代表论文，检索并核验 2023–2026 外部前沿文献，生成 12 个可执行的实验方案（Idea）。

## 一、主题概览与研究热点

### 1.2 三条主线趋势（2023–2026）

**趋势一：检索粒度从"文档/段落"向"更细语义单元"下沉。**
从段落级（LongRAG, arXiv:2406.15319 反其道而行之把单元做大）到 token 级（ColBERT, arXiv:2004.12832；XTR, arXiv:2304.01982；RetroLM 的 KV 页；RegionRAG 的视觉区域），核心争论是"检索单元多大才能兼顾召回与去噪"。本主题四篇论文（T-Retriever、HTSIR、RetroLM、RegionRAG、Token Importance）全部在"粒度"这一轴线上做文章，说明粒度选择是当前 RAG 最重要的设计自由度。

**趋势二：检索对象从"文本块"向"模型记忆/证据状态"扩展。**
RetroLM 把检索单元变成 KV 缓存页（直接操纵注意力计算）；ALEX 把知识编辑变成"分层语义记忆中的检索"；RALM 论文关注"检索到≠模型用了"的校准问题。这意味着 RAG 正在与知识编辑、不确定性估计、KV 缓存工程三条线融合，形成"检索增强 = 对模型知识的细粒度、可更新、可验证的控制"这一更宽泛叙事。

**趋势三：评测与数据质量从"附属"上升为"一等公民"。**
Double-Bench、RefineLab、RALM 校准实证、OptiHive 的验证测试组件，都把"如何评测、用什么数据评测"作为研究主体。外部趋势同样明显：RGB（arXiv:2309.01431）、RAGAS（arXiv:2309.15217）、OmniDocBench（arXiv:2412.07626，CVPR 2025）、以及 SIGIR 2026 的"denoising-first"视角论文（arXiv:2605.00505）都指向：RAG 系统的瓶颈已从"能不能检索到"转移到"检索到的内容模型能不能可靠地用起来、验证起来"。

### 1.3 本主题的空白地图（为第六节 Idea 提供动机锚点）

1. **"检索到"与"用上"之间的归因空白**：评测大多报端到端分数，无法回答"答案错了是检索错、还是生成没依赖证据、还是参数化知识盖过证据"。
2. **知识编辑与检索/记忆架构的割裂**：参数编辑（改权重）与外部记忆编辑（改存储）各自为战，KV 级可编辑记忆几乎空白。
3. **图/树索引的动态性空白**：T-Retriever、GraphRAG、HippoRAG 的索引都是静态一次性构建，数据更新/删除时缺乏增量维护与"图级知识编辑"。
4. **多向量检索中 token 重要性的静态化**：当前权重（IDF/固定微调）不随查询语义变化，检索侧与生成侧目标未联合优化。
5. **RALM 拒绝/校准与证据充分性脱节**：过度拒绝、拒绝与校准不对齐，缺"证据充分性"这一显式中间量。
6. **数据集/语料精炼没有面向检索-生成联合目标**。
7. **LLM 优化求解器仍依赖迭代修复回路，无检索记忆复用**。

## 二、收藏论文分类梳理（按子方向分组）

### 2.1 结构化/图 RAG
**T-Retriever（DMKM III · 论文 9）**
- 问题：图 RAG 分层信息管理两大缺陷——①逐层固定压缩配额破坏局部图结构；②只重拓扑忽略语义。
- 方案：把属性图检索形式化为"语义与结构引导的编码树"检索。创新点：(1) Adaptive Compression Encoding——用全局优化取代人工压缩配额；(2) S²-Entropy——联合优化结构内聚与语义一致的层次划分。
- 定位：图 RAG 从"图结构优先"走向"结构与语义联合"，是 GraphRAG（arXiv:2404.16130）与 RAPTOR（arXiv:2401.18059）树思想的结合体。

### 2.2 长上下文检索
**HTSIR（NLP I · 论文 41）**
- 问题：常规 RAG 基于孤立片段回答，缺乏文档内跨段整合，损害整篇连贯理解任务。
- 方案：受"人脑渐进整合"启发，检索前先对连续文本做分层两阶段摘要，构建多粒度摘要检索树；检索后由 query 相关重排器处理；再加 Refinement 模块让 LLM 反思修正。在 NarrativeQA、QASPER、QuALITY、QMSum 上以 GPT-4o mini 为生成器取得 SOTA。
- 定位：文档级/树形摘要检索（RAPTOR 的"查询感知"变体），偏系统流水线。

**RetroLM（NLP III · 论文 67）**
- 问题：传统 RAG 在长上下文处理上落后于其他高效方法，根因是"检索不准 + 上下文碎片化"。
- 方案：提出 KV 级检索增强——把 LLM 的 KV 缓存切成连续页，基于检索到的 KV 页做编码与解码；配套开发专用页检索器 + 无监督后训练（arXiv:2502.11444）。
- 定位：把"检索"下沉到注意力缓存层，直接对抗检索误差与碎片化，是本主题最有架构突破性的一篇。

### 2.3 多向量检索
**Incorporating Token Importance in Multi-Vector Retrieval（NLP IV · 论文 22）**
- 问题：ColBERT 的 Chamfer 式距离对所有 query token 等权求和，表达力有限。
- 方案：把距离改为 query token 贡献的加权和，权重反映 token 重要性；只训练 token 权重、多向量表示冻结。IDF 权重零样本在 BEIR 上 Recall@10 平均 +1.28%，少样本微调 +3.66%（arXiv:2511.16106）。
- 定位：轻量、可复现的 late interaction 增强，与 XTR（arXiv:2304.01982）形成对照（XTR 改 token 检索目标，本文改 token 聚合权重）。

### 2.4 视觉文档 RAG
**RegionRAG（CV V · 论文 85）**
- 问题：多模态 RAG 以整篇文档为检索单元，注入大量无关视觉内容。
- 方案：把检索范式从文档级变为"区域级"。训练时用有标签+无标签混合监督定位相关 patch；推理时动态把显著 patch 聚成完整语义区域。六基准平均 R@1 +10.02%、QA 准确率 +3.56%、视觉 token 用 71.42%（arXiv:2510.27261）。
- 定位：把"检索粒度"问题推广到多模态；与 ColPali（arXiv:2407.01449，页级多向量）形成粒度对照。

### 2.5 文档 RAG 评测
**Double-Bench（NLP IV · 论文 30）**
- 问题：现有文档 RAG 基准只看组件片段、用不完整 ground truth 的合成数据，无法反映真实瓶颈。
- 方案：3,276 文档（72,880 页）+ 5,168 单跳/多跳查询，6 语言 4 类文档；证据页级人工核实；动态更新防污染（arXiv:2508.03644）。实验发现文本与视觉嵌入差距在缩小、文档 RAG 框架普遍"无证据也作答"的过度自信。
- 定位：文档 RAG 评测从"页级合成"走向"证据页级、多语言、动态更新"，与 OmniDocBench（arXiv:2412.07626）互补（后者偏解析、前者偏 RAG 链路）。

### 2.6 知识编辑
**ALEX（NLP IV · 论文 105）**
- 问题：知识编辑在多跳问题下面临可扩展性与检索效率挑战。
- 方案：层次化记忆架构把编辑按语义聚簇，检索复杂度从 O(N) 降到 O(K+N/C)；集成推理查询合成（IQS）弥合查询-事实语义鸿沟；动态证据裁决（DEA）做两阶段检索。MQUAKE 上显著提升 MultiHop-ACC 与 HopWise-ACC，搜索空间减 80%+（arXiv:2511.14018）。
- 定位：外部记忆式知识编辑（MQuAKE 的 MeLLo 思路的工程化升级），用"分层+裁决"解决扩展性问题。

### 2.7 机器遗忘
**CEP（ML III · 论文 33）**
- 问题：学习型基数估计（CE）的多表关系数据删除面临属性级敏感、表间传播、域消失三类挑战。
- 方案：Cardinality Estimation Pruning——分布敏感性剪枝（半连接删除结果算敏感度）+ 域剪枝（移除被删空的域）。在 NeuroCard/FACE + IMDb/TPC-H 上最高删除率下 Q-error 最低，常优于全量重训，开销仅为微调时间的 0.3%–2.5%（arXiv:2511.20293）。
- 定位：把机器遗忘从通用模型（综述 arXiv:2209.02299）落到数据密集型 DB 系统，是"结构化数据上的遗忘"代表。

### 2.8 数据集精炼
**RefineLab（NLP III · 论文 68）**
- 问题：专家 QA 数据集也有覆盖/难度/事实性缺口，生成模型造的数据更糟。
- 方案：首个"LLM 驱动、token 预算约束"的 QA 数据精炼框架——把精炼建模为受约束优化：分配模块决定对每个样本施加哪些精炼操作，最大化质量、不超预算。在覆盖度、难度对齐、事实保真、干扰项质量四维持续逼近专家集（arXiv:2511.06530）。
- 定位：数据质量从"人工造"走向"自动精炼"，核心是 budget 约束下的策略分配——与 RL/组合优化同构。

### 2.9 LLM 求解器选择
**OptiHive（NLP I · 论文 15）**
- 问题：LLM 求解器不可靠，常依赖高延迟的迭代修复回路。
- 方案：单次批量生成多样化组件（求解器、问题实例、验证测试），过滤错误组件保证可解释；用统计模型推断组件真实性能，实现不确定性量化与求解器选择。多车场 VRP 最复杂问题上最优率从 5% 提到 92%（arXiv:2508.02503）。
- 定位：LLM 编程求解（LLM4CO）的可靠性工程化，核心是"一次性多样化生成 + 统计选择"而非迭代修复。

### 2.10 RALM 校准/拒绝
**Do RALMs Know When They Don't Know?（NLP VI · 论文 77）**
- 问题：检索增强模型（RALM）与拒绝后训练各自研究多，但没人评估 RALM 的拒绝能力。
- 发现：①检索全不相关时 RALM 仍倾向拒绝本可答对的问题（过度拒绝）；②上下文微调可缓解过度拒绝，但改进拒绝不必然改进校准/准确率；③拒绝感知 RALM + 不确定性弃权组合可提升整体答案质量（arXiv:2509.01476，AAAI 2026 camera-ready）。
- 定位：把"校准/拒绝"引入 RALM 评估，属可信 RAG（trustworthy RAG）方向，呼应 UQ 综述（arXiv:2412.05563）。

## 三、代表性论文精读（5 篇）

> 精读依据：五篇均检索到官方 arXiv 记录（含完整摘要、作者、版本历史），结合其引用的上游工作（ColBERT/XTR、GraphRAG/HippoRAG、MeLLo/MQuAKE、LongBench/RULER 等）做交叉分析。以下"方法细节"取自摘要级信息与同路线工作推断，非逐行复读全文，故"不足"部分以结构层面为主。

### 3.1 RetroLM: Retrieval-Augmented KVs for Long-Context Processing（NLP III · 论文 67，arXiv:2502.11444）

**背景与定位**：长上下文处理的效率路线大致有：稀疏注意力（StreamingLLM, arXiv:2309.17453；SnapKV, arXiv:2404.14469）、KV 量化（KIVI, arXiv:2402.02750；ThinK, arXiv:2407.21018）、KV 检索稀疏（Quest, arXiv:2406.10774；RetrievalAttention, arXiv:2409.10516）。RetroLM 独树一帜：不是"稀疏/压缩 KV"，而是**把"RAG 的检索单元"从文本块换成 KV 页**——检索到哪页，注意力就只看哪页，边检索边解码，省掉重复上下文编码。

**核心创新点**：
1. **KV 页级检索增强框架**：KV 缓存按连续页划分，检索+编码+解码耦合在页上，天然兼容碎片化上下文，且对检索不准更鲁棒。
2. **专用页检索器 + 无监督后训练**：页检索器学"哪页是关键证据页"；无监督后训练让模型学会利用"不完整但相关"的检索页，缓解检索误差累积。
3. **成本结构优势**：相比传统 RAG 每条查询重编码整段上下文，本方法只解码被检索页，重复编码开销被摊薄。

**不足/可改进**：
- 检索器与生成器是"先训检索、再后训练生成"的两阶段松耦合，缺少端到端（检索页→最终答案质量）的联合目标；监督信号（若从 LongBench 抽取正例页）依赖启发式，可迁移性存疑。
- 页粒度是固定的（工程上连续 N token），而"证据边界"是语义的——与 RegionRAG/HTSIR 的粒度自适应形成张力：KV 页粒度应与查询语义对齐，本文未做动态粒度。
- 未讨论**知识与 KV 的更新**：当文档集合变化（增/删/改）时，KV 页缓存如何失效/重算没有机制——直接与知识编辑问题接轨（见 3.4）。
- 评测在 LongBench/InfiniteBench/RULER 的"整篇理解"任务上强，但缺少"检索粒度/证据使用"的归因指标（见 3.3）。

**心得**：RetroLM 证明"检索增强"可以发生在注意力内部，这打开了一条融合 RAG、KV 缓存工程、知识编辑三条线的中间地带。它的最大价值是给"KV 级可编辑记忆"（本报告 Idea 3）提供了现成的工程骨架。

### 3.2 T-Retriever: Tree-based Hierarchical Retrieval for Textual Graphs（DMKM III · 论文 9，arXiv:2601.04945）

**背景与定位**：图 RAG 主流两派：全文图（GraphRAG, arXiv:2404.16130——LLM 抽取实体关系建图，索引贵、更新贵）与图记忆（HippoRAG, arXiv:2405.14831——PPR 图游走）。二者都假设图是"已经建好"的静态对象。T-Retriever 把关注点移到**图自身的分层组织**：属性图 = 带文本的节点/边，检索应利用其自然层次（聚类）而非强加压缩配额。

**核心创新点**：
1. **自适应压缩编码（Adaptive Compression Encoding）**：把"逐层压缩配额"换成全局优化——保留图的自然层次，避免逐层暴力聚合破坏局部结构。
2. **语义-结构熵 S²-Entropy**：层次划分的联合准则——既要结构内聚（图割质量）又要语义一致（簇内文本相似），把"拓扑优先"与"语义优先"两种旧做法统一进一个熵目标。
3. **树形检索管线**：把属性图检索改写为编码树上的检索，天然支持粗→精（先簇后叶）的多跳图推理。

**不足/可改进**：
- 编码树构建成本未给出端到端更新方案：若图数据增量流入，S²-Entropy 划分是否需要全量重算？没有"局部重编码"机制——这与图级知识编辑、机器遗忘直接相关（本报告 Idea 4）。
- 语义一致性依赖文本嵌入质量，对多语言/多模态图（如文档引文网络）的泛化未讨论。
- 与 LLM 的交互仍是"检索到子图→拼 prompt"，未把树结构反馈进生成（如按树路径引导推理），推理可解释性停留在"检索路径"层面。
- 未对标 HippoRAG 的 PPR 动态游走，S²-Entropy 是静态离线划分，对"查询相关的局部结构"不敏感。

**心得**：T-Retriever 的贡献本质是"**把图聚类的准则做成可微可解释的熵目标**"，这是图 RAG 从"启发式索引"走向"优化式索引"的一步。其最大软肋（静态树）恰是本主题知识编辑/遗忘方向的缺口所在。

### 3.3 Double-Bench: Assessing Document RAG（NLP IV · 论文 30，arXiv:2508.03644）

**背景与定位**：文档 RAG 评测谱系：通用端到端（RGB, arXiv:2309.01431；RAGAS, arXiv:2309.15217——自动合成评测）、长上下文（LongBench, arXiv:2308.14508；∞Bench, arXiv:2402.13718；RULER, arXiv:2404.06654）、多模态文档（OmniDocBench, arXiv:2412.07626 偏解析；ViDoRe/ColPali, arXiv:2407.01449 偏检索）。Double-Bench 的差异化：**只评 RAG 链路**（文档理解→检索→生成），不评文档解析；证据到页、多语言、动态更新防污染。

**核心创新点**：
1. **组件级细粒度评估**：对嵌入模型（9 个）、MLLM（4 个）、端到端框架（4 个）分别打分，能定位瓶颈在"检索"还是"生成"。
2. **证据页级人工核实的 ground truth**：5,168 条查询全部锚定在穷尽扫描的证据页上，比合成数据可信得多。
3. **动态更新机制**：按年回流新语料防数据污染——回应了 RAG 基准被 LLM 训练语料污染的普遍担忧。
4. **两个反直觉发现**：文本/视觉嵌入差距缩小（视觉嵌入变强）、文档 RAG 框架普遍"无证据也自信作答"（over-confidence dilemma）。

**不足/可改进**：
- 证据粒度止于"页"，而真实错误常发生在页内区域（RegionRAG 的区域级洞察）与跨页证据链（多跳）——缺"证据在答案中被实际使用程度"的归因指标。
- 对"过度自信"只做了现象描述，没有给出可操作的修正机制（见 Idea 7：证据充分性拒绝）。
- 未覆盖"检索到错误证据/矛盾证据"场景：5,168 查询都对应真实证据页，缺"无关/矛盾证据干扰"的诊断子集，无法测 RALM 的鲁棒性与拒绝（对照 NLP VI · 论文 77 的发现）。

**心得**：Double-Bench 的价值一半在数据、一半在"组件级归因"的评测哲学。但它停在了"哪部分错"（组件定位），没走到"为什么错"（证据使用/模型内部状态）。下一步评测基准应包含**反事实证据扰动**与**证据充分性标注**（Idea 1、Idea 6、Idea 7 均由此出发）。

### 3.4 ALEX: A Light Editing-knowledge Extractor（NLP IV · 论文 105，arXiv:2511.14018）

**背景与定位**：多跳知识编辑的谱系：参数编辑（MEMIT/ROME 类，改权重——本报告未核验其 ID 故不列）、外部记忆（MQuAKE 的 MeLLo，arXiv:2305.14795——线性存储所有编辑）、图记忆（GMeLLo, arXiv:2408.15903；CLEVER-CKE, arXiv:2407.10275）、推理链对齐（CaKE, arXiv:2503.16356；Reason-KE, arXiv:2509.01468）。ALEX 走"外部记忆 + 层次化 + 两阶段裁决"路线。

**核心创新点**：
1. **层次化记忆架构**：把编辑按语义聚类（cluster），检索复杂度从 O(N) 降到 O(K + N/C)（K=簇级检索, N/C=簇内检索），直接回应"编辑规模增大后外部记忆检索退化"的痛点。
2. **推理查询合成（IQS）**：为多跳问题合成"可检索中间事实"，弥合问题与事实之间的语义鸿沟——这是把多跳推理拆成子检索的标准动作（对照 MQUAKE 的迭代式 MeLLo）。
3. **动态证据裁决（DEA）**：两阶段检索（粗候选→细验证），抑制噪声证据进入推理。

**不足/可改进**：
- 聚簇是**静态**的：编辑流到达时如何增量归簇、簇分裂合并没有机制；编辑之间的**冲突**（同实体两条新事实）没有显式仲裁。
- O(K+N/C) 的复杂度分析是理想化假设（簇均匀、C 固定），对长尾/异质编辑分布会退化。
- 只测 MQUAKE 系列，未测**编辑对无关知识的污染**（编辑后模型对未涉及问题是否退化）与**时间演化**（旧编辑被新编辑覆盖）。
- 检索是文本级（query→fact），与 RetroLM 的 KV 级、与参数级编辑三者没有打通——"一个编辑到底改了什么"在三种表示下语义不一致。

**心得**：ALEX 是"外部记忆式知识编辑"的当前最优工程形态，但它的静态聚簇假设与检索-推理脱节，正是把**图结构（T-Retriever 的层次）、KV 表示（RetroLM）、编辑一致性验证（LLM-as-judge）**三者融合起来做"可编辑动态记忆"的空间（Idea 3、Idea 8）。

### 3.5 Incorporating Token Importance in Multi-Vector Retrieval（NLP IV · 论文 22，arXiv:2511.16106）

**背景与定位**：late interaction 多向量检索谱系：ColBERT（arXiv:2004.12832，Chamfer 距离）→ ColBERTv2（arXiv:2112.01488，残差压缩）→ XTR（arXiv:2304.01982，token 检索目标 + 评分近似）→ PLAID/WARP 引擎（arXiv:2501.17788）。本文在 ColBERT 式 Chamfer 距离上叠加"query token 权重"，属于**改动最小、可解释性最强的增强**。

**核心创新点**：
1. **加权 Chamfer 距离**：把"对每个 query token 取最近文档 token 后求和"改为加权和，权重=token 重要性。
2. **冻结多向量表示、只训权重**：部署成本极低——索引/向量库不变，只换打分函数；零样本可用 IDF，少样本微调即收敛。
3. **实证干净**：BEIR 上 Recall@10 零样本 +1.28%、少样本 +3.66%，直接可复现。

**不足/可改进**：
- 权重是**静态**的（IDF 或固定模型输出），不随查询语义变化——"of/a"的停用词在"介词敏感的查询"里重要性应翻转，静态权重做不到。
- 打分函数改了但**训练目标仍是检索召回**，没有与生成端（RAG 最终答案质量）联合优化；检索最优 ≠ RAG 最优。
- 未评估**文档 token 侧**的重要性（只加 query 侧），也未与 XTR 的 token 检索目标组合（两者正交，组合收益未知）。
- 只改打分、不改索引，意味着对"查询词向量本身需要重写/扩展"（长查询、多跳查询）没有帮助。

**心得**：这篇的价值是"最小侵入、可插拔"——非常适合作为 RAG 系统的即插即用组件。它的静态权重假设 + 检索生成目标脱节，直接给出 Idea 2（查询感知动态 token 重要性 + 检索-生成联合目标）。

## 五、外部前沿文献综述（含真实引用）

> 以下全部文献均通过 arXiv API/检索页核验过 ID。按子方向综述，作为第六节 Idea 的 novelty 论证背景。

### 5.1 RAG 总体与评测
- 综述基准：Gao et al., "Retrieval-Augmented Generation for Large Language Models: A Survey"（arXiv:2312.10997）——RAG 三阶段范式（预检索/检索/生成）与演进路线的标准框架；Lewis et al. 原始 RAG 论文（arXiv:2005.11401）。
- 自适应/可验证 RAG：Self-RAG（arXiv:2310.11511，自反思决定何时检索）、Corrective RAG（arXiv:2401.15884，检索质量纠偏）、Adaptive-RAG（arXiv:2403.14403，按问题复杂度路由）。三者共同点是"检索要不要/检索完怎么用"交给模型自己判断——但都**没有显式建模证据充分性**，这是 Idea 7 的动机。
- 评测：RGB（arXiv:2309.01431，端到端 RAG 基准）、RAGAS（arXiv:2309.15217，自动生成合成评测）、SIGIR 2026 视角论文 "LLM-Oriented Information Retrieval: A Denoising-First Perspective"（arXiv:2605.00505）——明确提出"最大化上下文窗口内的可用证据密度与可验证性"是新瓶颈，为 Idea 1（归因/证据使用评测）与 Idea 5（语料精炼）提供了理论背书。
- 长上下文基准：LongBench（arXiv:2308.14508）、∞Bench（arXiv:2402.13718）、RULER（arXiv:2404.06654）——RetroLM/HTSIR 的评测场。

### 5.2 图 RAG 与树形索引
- GraphRAG（arXiv:2404.16130，Microsoft）——全局查询聚焦摘要，索引昂贵；HippoRAG（arXiv:2405.14831）——PPR 图游走 + LLM 记忆，静态图索引；RAPTOR（arXiv:2401.18059）——递归抽象处理构建摘要树，树静态。
- 安全性警示：知识投毒攻击（arXiv:2508.04276，仅改几个词就让 GraphRAG 的 QA 精度从 95% 崩到 50%）——说明图 RAG 的"更新/验证"是待补的硬缺口，支撑 Idea 4。
- 2026 最新：LEDGER（arXiv:2606.28379，ACL 2026）——依赖感知图检索做长文档局部编辑，证明"图索引 + 局部更新"已是活跃前沿，但面向 agent 编辑而非知识编辑。

### 5.3 长上下文与 KV 缓存工程
- KV 量化/剪枝：KIVI（arXiv:2402.02750, ICML 2024）、ThinK（arXiv:2407.21018, ICLR 2025 Spotlight）、StreamingLLM（arXiv:2309.17453，attention sink）、SnapKV（arXiv:2404.14469）、PagedAttention（arXiv:2309.06180，页式 KV 内存——RetroLM 的"页"的工程基础）。
- KV 检索稀疏：Quest（arXiv:2406.10774, ICML 2024，query 感知页选择）、RetrievalAttention（arXiv:2409.10516，ANNS 检索 KV）——与 RetroLM 同属"把检索引入注意力"前沿，但 Quest 偏稀疏计算、RetroLM 偏 RAG 语义。
- KV 缓存 + RAG 工程：FusionRAG（arXiv:2601.12904，块级 KV 复用 + 重算 <15% token 保质量）、KV 缓存复用实验研究（arXiv:2603.20218）——说明"检索块 × KV 复用"是系统方向热点，为 Idea 3（KV 级可编辑记忆）提供工程佐证。
- 综述/评估：KV 缓存优化基准（arXiv:2607.05399，指出压缩率本身不能预测端到端性能）——支持"按工作负载选 KV 机制"的结论，与 Idea 3 的"按查询选页"呼应。

### 5.4 多向量与 token 级检索
- ColBERT（arXiv:2004.12832）→ ColBERTv2（arXiv:2112.01488）→ XTR（arXiv:2304.01982，NeurIPS 2023，token 检索目标）→ WARP 引擎（arXiv:2501.17788，SIGIR 2025）。
- 多模态扩展：ColPali（arXiv:2407.01449, ICLR 2025，视觉文档页级多向量）、HPC-ColPali（arXiv:2506.21601，patch 剪枝+量化）、"Lost in OCR Translation?"（arXiv:2505.05666，视觉 vs OCR RAG 系统对比）——为 Idea 6（区域级视觉检索评测）与 Idea 2 提供对照。

### 5.5 知识编辑与机器遗忘
- 知识编辑综述（arXiv:2401.01286）；多跳编辑基准 MQuAKE（arXiv:2305.14795, EMNLP 2023）。
- 2024–2025 方法：GMeLLo（arXiv:2408.15903，KG 记忆 + LLM 查询）、CLEVER-CKE（arXiv:2407.10275，跨语言检索-验证-生成）、CaKE（arXiv:2503.16356, EMNLP 2025，电路感知编辑，MQuAKE +20%）、Reason-KE（arXiv:2509.01468, EMNLP 2025 Findings，推理链对齐，抗干扰）——外部记忆式/推理链式编辑已成为主流，但"KV 级/图级可编辑记忆"仍空白（Idea 3、Idea 8）。
- 机器遗忘综述（arXiv:2209.02299）；CEP（本主题 ML III · 论文 33）是 DB 场景代表。跨综述未见"图/树索引 RAG 的知识遗忘"工作（Idea 4 佐证）。

### 5.6 不确定性、拒绝与可信 RAG
- UQ 综述：Shorinwa et al., "A Survey on Uncertainty Quantification of LLMs"（arXiv:2412.05563）；2026 ACL 综述"From Passive Metric to Active Signal"（arXiv:2601.15690）提出不确定性从诊断指标走向主动控制信号——与 Idea 7 的"证据充分性作为控制信号"完全同构。
- 本主题 RALM 论文（NLP VI · 论文 77，arXiv:2509.01476）是拒绝-校准-检索交叉的直接实证。

### 5.7 数据集/语料精炼
- 提示压缩：LLMLingua（arXiv:2310.05736，压缩 prompt 加速推理）。
- 2026 文档解析评测迭代：OmniDocBench（arXiv:2412.07626, CVPR 2025）→ PureDocBench（arXiv:2605.07492，指出 OmniDocBench 标注错误 12.08%、排名失真）——"评测数据本身要被评测"的观点与 RefineLab（NLP III · 论文 68）同频，支撑 Idea 5。

### 5.8 LLM 求解器与上下文工程

## 六、研究 Idea（12 个，完整实验方案）

> 通用约束：硬件 4 × NVIDIA L40（48GB，合计 192GB）；API：DeepSeek V4 Flash/Pro、Kimi K2.6/K3（K3 慎用）。全参微调建议 7B–13B（FSDP/DeepSpeed），LoRA/QLoRA 可到 30B–70B；检索/重排训练可并行跑在其余卡上。预算以"数十 GPU·天"为上限。

### Idea 1：检索贡献归因诊断框架（AttribBench）
- **中/英标题**：检索贡献归因与长上下文 RAG 错误诊断基准 / AttribBench: Retrieval-Contribution Attribution and Error Diagnosis for Long-Context RAG
- **一句话简介**：用反事实证据扰动 + LLM-as-judge，把 RAG 端到端错误归因到"检索缺失/证据没用/参数知识盖过证据"三类。
- **动机与现有不足**：RGB（arXiv:2309.01431）、RAGAS（arXiv:2309.15217）、Double-Bench（NLP IV · 论文 30）都只给组件级或端到端分数；RALM 论文（NLP VI · 论文 77）虽发现"检索全不相关时仍过度拒绝"，但没有一套指标把"证据是否真的被模型用上"测出来。
- **核心创新点**：(1) 三类归因标签的自动构造流水线（正证据/弱证据/矛盾证据三类反事实扰动）；(2) "证据利用率"（Evidence Utilization Rate）与"参数知识凌驾度"两个新指标；(3) 与生成可追溯性（citation）结合，形成可直接使用的诊断工具。
- **方法概要**：①选 3–5 个长上下文数据集，用 DeepSeek 合成多跳问题并人工抽检 200 条；②每个问题构造 4 个实验臂：全文、正确证据、无关证据、矛盾证据；③DeepSeek V4 Pro 作 judge 判定各臂答案与证据的一致性（一致性矩阵）；④用一致性矩阵分解出三类归因误差并输出组件报告。
- **数据集与基线**：LongBench（arXiv:2308.14508）、∞Bench（arXiv:2402.13718）、RULER（arXiv:2404.06654）子集 + Double-Bench 子集；对照基线方法：naive RAG、Self-RAG（arXiv:2310.11511）、Corrective RAG（arXiv:2401.15884）。
- **评测指标**：主指标＝归因一致率（人评 vs 自动归因）；消融＝每类误差的稳定性、judge 模型选择（DeepSeek V4 Pro vs Kimi K2.6）。
- **算力与训练方案**：无需训练，纯推理 + API 评测；4×L40 并行跑 7B/13B 生成器（如 Qwen2.5-7B/13B），每卡 1 个模型实例，约 3–5 天可跑完 1 万+问题的矩阵。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 负责问题/证据合成与一致性判定；Kimi K2.6 生成矛盾证据并做交叉 judge。
- **投稿目标与优先级**：EMNLP 2027（benchmark/资源轨）或 ACL 2027；优先级：中高。
- **可行性与风险**：全 API/推理，无训练风险。风险＝judge 偏差与人工标注成本；对策＝200 条人工抽检 + 双模型交叉验证。

### Idea 2：查询感知的动态 token 重要性多向量检索（QIA-Late）
- **中/英标题**：查询感知的 Token 重要性加权多向量检索 / Query-Adaptive Token Importance for Late-Interaction Multi-Vector Retrieval
- **一句话简介**：把收藏论文 Token Importance（NLP IV · 论文 22）的静态权重升级为查询感知的动态权重，并与生成端目标联合训练。
- **动机与现有不足**：ColBERT 系（arXiv:2004.12832；arXiv:2112.01488）等权聚合，Token Importance 论文只训静态权重（IDF/固定微调），权重不随查询语义变化；XTR（arXiv:2304.01982）改了 token 检索目标但没动权重；且这些方法都只优化检索召回，不与下游 RAG 答案质量对齐。
- **核心创新点**：(1) query-aware token weight 模块（轻量 gate，输入 query token 向量与全局查询表示）；(2) 检索-生成联合目标（检索 loss + 检索上下文上的 LM loss，用"答案可读性/忠实度"正则）；(3) 权重可解释输出（可诊断查询中哪些词驱动召回）。
- **方法概要**：在 ColBERTv2/XTR 结构上加 token-weight gate；训练分两阶段：先在 BEIR 13 任务上训检索；再用检索结果上生成 loss 微调 gate（冻结向量编码器）。文档 token 侧权重作为消融。
- **数据集与基线**：BEIR、MS MARCO、NQ、HotpotQA（检索+端到端 RAG）；基线必须对比：ColBERTv2、XTR、Token Importance（NLP IV · 论文 22 复现）、WARP 引擎部署（arXiv:2501.17788）。
- **评测指标**：主指标＝Recall@10 / nDCG@10（检索）+ EM/F1（RAG 生成）；消融＝静态 vs 动态权重、是否联合生成 loss、文档侧权重、压缩率。
- **算力与训练方案**：多向量检索器为 encoder 级（~100M–1B，如 e5 系/BGE），单卡可训；4×L40 上 1–2 天跑完检索阶段，FSDP 全参 3B–7B 生成器联合微调约 2–3 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek 合成查询-文档对与多样化查询改写用于 gate 训练；Kimi K2.6 构造 hard negative 与重排训练数据。
- **投稿目标与优先级**：SIGIR 2027 / ACL 2027；优先级：中高（检索社区接受度高、改动可插拔）。
- **可行性与风险**：风险＝多向量检索训练数据成本与 PLAID/WARP 工程对接；对策＝先在 BEIR 单任务小规模验证再扩展；若生成联合目标不稳定，退化为"仅 query-aware gate"仍成立。

### Idea 3：KV 级可编辑长上下文记忆（KV-Edit）
- **中/英标题**：KV 级知识编辑：可更新、可验证的长上下文记忆 / KV-Edit: Editable Key-Value Memories for Long-Context Processing
- **一句话简介**：把知识编辑作用到 RetroLM 式 KV 页上——编辑 = 对目标事实的 KV 页做定向重算 + 检索器联动，实现不改参数的长上下文记忆更新。
- **动机与现有不足**：参数编辑（ROME/MEMIT 类）改权重风险大、编辑爆炸；外部记忆（ALEX、MeLLo）是文本级存储，检索-推理脱节；RetroLM（NLP III · 论文 67）证明 KV 页可被精确检索，但没把"编辑"定义为 KV 操作；现有方法也没有"编辑后无关知识不退化"的评测。
- **核心创新点**：(1) 编辑操作符定义：Replace（重算目标事实页 KV）、Propagate（沿 KV 页依赖图传播）、Revoke（作废旧事实页）；(2) 与 RetroLM 检索器联动的"编辑后验证"闭环；(3) 编辑污染指标（unrelated-set 退化度）。
- **方法概要**：基于 RetroLM 框架（arXiv:2502.11444 复现）切 KV 页；用 DeepSeek 生成编辑事实与多跳验证问题；编辑时对含目标事实的页以"新事实 + 前缀"重算 KV 并替换，更新页级索引；用检索器重选页 + 生成器作答；对照参数编辑与外部记忆。
- **数据集与基线**：MQuAKE / MQuAKE-CF（arXiv:2305.14795）多跳编辑；长上下文子集（LongBench 修改版）；基线：MeLLo、GMeLLo（arXiv:2408.15903）、CaKE（arXiv:2503.16356）、ALEX（NLP IV · 论文 105）、RetroLM 直接接新事实。
- **评测指标**：主指标＝MultiHop-ACC / HopWise-ACC（MQuAKE 标准）+ 编辑污染度；消融＝编辑方式（replace vs propagate vs revoke）、页粒度、检索器是否联动、编辑规模（1/10/100/1000 条）。
- **算力与训练方案**：生成器选 Qwen2.5-7B/13B（可 LoRA），KV 重算与页检索器（BERT 级）在 4×L40 上并行；估计 3–5 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek 生成多跳编辑测试集与干扰事实；Kimi K2.6 做编辑后答案一致性 judge。
- **投稿目标与优先级**：NeurIPS 2026 / ACL 2027；优先级：高（KV×编辑×RAG 交叉点新）。
- **可行性与风险**：最大风险＝KV 页的语义定位不精确（哪些页含目标事实）；对策＝先用"事实→页"映射标注评估定位准确率，再决定是否加弱监督页检索器训练。

### Idea 4：图 RAG 的增量更新与图级知识编辑（GraphDelta）
- **中/英标题**：面向分层编码树的增量图 RAG / GraphDelta: Incremental Updates and Graph-level Knowledge Editing for Hierarchical Graph RAG
- **一句话简介**：为 T-Retriever 式编码树设计局部重编码 + 编辑传播机制，使图 RAG 在数据增删改时无需全量重建。
- **动机与现有不足**：T-Retriever（DMKM III · 论文 9）的 S²-熵编码树是静态离线划分；GraphRAG（arXiv:2404.16130）索引昂贵且对投毒脆弱（arXiv:2508.04276）；HippoRAG（arXiv:2405.14831）PPR 游走也假设图固定。工业场景（知识库日更）需要"改一条事实只动局部"。
- **核心创新点**：(1) 增量编码树：编辑/删除叶节点后只重算最小受影响子树 + 熵再平衡（必要时分裂/合并簇）；(2) "编辑传播"算子：三元组改动沿层次摘要簇向上传播，保持父簇语义一致；(3) LLM 一致性校验闭环（每个更新轮次校验簇摘要）。
- **方法概要**：在 T-Retriever 复现（arXiv:2601.04945）基础上加增量模块；图变更事件流（新增/修改/删除实体关系）→ 定位叶节点 → 局部重编码 → 熵再平衡 → LLM 校验；评测在不同更新批量（100/1k/10k 条）下的精度与重编码比例。
- **数据集与基线**：HotpotQA、MuSiQue、2WikiMultiHopQA；基线：T-Retriever 全量重建、GraphRAG、HippoRAG、naive RAG。
- **评测指标**：主指标＝EM/F1/答案准确率（更新后数据集）；消融＝重编码比例（更新成本）、编辑后多跳保持率、摘要一致性（人工+LLM 抽检）。
- **算力与训练方案**：图构建与摘要靠 DeepSeek API；编码树聚类可轻量（无大模型训练）；4×L40 用于 7B 生成器评测；估算 3–6 GPU·天 + 大量 API 调用。
- **DeepSeek/Kimi API 用法**：DeepSeek 做实体/关系抽取、簇摘要与一致性校验；Kimi 生成"编辑测试集"（修改后的事实版本）。
- **投稿目标与优先级**：ACL 2027 / WWW 2027 / KDD 2027；优先级：高。
- **可行性与风险**：风险＝局部重编码可能导致熵目标次优（长期漂移）；对策＝定期全量重平衡（week 级）作为兜底，论文中量化漂移上界。

### Idea 5：面向 RAG 检索-生成的语料自动精炼（CorpusRefine）
- **中/英标题**：检索感知的语料精炼实验室 / CorpusRefine: Retrieval-aware Corpus Refinement under a Token Budget
- **一句话简介**：把 RefineLab 的"预算约束优化"从 QA 评测数据搬到 RAG 语料与检索训练对上，同时优化"检索可召回性 + 生成可利用性"。
- **动机与现有不足**：RefineLab（NLP III · 论文 68）面向评测集，不管检索侧；RAG 性能受语料切分、噪声、冗余影响大（arXiv:2605.00505 的 denoising-first 论）；LLMLingua（arXiv:2310.05736）只压 prompt，不改善索引。
- **核心创新点**：(1) 联合精炼目标（噪声去除/语义完整切分/冗余合并/证据摘要四类操作的组合选择）；(2) 按"查询难度 × 收益"分配精炼预算（继承 RefineLab 的 assignment 思想并加检索可召回性维度）；(3) 精炼后的证据可追溯性（保留 chunk→原文链接）。
- **方法概要**：①在 NQ/HotpotQA/MS MARCO 上构建检索评测集；②对每个语料块计算噪声/冗余/完整性得分（DeepSeek judge + 嵌入距离）；③分配模块决定每块施加的操作（重写/合并/切分/删/加摘要），在 token 预算约束下最大化联合目标；④重索引后评估检索+生成。
- **数据集与基线**：NQ、HotpotQA、MS MARCO、BEIR 子集；基线：原始语料、自适应切分、LLMLingua、RefineLab 直接迁移（作为对照）、无预算约束的暴力精炼。
- **评测指标**：主指标＝Recall@k / nDCG@10（检索）+ EM/F1（生成）+ 预算使用率；消融＝各精炼操作贡献、budget 约束强度。
- **算力与训练方案**：精炼阶段全 API；评估阶段 4×L40 跑 7B 生成器 + 训练一个小 cross-encoder 重排器（1–2 GPU·天，并行于 API 精炼）。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 做语料重写/合并/摘要与预算分配；Kimi K2.6 做 LLM-as-judge 质量评测。
- **投稿目标与优先级**：SIGIR 2027 / EMNLP 2027；优先级：高（实用、可与工业 RAG 对接）。
- **可行性与风险**：风险＝精炼误伤证据（如把关键句删掉）；对策＝精炼前后检索集 A/B 对比 + 证据链保留约束。

### Idea 6：区域级视觉文档 RAG 评测（RegionBench）
- **中/英标题**：区域级视觉文档 RAG 评测基准 / RegionBench: Region-level Evidence Annotation and Evaluation for Visual Document RAG
- **一句话简介**：构建带"区域级证据"标注的多语言视觉文档问答基准，量化页级 vs 区域级检索的精度与 token 效率差异。
- **动机与现有不足**：RegionRAG（CV V · 论文 85）提出区域级检索但无标准基准；Double-Bench（NLP IV · 论文 30）证据止于页；OmniDocBench（arXiv:2412.07626）偏解析不评 RAG；ColPali（arXiv:2407.01449）是页级多向量——"证据到底在页内哪里"没有可复现评测。
- **核心创新点**：(1) 区域（bbox + 语义 region）级证据标注管线（VLM 定位 + DeepSeek 校验 + 人工抽检）；(2) 双粒度评测协议（页级 vs 区域级检索对比 + 视觉 token 压缩率）；(3) 区域级检索到生成的可追溯评估。
- **方法概要**：在论文/财报/手册/表格四类双栏文档上，用 Qwen-VL 系 VLM 定位证据区域、DeepSeek 生成问题与理由，人工抽检 300 条；统一评测协议下跑各类检索器。
- **数据集与基线**：自建 + 复用在 DocVQA、ViDoRe、Double-Bench 子集；基线：RegionRAG、ColPali、OCR+BGE dense、CLIP 式稠密。
- **评测指标**：主指标＝区域级 Recall@1 / 证据命中率、QA 准确率；消融＝粒度选择（页/区域/混合）、视觉 token 压缩率、多语言表现。
- **算力与训练方案**：region 检索器可在 L40 上 LoRA 微调 Qwen2.5-VL-7B（2–3 GPU·天）；数据标注靠 API。
- **DeepSeek/Kimi API 用法**：DeepSeek 生成 QA 与证据理由；Kimi 做跨语言问题合成与 judge 复核。
- **投稿目标与优先级**：CVPR 2027 / ACM MM 2027 / ECCV 2026（若进度快）；优先级：中高。
- **可行性与风险**：风险＝区域标注成本与 VLM 定位噪声；对策＝先 500 条小规模标定定位器准确率（≥85%）再扩量；标注失败样例计入报告。

### Idea 7：证据充分性感知的 RALM 拒绝与校准（EvidenceGate）
- **中/英标题**：证据充分性门控：RALM 的按需回答与拒绝 / EvidenceGate: Evidence-Sufficiency Gated Answering and Refusal for RALMs
- **一句话简介**：显式建模"检索到的证据是否足以支撑答案"，训练一个证据-答案对齐校验器，把 RALM 的拒绝/回答决策从置信度启发式升级为证据充分性门控。
- **动机与现有不足**：RALM 论文（NLP VI · 论文 77）发现过度拒绝、拒绝与校准脱节；Self-RAG（arXiv:2310.11511）有反思 token 但不显式建模证据充分性；UQ 综述（arXiv:2412.05563）与 2026 ACL 综述（arXiv:2601.15690）指出不确定性应从诊断走向控制信号——中间缺一个"证据充分性"量化器。
- **核心创新点**：(1) 证据充分性打分器（检索证据 + 模型内部不确定性 + 证据-答案对齐的联合特征）；(2) 用合成四态数据（证据充分/不足/矛盾/缺失）训练门控策略（含 LLM-as-judge 蒸馏到小模型）；(3) 门控与拒绝后训练/DPO 联合优化。
- **方法概要**：①用 DeepSeek 构造四态训练集；②训练小校验器（DeBERTa/Qwen2.5-0.5B 级）回归证据充分性；③生成阶段两分支（回答 vs 拒绝）由门控裁决；④与基于 logprob 的弃权基线对比。
- **数据集与基线**：自建四态集 + NQ/TriviaQA（已知/未知问题）+ RGB（arXiv:2309.01431）子集；基线：RALM 直接作答、refusal post-training、Self-RAG、LogProb 阈值弃权、UQ 基线。
- **评测指标**：主指标＝回答准确率 + 拒绝正确率（该拒则拒/该答则答）+ 校准 ECE；消融＝门控特征组合、judge 蒸馏质量、合成数据规模。
- **算力与训练方案**：校验器小（0.5–1B）单卡可训；7B RALM LoRA 微调 2–3 GPU·天；4×L40 并行。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 生成四态标注与 judge；Kimi K2.6 合成矛盾/无关证据并做交叉验证。
- **投稿目标与优先级**：EMNLP 2026 / NeurIPS 2026；优先级：高（可信 RAG 热点）。
- **可行性与风险**：风险＝judge 偏差传播进训练信号；对策＝人工抽检 300 条四态标注 + 双模型 agreement 过滤低置信标注。

### Idea 8：可扩展的多跳编辑图记忆（GraphMemKE）
- **中/英标题**：面向多跳知识编辑的动态图记忆检索 / GraphMemKE: Dynamic Graph Memory with Scalable Retrieval for Multi-Hop Knowledge Editing
- **一句话简介**：用"编辑即图节点更新"的动态图记忆 + 图游走计划 + LLM 推理验证，替代 ALEX 的静态聚簇与 MeLLo 的线性存储。
- **动机与现有不足**：ALEX（NLP IV · 论文 105）语义聚簇静态、无编辑冲突仲裁、复杂度分析理想化；MeLLo（arXiv:2305.14795）线性存储随编辑数退化；CaKE（arXiv:2503.16356）走参数电路路线但需微调。缺"动态、有结构、可验证"的外部记忆。
- **核心创新点**：(1) 动态图记忆：编辑流建图（实体/关系/新事实），带时间戳与冲突解决（新旧事实以证据强度裁决）；(2) 推理 = 图游走计划（子图展开）+ LLM 分步验证；(3) 编辑规模伸缩性作为一等指标。
- **方法概要**：①编辑流→DeepSeek 抽取三元组建图，冲突仲裁；②检索 = 查询实体子图展开（BFS/PPR 变体）；③生成 = 游走路径 + LLM 推理，逐跳验证；④评测编辑数 1/10/100/1000 下的精度、延迟、内存。
- **数据集与基线**：MQuAKE / MQuAKE-CF（arXiv:2305.14795）；基线：MeLLo、GMeLLo（arXiv:2408.15903）、CLEVER-CKE（arXiv:2407.10275）、ALEX、CaKE。
- **评测指标**：主指标＝MultiHop-ACC / HopWise-ACC；消融＝编辑规模伸缩曲线、冲突仲裁策略、游走深度、图构建质量（LLM 抽取正确率）。
- **算力与训练方案**：无大模型训练（API 为主）；可选 7B 推理游走策略 LoRA 微调（2 GPU·天）；4×L40 用于生成评测。
- **DeepSeek/Kimi API 用法**：DeepSeek 做图构建、推理步骤与冲突仲裁；Kimi K2.6 做多跳答案 judge。
- **投稿目标与优先级**：ACL 2027 / EMNLP 2026；优先级：高。
- **可行性与风险**：风险＝LLM 抽取三元组质量与冲突仲裁复杂度；对策＝先用小规模图（100 edits）人工审计图构建准确率，设质量阈值。

### Idea 9：查询自适应的"粗→精"压缩检索（MG-2）
- **中/英标题**：混合粒度压缩检索：查询自适应的粗到精长上下文管线 / MG-2: Query-Adaptive Coarse-to-Fine Compressed Retrieval for Long-Context QA
- **一句话简介**：把 HTSIR 的多粒度摘要树、LLMLingua 式压缩与一个轻量粒度路由器组合成"先粗定位、再精读取"的长上下文 QA 管线。
- **动机与现有不足**：HTSIR（NLP I · 论文 41）摘要树离线静态、与查询无关；RAPTOR（arXiv:2401.18059）同样静态；LLMLingua（arXiv:2310.05736）粒度单一；RetroLM（NLP III · 论文 67）需专用训练且页粒度固定——缺一个"按查询难度动态选粒度"的轻量方案。
- **核心创新点**：(1) 查询感知粒度路由器（小模型，判"粗摘要够不够/要不要下钻到 token 级"）；(2) 两阶段证据渐进（先簇级摘要定位、再压缩后细粒度内容）；(3) 与生成器反思闭环（Refinement，继承 HTSIR 的优点并注入压缩容错）。
- **方法概要**：①DeepSeek 离线构建多粒度摘要树；②在线 router 选粒度 → 检索 → LLMLingua 压缩 → 重排 → 生成 → 反思修正；③router 用合成"查询-最优粒度"对训练。
- **数据集与基线**：NarrativeQA、QASPER、QuALITY、QMSum（HTSIR 同款）+ LongBench 子集；基线：HTSIR、RAPTOR、LongRAG（arXiv:2406.15319）、naive RAG + LLMLingua。
- **评测指标**：主指标＝EM/F1/ROUGE + 检索 token 数与延迟（效率）；消融＝粒度路由准确率、反思模块贡献、压缩率。
- **算力与训练方案**：router 为小模型（<100M）训练即几分钟；生成器可用 DeepSeek API 或本地 7B；4×L40 完全够。
- **DeepSeek/Kimi API 用法**：DeepSeek 建树/摘要/反思生成；Kimi 构造"查询-最优粒度"训练数据并做 judge。
- **投稿目标与优先级**：ACL 2027 / NAACL 2027；优先级：中高。
- **可行性与风险**：风险＝多粒度树构建的 API 成本与 router 过拟合；对策＝router 在跨域留出集上验证泛化，失败则退化为固定两阶段。

### Idea 10：检索增强的 LLM 优化求解器选择（OptiRetrieve）
- **中/英标题**：检索增强的 LLM 优化求解器生成与统计集成选择 / OptiRetrieve: Retrieval-Augmented LLM Solver Generation with Statistical Ensemble Selection
- **一句话简介**：给 LLM 求解器生成加一层"问题-求解器"可检索示例库，用相似历史问题做 few-shot，再以统计建模选优——把 OptiHive 的一次性生成与 RAG 复用结合。
- **动机与现有不足**：OptiHive（NLP I · 论文 15）每次从零生成、不复用历史；"Optimization Modeling with RAG"（arXiv:2608.00015）证明 RAG 示例让建模准确率 40%→72%，但没用统计选择；LLM4CO 基线普遍靠迭代修复、延迟高。
- **核心创新点**：(1) 优化问题-求解器对的可检索记忆库（按问题结构/约束特征索引）；(2) 检索相似问题 + 其最优求解器代码作为 in-context 示例；(3) 用 OptiHive 式统计模型对"检索增强的候选求解器"做选择与不确定性量化。
- **方法概要**：①构建优化问题库（NL4OPT/MAMO/多车场 VRP 变体，DeepSeek 生成+求解器验证）；②问题嵌入检索 top-k 相似历史问题；③批量生成候选求解器（含检索示例）；④统计模型（伯努利/混合模型）估计真实最优率并选优，输出可解释。
- **数据集与基线**：NL4OPT、MAMO、OptiBench 类（求解器可验证的优化问题集）；基线：LLM 直接生成、OptiHive 原版、检索示例但无统计选择、迭代修复基线。
- **评测指标**：主指标＝最优率（Optimality Rate）+ 可行率；消融＝检索 k、示例数、统计模型 vs 简单多数投票、是否 RAG。
- **算力与训练方案**：无训练或极轻量；4×L40 跑本地 7B–30B 求解器生成与求解验证（并行评估）。
- **DeepSeek/Kimi API 用法**：DeepSeek 生成求解器代码、问题库与统计模型辅助；Kimi 做示例标注与结果 judge。
- **投稿目标与优先级**：AAAI 2027 / IJCAI 2027 / NeurIPS 2026；优先级：中。
- **可行性与风险**：风险＝问题相似度检索质量、统计模型在小库上的方差；对策＝检索用结构特征+语义双通道；统计模型加正则并做 bootstrap 置信区间。

### Idea 11：学习型基数估计的多表遗忘评测协议（ForgetCE-Bench）
- **中/英标题**：学习型基数估计的标准化遗忘评测 / ForgetCE-Bench: A Standardized Forgetting Evaluation Protocol for Learned Cardinality Estimation
- **一句话简介**：为 CEP 类遗忘方法建立统一评测协议，覆盖行删除、域删除、表间级联删除三类，并补齐"删除目标精确性与隐私泄露"指标。
- **动机与现有不足**：CEP（ML III · 论文 33）只报 Q-error 与开销；机器遗忘综述（arXiv:2209.02299）批评缺乏统一评估与隐私度量；DB 社区无跨方法可比基准。
- **核心创新点**：(1) 三类删除任务的基准定义（行/域/表间级联）；(2) 指标集扩展：删除目标精确性（被删元组对估计的影响是否消除）+ 保留数据性能 + 可归因性（能否检测残留记忆）；(3) 与全量重训的"上界"对照协议。
- **方法概要**：①IMDb/TPC-H 上构造删除任务（不同删除比率 10%–70%）；②实现 CEP + 全量重训 + 随机掩码基线 + 近似遗忘（如 Fisher 信息掩码）；③统一评测脚本输出指标矩阵。
- **数据集与基线**：IMDb、TPC-H（NeuroCard/FACE 架构）；基线：全量重训、CEP、随机参数掩码、无遗忘（直接保留）。
- **评测指标**：主指标＝删除后 Q-error；消融＝遗忘精确性（遗忘指标）、保留集性能、计算开销（vs 重训时间）、删除比率敏感性。
- **算力与训练方案**：NeuroCard/FACE 规模小（单卡可训），4×L40 轻松覆盖多配置并行跑；估计 3–5 GPU·天。
- **DeepSeek/Kimi API 用法**：DeepSeek 生成删除后查询集与归因验证说明；Kimi 做评测协议文档化与结果审查。
- **投稿目标与优先级**：ICDE 2027 / VLDB 2027；优先级：中。
- **可行性与风险**：风险＝领域较窄（DB 社区接受度）、遗忘指标设计主观；对策＝指标定义与 DB 社区既有（如 membership inference）对齐，附补充实验。

### Idea 12：自演化检索摘要索引（Evolving Index）
- **中/英标题**：查询驱动的自演化检索摘要树 / Evolving Summary Index: Query-Driven Self-Evolving Retrieval Index
- **一句话简介**：让 RAPTOR/HTSIR 式摘要树随"新内容流入 + 查询反馈"在线生长/合并/修剪，实现持续学习的长期记忆 RAG。
- **动机与现有不足**：RAPTOR（arXiv:2401.18059）、HTSIR（NLP I · 论文 41）的树是静态构建；图 RAG 侧 LEDGER（arXiv:2606.28379）做到依赖图局部更新但非摘要树；上下文工程综述（arXiv:2605.00505；arXiv:2604.20874）指出"持续上下文"是本质需求——缺在线演化的摘要索引。
- **核心创新点**：(1) 索引演化算子（split/merge/refine）由"查询命中分布 + 新文档流"驱动；(2) 探索-利用平衡的演化策略（高命中子树细分、低价值簇合并）；(3) 与 LLM 自评价闭环（演化决策经 LLM 反思校验）。
- **方法概要**：①初始多粒度摘要树；②在线维护：新文档进入→定位子树→摘要重算；查询日志驱动细分/合并；③演化日志驱动离线分析（哪些查询类型受益）。
- **数据集与基线**：QMSum、LongBench 多文档子集、自建"流式文档+查询"持续 QA 场景；基线：RAPTOR、HTSIR、固定索引 + 周期性全量重建。
- **评测指标**：主指标＝检索 Recall@k + 生成 F1（随文档流长度）；消融＝演化成本（token/延迟）、演化策略（split/merge/refine）、日志驱动 vs 随机。
- **算力与训练方案**：轻量无大模型训练；LLM 调用为主；4×L40 跑 7B 生成评测与重排器（可选 1 GPU·天）。
- **DeepSeek/Kimi API 用法**：DeepSeek 做摘要生成与演化决策；Kimi 做演化前后质量评估。
- **投稿目标与优先级**：SIGIR 2027 / ACL 2027；优先级：中。
- **可行性与风险**：风险＝与 Idea 4（图编辑传播）在"增量"主题上邻近——本 idea 明确聚焦"文档摘要树 + 查询日志驱动"，Idea 4 聚焦"属性图编码树 + 三元组编辑"，在论文里互相引用做差异化；风险＝演化导致索引漂移，对策＝基线对比"周期全量重建"。

## 七、综述性结论与投稿策略

### 7.1 核心结论
1. **粒度是 2024–2026 RAG 的第一设计自由度**：本主题 11 篇中过半在"检索单元粒度"（文档/区域/KV页/token/树节点）上做文章。粒度下沉能去噪提效（RegionRAG、RetroLM、Token Importance），粒度放大能保语义完整（LongRAG）。**"查询自适应的动态粒度"仍是未解问题**（Idea 2、9 直击）。
2. **"检索到 ≠ 用上"是最大的评测与可靠性缺口**：Double-Bench 的过度自信发现、RALM 的过度拒绝发现，共同指向"证据使用/证据充分性"这一缺失的中间量（Idea 1、7）。
3. **知识编辑与 RAG/索引架构正在融合但尚未打通**：参数编辑、外部记忆、KV 级检索三条线各做各的；"可编辑的 KV 记忆"与"可编辑的图/树索引"是两块明确的处女地（Idea 3、4、8）。
4. **数据与评测本身成为研究对象**：RefineLab、Double-Bench、PureDocBench 的批评（arXiv:2605.07492）都说明"评测数据质量与检索语料质量"值得专门研究（Idea 5、6）。

### 7.2 投稿策略建议
- **高优先级、高新颖性**：Idea 3（KV 级可编辑记忆）、Idea 4（图 RAG 增量编辑）、Idea 7（证据充分性门控）、Idea 8（动态图记忆编辑）——选题落在 RAG×知识编辑×可信 AI 交叉点，2026–2027 正是窗口期。
- **中高优先级、工程落地强**：Idea 1（归因评测）、Idea 2（查询感知多向量）、Idea 5（语料精炼）、Idea 6（区域级视觉评测）——评测/检索社区（SIGIR/EMNLP/ACL）接受度高，可快速复现。
- **中优先级、依赖领域时机**：Idea 9、10、11、12——选题稍成熟或领域较窄（DB、OR），适合作为第二梯队或 workshop 预热。
- **会议时序**：EMNLP 2026（约 2026 年中投稿）适合 Idea 7；NeurIPS 2026 / ICLR 2027 适合 Idea 3、8；ACL 2027 / SIGIR 2027 / CVPR 2027 覆盖 Idea 1、2、4、5、6、9、12。
- **资源匹配**：所有 12 个 idea 均可在 4×L40（192GB）内完成（多为 API + 推理 + 小模型训练）；训练最重的是 Idea 2（多向量检索 + 生成联合微调）与 Idea 3（KV 页检索器），按 7B–13B FSDP 全参或 30B LoRA 规划 GPU·天即可。

### 7.3 一句话总结
> 本主题从"检索增强"出发，实际指向一个更深的命题：**让大模型的外部知识在粒度、可编辑性、证据充分性三个维度上都可被精确控制与验证**——这正是 RAG 与知识管理下一个三年的主线，也是本报告 12 个 idea 共同的落点。
