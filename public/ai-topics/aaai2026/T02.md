# T02 视频理解与视频多模态大模型 调研报告

> 主题范围：长视频理解、视频时刻检索、跨视频推理、时间推理、视频VQA基准、视频分类、视频LLM训练对齐。
> 收录论文：9 篇（AAAI 2026 收藏论文）。精读 4 篇代表论文全文，通读其余 5 篇摘要并全部纳入分析。
> 检索时间：2026-08。所有外部文献均标注真实 arXiv ID / DOI，无编造引用。

## 一、主题概览与研究热点

本主题的 9 篇收藏论文覆盖了"视频理解 + 视频多模态大模型（Video MLLM/LLM）"的全部关键面，按研究动作可分为**训练无关（training-free）的检索/压缩范式**与**训练范式**两大阵营，并按任务可分为六条主线：

1. **长视频理解（hour-level）**：`APVR`（Computer Vision III · 论文 3）以 training-free 的"关键帧检索 + 关键 Token 检索"双粒度方案突破 memory wall，是训练无关范式的代表作。
2. **视频-文本对齐与检索**：`GranAlign`（Computer Vision IV · 论文 32）面向零样本视频时刻检索（ZVMR）解决"语义粒度不匹配"；`AMD-Net`（Computer Vision VII · 论文 31）以外观-运动解耦解决文本-视频检索中的单一全局表示过度简化问题。
3. **视频 LLM 时间推理训练对齐**：`TEMPLE`（Computer Vision V · 论文 53）用 DPO + 渐进式 Pre-SFT 对齐激励时间理解，是"训练范式"在时间维度上的代表。
4. **视频分类**：`SurdCRL`（Computer Vision XII · 论文 71）把物体中心的时空交互分解为协同/独特/冗余因果分量，面向事件级视频分类。
5. **跨视频推理**：`CrossVid`（Computer Vision V · 论文 38）是首个全面评估多视频时空推理的基准，实测最强模型 Gemini-2.5-Pro 平均仅 50.4%（人类 89.2%），暴露出"跨视频证据整合"这一结构性缺口。
6. **视频 QA 基准（领域/视角）**：`VisAssist`（Computer Vision III · 论文 7，视障第一人称）、`EgoCross`（Computer Vision V · 论文 77，跨领域第一人称）、`UVLM`（Computer Vision XI · 论文 22，水下世界）。

**研究热点判断**：收藏论文呈现"两强两弱"格局——(a) 强在**training-free 检索/压缩**（APVR）与**时间对齐方法**（TEMPLE）已相当成熟并被当作主流；弱在 (b)**跨视频（multi-video）证据整合**几乎没有方法，仅有基准；(c)**第一人称/极端领域的可靠性与泛化**仍缺方法（只有基准）。这三点正是外部 2023-2026 文献（详见第五节）里最活跃、也最缺"可复现方法"的空白带。此外，**可验证奖励的强化学习（RLVR）**与**证据接地（evidence-grounded）**正在重塑视频 LLM 的时间推理训练，是 2026 年的最前沿信号。

## 二、收藏论文分类梳理（按子方向分组）

### 2.1 长视频理解：训练无关检索范式
- **Computer Vision III · 论文 3 · APVR: Hour-Level Long Video Understanding with Adaptive Pivot Visual Information Retrieval**（arXiv:2506.04953）
  训练无关框架，双粒度（Pivot Frame Retrieval + Pivot Token Retrieval）分层检索/保留关键视觉信息，把 7B 模型的处理能力从 256 帧扩展到 1024 帧，在 LongVideoBench/VideoMME/MLVU 上相对基线最高提升 9.5%/4.6%/9.7%，超过多数训练式方法。

### 2.2 视频时刻检索 / 文本-视频检索
- **Computer Vision IV · 论文 32 · GranAlign: Granularity-Aware Alignment Framework for Zero-shot Video Moment Retrieval**（arXiv:2601.00584）
  训练无关 ZVMR 框架：粒度查询重写（simplified/detailed）+ 查询感知描述生成（query-agnostic/query-aware），按粒度配对打分，在 QVHighlights/Charades-STA/ActivityNet-Captions 三个基准刷新 SOTA。
- **Computer Vision VII · 论文 31 · Appearance-Motion Decomposed Alignment for Text-Video Retrieval**（AMD-Net, DOI: 10.1609/aaai.v40i10.37745）
  有监督文本-视频检索：判别性外观学习（SVD 原型初始化）+ 多尺度运动学习解耦外观与运动线索，高阶交叉聚合提升原型韧性，五个标准基准优于 SOTA。

### 2.3 视频 LLM 时间推理与训练对齐
- **Computer Vision V · 论文 53 · TEMPLE: Incentivizing Temporal Understanding of Video Large Language Models via Progressive Pre-SFT Alignment**（arXiv:2503.16929）
  自动流水线构建时间密集 DPO 偏好对（扰动：clip dropping/shuffling/reversal），课程学习渐进增加扰动难度，并在 SFT 之前做偏好优化（Progressive Pre-SFT Alignment），仅用 ~25K 自生成 DPO 数据就在 VideoMME/MLVU/Vinoground/TempCompass 一致提升。

### 2.4 视频分类
- **Computer Vision XII · 论文 71 · Introducing Decomposed Causality with Spatiotemporal Object-Centric Representation for Video Classification**（SurdCRL, DOI: 10.1609/aaai.v40i15.38286）
  提出 SURD 因果理论：时空实体建模 + 双路因果推理（前门/后门干预）+ 因果组合选择，把物体中心时空交互分解为协同/独特/冗余因果分量，在两个基准上验证事件级视频分类更优。

### 2.5 跨视频推理（基准）
- **Computer Vision V · 论文 38 · CrossVid: A Comprehensive Benchmark for Evaluating Cross-Video Reasoning in Multimodal Large Language Models**（arXiv:2511.12263）
  首个全面 CVR 基准：4 个高层维度（比较分析/时间理解/多视角推理/自由问答）10 个任务、5331 视频、9015 QA 对，半自动（Qwen2.5-VL-72B 生成帧描述 + DeepSeek-R1 生成 QA + 10 名专家质检）流水线构建；22 个模型评测，Gemini-2.5-Pro 最优仅 50.4%，FSA 任务仅 13.4%（人类 85.2%）。

### 2.6 视频 QA 基准（视角与领域）
- **Computer Vision III · 论文 7 · VisAssist: A Visually Impaired-Captured Video Question Answering Benchmark for Assistive Systems**（DOI: 10.1609/aaai.v40i6.42410）
  首个大规模视障用户拍摄视频 QA 数据集（13,413 视频），揭示模型在第一人称空间推理、缺失信息 vs 拍摄质量差判别（危险幻觉）、非拉丁文本理解的系统性缺陷。
- **Computer Vision V · 论文 77 · EgoCross: Benchmarking Multimodal Large Language Models for Cross-Domain Egocentric Video Question Answering**（arXiv:2508.10729）
  跨域第一人称视频 QA 基准：手术/工业/极端运动/动物视角四域、798 片段 ~1000 QA 对、预测/识别/定位/计数四任务，OpenQA+CloseQA 双格式；实测模型域外泛化差，并给出微调与 RL 的试点。
- **Computer Vision XI · 论文 22 · UVLM: Benchmarking Video Language Model for Underwater World Understanding**（arXiv:2507.02373）
  水下观测基准：419 类海洋生物、20 类观测子任务、光照变化/浊度/视角等水下挑战，人机协作构建；微调 VidLM 能显著提升水下理解且对 in-air 基准有轻微正向迁移。

## 三、代表性论文精读（4 篇，含创新点/不足/心得）

### 3.1 APVR —— 长视频理解（训练无关范式代表）

**论文信息**：Computer Vision III · 论文 3 · APVR: Hour-Level Long Video Understanding with Adaptive Pivot Visual Information Retrieval（arXiv:2506.04953，AAAI 2026；东南大学 + 中兴）

**方法细节（精读要点）**：
- 双组件：**PFR（Pivot Frame Retrieval）** 用 LLM 把查询展开为 Objects/Descriptions/Relations/Semantics 四类语义信息，由 CLIP（语义相似度）+ Grounding-DINO（目标检测空间置信度）加权打分（λ=0.5），配合时间扩散（temporal diffusion，沿时间窗传播分数）与自适应重采样（高分集 + 高熵不确定集，Multinomial+Uniform 混合），迭代 P 轮（最优 P=3, stride=4）选出 Top-K 关键帧（K 可到 1024）。
- **PTR（Pivot Token Retrieval）** 在 MLLM 内做 query-aware 的多层注意力打分，动态分块（chunk-wise）选择 + 多头软投票（head-wise soft voting）压缩 KV cache 中的视觉 token。
- 完全训练无关（training-free），即插即用，三套 7B 基座（Qwen2-VL / Qwen2.5-VL / VideoLLaMA3）均显著提升：LongVideoBench 最高 64.9（+9.5%），VideoMME 68.4（+4.6%），MLVU 76.1（+9.7%），超过多数 8B/14B 训练式方法与 GPT-4V/Gemini-1.5-Pro。

**创新点**：把"帧级检索 + Token 级检索"统一到同一查询感知框架，用双粒度同时突破 memory wall 与信息丢失；用 LLM 查询展开把文本语义注入检索打分，弥补了纯视觉检索的语义盲区；训练无关设计使其可附着在任何快速演进的 MLLM 上。

**不足与空白**：
1. **检索启发式不可学习**：打分权重 λ、迭代次数 P、初始步长 ∇、K 均为手工超参，且 CLIP/Grounding-DINO 是冻结的外部模型，不针对目标 MLLM 的注意力分布优化——存在"检索器与推理器目标不一致"问题。
2. **无"证据充分性"判断**：固定 K（如 1024 帧）没有早停机制，对简单问题浪费预算、对复杂问题可能仍不足；没有把"已收集证据是否足够作答"纳入决策。
3. **检索打分不区分问题类型**：对"状态变化/相对位置/因果关系"等不同推理类型，检索信号应不同（关系类问题更需要 Grounding-DINO 的跨帧关系，纯相似度类问题更需要 CLIP），APVR 未做类型自适应。
4. **无训练信号回流**：既然检索是"为 QA 服务"，理想上应以 QA 正确性作为检索器的训练信号（RLVR），APVR 完全隔离。

**心得**：APVR 证明了"智能检索是参数规模的替代方案"，但其"启发式 + 手工超参 + 无早停"的局限恰好是 2026 年 `AdaptToken`、`TimeSearch-R`、`FrameThinker` 等"可学习/可验证"范式的机会窗口——本报告的 Idea 3 与 Idea 12 直接针对此缺口。

### 3.2 TEMPLE —— 视频 LLM 时间推理训练对齐

**论文信息**：Computer Vision V · 论文 53 · TEMPLE: Incentivizing Temporal Understanding of Video Large Language Models via Progressive Pre-SFT Alignment（arXiv:2503.16929，AAAI 2026；北大 + 港大 + 快手）

**方法细节（精读要点）**：
- **动机**：Video LLM 时间推理弱源于 (a) 数据里时间对应弱、(b) 纯 next-token 预测缺少显式时间监督。先做初步分析：Qwen2-VL-7B 详细描述事件召回率仅 35.0%（幻觉多、漏报多）。
- **DPO 数据流水线**：三步——① 视频筛选（TransNetV2 场景检测 + SigLIP 相似度分组，保留 4~32 个独特事件组的"时间密集"视频，clip 限 16s）；② 扰动策略（clip dropping / shuffling / reversal，由难度因子 r 控制强度）；③ 响应生成（clean 输入为 chosen，perturbed 输入为 rejected；采用 context-aware 分段描述聚合为全局描述）。全程自给自足，不依赖外部 LLM/API。
- **Progressive Pre-SFT Alignment**：难度课程（r=16→8→4→2 逐步降低，即扰动加强）+ 把 DPO 放在 SFT 之前（反常规的"先对齐后指令微调"），训练曲线显示 Pre-SFT 后 loss 更低、梯度更稳。
- **效果**：Qwen2-VL-7B 上 VideoMME 时间感知 +3.6、时间推理 +2.8，Vinoground +3.2（~10% 相对提升）；与 post-SFT DPO（TPO、LLaVA-Hound）正交可叠加；数据可跨架构/规模迁移但自生成最优。

**创新点**：首次系统论证"时间对齐应发生在 SFT 之前"；用扰动对比把"时间结构"转化为可自动生成的偏好信号；难度课程提升数据效率；全自动无外部模型依赖。

**不足与空白**：
1. **"答案对但证据错"不可检测**：扰动-DPO 本质教模型"区分 clean 与 corrupted 输入"，但不保证模型依据**正确的**时空证据作答——模型可能靠首帧/末帧捷径答对。TEMPLE 没有证据定位或接地的奖励/约束。
2. **偏好信号只是"相对比较"**：无绝对正确性的可验证奖励；对"多跳时间推理"（先 A 后 B 才导致 C）这类复杂时间关系，扰动对区分度不足。
3. **单任务（detailed captioning）**：偏好对只基于描述任务，未覆盖"时间定位/排序/计数"等时间密集任务的监督。
4. **无检索-推理协同**：TEMPLE 假设输入帧均匀采样（≤64 帧），与 APVR 类检索方法是正交关系但从未融合——"检索到的时间证据 + 时间对齐训练"是明显空白。

**心得**：TEMPLE 属于"偏好学习（DPO）"流派；2026 年外部文献显示该流派正向 **RLVR + 可验证奖励** 演进（`Video-R1`、`TimeSearch-R`、`VideoSSR`、`VSeek`）。本报告 Idea 1、4、5 均以"把 TEMPLE 的时间对齐升级为证据可验证的 RL"为主线。

### 3.3 CrossVid —— 跨视频推理基准

**论文信息**：Computer Vision V · 论文 38 · CrossVid: A Comprehensive Benchmark for Evaluating Cross-Video Reasoning in Multimodal Large Language Models（arXiv:2511.12263，AAAI 2026；小红书）

**方法细节（精读要点）**：
- **任务设计**：4 维 10 任务——比较分析（行为理解 BU / 叙事理解 NC / 烹饪比较 CC / 程序错误分析 PEA）、时间理解（情节推断 PI / 功能步对齐 FSA / 程序步排序 PSS）、多视角推理（多视角空间推理 MSR / 多视角物体计数 MOC）、自由问答（比较烹饪 QA CCQA）。来源 6 个数据集（Animal Kingdom / MovieChat-1K / YouCook2 / VisDrone / Charades / Assembly101），每 query 平均需理解 ~770 秒视频，组内视频 2~6 个。
- **标注流水线**：Qwen2.5-VL-72B 帧描述（含元数据上下文）→ DeepSeek-R1 任务定制 prompt 生成 QA+rationale → 10 名专家三阶段过滤/精修/质控；FSS 任务做"时间重排（±1~5s 偏移）"防捷径。
- **关键结果**：22 个模型，Gemini-2.5-Pro 最优平均 50.4%（人类 89.2%）；闭源 >> 开源；thinking 模型占优；FSA 是断崖任务（Gemini 13.4% vs 人类 85.2%）；帧数越多整体越好但会引入无关帧噪声；CoT 有助但非全任务一致。
- **错误四类**：关键帧丢失（帧预算被多视频稀释）、单视频理解错、跨视频比较错、格式错。

**创新点**：首个系统化、大规模、任务分层的 CVR 基准；把"多视频同时推理"从多视角扩展到一般场景；误差分析揭示"证据分布整合"这一核心瓶颈。

**不足与空白**：
1. **有基准无方法**：论文只做评测，没有任何训练/推理方法解决 CVR；实测 gap（50.4 vs 89.2）巨大，方法层完全空白。
2. **输入组织 naive**：评测时把所有视频均匀抽帧后拼成一个序列喂给模型——帧预算被多个视频均摊（关键帧丢失），且无跨视频 token 聚合机制。
3. **无证据接地标注**：只有答案正确率，没有"支撑区间"，无法诊断"答对靠运气还是靠证据"（与 TEMPLE 的问题同构）。
4. **多视角任务太少**：MSR/MOC 仅 2 个任务、各 ~600 QA，且仅 VisDrone 一个来源，空间推理评估深度有限。
5. **合成 QA 依赖 DeepSeek-R1**：自动生成上限受 teacher 能力限制，专家只是过滤/精修。

**心得**：CrossVid 是最有价值的"缺口说明书"——它把 CVR 的四大错误类型摆上台面。本报告 Idea 2（跨视频证据路由）、Idea 5（FSA 对齐）、Idea 10（证据接地的多视频基准）都从这里生长。

### 3.4 GranAlign —— 零样本视频时刻检索（ZVMR）

**论文信息**：Computer Vision IV · 论文 32 · GranAlign: Granularity-Aware Alignment Framework for Zero-shot Video Moment Retrieval（arXiv:2601.00584，AAAI 2026；中央大学 + KAIST + ETRI）

**方法细节（精读要点）**：
- **问题**：ZVMR 的语义粒度不匹配——一般查询（"a cute dog"）覆盖高但精度低，详细查询（"a baby Golden Retriever is walking around"）精度高但覆盖差，现有单路径重写（Moment-GPT 等）两头不讨好。
- **方法**：查询侧用 LLaMA-3 指令重写为 simplified（替换生僻词、保留核心实体动作）与 detailed（保留所有细节）两类多句变体；视频侧对 top-K% 候选帧生成 query-agnostic caption（全帧）+ query-aware caption（查询意图注入）；按"simplified↔agnostic、detailed↔aware"粒度配对，SentenceTransformer 余弦打分取平均，Moment Proposal Generator 合并邻近高分帧 → 长度正则 → NMS → 后排序。
- **效果**：QVHighlights 测试集全指标 SOTA（mAP@avg 提升 3.23%），Charades-STA、ActivityNet-Captions 亦刷新，训练无关、成本可控。

**创新点**：明确诊断"粒度错配"这一 ZVMR 根因并给出显式对齐机制；双路径（高召回粗路径 + 高精度细路径）互补打分比单一路径重写本质更优；查询感知描述把查询意图嵌入视频内容，弥补"视觉正确但语义不对齐"。

**不足与空白**：
1. **逐帧独立打分破坏时间结构**：Sf 是逐帧余弦相似度，跨帧连续性与状态转移信息被丢弃，靠 MPG 合并/ NMS 补救是后处理而非建模；对"先 A 后 B"这类状态变化型 query 基本失效。
2. **无运动/物体轨迹建模**：不看光流、不跟踪物体，纯语义余弦；而 moment 的时间边界往往由动作/物体出现消失定义。
3. **query-aware caption 有幻觉风险**：注入查询意图到描述可能"无中生有"，论文自己承认需靠另一路径平均来对冲。
4. **语义相似度是离线单模态句向量**：SentenceTransformer 不感知视频帧内容动态，上限受嵌入模型质量约束；未与 CLIP 视觉-文本对齐融合。
5. **只做粗-细两档粒度**：真实查询粒度是连续谱，"两档"仍是离散近似。

**心得**：GranAlign 的"双路径粒度对齐"思想很强，但其"逐帧打分 + 后处理 NMS"的架构决定了它长于定位但短于"时间推理型"检索。本报告 Idea 8 用时间一致打分、轨迹条件化、连续粒度加权去升级它。

## 六、研究 Idea（12 个，完整格式）

> 硬件假设：4 × NVIDIA L40（48GB，合计 192GB）。FSDP/DeepSpeed 全参微调 7B-13B；LoRA/QLoRA 可微调 30B-70B；可并行跑推理与数据合成。
> 每个 idea 均给出可复现的方法概要、公开数据集/基线、主指标+消融、算力预算、API 分工、投稿与风险。

### Idea 1（高）时间证据可验证的强化对齐：为视频 LLM 注入接地的时间推理 / Evidence-Grounded Temporal RLVR for Video LLMs

- **一句话简介**：用"时间证据定位"的可验证奖励替代纯答案正确性奖励，让视频 LLM 在 RL 阶段学会依据正确的时空证据作答。
- **动机与现有不足**：TEMPLE（Computer Vision V · 论文 53）的扰动-DPO 只能教模型"识别扰动"，无法保证回答建立在正确证据上（right-answer-wrong-evidence）；`Video-R1`（arXiv:2503.21776）、`TimeSearch-R`（arXiv:2511.05489）用答案正确性 RLVR 却无细粒度时间证据奖励；`SER`（arXiv:2606.24726）引入 LLM 裁判证据奖励但依赖几何检查且需密集标注。目前缺少"答案正确 + 证据正确 + 证据充分"三者统一的训练目标。
- **核心创新点**：(1) 把问题编译成时间逻辑原语清单（关键对象、动作、时间顺序约束），对模型输出的证据区间做**符号-语义双轨验证**，得到可缩放的证据奖励（temporal IoU、coverage、groundedness）；(2) 双奖励分解 `r = r_ans + λ·r_evid`，证据奖励权重随课程逐渐提升；(3) 与 TEMPLE 式 Pre-SFT DPO 组合，先时间偏好对齐再证据 RLVR。
- **方法概要**：基座 Qwen2.5-VL-7B。数据 = LLaVA-Video 子集 + 自建时间证据 QA（DeepSeek V4 Pro 生成原语/标准答案/证据区间，人工抽样校准）。训练两阶段：A) Pre-SFT DPO（复用 TEMPLE 扰动流水线，LoRA rank 64）；B) GRPO：策略输出（答案 + 证据区间 [start,end]），奖励由时间逻辑自动机（可验证子集）+ 轻量 LLM-judge（开放子集）计算。
- **数据集与基线**：LongVideoBench / VideoMME / MLVU / LVBench（arXiv:2406.08035）/ Vinoground（arXiv:2410.02763）/ TempCompass / Haystack-LVBench 与 Haystack-Ego4D。基线：Qwen2.5-VL-7B、TEMPLE、TPO（arXiv:2501.13919）、Video-R1、TimeSearch-R、FrameThinker（arXiv:2509.24304）。
- **评测指标**：主指标 VideoMME 时间感知/推理子集、Vinoground (Text)、LVBench accuracy；消融指标证据区间 tIoU、groundedness（LLM-judge）、Pass@1/4、证据奖励权重 λ 与课程扫描。
- **算力与训练方案**：7B LoRA（rank 64，ViT 冻结）。数据合成离线（API）；DPO 阶段约 25K 对 ≈ 2 GPU·天；GRPO 阶段 32K 样本、每组 8 rollout、3 epoch ≈ 6-10 GPU·天；评测并行 1-2 GPU·天。总计 **10-14 GPU·天**，4×L40 内完成（2 卡训练 + 2 卡 rollout/评测）。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 生成时间原语解析 + 标准答案与证据区间（teacher）；DeepSeek V4 Flash 批量生成扰动问答对与难例筛选；Kimi K2.6 作 LLM-as-judge 评估证据充分性与 groundedness。
- **投稿目标会议与优先级**：CVPR 2027（高）。
- **可行性与风险**：最大风险是证据奖励的准确性与时间逻辑原语覆盖不齐。对策：双轨奖励（符号验证子集 + LLM-judge 子集）、按任务类型校准 λ、先在小数据上验证奖励与准确率相关性再全量训练。

### Idea 2（高）跨视频证据路由与聚合网络 / Cross-Video Evidence Routing and Aggregation (CVRA)

- **一句话简介**：针对 CrossVid 暴露的"多视频证据无法整合"瓶颈，设计查询感知的跨视频 token 预算分配 + 跨视频语义对应图推理。
- **动机与现有不足**：CrossVid（Computer Vision V · 论文 38）实测 Gemini-2.5-Pro 仅 50.4%（人类 89.2%），FSA 仅 13.4%；主要错误是"关键帧丢失"——多视频均匀拼接把帧预算均摊、无跨视频比较操作。现有方法全是评测（All-Angles Bench arXiv:2504.15280、EgoExoLearn）而无训练方法。
- **核心创新点**：(1) **查询感知跨视频帧预算分配**（可学习 router 按 query 与各视频相关性分配帧数）；(2) **跨视频语义对应图**（entity/action 级跨视频对齐边，引导 LLM 注意力做跨视频聚合）；(3) 面向比较/聚合任务的对比式指令数据与训练目标。
- **方法概要**：基座 Qwen2.5-VL-7B + 轻量 Cross-Video Router（MLP，输入 query 嵌入 + 各视频 CLIP 摘要，输出每视频帧预算）。两阶段：SFT（CrossVid QA + DeepSeek 合成多视频比较数据）；GRPO（奖励 = 答案正确性 + 对应图覆盖 + 预算正则）。推理时逐视频编码 + CLS token 内存，仅聚合阶段进 LLM。
- **数据集与基线**：CrossVid（9015 QA）、All-Angles Bench、EgoExoLearn、MMVU（arXiv:2501.12380）。基线：CrossVid 报告的 22 个模型结果、Qwen2.5-VL-7B/72B、InternVL3-8B。
- **评测指标**：主指标 CrossVid O.Avg 及各维度（C.Avg/T.Avg/M.Avg/CCQA）；消融指标帧预算分配可视化、对应图边数与召回、有无 CoT、帧数-准确率曲线。
- **算力与训练方案**：SFT 20K 样本 7B LoRA ≈ 4-6 GPU·天；GRPO ≈ 6-8 GPU·天；合成数据离线（API）。总计 **≈12 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 合成多视频比较型 QA 与跨视频 reasoning 链（teacher）；Kimi K2.6 作跨视频答案 LLM-judge 与证据归属判断。
- **投稿目标会议与优先级**：NeurIPS 2026（高）。
- **可行性与风险**：多视频长输入显存压力是最大风险。对策：逐视频编码 + 内存 token 聚合（参照 `OmniAgent`/`StreamForest` 的持久记忆范式），聚合阶段才进 LLM，4×L40 可支撑 6 视频 × 32 帧。

### Idea 3（中高）可学习的自适应关键检索：把 APVR 从启发式变成 RL 策略 / Learnable Adaptive Pivot Retrieval (LAPR)

- **一句话简介**：把 APVR 的帧/Token 两级检索做成轻量可学习选择器，用 RL 以"下游 QA 正确率"为奖励端到端优化。
- **动机与现有不足**：APVR（Computer Vision III · 论文 3）训练无关但打分权重 λ、迭代 P、stride ∇、K 全是手工超参，冻结 CLIP/Grounding-DINO 与目标 MLLM 的注意力分布不一致；`AdaptToken`（arXiv:2603.28696）用熵做全局预算但不可学习；`TimeSearch-R`/`FrameThinker` 已证明"可学习检索 + RL"有效，但未在帧+Token 双粒度上统一。
- **核心创新点**：(1) 用轻量选择器（2B Qwen2.5-VL scorer）蒸馏 APVR 打分并继续 RL 优化，替代手工超参；(2) 奖励 = 答案正确性 + 检索证据命中（GT 区间 IoU）− 预算惩罚；(3) 检索难度课程（先易后难的 query 类型）。
- **方法概要**：训练 2B scorer（监督自 APVR 打分 + 检索成功率），再对 7B 主模型用 GRPO 联合优化"检索动作 + 作答"；检索动作空间 = {每视频帧数, 每帧 token 保留率}，等价于把 APVR 的 PFR/PTR 迭代参数化并端到端训练。
- **数据集与基线**：LongVideoBench / VideoMME / MLVU / LVBench + Haystack-LVBench。基线：APVR、AKS（arXiv:2502.21271）、QuoTA（arXiv:2503.08689）、AdaptToken、TimeSearch-R。
- **评测指标**：主指标 LVB/VideoMME accuracy、LVBench；消融指标检索 precision/recall（GT 框）、token 预算曲线、延迟、检索器规模。
- **算力与训练方案**：2B scorer 蒸馏 ≈ 1-2 GPU·天；7B LoRA GRPO ≈ 6-8 GPU·天；合计 **≈10 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 大规模查询展开与蒸馏数据生成；Kimi K2.6 评测检索结果质量。
- **投稿目标会议与优先级**：ICCV 2027（中高）。
- **可行性与风险**：RL 动作空间大、奖励噪声高。对策：先蒸馏降低方差，再对"检索器"固定主模型做冷启动，检索奖励用 GT 框打折避免稀疏。

### Idea 4（中高）视频原生自监督 RLVR：状态转移验证奖励 / Video-Native Self-Supervised RLVR with State-Transition Rewards

- **一句话简介**：用完全无标注、自动可验证的视频原生预文本任务（状态转移合法性/乱序重排/插值预测）做 RLVR，训练视频 LLM 的时间推理。
- **动机与现有不足**：TEMPLE 靠扰动-DPO 没有绝对可验证奖励；`VideoSSR`（arXiv:2511.06281）提出三预文本（Anomaly Grounding/Object Counting/Temporal Jigsaw）但未专门针对"状态转移"与长程时间依赖；`Spatial-SSRL`（arXiv:2510.27606）只做空间。时间维的"先 A 后 B 才 C"这类因果结构未被自监督信号覆盖。
- **核心创新点**：(1) 提出**状态转移验证**预文本（判断两帧是否构成合法动作转移、检测倒放/乱序、多尺度 Jigsaw）；(2) 全部奖励可符号验证（GT 即任务构造本身），零人工标注；(3) 与 TEMPLE 式 Pre-SFT DPO 组合，形成"无监督自检 + 偏好对齐"双通道。
- **方法概要**：数据 = 大规模公开视频（Kinetics/VGGSound/YouTube 采样）离线切片段、构造转移/乱序样本。GRPO：策略对给定样本输出正确顺序或合法性标签；奖励由构造 GT 自动计算。评估下游 17 基准子集。
- **数据集与基线**：自建 VideoSSR-30K 式数据；下游 VideoMME / MLVU / TempCompass / Vinoground / LVBench。基线：VideoSSR、Spatial-SSRL、Qwen2.5-VL、TEMPLE。
- **评测指标**：主指标 TempCompass MC、Vinoground (Text)、VideoMME 时间子集；消融指标预文本自身准确率、下游零样本迁移、与 VideoSSR 预文本的叠加增益。
- **算力与训练方案**：数据构造离线（CPU/单卡）；7B LoRA GRPO 10-14 GPU·天（三预文本 × 4 epoch）。合计 **12-15 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 预文本数据清洗、难例筛选、负样本增强；Kimi K2.6 验证预文本任务的模型输出合理性（抽查）。
- **投稿目标会议与优先级**：CVPR 2027（中高）。
- **可行性与风险**：最大风险是预文本到下游的正迁移不确定。对策：先跑 VideoSSR 预文本对比消融确认增益方向，再扩规模；若转移弱，转作"对齐冷启动 + DPO"混合。

### Idea 5（高）跨视频功能步对齐网络：攻克 CrossVid 最难任务 / Cross-Video Functional Step Alignment (FSA-Net)

- **一句话简介**：把"跨视频功能等价步骤对齐"设为核心训练目标，教会模型跨视频语义对齐与区间定位。
- **动机与现有不足**：CrossVid FSA 人类 85.2% vs 最强模型 13.4%，是最大的方法缺口；现有时间定位方法只在单视频内做（Moment-DETR、TimeChat、GroundVTS arXiv:2604.02093），无跨视频"功能等价"对齐训练；YouCook2/Assembly101 含步骤级标注却未被用于跨视频对齐。
- **核心创新点**：(1) 构建跨视频步骤对齐训练集（YouCook2 同食谱不同实例、Assembly101 多视角同一程序）；(2) **时间-功能双嵌入对齐目标**（步骤对比学习 + 区间级伪标签）；(3) 输出规范化为 [start,end] 区间并做序列推理（对比两个视频的步骤序列）。
- **方法概要**：两阶段：A) 在步骤对齐对上 SFT（对比损失 + 区间回归）；B) GRPO（奖励 = 区间 IoU + 功能语义等价 LLM-judge）。基座 Qwen2.5-VL-7B，输出格式严格为时间区间。
- **数据集与基线**：训练 YouCook2、Assembly101、Charades-STA（伪标签）；评测 CrossVid FSA/PSS、QVHighlights、Charades-STA。基线：CrossVid 报告模型、GroundVTS、Chrono（arXiv:2406.18113）、LLaVA-MR（arXiv:2411.14505）。
- **评测指标**：主指标 CrossVid FSA accuracy、QVHighlights mAP@avg 与 R1@0.5；消融指标有无跨视频伪标签、对比损失权重、区间规范化格式影响。
- **算力与训练方案**：SFT 5 GPU·天 + GRPO 6 GPU·天（7B LoRA）。合计 **≈11 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 为同食谱不同视频生成步骤语义标注与"等价/不等价"判断（teacher 伪标签）；Kimi K2.6 做功能等价 LLM-judge 奖励。
- **投稿目标会议与优先级**：CVPR 2027（高）。
- **可行性与风险**：跨视频步骤伪标签有噪声。对策：课程式从同食谱对到跨程序对，伪标签置信度过滤，人工抽检 5%。

### Idea 6（中高）视障辅助视频理解的"缺失-画质"判别与空间推理校准 / Assistive Vision: Missing-Info vs. Poor-Quality Discrimination with Calibrated Spatial Reasoning

- **一句话简介**：基于 VisAssist 缺陷，训练第一人称辅助视频 LLM 能区分"信息缺失"与"画质差"，输出置信度与"建议补拍"动作。
- **动机与现有不足**：VisAssist（Computer Vision III · 论文 7）揭示三类系统缺陷——第一人称空间推理弱、无法区分信息缺失 vs 拍摄质量差（→危险幻觉）、非拉丁文本脆弱；目前无任何方法层工作，且辅助场景要求安全校准（宁可说"不确定"也不能瞎猜）。
- **核心创新点**：(1) 三类决策输出（回答 / 报告信息缺失 / 报告画质受限）+ 不确定性校准；(2) 合成第一人称空间推理与退化场景数据（运动模糊/遮挡/裁剪/抖动增强）做 RL 校准；(3) 安全拒绝奖励——对"证据不足却自信作答"重罚。
- **方法概要**：数据 = VisAssist + 在 Ego4D/Kinetics 子集上做退化增强（DeepSeek 生成标签与拒绝样本）；训练 SFT + 带校准奖励的 GRPO（正确回答加分、低置信度正确回答加分、高置信度错误回答重罚）；评测含 ECE 校准曲线。
- **数据集与基线**：VisAssist、EgoSchema（NeurIPS 2023）、NExT-QA 子集。基线：Qwen2.5-VL、VideoLLaMA3、Gemini-2.5-Pro（API 参考）。
- **评测指标**：主指标 VisAssist accuracy + 三类决策 F1 + 期望校准误差（ECE）；消融指标有无校准奖励、合成退化增强比例、拒绝率-准确率权衡（coverage）。
- **算力与训练方案**：合成数据离线（API + 图像处理）；7B LoRA SFT + GRPO ≈ 8-10 GPU·天。合计 **9-11 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 合成低画质/遮挡/抖动场景的 QA 与"信息缺失"标签；Kimi K2.6 做辅助回答的安全性一致性验证。
- **投稿目标会议与优先级**：CVPR 2027（Assistive Vision 相关 workshop/主会）或 AAAI 2027（中高）。
- **可行性与风险**：数据集规模有限、安全要求高。对策：人工评审安全边界，先做"拒绝→补拍"闭环 demo；风险点集中在校准奖励的权重调节。

### Idea 7（高）领域自适应第一人称视频理解（EgoCross Challenge 导向）/ Domain-Adaptive Egocentric Video Understanding

- **一句话简介**：面向手术/工业/极限运动/动物视角四域，用"共享+专属双 LoRA + 域自适应 GRPO + 合成目标域数据"提升跨域泛化。
- **动机与现有不足**：EgoCross（Computer Vision V · 论文 77）显示通用与专用模型域外泛化均差；`OmniEgo-R2`（arXiv:2605.24481）每域单独 SFT + 路由获得第二，但需大量目标域数据且不做联合/自适应训练；EgoCross Challenge（arXiv:2608.04589）官方已举办一届，方法仍缺。
- **核心创新点**：(1) **领域共享 + 领域专属双 LoRA**（共享学通用第一人称结构，专属学域内视觉语法，如手术器械纹理/动物视角运动学）；(2) 域自适应 GRPO（对难域——手术/极端运动——加大探索与奖励缩放）；(3) 合成目标域数据（DeepSeek 生成域内描述与 QA + 风格增强）。
- **方法概要**：基座 Qwen2.5-VL-7B；四域数据混合训练，训练时按域路由到专属 LoRA；评测 EgoCross 官方测试。
- **数据集与基线**：EgoCross、EgoExo4D（arXiv:2311.18259）、EgoSchema。基线：Qwen2.5-VL-7B、OmniEgo-R2（Open-Source 方案）、VideoLLaMA3。
- **评测指标**：主指标 EgoCross O.Avg（四域平均）；消融指标各域准确率、共享/专属 LoRA 消融、跨域迁移（训练域子集 → 评测全域）。
- **算力与训练方案**：双 LoRA（rank 32×2）+ GRPO ≈ 10-14 GPU·天。合计 **11-15 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 合成手术/工业/极限运动/动物视角场景描述与 QA（遵守数据许可）；Kimi K2.6 作域内答案 LLM-judge。
- **投稿目标会议与优先级**：CVPR 2027 或直接打 EgoCross Challenge @ EgoVis 2027（高）。
- **可行性与风险**：合成数据域逼真度不足是主要风险。对策：仅用合成数据做"冷启动 + 域路由预热"，真实数据负责精调；严格核查目标域数据许可。

### Idea 8（中）时间感知的零样本视频时刻检索 / Temporal-Aware Zero-shot Video Moment Retrieval

- **一句话简介**：把 GranAlign 的"逐帧余弦 + NMS"升级为带时间一致性约束、运动/轨迹条件化、连续粒度加权的打分框架。
- **动机与现有不足**：GranAlign（Computer Vision IV · 论文 32）逐帧独立打分破坏时间结构、无运动/物体轨迹建模、query-aware caption 有幻觉、语义相似度受 SentenceTransformer 上限约束；Moment-GPT（arXiv:2404.03171）/Chrono 亦未解决时间结构传播。
- **核心创新点**：(1) **时间一致性打分**：帧级相似度沿时间维做图扩散/CRF 平滑，约束连续性（利用状态转移/相邻帧平滑）；(2) **运动/轨迹条件化**：用 Grounding-DINO 框轨迹与光流引导打分窗口，动作出现/消失处局部加严；(3) **连续粒度加权**：按查询类型动态混合 simplified/detailed 路径权重（替代固定双路径平均）。
- **方法概要**：训练无关主框架（改进 GranAlign 的 Sf 计算 + 图扩散后处理）+ 可选 2B 轻量重排器微调提升上限。
- **数据集与基线**：QVHighlights、Charades-STA、ActivityNet-Captions、Moment-XL 长视频子集。基线：GranAlign、Moment-GPT、Chrono、GroundVTS。
- **评测指标**：主指标 R1@0.5/0.7、mAP@0.5/mAP@avg；消融指标时间图消融、运动条件消融、粒度权重自适应消融。
- **算力与训练方案**：主框架训练无关（推理用 API 生成 caption）；可选 2B 重排器微调 2-4 GPU·天。合计 **3-5 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 批量查询重写与 query-aware caption 生成（成本远低于 Qwen2.5-VL 单帧描述）；Kimi K2.6 抽查 caption 幻觉。
- **投稿目标会议与优先级**：ACMMM 2026 或 ICME 2027（中）；若重排器效果显著可冲 CVPR 2027。
- **可行性与风险**：纯打分方法存在天花板。对策：用轻量重排器对冲；时间图扩散参数需在验证集校准。

### Idea 9（中高）查询条件的极端视频 token 压缩 + 位置偏置校正 / Query-Conditioned Extreme Token Compression for Long Video

- **一句话简介**：学习式"每帧 ≤1 token"压缩并校正长上下文注意力的头尾偏置，让 7B 模型在 4×L40 上消化更长视频。
- **动机与现有不足**：`XComp`（arXiv:2604.14149，NeurIPS 2025）做到每帧 1 token 但压缩无查询条件、只用 2.5% SFT 数据；`FlexSelect`/`AdaptToken` 训练无关有信息丢失；APVR 训练无关、K 固定。现有方法普遍忽略 LLM 长上下文的头尾位置偏置。
- **核心创新点**：(1) **查询条件 token 合成**（用 query embedding 门控每帧压缩，区分"信息锚"与"故事线锚"）；(2) 局部注意力分块 + 位置重标注消除头尾偏置；(3) 只做压缩 SFT（<5% 数据量），即插即用于 Qwen2.5-VL 系。
- **方法概要**：从 VideoChat-Flash（arXiv:2501.00574）或 Qwen2.5-VL-7B 初始化，LoRA 训练"压缩器"；训练信号 = 帧重建自监督 + 少量 LVQA；推理时 ≤8K 视觉 token 预算。
- **数据集与基线**：LVBench、VideoMME、MLVU、LongVideoBench、StreamingBench。基线：XComp、FlexSelect、AdaptToken、VideoChat-Flash、Tempo（arXiv:2604.08120）。
- **评测指标**：主指标 8K token 预算下 LVBench/VideoMME accuracy；消融指标压缩比-准确率曲线、位置偏置诊断（首/中/尾区间命中率）、重建损失消融。
- **算力与训练方案**：7B LoRA 压缩 SFT ≈ 4-6 GPU·天；推理与评测 ≈ 2 GPU·天。合计 **<10 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 生成"帧→关键描述"压缩训练数据与评测辅助；Kimi K2.6 验证压缩后视频的可读性。
- **投稿目标会议与优先级**：NeurIPS 2026 / ECCV 2027（中高）。
- **可行性与风险**：极端压缩的信息丢失是核心风险。对策：重建损失 + 查询条件门控 + 关键帧兜底（保留 top 帧全 token）。

### Idea 10（中）时间接地多视频 QA：基准与合成-验证流水线（CrossVid 2.0） / Temporal-Grounded Multi-Video QA Benchmark & Synthetic Pipeline

- **一句话简介**：构建带证据区间标注的多视频 QA 基准，并提出"合成-验证-再合成"半自动流水线，让 CVR 方法可被客观诊断。
- **动机与现有不足**：CrossVid 只有答案正确率、无证据区间，无法诊断"答对但证据错"；其合成流水线只依赖 DeepSeek-R1 单 teacher、无独立验证环节；`TimeSearch`/Haystack 类证据基准只覆盖单视频检索。
- **核心创新点**：(1) 每题的**证据区间标注**（支撑答案的视频片段）；(2) "合成 → 双 LLM 交叉验证 → 专家抽检"闭环流水线，过滤率可量化；(3) 新指标 **Evidence-Grounded Accuracy (EGA)** = 答案正确 ∧ 证据区间与 GT 的 tIoU≥阈值。
- **方法概要**：从 YouCook2 / Assembly101 / VisDrone / Animal Kingdom 建组，DeepSeek V4 Pro 生成 QA+证据区间，Kimi K2.6 与 DeepSeek V4 Pro 交叉验证过滤，人工抽检 ~10%。
- **数据集与基线**：新基准（~5K QA）+ 在 CrossVid、All-Angles Bench 上复评。基线：Qwen2.5-VL-7B/72B、InternVL3-8B。
- **评测指标**：主指标 EGA、O.Avg；消融指标流水线过滤率、双 LLM 一致性、专家抽检一致率。
- **算力与训练方案**：数据合成与验证离线（API）；22 个开源模型评测 on 4×L40 ≈ 2-3 GPU·天。合计 **3-5 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Pro 合成 QA + 证据区间（teacher）；Kimi K2.6 与 DeepSeek 交叉验证（judge）；DeepSeek V4 Flash 初筛。
- **投稿目标会议与优先级**：NeurIPS 2026 Datasets & Benchmarks / CVPR 2027（中）。
- **可行性与风险**：证据区间标注质量与跨模型可比性。对策：区间标注协议 + 双 annotator 一致性测试；风险在自动生成的区间边界误差。

### Idea 11（中）水下与极端环境视频理解的持续自适应 / Continual Domain Adaptation for Underwater and Extreme-Environment Video Understanding

- **一句话简介**：在 UVLM 基础上用"退化增强 + 领域适配器 + 持续学习"提升水下 VidLM，且避免灾难性遗忘。
- **动机与现有不足**：UVLM（Computer Vision XI · 论文 22）只评测 2 个 VidLM、无方法；水下光照变化/浊度/视角多样且领域数据稀缺；通用域微调易遗忘 in-air 能力。
- **核心创新点**：(1) 水下退化模拟增强（浊度/光照/视角/运动模糊合成）；(2) 领域适配器 + 持续学习（LoRA 增量 + EWC 约束）；(3) 水下专用评测分解（生物/环境 × 内容/变化观测）。
- **方法概要**：Qwen2.5-VL-7B LoRA 微调，增强数据与真实数据混合；评测 UVLM 20 子任务与 VideoMME（检查遗忘）。
- **数据集与基线**：UVLM、可公开水下视频（如 DeepFish 子集）、VideoMME。基线：Qwen2.5-VL、UVLM 原文两个 VidLM、VideoLLaMA3。
- **评测指标**：主指标 UVLM 20 子任务平均准确率；消融指标增强消融、适配器消融、VideoMME 遗忘率（Δ）。
- **算力与训练方案**：7B LoRA ≈ 5-8 GPU·天。合计 **6-9 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 合成水下场景描述与 QA；Kimi K2.6 校验水下术语/识别正确性。
- **投稿目标会议与优先级**：ICRA 2027 / ICLR 2027 海洋 AI 方向（中）。
- **可行性与风险**：公开水下数据许可与标注噪声。对策：仅用明确开放许可数据；评测含专家抽检。

### Idea 12（中高）证据充分性驱动的自适应推理预算 / Evidence-Sufficiency-Driven Adaptive Inference for Video LLMs

- **一句话简介**：把"模型自我不确定性"变成可学习的早停/预算 RL 策略，训练视频 LLM 在 token 预算约束下最大化准确率。
- **动机与现有不足**：`AdaptToken`（arXiv:2603.28696）用熵做训练无关早停，但无学习、未对预算做多目标优化；APVR 固定 K 帧浪费/不足；`StreamForest`（arXiv:2509.24871）证明 1024 token 下保留 96.8% 准确率，说明预算控制是独立且重要的研究方向。
- **核心创新点**：(1) 将早停/预算决策建模为 **RL 策略**（状态 = 已看片段的熵/自信息/证据覆盖，动作 = 继续/停止/扩预算）；(2) 预算感知奖励 `accuracy − β·cost`，以"预算-准确率曲线 AUC"为优化目标；(3) 跨模型迁移（7B 上训练，72B 上直接可用）。
- **方法概要**：GRPO 训练 7B 基座 + 策略头，在多个长视频基准上滚动式推理；停止后直接作答。
- **数据集与基线**：VideoMME、LongVideoBench、LVBench、StreamingBench。基线：AdaptToken、FlexSelect、StreamForest、APVR。
- **评测指标**：主指标预算约束下 accuracy（曲线下面积 AUC）；消融指标早停率、冗余 token 占比、预算权重 β 扫描。
- **算力与训练方案**：7B LoRA GRPO ≈ 6-8 GPU·天。合计 **7-9 GPU·天**。
- **DeepSeek/Kimi API 用法**：DeepSeek V4 Flash 难例识别与预算效率评测；Kimi K2.6 验证"早停"答案质量。
- **投稿目标会议与优先级**：NeurIPS 2026（中高）。
- **可行性与风险**：多目标奖励（准确率 vs 预算）难平衡。对策：以 AUC 为主指标固定多个 β 点报告，避免单一权衡点过拟合。

## 七、综述性结论与投稿策略

### 7.1 核心结论

1. **9 篇收藏论文的方法论天平失衡**：5 篇为基准/评测（CrossVid、EgoCross、VisAssist、UVLM、SurdCRL），仅 4 篇为方法（APVR、GranAlign、TEMPLE、AMD-Net），且方法集中在"训练无关检索/压缩"与"偏好对齐"两个技术流派。
2. **三大空白明确**：(a) 跨视频/多视频证据整合无方法（CrossVid gap 50.4 vs 89.2）；(b) 视频 LLM 时间推理缺少"证据接地 + 可验证奖励"的训练目标（TEMPLE 只教检测扰动）；(c) 第一人称/极端领域（视障、手术、水下）只有基准、无可靠性与校准方法。
3. **2026 技术拐点确认**：外部文献显示长视频理解正从"启发式检索"转向"**可学习选择 + RLVR + agentic 主动感知**"（FrameThinker、TimeSearch-R、VSeek、OmniAgent、VideoSSR、Spatial-SSRL、SER）；同时 token 压缩在"每帧 1 token + 位置偏置校正"上取得进展（XComp）。谁先把这些信号整合进一个"检索-推理-验证"闭环，谁就有望在 CVPR 2027 占先。

### 7.2 投稿策略建议

- **高优先级冲刺（CVPR 2027）**：Idea 1（证据接地时间 RLVR）、Idea 5（跨视频功能步对齐）、Idea 7（EgoCross 域自适应）——三者分别命中时间推理、跨视频、第一人称三大空白，且与 2026 外部最热信号（RLVR/证据奖励/agentic）直接对齐。
- **中高优先级（NeurIPS 2026）**：Idea 2（跨视频证据路由）、Idea 9（查询条件极端压缩）、Idea 12（证据充分性预算）——效率与多视频两个高效能方向，NeurIPS 对 RL/效率类工作友好。
- **组合策略**：Idea 1 + Idea 3 + Idea 4 可合成一篇"**视频 LLM 的时间证据 RL 训练框架**"大论文（检索可学习 + 自监督可验证奖励 + 证据接地奖励三段式）；Idea 2 + Idea 5 + Idea 10 可合成"CVR 从基准到方法"系列（Idea 10 的基准可作为 Idea 2/5 的实验平台）。
- **风险对冲**：每篇主论文搭配一个低成本 idea（Idea 8、Idea 11）作为备选投稿（ACMMM/ICME/ICRA），避免单点押注。全部 12 个 idea 均在 4×L40、≤15 GPU·天的预算内可完成。
