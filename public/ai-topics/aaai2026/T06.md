## 一、主题概览与研究热点

LLM agent 已成为 AAAI 2026 最活跃的研究方向之一，本主题 20 篇收藏论文覆盖六大子方向：

1. **GUI 智能体（视觉定位与操作）**：从静态一次性视觉输入转向"主动感知"（何时/是否/如何观察界面），并借力 RLVR（Reinforcement Learning with Verifiable Rewards）提升定位的语义对齐（GUI-Eyes、InfiGUI-G1）。
2. **多智能体协作框架与协议**：从朴素"多智能体辩论（MAD）"转向结构化的角色分工、人格塑造、反事实测试、软件工程化协作（MUG、MAPS、Agent-Event-Coder、WikiMAG、DanceHA、MACoT）。
3. **智能体记忆与长期学习**：把经验组织成图/结构化记忆，做生成式重组与联想检索，驱动 agent 跨会话持续进化（CA3Mem）。
4. **工具选择、工具生成与代码**：绕过"每步 LLM 推理"的统计式工具路由（AutoTool）、企业工具自动生成与闭环验证（ToolSmith）、成对查询式代码选择（ExPairT-LLM）、规划+修复的代码生成（Self-PR）。
5. **Agent 基准评测**：面向真实社交媒体环境的逼真 agent 基准（SoMe），揭示主流 LLM agent 在现实场景的显著不足。
6. **MARL 上下文协调与工作流合成**：用去中心化记忆检索做多智能体上下文协调（MAICC）、仅通信联合行动估计联合信念（Dec-POMDP 共享建议）、隐私约束下的联邦式多智能体工作流合成（DAWN）。

**研究热点信号**：
- **GUI agent 进入"强化学习"时代**：GUI-R1（arXiv:2504.10458）、InfiGUI-G1、GUI-Eyes 等表明，RLVR/GRPO 以 3K 量级数据即可逼近乃至超越百万级 SFT 数据的性能，"数据效率 + 主动感知"成为核心竞争点。
- **多智能体从"辩论"走向"事实验证与分工治理"**：Problem Drift（arXiv:2502.19559）、Memory Contagion（arXiv:2606.23195）等揭示辩论/记忆会引入偏见与漂移，反事实测试（MUG）、可验证反馈（AEC）成为纠偏手段。
- **记忆系统成为 agent 基础设施**：MemGPT（arXiv:2310.08560）、HippoRAG（arXiv:2405.14831）之后，AgeMem（arXiv:2601.01885）、H-Mem（arXiv:2605.15701）、FadeMem（arXiv:2601.18642）等把记忆操作本身训练进策略，从"工具化记忆"走向"策略化记忆"。
- **工作流合成自动化**：AFlow（arXiv:2410.10762）、EvoMAS（arXiv:2605.08769）、OneFlow（arXiv:2601.12307）、DAWN 显示，工作流不再手工设计，而是通过搜索/RL/联邦学习自动合成与演化。
- **安全与评测成为刚需**：tool selection 的提示注入（ToolHijacker，arXiv:2504.19793）、特权滥用（ToolPrivBench，arXiv:2606.20023）、LLM-as-judge 可靠性（RuVerBench，arXiv:2606.29920）表明，评测与安全正与能力提升并重。

## 三、代表性论文精读（5 篇）

### 3.1 GUI-Eyes: Tool-Augmented Perception for Visual Grounding in GUI Agents（Multiagent Systems · 论文 7）
**原文**：arXiv:2601.09770。

**核心创新**：
1. **主动感知范式**：把"静态、一次性截图"升级为"两阶段推理决定是否/如何调用视觉工具（裁剪/缩放）"，即 agent 学会*何时看、看哪里、怎么看*。
2. **两级策略渐进感知**：粗粒度探索定位 ROI，再细粒度 grounding 精准落点，两级 policy 协调，缓解"一次性全屏定位"的噪声。
3. **空间连续奖励**：把工具使用的监督从"坐标是否命中"细化为"位置邻近度 + 区域重叠"的连续信号，缓解 GUI 环境奖励稀疏问题。

**实验**：GUI-Eyes-3B 用 3K 标注样本在 ScreenSpot-Pro 达 44.8% 定位准确率，显著优于监督与 RL 基线。

**不足与空白**：
- 仅在 *grounding* 基准上验证，未在**任务级**环境（OSWorld、WebArena）上报告端到端成功率，主动感知对完整多步任务的价值存疑；
- 视觉工具集（裁剪/缩放）是预设的，未涉及*何时不该用视觉工具而用 DOM/accessibility tree* 的跨来源感知融合；
- 训练依赖工具调用轨迹标签（是否调用、调用哪个工具），标注成本高；空间连续奖励的普适性（不同分辨率/窗口缩放）未探讨。

**心得**：GUI agent 的竞争已从"大模型能力"转向"感知策略 + 数据效率"；与 GUI-R1（arXiv:2504.10458）的 RLVR 路线互补，但两者都欠缺**跨会话记忆**——这是我后续 idea 的核心切入点之一。

### 3.2 CA3Mem: Evolving Generalist Virtual Agents with Generative and Associative Memory（Computer Vision XII · 论文 85）
**原文**：DOI: 10.1609/aaai.v40i15.38300。

**核心创新**：
1. **结构化记忆图**：受海马体启发的经验图（CA3 联想理论），把零散经验组织为可检索、可组合的图结构，而非孤立片段。
2. **生成式记忆重组**：在记忆图上组合/杂交不同经验，*合成新解决方案*以驱动 agent 进化，突破"只重放旧轨迹"。
3. **联想检索（扩散激活）**：以 spreading activation 召回"上下文相关且互补"的经验集合，替代脆弱的纯语义 top-k 检索。

**实验**：OSWorld 与 WebArena 上长时域规划、组合泛化、持续适应均明显提升。

**不足与空白**：
- 重组信号缺乏**明确奖励/验证**：哪些"合成方案"是真正有用的缺乏自动判断，容易合成幻觉方案；
- 记忆图为文本描述（轨迹转写），未充分融合**视觉状态记忆**，对 GUI 这类强视觉环境的信息损失大；
- 图规模增长与检索开销、以及"记忆污染后如何纠错/遗忘"未涉及（与 Memory Contagion arXiv:2606.23195、FadeMem arXiv:2601.18642 的问题互补）。

**心得**：记忆系统的瓶颈从"能不能存/取"转向"能不能**进化出新的有用方案**"以及"如何验证进化的价值"。这为我的 idea #1（感知记忆）与 idea #2（验证驱动的记忆进化）提供了直接空间。

### 3.3 MAPS: Multi-Agent Personality Shaping for Collaborative Reasoning（Data Mining and Knowledge Management III · 论文 53）
**原文**：DOI: 10.1609/aaai.v40i19.38669。

**核心创新**：
1. **人格驱动的异质协作**：基于大五人格（Big Five）为 agent 分配不同人格特质，塑造不同推理风格，克服多 agent 行为同质化；
2. **Critic 反射机制**：引入 Critic agent 反思中间输出、重审错误步骤、迭代精炼，突破"一次性回答"。

**实验**：三个推理基准上显著优于基线；跨不同 LLM 泛化、消融验证多 agent 协作收益。

**不足与空白**：
- 人格分配是**预定义静态**的，未随任务难度/内容自适应（难题该用什么人格组合没有建模）；
- Critic 与主 agent 共用同一 LLM，批判能力受同源偏见限制；
- 基准偏"单轮/数学/常识推理"，未覆盖长时域、工具交互、多模态场景；
- 人格有效性依赖提示词表述，跨 prompt 措辞的稳定性存疑（与 RobustFlow arXiv:2509.21834 的"指令变体鲁棒性"问题同源）。

**心得**：角色/人格治理（persona）方向正在从"提升能力"转向"分析偏见与公平"（对照 NLP II·论文 84），MAPS 未考虑人格可能引入的社会性偏见——两篇论文形成了天然的"能力 vs. 公平"张力，可做联合研究。

### 3.4 AutoTool: Efficient Tool Selection for Large Language Model Agents（Natural Language Processing II · 论文 46）
**原文**：arXiv:2511.14650（AAAI 2026）。

**核心创新**：
1. **工具使用惯性建模**：发现工具调用遵循可预测的序列模式，用有向图（节点=工具，边=转移概率）编码统计惯性；
2. **旁路 LLM 推理**：遍历图结构选择工具与参数，大幅减少"每一步都要 LLM 决定用哪个工具"的推理开销，成本最高降 30%；
3. **参数级信息整合**：在工具输入生成阶段注入参数级信息。

**不足与空白**：
- 图是**离线静态**的，冷启动（无历史轨迹）与工具集动态更新（新工具上线）场景失效；
- "惯性"假设在任务分布漂移时可能误导（统计图无法捕捉长尾任务语义）；
- 成功率仅"competitive"，缺少对**安全/特权工具选择**的约束（对照 ToolPrivBench arXiv:2606.20023 发现的过度特权问题）；
- 未测与最强开源 ReAct/RAG 类 agent 的严格吞吐-质量权衡。

**心得**：AutoTool 证明"统计结构 + 最小 LLM 调用"是可行的降本路径，但静态图是最大软肋——把图变成**在线学习、可更新、带安全约束**的工具路由是我 idea #3 的直接动机。

### 3.5 SoMe: A Realistic Benchmark for LLM-based Social Media Agents（Application Domains II · 论文 62）
**原文**：DOI: 10.1609/aaai.v40i2.37113。

**核心创新**：
1. **首个真实社交媒体 agent 基准**：8 类社交任务（内容创作、社区管理、信息验证、用户互动等），规模达 916 万帖 / 6591 用户 / 25686 报告 / 17869 人工标注查询；
2. **工具化 agent 评测环境**：让 agent 通过多种 agent 工具访问/分析社交数据，贴近真实平台 API；
3. **自动化评估协议 + 人工验证参考解**，给出主流闭源/开源 LLM 的首个系统性能画像。

**实验发现**：主流闭源与开源 LLM 都无法令人满意地完成社交 agent 任务，尤其在社会动态理解、用户意图把握上显著不足。

**不足与空白**：
- 基准是**静态快照**，不能测 agent 在非平稳、漂移平台上的适应能力（与 LLM 社交模拟的"演化"趋势脱节）；
- 任务难度高且缺少可操作的失败模式分类学（哪些子技能薄弱？）；
- 评测依赖 LLM/人工混合，成本高、可扩展性有限。

**心得**：SoMe 的"真实但静态"暴露了一个通用基准方法论缺口——**动态/自适应基准**。这一缺口也是 idea #9（非平稳环境适应基准）的立足点。

| NLP VI·13·SlideTailor | 隐式偏好蒸馏（示例对+模板）+ 语音链对齐 | 规模小；依赖示例质量；布局评测主观 |
| AAAI Emerging Trends·114·Self-PR | 方案库 + 自适应选择 + 迭代修复 | 修复可能循环；聚类粒度敏感；学生摘要规模小 |
| AAAI Emerging Trends·276·ToolSmith | 企业工具自动生成 + 沙箱闭环验证 | 依赖 API 规范/TSR；沙箱覆盖有限；缺公开基准 |
| Cognitive Modeling·35·Agentic-DRS | 元 agent 编排多专家评审；图匹配示例选择；DRS-BENCH | 设计评价主观；基准一致性待检验；跨风格泛化未验证 |

**跨论文共性空白（横向观察）**：
1. **验证/奖励信号稀缺**：MUG、CA3Mem、DAWN、MACoT、ExPairT 的共同痛点是"不知道什么是对/有用的结果"，可验证执行反馈（代码运行、API 调用、规则校验）是统一突破口。
2. **静态 vs. 动态**：AutoTool（静态图）、SoMe（静态基准）、MAPS（静态人格）都缺"在线适应"能力——动态、非平稳、自适应的 agent 是一个未饱和方向。
3. **记忆缺纠错与偏见治理**：CA3Mem 无遗忘/纠错，Persona-Bias 只观测不缓解，记忆污染（对照 arXiv:2606.23195）无人干预。
4. **安全/公平缺位**：AutoTool、ToolSmith、GUI-Eyes 均未考虑特权工具、注入攻击、偏见放大。

### Idea 1｜GUI 智能体的跨会话主动感知记忆
- **标题**：Perception-as-Memory: 面向 GUI 智能体的跨会话主动感知记忆（Perception-as-Memory: Cross-Session Active Perception Memory for GUI Agents）
- **一句话简介**：让 GUI agent 把"如何看界面"（感知策略与界面先验）沉淀为可跨会话复用的记忆，使主动感知越用越快。
- **动机与现有不足**：GUI-Eyes 学会"何时/如何调用视觉工具"，但每次会话都从零感知；CA3Mem 的记忆图是文本轨迹，缺视觉状态记忆。二者分离导致"感知效率"与"长期记忆"无法相互增益。
- **核心创新点**：(1) 提出"感知记忆"——按 app/页面指纹存储有效的感知策略（裁剪区域、缩放档位、视觉工具序列）；(2) 记忆驱动主动感知：两级策略先查记忆命中，再决定是否启动视觉工具，减少无效观测；(3) 感知记忆自动演进：任务成功后把感知策略写回记忆图并做生成式重组。
- **方法概要**：以 Qwen2.5-VL-7B 为底座（LoRA 微调）。数据流水线：在 ScreenSpot-Pro + 自采 500 页 GUI 快照上，用 DeepSeek V4 Pro 标注"感知决策轨迹"（是否缩放/裁剪、命中区域）。感知记忆用 KV 结构（页面指纹→感知策略→成功率统计），检索用"扩散激活式"的页面-元素图。训练两阶段：①SFT 记忆感知的行为克隆；②GRPO 用 grounding 命中率 + 调用次数（省观测）做奖励。
- **数据集与基线**：ScreenSpot-Pro、OSWorld、WebArena。基线：GUI-Eyes、GUI-R1、SeeClick、纯 RLVR 无记忆、MemGPT 式文本记忆 agent。
- **评测指标**：主指标：任务级成功率 + 平均每任务观测数（感知成本）。消融：有无记忆、记忆图 vs 纯 top-k 检索、是否扩散激活。
- **算力与训练方案**：Qwen2.5-VL-7B 全参 FSDP（4×L40）约 8 GPU·天 SFT + 10 GPU·天 GRPO；轨迹采集用 4 卡并行 rollout，共约 25 GPU·天。
- **API 用法**：DeepSeek V4 Pro 生成感知决策训练标签（LLM-as-teacher）；DeepSeek V4 Flash 作为沙箱环境中的执行/校验后端；Kimi K2.6 做记忆检索的语义判定。
- **投稿目标与优先级**：NeurIPS 2026（高）。
- **可行性与风险**：风险=OSWorld 环境搭建与 rollout 稳定性；缓解=先用 ScreenSpot-Pro 验证感知记忆收益，再上任务级环境；训练量可控（7B LoRA/全参均可）。

### Idea 2｜工具验证的反事实多智能体事实性裁决
- **标题**：TVC: Tool-Verified Counterfactual Tests for Multi-Agent Factuality（工具验证的反事实多智能体事实性裁决）
- **一句话简介**：把 MUG 的"图像反事实测试"推广为"工具可验证的反事实测试"，让多智能体裁决有可执行的地面真值。
- **动机与现有不足**：MUG 靠修改图像引入反事实证据识别幻觉 agent，但仅在可编辑图像域；开放域（百科/代码/数据）无法构造反事实图像。多智能体辩论（MAD）的共识只保证"一致"而非"正确"。
- **核心创新点**：(1) 反事实测试工具化——把关键论断转译为可执行检查（代码断言、API 查询、检索-比对），自动生成反事实问题；(2) 设计"卧底检测"协议：向 N 个 agent 注入真/假反事实事实，用正确率识别幻觉 agent，再以非幻觉子集做加权裁决；(3) 裁决结果回写记忆做"事实轨迹"（与 CA3Mem 记忆图衔接）。
- **方法概要**：数据：GAIA + HotpotQA + 自采 2K 带可执行答案的 QA。流水线：问题→论断抽取（DeepSeek V4 Pro）→反事实构造（改数值/日期/实体）→工具执行（Python REPL + Search API）给真值→N 个 agent 回答→幻觉检测→加权聚合。端到端在 3 个任务上做零样本评测，不训练主干，仅评测协议。
- **数据集与基线**：GAIA、HotpotQA、FEVER（事实性）。基线：MAD、单 agent CoT+self-consistency、LLM-judge、MUG 原协议（图像场景单独测）。
- **评测指标**：主指标：事实性准确率（相对工具真值）+ 幻觉 agent 检出率（F1）。消融：反事实注入比例、agent 数、加权 vs 投票。
- **算力与训练方案**：无需大训练；仅需 API 调用 + 单卡本地部署 7B judge 做对照。全程 <5 GPU·天。
- **API 用法**：DeepSeek V4 Flash 充当多数 agent 后端（成本低，适合"群体"）；DeepSeek V4 Pro 做论断抽取与反事实构造；Kimi K2.6 做长文证据比对。
- **投稿目标与优先级**：ACL 2027（中）或 AAAI 2027（高，若含评测基准）。
- **可行性与风险**：风险=反事实构造质量参差；缓解=人工抽检 200 例 + 工具真值优先；不需要大模型训练，硬件风险低。

### Idea 3｜在线自适应的工具调用图路由
- **标题**：OnlineTool: 在线自适应的工具调用图与安全感知路由（OnlineTool: Online Adaptive Tool-Invocation Graph with Safety-Aware Routing）
- **一句话简介**：把 AutoTool 的静态"惯性图"升级为在线可更新、带特权约束、冷启动引导的图路由。
- **动机与现有不足**：AutoTool 图离线构建、不随任务与工具集演化，冷启动失效；且无视工具特权差异（ToolPrivBench 显示 agent 倾向过度使用高特权工具），也无注入防御（ToolHijacker 可污染工具库）。
- **核心创新点**：(1) 在线图更新——执行中动态更新工具-工具转移概率与参数模板，新增工具自动以语义嵌入冷启动入图；(2) 安全感知路由——对工具打"特权/风险"标签，路由目标加入最小特权约束（同效低特权工具优先）；(3) 图-LLM 混合：图高置信时旁路 LLM，低置信或涉敏工具时回退 LLM 推理 + 沙箱校验。
- **方法概要**：在 ToolBench/自采 30K agent 轨迹上构建初始图；部署期每步：图打分→置信阈值判断→（低置信）LLM 调用→执行→更新图。最小特权约束用整数规划式打分 + 规则引擎。安全模块：涉及特权工具时强制经过执行沙箱（复用 ToolSmith 式验证）。
- **数据集与基线**：ToolBench、BFCL、tau-bench 子集。基线：ReAct、AutoTool、ToolLLM、带检索的 ToolRAG。
- **评测指标**：主指标：任务完成率 + 推理 token 成本（比 ReAct 降幅）+ 高特权工具使用率。消融：在线更新 vs 静态图、安全约束有无、冷启动引导有无。
- **算力与训练方案**：无大规模训练；图更新为在线统计；本地仅需 7B 小模型做低置信回退（可选 LoRA 微调 5 GPU·天）；主要成本在 rollout 评测，约 10 GPU·天。
- **API 用法**：DeepSeek V4 Flash 作为默认工具选择主模型（对比本地 7B 回退）；DeepSeek V4 Pro 生成初始轨迹图；Kimi K2.6 做工具描述语义嵌入与相似度检索。
- **投稿目标与优先级**：ACL 2027（高）或 ICLR 2027（中）。
- **可行性与风险**：风险=在线更新可能导致路由不稳定/震荡；缓解=加衰减窗口与置信门槛；安全模块实现复杂度高，可先做"最小特权 + 注入检测"子集。

### Idea 4｜多智能体社会性偏见的记忆级缓解与基准
- **标题**：FairMem-Soc: 基于记忆治理的多智能体角色偏见缓解（FairMem-Soc: Memory-Governed Mitigation of Persona-Induced Bias in Multi-Agent Systems）
- **一句话简介**：把 NLP II·论文 84 揭示的角色偏见从"只观测"推进到"可缓解"，并发布跨记忆场景的偏见基准。
- **动机与现有不足**：Persona-Induced Bias 发现优势群体 persona 被更不信任/更不坚持、存在内群体偏好，但无缓解方案；Memory Contagion（arXiv:2606.23195）证明偏见可通过记忆跨时间传播，说明"缓解必须进入记忆层"。
- **核心创新点**：(1) 记忆级去偏——在共享/个体记忆中显式标记"角色来源"，检索时做来源平衡采样，抑制内群体偏好；(2) 角色轮换对抗训练——训练期让同一 agent 随机轮换 persona 并监督其行为一致性，使"角色改变不改变可信度"；(3) 发布 **SocBias-Bench**：多模型 × 多群体规模 × 多轮交互 × 带记忆延续的偏见度量基准。
- **方法概要**：沿用论文 84 的协作问题求解 + 说服任务设定，扩展为多会话（带记忆）；实现三套缓解（来源平衡检索、轮换一致性微调、偏见感知 Critic）并测组合效果。数据合成用 DeepSeek V4 Flash 大规模生成对话；度量沿用 trustworthiness/insistence 协议 + 新增内群体偏好系数。
- **数据集与基线**：自建 SocBias-Bench（2K 任务 × 3 模型）；基线：无缓解 MAD、论文 84 原协议、单 agent 去偏提示。
- **评测指标**：主指标：偏见缺口（优势 vs 劣势 persona 的信任/坚持差）+ 群体决策公平性。消融：缓解机制逐一开/关、记忆窗口长度。
- **算力与训练方案**：7B 模型 LoRA 微调（一致性训练）约 8 GPU·天；对话生成全部走 API；评测 rollout 约 5 GPU·天。
- **API 用法**：DeepSeek V4 Flash 大批量合成对话与多 agent 模拟；DeepSeek V4 Pro 做偏见度量 judge；Kimi K2.6 做长会话记忆延续的评测环境。
- **投稿目标与优先级**：ACL 2027（中）或 FAccT 2027 类安全公平会议（高价值但需合规）。
- **可行性与风险**：风险=偏见度量可能随 prompt 抖动；缓解=固定协议 + 多 seed + 人抽检；缓解有效性可能有限，需报告诚实边界。

### Idea 5｜差分隐私异构联邦多智能体工作流合成
- **标题**：FedMAS-DP: 带差分隐私与异构基座的联邦多智能体工作流合成（FedMAS-DP: Federated Multi-Agent Workflow Synthesis with Differential Privacy and Heterogeneous Backbones）
- **一句话简介**：在 DAWN 的联邦工作流合成基础上，解决"异构基座不可聚合"与"隐私预算"两个缺口。
- **动机与现有不足**：DAWN 用参数共振 + 结构引力聚合各客户端工作流生成器，但假设各客户端用同构模型；现实中组织用不同 LLM/不同提示模板，参数级 SVD 去噪无法对齐异构语义；且无差分隐私保证。
- **核心创新点**：(1) **工作流级联邦对齐**——不再对齐模型参数，而是对齐"工作流图结构 + 节点语义"，用图匹配 + 原型学习聚合异构客户端；(2) 差分隐私预算分配——对成功轨迹注入噪声并动态调节每轮预算；(3) 跨客户端技能库——共享"技能原型"（提示模板 + 工具绑定）而非共享数据。
- **方法概要**：延续 DBS 基准（Difficulty-Based Skew）并扩展为"异构基座"设定（各客户端分别用 DeepSeek/Kimi/Qwen 系后端）。联邦算法：客户端本地用 AFlow 式搜索生成工作流图→语义归一化（LLM 把节点提示转写成共享 schema）→服务端用 Gromov-Wasserstein 图对齐聚合 + DP 加噪→下发原型图正则。
- **数据集与基线**：DBS、GAIA 拆分成客户端分片、HLE。基线：DAWN、AFlow、FedAvg 式 LLM 微调、集中式上界。
- **评测指标**：主指标：全局任务成功率 + 客户端间图分歧度 + 隐私预算（ε）预算消耗。消融：DP 有无、异构 vs 同构、技能库有无。
- **算力与训练方案**：无大模型训练；工作流搜索成本 = 客户端 rollout（DeepSeek API 主导）；本地 4 卡仅做图匹配与原型学习（轻量），约 10 GPU·天。
- **API 用法**：各客户端 agent 由 DeepSeek V4 Flash / Kimi K2.6 分别充当（制造异构）；DeepSeek V4 Pro 做语义归一化与原型提炼。
- **投稿目标与优先级**：NeurIPS 2026（中）或 IJCAI 2027（中）。
- **可行性与风险**：风险=语义归一化有信息损失，图匹配不稳定；缓解=原型数小 + 人审 100 图；隐私-效用权衡需系统评估，避免过度宣称。

### Idea 6｜认知负载自适应的思维链合成与蒸馏
- **标题**：LoadCalib: 面向小模型的认知负载自适应思维链合成（LoadCalib: Cognitive-Load-Calibrated Chain-of-Thought Synthesis for Small Models）
- **一句话简介**：把 MACoT 的"反思密度匹配"从人工调参升级为按样本难度自动校准的 CoT 合成器。
- **动机与现有不足**：MACoT 发现过多自我反思伤害小模型，但最优反思密度是经验值；同题不同难度样本的最佳负载不同；合成 CoT 也受教师能力上限约束。
- **核心创新点**：(1) **难度感知负载预测器**——训练轻量分类器预测题目难度，映射到反思密度档位；(2) **RL 式 CoT 合成器**——以"学生模型蒸馏后准确率"为奖励，用 REINFORCE 调 CoT 生成器（长度/反思密度/步骤粒度）；(3) 提出负载-收益曲线作为可迁移诊断工具。
- **方法概要**：教师 DeepSeek V4 Pro 生成候选 CoT 池（多档反思密度）；难度预测器用 BERT 级编码器在 10K 标注上训练；CoT 合成器为 7B 生成模型，奖励 = 学生（Qwen2.5-7B）在验证集蒸馏后 acc + 长度惩罚。数据：GSM8K、MATH、ASDiv 等。
- **数据集与基线**：GSM8K / MATH / ASDiv（蒸馏）+ MMLU 子集（泛化）。基线：MACoT、长 CoT 直接蒸馏、R1-Distill、无反思 CoT。
- **评测指标**：主指标：学生蒸馏后 pass@1（数学准确率）。消融：负载预测器有无、RL vs 启发式档位、反思密度档位数。
- **算力与训练方案**：7B 学生 LoRA 微调多轮（每轮 3 GPU·天，共 4-6 轮）+ 7B 合成器 LoRA（REINFORCE，8 GPU·天）；教师合成走 API。总计约 30 GPU·天。
- **API 用法**：DeepSeek V4 Pro 生成多档 CoT 池与难度标注；DeepSeek V4 Flash 廉价批量合成候选；Kimi K2.6 做长推理 CoT 对照。
- **投稿目标与优先级**：ACL 2027（高）或 EMNLP 2026（中）。
- **可行性与风险**：风险=RL 信号噪声（学生 acc 波动大）；缓解=种子固定 + 多档采样平均；训练循环较长，需控制轮次。

### Idea 7｜基于技能基元的去中心化 MARL 上下文协调
- **标题**：SkillCoord: 技能基元驱动的多智能体上下文协调（SkillCoord: Skill-Primitive-Driven In-Context Coordination for Multi-Agent RL）
- **一句话简介**：把 MAICC 的"轨迹检索作上下文"升级为"团队技能基元检索 + 信用校准"，提升未见过任务上的协调适应。
- **动机与现有不足**：MAICC 检索整段轨迹做上下文，细粒度任务信息被长轨迹稀释，且去中心化近似中心化嵌入存在蒸馏误差；在线/离线记忆的平衡是启发式。
- **核心创新点**：(1) 技能基元库——离线把成功轨迹聚类为"团队技能基元"（短子目标 + 分工模式），检索对象从整轨迹降为基元；(2) 中心化-去中心化一致性训练——用对比学习 + 蒸馏损失减小近似误差；(3) 基于混合效用（个体+团队回报）的在线记忆权重自调节，替换启发式平衡。
- **方法概要**：沿用 LBF 与 SMAC v1/v2 环境。流水线：离线收集成功轨迹→技能聚类（行为聚类 + LLM 语义标注可选）→中心化嵌入训练→去中心化策略蒸馏→在线执行时检索基元 + 混合效用校准。策略网络为 1M 级 MARL 网络（PPO/VDN/QMIX 底座）。
- **数据集与基线**：Level-Based Foraging、SMAC v1/v2（含未见地图）。基线：MAICC、ICAL（in-context alignment learning）、QMIX、MAPPO、带记忆的 AdHoc。
- **评测指标**：主指标：未见任务平均回报 / 胜率（快速适应）。消融：基元 vs 整轨迹、蒸馏损失有无、在线权重调节有无。
- **算力与训练方案**：MARL 网络规模小（<1B 参数），4×L40 并行 8 环境采样，训练 5-8 GPU·天；技能聚类为轻量计算。
- **API 用法**：DeepSeek V4 Flash 可选作技能基元的语义命名/检索增强（对照纯行为聚类）；无需大模型训练。
- **投稿目标与优先级**：NeurIPS 2026（中）或 AAMAS 2027（高，MARL 社区契合）。
- **可行性与风险**：风险=技能基元聚类质量敏感；缓解=多种聚类粒度交叉验证 + 基元数消融；中心化-去中心化差距可能在复杂 SMAC 地图放大，需早测。

### Idea 8｜不确定度引导的 GUI 语义对齐课程式 RLVR
- **标题**：CurriGUI: 不确定度引导的课程式 RLVR 用于 GUI 语义对齐（CurriGUI: Uncertainty-Guided Curriculum RLVR for GUI Semantic Alignment）
- **一句话简介**：把 InfiGUI-G1 的探索奖励与"课程难度 + 不确定度重采样"结合，进一步缓解 GUI grounding 语义对齐的稀疏探索。
- **动机与现有不足**：AEPO 用多答案生成 + 效率奖励提升探索，但均匀采样训练样本，难样本先学、易样本后学的课程顺序缺位；对哪些样本该多花探索的"不确定度"信号未用。
- **核心创新点**：(1) 不确定度驱动的样本重采样——以多答案分歧/自集成熵为不确定度，对高分歧（难语义对齐）样本加大探索预算；(2) 课程式 RLVR——先易后难（空间对齐→组合语义→跨平台），每阶段动态推进；(3) 把探索奖励 η=U/C 从全局改为不确定度加权。
- **方法概要**：底座 Qwen2.5-VL-3B/7B。数据：ScreenSpot / ScreenSpot-Pro + WidgetCaptioning + 自采 Web 指令对。流程：SFT 冷启→不确定度估算（N 次采样）→按不确定度分桶排课→GRPO 训练（AER 加权奖励 + 可验证坐标命中）→跨平台验证（移动/Web/桌面）。
- **数据集与基线**：ScreenSpot-Pro、GUIEnv 系 grounding 基准、MiniWob++（任务级可选）。基线：InfiGUI-G1、GUI-R1、朴素 RLVR、随机采样 RLVR。
- **评测指标**：主指标：grounding 准确率（尤其语义对齐类）。消融：课程有无、不确定度重采样有无、AER 加权有无、3B vs 7B。
- **算力与训练方案**：7B 全参 FSDP 需约 15 GPU·天/阶段，但用 3B 起步（8 GPU·天）验证；4 卡并行 rollout；总计 25-30 GPU·天。
- **API 用法**：DeepSeek V4 Pro 生成复杂语义对齐的负例/难例（扩充难样本）；DeepSeek V4 Flash 大批量弱标注候选；Kimi K2.6 做难样本池的语义一致性筛（judge）。
- **投稿目标与优先级**：ICLR 2027（中）或 CVPR 2027（高，GUI/多模态视觉社区）。
- **可行性与风险**：风险=RLVR 训练不稳定、课程顺序难定；缓解=先 3B 小规模调参，固定种子 + 早停；ScreenSpot-Pro 任务级奖励稀疏仍需规则化。

### Idea 9｜非平稳环境下的智能体适应能力基准（自适应基准）
- **标题**：EvoBench: 面向非平稳/漂移环境的 LLM 智能体适应基准（EvoBench: An Adaptation-Centric Benchmark for LLM Agents under Non-Stationary Environments）
- **一句话简介**：把 SoMe 的"静态快照"评测升级为"环境主动漂移"的动态基准，量化 agent 的在线适应能力。
- **动机与现有不足**：现有 agent 基准（SoMe、AgentBench、tau-bench）都是固定环境-固定工具-固定用户；真实部署中平台规则、工具接口、用户分布持续漂移，而"适应速度"这一维度无人评测。
- **核心创新点**：(1) 漂移引擎——按脚本/LLM 调度器在评测中途改变：工具 schema（参数改名/新增废弃工具）、UI 布局、用户偏好分布；(2) 适应指标套件——适应期成功率曲线下面积（AUC）、震荡度、漂移后恢复步数；(3) 两模式：无记忆 vs 带记忆，量化记忆系统对适应的贡献。
- **方法概要**：以 SoMe 8 类任务为基底重构为动态版（保留 916 万帖池，新增漂移注入层）；另构建 3 个域（GUI WebArena 子集、tool tau-bench 子集、社交 SoMe）各 4 种漂移类型 × 3 种强度。评测 harness 统一，支持多种 agent 接入。
- **数据集与基线**：SoMe（改造）、tau-bench（改造）、WebArena（子集）。基线：ReAct、带 MemGPT/CA3Mem 记忆的 agent、AutoTool 式图路由、无记忆单 agent。
- **评测指标**：主指标：漂移后适应 AUC + 平均成功率。消融：漂移类型 × 强度 × 有无记忆。
- **算力与训练方案**：无需训练；成本在评测 rollout（API + 本地沙箱）。4×L40 跑 WebArena 沙箱，约 8-12 GPU·天；社交/工具域走 API。
- **API 用法**：DeepSeek V4 Flash 作为被测 agent 后端之一（成本低，便于多 trial）；DeepSeek V4 Pro 生成漂移剧本与用户偏好迁移；Kimi K2.6 作为带记忆长会话 agent 基线。
- **投稿目标与优先级**：NeurIPS 2026（高，基准/评测方法论契合）或 ICLR 2027（中）。
- **可行性与风险**：风险=漂移设计可能过拟合特定评测；缓解=公开漂移引擎 + 多域交叉验证 + 社区共建；基准工作量较大，建议先做社交域 MVP。

### Idea 10｜从成对查询蒸馏可验证代码选择器
- **标题**：PairDistill: 把成对查询蒸馏为可训练代码选择器（PairDistill: Distilling Pairwise-Query Code Selection into a Trained Verifier）
- **一句话简介**：把 ExPairT-LLM 的"测试时 LLM oracle 成对查询"蒸馏为端到端可训练的选择器，降低推理成本并提升等价性判别。
- **动机与现有不足**：ExPairT 用成对成员/等价查询 + 锦标赛选程序，对判定错误鲁棒，但测试时每次都要查询 LLM oracle，成本高；且无训练，无法适应特定代码分布。
- **核心创新点**：(1) 离线蒸馏——用 DeepSeek V4 Pro 在 HumanEval/MBPP 上构造大规模成对偏好对，训练一个 1B-3B 验证器（pairwise preference / equivalence model）；(2) 训练时锦标赛 + 概率校准——把查询换成验证器的成对比较，保持对错误的鲁棒性；(3) 在线微调——在数据集内失败案例上持续 DPO 校准验证器。
- **方法概要**：数据流水线：LLM 生成 N 个候选程序 → DeepSeek V4 Pro 判"成员/等价" → 构造偏好对 → 训练验证器（LoRA，1.5B/3B）。测试：对候选程序跑锦标赛（验证器裁决），输出胜者。对照 ExPairT 的 LLM oracle。
- **数据集与基线**：HumanEval、MBPP、CodeContests（子集）、APPS（子集）。基线：ExPairT-LLM、pass@k 自采样、LLM-judge 选择、单元测试选择（上界）。
- **评测指标**：主指标：pass@1（选择后）+ 单样本选择成本（对比 oracle 查询数）。消融：验证器规模、蒸馏偏好量、锦标赛 vs 单次配对、DPO 微调有无。
- **算力与训练方案**：3B 验证器 LoRA 训练约 6 GPU·天；偏好对构建走 API；评测 rollout 约 4 GPU·天。
- **API 用法**：DeepSeek V4 Pro 离线构建成对偏好数据集（LLM-as-annotator）；DeepSeek V4 Flash 批量候选程序生成；Kimi K2.6 做难例等价判断交叉验证。
- **投稿目标与优先级**：ICLR 2027（中）或 AAAI 2027（高，若含代码基准）。
- **可行性与风险**：风险=验证器对复杂语义等价判别弱，蒸馏有上限；缓解=保留少量 oracle 兜底 + 置信度路由；确保与 ExPairT 同设置公平对比。

### Idea 11｜图网络性能预测器加速多智能体工作流合成
- **标题**：PerfSurrogate: 工作流性能预测器驱动的快速工作流合成（PerfSurrogate: GNN Surrogate for Fast Multi-Agent Workflow Synthesis）
- **一句话简介**：用轻量 GNN 预测"待选工作流"的任务成功率，把合成搜索（AFlow/DAWN 式）从"每步真跑 LLM"改为"先预测后验证"。
- **动机与现有不足**：AFlow/DAWN 合成工作流需要反复执行 LLM 验证，成本高昂；FLORA-Bench（arXiv:2503.11301）证明 GNN 可预测工作流性能，但仅在静态工作流集合上验证，未与合成搜索闭环。
- **核心创新点**：(1) 把工作流图（节点=agent 角色/工具，边=消息流）编码为 GNN，预测任务成功率；(2) 预测器与搜索闭环——MCTS/进化搜索用预测器剪枝候选，仅对高预测候选做真实执行验证；(3) 主动学习——预测不确定的候选优先真实执行并回填训练预测器。
- **方法概要**：构建工作流-性能数据集：在 GAIA 子集/多域任务上枚举 5K 个工作流并真实执行（DeepSeek V4 Flash 后端），得成功率标签；训练 GNN（节点属性=角色/tool 语义嵌入，边=消息类型）。搜索时：生成候选图→GNN 打分→top-k 执行→回填。
- **数据集与基线**：GAIA（subset）、HLE、MultiHop 推理任务。基线：AFlow、EvoMAS、随机搜索 + 全执行、FLORA-Bench 预测（开环）。
- **评测指标**：主指标：合成工作流最终成功率 + 达到同等质量所需的执行次数（降本倍数）。消融：预测器有无、剪枝阈值、主动学习策略。
- **算力与训练方案**：GNN 很小（<100M），4 卡共享训练 <1 GPU·天；数据构建 = 5K 工作流执行（API + 本地）约 5 GPU·天；搜索阶段 5 GPU·天。
- **API 用法**：DeepSeek V4 Flash 作为所有工作流节点的执行后端（批量低本）；DeepSeek V4 Pro 对低置信预测做验证；Kimi K2.6 生成节点语义嵌入标注。
- **投稿目标与优先级**：ICLR 2027（中）或 AAAI 2027（高）。
- **可行性与风险**：风险=预测器在小样本域偏差大；缓解=多域混合训练 + 不确定性门控；与 DAWN 的联邦设定衔接作为扩展。

### Idea 12｜安全感知的企业工具自动生成与验证闭环
- **标题**：ToolForge: 面向企业 API 的安全工具生成与沙箱验证闭环（ToolForge: Safety-Aware Enterprise Tool Generation with Sandboxed Validation）
- **一句话简介**：把 ToolSmith 的闭环验证 + AutoTool 的高效路由 + 注入/特权防御整合为一个企业工具全生命周期框架。
- **动机与现有不足**：ToolSmith 能生成并验证工具但未防注入（工具文档可被污染）与过度特权；AutoTool 高效但无安全；ToolHijacker 证明现有工具库易被注入攻击。
- **核心创新点**：(1) 生成时安全契约——工具生成时强制输出"最小权限声明 + 参数白名单 + 变更类型标注"，沙箱按契约执行；(2) 双通道校验——状态变更工具用参数派生查询回查（ToolSmith 思路）+ 静态注入扫描（工具文档敏感指令检测）；(3) 安全路由——生成工具进入 AutoTool 式图路由时带特权标签，路由优先低特权工具。
- **方法概要**：数据：自采 20 个企业 API（OpenAPI 规格，含购物/CRM/支付类），构造 200 个 TSR。流水线：TSR+OpenAPI→生成工具函数→安全契约提取→NL 测试生成→沙箱执行→状态回查→诊断反馈重生成→注入/特权评分→入路由图。评测含对抗性注入样本。
- **数据集与基线**：自建 EnterpriseToolBench（200 任务）；基线：ToolSmith、直接 GPT 生成、ReAct+工具库、图路由无安全版。
- **评测指标**：主指标：工具功能正确率 + 沙箱/契约通过率 + 注入攻击成功率（越低越好）+ 高特权工具使用率。消融：契约有无、注入扫描有无、路由特权约束有无。
- **算力与训练方案**：无大模型训练；7B 本地模型可选微调工具生成（LoRA 5 GPU·天）；主要成本为 API 生成 + 沙箱执行，约 8 GPU·天。
- **API 用法**：DeepSeek V4 Pro 生成工具与安全契约；DeepSeek V4 Flash 批量 NL 测试与图路由推理；Kimi K2.6 作为注入检测的独立 judge（避免同源偏置）。
- **投稿目标与优先级**：IEEE S&P/CCS 2027（高，安全契合）或 ACL 2027（中）。
- **可行性与风险**：风险=沙箱无法覆盖全部副作用，状态回查复杂；缓解=限定无外部依赖的沙箱子集先做；安全声明需谨慎，不做绝对保证。

## 七、综述性结论与投稿策略

### 7.1 主要结论
1. **GUI agent 与"主动感知 + 强化学习"是本主题最强增长点**：GUI-Eyes、InfiGUI-G1 与外部的 GUI-R1、MagicGUI、UItron 形成合流；3K 数据即可逼近大模型 SFT 方案，数据效率成为新壁垒。
2. **记忆系统的下一个战场是"进化 + 验证 + 治理"**：CA3Mem 做"重组出新方案"，但缺价值验证；外部 AgeMem/FadeMem/ChronoMem 在做"记忆即策略"，Memory Contagion 提示记忆会传播偏见——"如何进化出有用且无害的记忆"是空白。
3. **多智能体的收益正在被"漂移/偏见/低效"质疑**：Problem Drift、OneFlow（单 agent 可模拟同构工作流）、ConSensus（混合融合更省）都在压缩"无脑多 agent"的空间；结构化分工 + 事实验证 + 自适应拓扑才是方向。
4. **工具与工作流方向走向"合成 + 安全 + 在线适应"**：AutoTool（统计路由）、ToolSmith（闭环生成）、DAWN（联邦合成）单点成军，但静态/安全/异构基座三处缺口可组合出新工作。
5. **评测转向"动态、适应、可执行验证"**：SoMe 的静态真实感被"非平稳适应"需求补足；可执行验证（工具/代码/状态）正在取代纯文本指标。

### 7.2 投稿策略建议
- **NeurIPS/ICML**：偏方法 + 理论/RL 的 idea（#7 MARL 技能基元、#8 课程式 RLVR、#1 感知记忆），打磨理论（奖励设计、收敛性）。
- **ACL/EMNLP**：偏 NLP 应用的 idea（#2 工具验证反事实裁决、#6 认知负载 CoT、#3 在线工具路由），强调数据集与评测。
- **AAAI 2027**：idea 基准/系统型（#9 EvoBench、#11 PerfSurrogate、#10 PairDistill）契合 AAAI 的综合口味，且 AAAI 对"完整系统 + 诚实消融"宽容。
- **安全/公平会议（IEEE S&P、FAccT）**：#12 ToolForge、#4 FairMem-Soc 可做专题投递，先发制人。
- **资源最优组合**：4×L40 支持 7B-13B 全参与 30B LoRA；建议 idea #1/#6/#8 用 7B 全参（FSDP）+ GRPO；#2/#3/#5/#9/#10/#11/#12 以 API + 轻量本地为主，预算在 5-30 GPU·天/idea，12 个 idea 中选 3-4 个排期 2026 下半年并行推进（4 卡可并行 2 个 rollout 型 idea）。

### 7.3 风险提示
- 所有 idea 都强调"与基线同设置公平对比"——GUI-Eyes/InfiGUI-G1/CA3Mem 的复现（官方代码是否开源）是前置风险，应在立项 1 周内核实。
- RL 类 idea（#1/#6/#8）训练稳定性是最大技术风险，先 3B 起跑验证再扩 7B。
- 基准类 idea（#9）工程量大于算法量，注意分阶段交付。
