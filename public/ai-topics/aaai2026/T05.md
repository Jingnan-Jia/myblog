## 一、主题概览与研究热点

本主题共 28 篇 AAAI 2026 收藏论文，覆盖六个子方向：

| 子方向 | 篇数 | 代表论文（Session·论文号） |

| MoE 压缩与路由 | 3 | ML IV·86、ML VI·83、ML IX·68 |

| 数据选择与黑盒调优 | 3 | NLP II·83、NLP V·51、NLP V·81 |
| 极致压缩（权重级） | 1 | NLP IV·66 |

**2025–2026 年热点趋势**：

1. **PEFT 从"加参数"走向"感知输入/感知 token"**。经典 LoRA/DoRA 已非增量研究点，本批论文（GateRA、ProLoG、SFP、LoKI）转向 token 级门控、难度自适应、减法结构、防遗忘机制，说明 PEFT 研究进入"精耕细作"阶段：如何在同等参数预算下做到**输入自适应 + 保留通用能力**是共同命题。

2. **MoE 走向"高效化三件套"**：结构级（专家特化与路由）、压缩级（专家剪枝/合并/量化/蒸馏）、部署级（微专家跨矩阵粒度）。Sub-MoE/CAMERA 说明**专家冗余分析**是当前最活跃的 MoE 压缩切入点；B-Distill 开辟 MoE→MoE 蒸馏新设置；MASS/TopicLoRA 则强调**语义特化**与**主题对齐**的路由设计。

3. **KV cache 压缩从"启发式驱逐"走向"无损/学习型/模态感知"**：KeepKV 主张合并+无扰动补偿，DAVID 提出模态融合度驱动的分层策略，HACK 把头部划分为语义/结构两类，说明 KV 压缩已从单一注意力分数启发式升级为**多维度自适应预算分配**。

4. **推理效率进入"预算控制"时代**：o1/R1 之后学界普遍意识到 overthinking 问题，本批论文出现两条路线——**训练侧预算控制**（SABER 的 token 预算 RL、MARS 的三阶段自适应、TIV 的向量注入）与**推理侧干预**（PI 的测试时提示干预、ModelSwitch 的多模型切换、InTRO 的 token 级自我反馈）。

5. **数据选择从"数量→质量"转向"难度×多样性×贡献度"联合优化**：RICo 提出无梯度贡献度量，NLP II·83 把多样性细化到 token 统计层面，说明 SFT 数据工程已进入可量化的精细调度阶段。

## 二、收藏论文分类梳理（按子方向分组）

### 2.1 PEFT / LoRA（7 篇）

- **（Computer Vision IV · 论文 48 · Less Is More: Rethinking Parameter-Efficient Fine-Tuning from a Subtractive Perspective）**：提出**减法微调范式（SFP）**，用伪逆矩阵构造紧凑滤波器块替换冗余模块，冻结其余参数，VTAB 上比全量微调高 8.47%、参数减少 12%。方向反主流（减法 vs 加法）。
- **（Machine Learning VI · 论文 82 · ProLoG: Hybrid Prompt and LoRA Based Adaptation of Vision-Language Models for OOD Generalization）**：Prompt Tuning + LoRA 混合适配 VLM，用 LLM 生成的类别属性文本做增强正则化，并以任务相似度分数自适应决定推理时用 prompt 还是 LoRA，兼顾 ID 精度与 OOD 泛化。
- **（Machine Learning IX · 论文 52 · Optimizing LoRA Allocation of MoE with the Alignment of Topic Correlation）**：**TopicLoRA**，用 Big-Bench 类别构建主题先验图（GNN 增强表示），KL 双损失软对齐"输入-查询相关性"与"主题引导路由分布"，在 MMLU/GSM8K/Flanv2 上平均超 PEFT 基线 2.40%。
- **（Natural Language Processing II · 论文 40 · Hybrid Routing for a Mixture of LoRA Experts）**：**HotMoE**，浅层用 expert-expert attention（跨任务协作）、深层用 token-expert attention（任务语义精对准），配合相似度引导辅助损失，多任务指令调优中仅用 3.1% 可训练参数即显著提升。
- **（Natural Language Processing III · 论文 94 · GateRA: Token-aware Modulation for Parameter-Efficient Fine-tuning）**：在 LoRA/DoRA/HiRA 分支上加 **token 级自适应门控**，prefill 阶段抑制更新、decode 阶段增强适应，熵正则鼓励近二值稀疏门控，理论证明等价于 PEFT 路径上的软梯度掩蔽。
- **（Natural Language Processing IV · 论文 107 · LoKI: Low-Damage Knowledge Implanting of Large Language Models）**：基于 Transformer 知识存储机制（前向 MLP 中知识书写）设计 PEFT，显著缓解灾难性遗忘（CF），任务性能接近甚至超过全参微调。
- **（AAAI Emerging Trends in AI · 论文 279 · AutoTuneX: Interactive Automated Fine-Tuning for Large Language Models）**：基于 Bandit Limited Discrepancy Search 的自动化超参优化系统 + agentic chat 运行时，属**工程/工具型**贡献。

### 2.2 MoE 压缩与路由（3 篇）

- **（Machine Learning IV · 论文 86 · Sub-MoE: Efficient Mixture-of-Expert LLMs Compression via Subspace Expert Merging）**：对拼接专家权重做**联合 SVD**，提取共享 U 矩阵、合并专家专属 V 分量，缓解专家合并且冲突；K-means 输出相似度聚类 + 频域合并。Mixtral-8×7B 上 25%/50% 专家削减保持 96%/86% 性能。
- **（Machine Learning VI · 论文 83 · How Many Experts Are Enough? Towards Optimal Semantic Specialization for Mixture-of-Experts）**：**MASS**，梯度语义漂移检测器 + token 级路由置信度驱动的自适应专家扩展，合成设置下证明收敛到成本-性能最优平衡点。
- **（Machine Learning IX · 论文 68 · CAMERA: Multi-Matrix Joint Compression for MoE Models via Micro-Expert Redundancy Analysis）**：引入**跨矩阵的"微专家"**压缩单元，training-free 分析微专家贡献方差，衍生结构化剪枝（CAMERA-P）与混合精度量化（CAMERA-Q），Qwen2-57B 全量分析 <5 分钟/A100。

### 2.3 知识蒸馏（4 篇）

- **（Machine Learning V · 论文 63 · Balanced Knowledge Distillation for Large Language Models with Mix-of-Experts）**：**B-Distill**，开创 **MoE→MoE 蒸馏**设置；蒙特卡洛路由扰动解决"专家覆盖不足"，熵感知路由器蒸馏纠正"路由不平衡"，Rouge-L 最高提升 6.6%。
- **（Machine Learning V · 论文 68 · Distilling Cross-Modal Knowledge via Feature Disentanglement）**：跨模态（视觉→语言）蒸馏中按**频域解耦**——低频强对齐、高频松弛对齐 + 尺度一致性损失 + 共享分类器，缓解模态表示不一致。
- **（Natural Language Processing III · 论文 26 · GrayKD: Distilling Better Knowledge from Black-box LLM via Multi-rationale Injection）**：**"灰盒"蒸馏**，通过轻量 cross-attention 把黑盒 teacher 的多条 rationale 注入学生（teacher mode），再以 softmax 级知识训练（student mode），接近白盒效果、保持黑盒适用性。
- **（Natural Language Processing V · 论文 50 · LLM-Oriented Token-Adaptive Knowledge Distillation）**：**AdaKD**，统一 token 难度指标驱动两个模块——Loss-driven Adaptive Token Focusing（聚焦学生不稳定 token）+ 逆难度温度缩放（难 token 低温纠错、易 token 高温泛化），即插即用。

### 2.4 KV cache 压缩与上下文管理（4 篇）

- **（Machine Learning III · 论文 9 · DAVID: Dual-stage Adaptive Vision-text Integrated Decoupling for Multimodal KV Cache Eviction）**：观察浅层视觉-文本融合低、深层融合高，据此浅层**解耦逐出**、深层**超模态逐出**，用轻量融合度量+阈值切换层策略。
- **（Machine Learning VII · 论文 3 · Head-Aware KV Cache Compression for Efficient Visual Autoregressive Modeling）**：**HACK**，VAR 模型注意力头分为 Contextual（语义）与 Structural（空间）两类，离线分类后按类分配非对称缓存预算，复杂度 O(n⁴)→O(Bn²)，70% 压缩无质量损失。
- **（Natural Language Processing IV · 论文 67 · KeepKV: Achieving Periodic Lossless KV Cache Compression for Efficient LLM Inference）**：**合并式无损压缩**，Electoral Votes 机制记录合并历史并自适应调整注意力分数，Zero Inference-Perturbation Merging 补偿合并损失，10% 预算下仍保持高质量、吞吐提升 2×+。
- **（AAAI Emerging Trends in AI · 论文 220 · Algorithms for Context Engineering in LLM Inference: Optimization of Placement, Compression, and Scheduling）**：把**放置/压缩/调度**建模为耦合优化问题，含可证明近似保证的显著性感知保留策略、分层压缩误差传播界、概率预取调度；偏框架/提案型（无完整实验）。

### 2.5 高效推理 / CoT 压缩 / 自适应推理 / 测试时计算（6 篇）

- **（Machine Learning I · 论文 68 · Do We Truly Need So Many Samples? Multi-LLM Repeated Sampling Efficiently Scales Test-Time Compute）**：**ModelSwitch**，重复采样-投票框架中纳入多模型（含弱模型），以样本一致性为信号动态切换，7 数据集上超 self-consistency 与多智能体辩论且省成本，有理论分析。
- **（Natural Language Processing I · 论文 22 · TIV: Thought Injection via Vectors for Efficient Reasoning in Large Reasoning Models）**：**向量注入思维**，把 token 级推理压缩成可学习向量注入各层末 token 的后注意力隐状态，两阶段 RL（校准→向量策略蒸馏），保留 99% 精度、输出缩短 65%+。
- **（Natural Language Processing V · 论文 67 · Test-time Prompt Intervention）**：**PI**，测试时 When/How/Which 三模块干预（何时干预、如何干预、干预后采样），把人类解题经验与认知科学原理注入推理路径，缩短 CoT 并减少幻觉。
- **（Natural Language Processing VI · 论文 8 · MARS: Multimodal Adaptive Reasoning Model for Avoiding Overthinking）**：多模态三阶段训练（CoT Masking → 自适应难度指令 → 基于信息瓶颈 GRPO 的轻量 RL），CoT 长度降 90.2%、精度反升 0.54%。
- **（Natural Language Processing VI · 论文 54 · SABER: Switchable and Balanced Training for Efficient LLM Reasoning）**：对训练样本画像其基础模型思考 token 用量并分到预算层，长度感知奖励 + no-think 样本，支持 NoThink/FastThink/CoreThink/DeepThink 四档推理模式；FastThink 减 65.4% 长度且 MATH 精度 +3.6%。
- **（Natural Language Processing VI · 论文 81 · InTRO: In-Token Rationality Optimization via Self-Feedback）**：用"生成策略 vs 答案条件化策略"的信息差异估计 **token 级修正因子**做信息性下一 token 选择，单次前向即获得自我反馈，6 个数学基准相对提升最高 20%，CoT 更简洁且可跨域迁移。

### 2.6 数据选择与黑盒调优（3 篇）

- **（Natural Language Processing II · 论文 83 · From Macro to Micro: Probing Dataset Diversity in Language Model Fine-Tuning）**：对 SFT 多样性提出**宏观（整条指令语义）/中观（指令单元）/微观（响应 token 统计分布）**三层分类，实验表明响应侧微观多样性与性能相关最强且最高多样性最优。
- **（Natural Language Processing V · 论文 51 · Advanced Black-Box Tuning of Large Language Models with Limited API Calls）**：用 **Gaussian Process 代理**拟合"LogitMap 对"，以最少但高信息量的 API 查询逼近 foundation model 输出指导 proxy 训练；准确率 55.92%→86.85%，API 查询频率降至 1.38%。
- **（Natural Language Processing V · 论文 81 · RICo: Refined In-Context Contribution for Automatic Instruction-Tuning Data Selection）**：**无梯度**细粒度贡献度量（ICL 启发），量化样本对任务级/全局性能的贡献；LLaMA3.1-8B 上 15% 选择数据超全量 5.42 个百分点；选择出的样本是"多样+适中难度"，而非单纯最难。

### 2.7 极致压缩（1 篇）

- **（Natural Language Processing IV · 论文 66 · PocketLLM: Ultimate Compression of Large Language Models via Meta Networks）**：编码器把 LLM 权重投影到离散潜码、用紧凑 codebook 表示、轻量解码器还原，Llama2-7B 压缩 10× 精度损失可忽略。

## 三、代表性论文精读（5 篇）

### 3.1 PEFT 代表：GateRA（Natural Language Processing III · 论文 94 · GateRA: Token-aware Modulation for Parameter-Efficient Fine-tuning，arXiv:2511.17582）

**精读要点**：
- **问题**：LoRA/DoRA/HiRA 对所有 token 施加静态、输入无关的低秩更新，忽略输入难易差异，导致平凡内容过拟合、关键区域欠适应，且 prefill 与 decode 动力学不同却被同样对待。
- **方法**：在标准 PEFT 分支引入自适应门控 g(x)，按 token 实时调节更新强度；熵正则把门控推向近二值（可解释、稀疏、无硬阈值）；理论分析证明等价于在 PEFT 路径上做软梯度掩蔽。
- **关键观察**：可视化显示相位敏感行为——prefill 冗余 token 被自动抑制，decode 阶段强化适应。

**不足与空白**：
1. **rank 固定**：门控只调制更新"强度"，不调制更新"秩"，容易 token 的强更新仍占用高秩，困难 token 需要的高秩却受上限约束；
2. **无遗忘保护**：GateRA 未显式处理通用能力保留，极端适应时仍可能灾难性遗忘；
3. **门控开销**：token 级门控增加每步计算与激活内存，作者未量化在长上下文/批量推理下的真实端到端收益。

**启示**：PEFT 的下一步是**"rank × 强度 × 遗忘"三维联合自适应**，即让秩分配、更新强度与知识保留在同一可微框架内协同（见 Idea 1）。

### 3.2 MoE 压缩代表：Sub-MoE（Machine Learning IV · 论文 86 · Sub-MoE: Efficient Mixture-of-Expert LLMs Compression via Subspace Expert Merging，arXiv:2506.23266）

**精读要点**：
- **问题**：专家合并方法被"专家专业化引起的参数冲突"限制——直接对权重平均/合并会互相抵消。
- **方法**：两阶段。(1) 自适应专家聚类：对专家输出做余弦相似度 K-means，聚功能一致的专家；(2) 子空间专家合并：**Experts Union Decomposition**——对同组专家拼接权重联合 SVD，提取共享 U 矩阵（冲突参数低秩投影），专家专属 V 分量按频域合并，用合并 V 重建专家。可扩展专家内压缩。
- **结果**：Mixtral-8×7B 上 25%/50% 专家削减保持 96%/86%；优于现有剪枝/合并方法。

**不足与空白**：
1. **training-free 上限**：合并后不重新训练，复杂推理任务（数学/代码）性能衰减更明显，缺少"合并→蒸馏/微调恢复"闭环；
2. **聚类粒度粗糙**：K-means 按输出相似度聚类，未利用微专家（CAMERA 式跨矩阵）冗余结构，冲突消除仍停留在专家级；
3. **路由与共享知识割裂**：合并过程忽略共享专家与路由分布，可能破坏 token 选择专家的一致性。

**启示**：MoE 压缩的正确姿势是**"冗余分析（微专家粒度）→ 子空间对齐合并 → 蒸馏微调恢复"**三阶段流水线（见 Idea 3）。

### 3.3 蒸馏代表：B-Distill（Machine Learning V · 论文 63 · Balanced Knowledge Distillation for Large Language Models with Mix-of-Experts，AAAI 2026 录用）

**精读要点**：
- **问题**：MoE 蒸馏现有 dense-to-dense 与 moe-to-dense 两种，架构不匹配使学生吸收不充分；新设置 **MoE→MoE** 引入两类不平衡：(a) 专家覆盖不足——传统蒸馏只利用 teacher 路由器激活的少数专家；(b) 路由不平衡——学生路由分布偏离 teacher，学不会如何分发专家。
- **方法**：蒙特卡洛探索随机扰动路由器概率，使每个 teacher/student 专家都被采样且不扩大搜索空间；熵感知路由器蒸馏，把学生路由对齐 teacher 同时遏制负载坍缩。
- **结果**：Rouge-L 最高提升 6.6%。

**不足与空白**：
1. **专家粒度粗**：B-Distill 在整专家粒度蒸馏，未触及 CAMERA 揭示的跨矩阵微专家冗余结构；
2. **隐状态对齐缺失**：主要靠 logit/路由信号，未做子空间级（SVD 对齐）的隐层蒸馏，导致架构差异吸收有限；
3. **下游验证单薄**：以 Rouge-L 为主要指标，缺少 MMLU/GSM8K/HumanEval 等多任务与缩放分析。

**启示**：把 B-Distill 的路由平衡机制与 Sub-MoE 的子空间对齐、CAMERA 的微专家粒度结合，可显著提升 MoE→MoE 蒸馏效果（见 Idea 3）。

### 3.4 KV cache 代表：KeepKV（Natural Language Processing IV · 论文 67 · KeepKV: Achieving Periodic Lossless KV Cache Compression for Efficient LLM Inference，arXiv:2504.09936）

**精读要点**：
- **问题**：驱逐式压缩信息丢失致幻觉；合并式保留更多信息但引入合并前后注意力分布不一致，退化生成质量。
- **方法**：(1) Electoral Votes 机制记录合并历史、自适应调整注意力分数（保住被合并 key 的"选票"）；(2) Zero Inference-Perturbation Merging 补偿合并造成的注意力损失；(3) 单步无损、多步提供误差界。
- **结果**：吞吐提升 2×+，仅 10% KV 预算仍保持生成质量。

**不足与空白**：
1. **预算分配与内容无关**：合并预算按统一策略分配，未按头部/层/模态重要性差异做非对称预算（HACK/DAVID 的思路未融合）；
2. **学习型评分缺失**：Electoral Votes 仍是规则式，可被一个从全缓存注意力蒸馏出的轻量评分器替代，以获得更强的跨模型可迁移性；
3. **与推理阶段脱节**：长 CoT 推理中早期推理步的 KV 往往冗余，KeepKV 未感知"推理阶段"来激进释放（见 Idea 6）。

**启示**：KV 压缩应向**"学习型重要性评分 + 层/头/模态非对称预算 + 推理阶段感知"**三者收敛（见 Idea 5、6）。

### 3.5 高效推理代表：SABER（Natural Language Processing VI · 论文 54 · SABER: Switchable and Balanced Training for Efficient LLM Reasoning，DOI:10.1609/aaai.v40i41.40799）

**精读要点**：
- **问题**：CoT 推理统一施加给所有问题，简单题也付全量推理成本。
- **方法**：先对每个训练样本画像基础模型思考 token 用量并分配到预定义预算层；微调时用系统提示 + 长度感知奖励约束模型遵守预算；并行加入 no-think 样本保证关掉显式推理仍可靠；推理时支持 NoThink/FastThink/CoreThink/DeepThink 四档。
- **结果**：FastThink 减 65.4% 推理长度、MATH 精度反升 3.6%；跨规模跨域泛化好。

**不足与空白**：
1. **离散预算、超参多**：预算层数量与边界需要人工设定并逐模型 profile，迁移成本高；
2. **难度信号粗糙**：以基础模型 token 用量画像难度，未利用更强模型（如 DeepSeek-V4）的难度先验做合成标签；
3. **与 KV/内存耦合缺位**：预算控制只减 token 数，未与 KV 缓存释放联动，推理内存峰值问题未解。

**启示**：SABER 的预算控制 + 连续化难度标签 + 与 KV 管理耦合，是高效推理的明确演进方向（见 Idea 6、7）。

## 六、研究 Idea（12 个，完整实验方案）

> 所有方案基于 4×L40（192GB）与 DeepSeek/Kimi API，优先控制在数十 GPU·天。

### Idea 1：DR-LoRA —— 难度自适应动态秩 LoRA 与遗忘补偿
**Difficulty-Aware Dynamic-Rank LoRA with Catastrophic-Forgetting Compensation**

**一句话简介**：让 LoRA 的**秩分配、更新强度、知识保留**在同一可微框架内协同，按 token/样本难度动态分配秩并补偿灾难性遗忘。

**动机与现有不足**：GateRA 实现了 token 级更新强度门控但秩固定（NLP III·94）；AdaLoRA 做静态秩分配（arXiv:2303.10512）但无输入自适应；LoKI 用机制先验防遗忘（NLP IV·107）但不感知难度。三者各自解决一个维度，尚无联合方案。

**核心创新点**：
1. 按难度动态分配秩：每层并行 r=1..R 的秩分量，轻量路由器输出秩软掩码，难度由信息差异估计器（InTRO 的修正因子思想，NLP VI·81）实时估计；
2. 冻结原模型作 teacher 的 reverse-KL 蒸馏正则，在任务适应中显式保留通用能力（防遗忘）；
3. 训练后对低激活秩分量做减法合并（融合 SFP 思想，CV IV·48），同时减参与提速。

**方法概要**：
- 基座 LLaMA-3-8B / DeepSeek-R1-Distill-7B，LoRA 分支扩展为 R 个秩分量（R=8，秩 4/8/16/32 混合），门控路由器 g(x)∈[0,1]^R；
- 损失 = CE + λ₁·难度加权 CE + λ₂·reverse-KL(冻结原模型) + λ₃·秩稀疏正则（鼓励近二值）；
- 难度估计器 = 生成策略与答案条件策略的 per-token 信息差异，初始化后与小模型共训；
- 训练后：按路由器统计剪除长期低门控的秩分量，剩余分量与基座合并。

**数据集与基线**：训练 CommonsenseQA/GSM8K/MATH/MMLU 混合指令；评测 MMLU、GSM8K、MATH、MMLU-PRO。基线：LoRA、DoRA（arXiv:2402.09353）、AdaLoRA（arXiv:2303.10512）、GateRA（arXiv:2511.17582）、HiRA、全参微调。

**评测指标**：主指标=任务 acc + 通用能力保持率（zero-shot MMLU/MATH 对比微调前后）；消融=平均有效秩/参数量、门控稀疏度、推理延迟、遗忘率（类 LoRA Learns Less 测法）。

**算力与训练方案**：4×L40；FSDP 2 卡 + QLoRA 8B；~12k 步、bs=64、约 1 个 epoch 混合数据；预计 10–20 GPU·天。

**DeepSeek/Kimi API 用法**：用 DeepSeek-V4 对训练样本生成多步推理链并标注难度等级（1–10），作为难度估计器的监督信号与评测 judge。

**投稿目标与优先级**：NeurIPS 2026（高）。

**可行性与风险**：风险=门控路由器在长序列下开销放大（需在 3.1 中量化为收益）；秩分量并行增加显存 ~15%（4×48GB 充足）；难度估计器依赖基模型采样质量（低风险，可用 API 增强）。

### Idea 2：COMET —— 可组合子空间正交 LoRA 专家
**Composable Subspace-Orthogonal PEFT Experts with Conflict-Aware Routing**

**一句话简介**：让多个任务 LoRA 专家在共享子空间内正交化训练，实现"可合并、可增减、可组合"的多任务 PEFT 平台。

**动机与现有不足**：HotMoE（NLP II·40）与 TopicLoRA（ML IX·52）专注路由，但多个 LoRA 专家直接组合/合并时存在参数冲突（Sub-MoE 在 MoE 侧已指出该问题，ML IV·86）；LoRA Hub 类工作只在推理时合并权重，无冲突控制；现有"多 LoRA 合并"普遍掉点。

**核心创新点**：
1. 共享子空间 + 正交化：所有任务 LoRA 专家在联合 SVD 得到的共享 U 矩阵下训练其专属 V 分量，训练中加正交性约束，使合并时冲突可证明减少；
2. 冲突感知路由：路由器按"候选专家对输入的适配分数 + 相互干扰度量"动态选择专家子集，而非只看任务相似度；
3. 增量可扩展：新任务只需新增一个 V 分量，支持运行时增减专家、无损合并。

**方法概要**：
- 基座 LLaMA-3-8B；对 T 个任务各训练一个 LoRA 专家，初始化时做联合 SVD 得到共享 U（维数 d×r）；
- 训练损失 = 任务 CE + Σ_t 专家间正交正则（V_i^T V_j→0）+ 路由一致性正则；
- 推理：评分器输出 (adapt_score, interference) 决定激活专家子集；可选合并 (weighted sum in shared subspace)。

**数据集与基线**：Flan-v2、MMLU、GSM8K、HumanEval、MT-Bench（多任务场景）；基线 LoRA、LoRA+（arXiv:2402.12354）、MoE-LoRA（MoEfication 式结构）、HotMoE（NLP II·40）、TopicLoRA（ML IX·52）、Naive LoRA Merging（Task Arithmetic / LoRA Hub）。

**评测指标**：主指标=各任务 acc 与平均 acc；消融=专家组合数量 vs acc 曲线、任务间干扰（负迁移）、合并无损度、推理延迟、新增专家训练成本。

**算力与训练方案**：4×L40；QLoRA 8B 并行训练 T=6 个任务专家（每任务 1 卡）+ 1 卡路由器；预计 15–25 GPU·天。

**DeepSeek/Kimi API 用法**：Kimi K2.6/DeepSeek-V4 合成多任务指令对与任务描述嵌入（用于路由特征），DeepSeek-V4 做 LLM-as-judge 评测 MT-Bench。

**投稿目标与优先级**：ICML 2027（中）。

**可行性与风险**：风险=正交约束可能降低单任务上限（需与 GateRA 式难度调制结合消融）；SVD 共享子空间对异构任务秩需求敏感（建议 r 按任务自适应）。

### Idea 3：MEKD —— 微专家均衡 MoE→MoE 蒸馏
**Micro-Expert Balanced MoE-to-MoE Distillation with Subspace Alignment**

**一句话简介**：把蒸馏粒度推进到**跨矩阵微专家**层面，融合路由平衡（B-Distill）、子空间对齐（Sub-MoE）与冗余分析（CAMERA），蒸馏 MoE→小 MoE。

**动机与现有不足**：B-Distill 解决 MoE→MoE 的覆盖与路由不平衡但只在整专家粒度（ML V·63）；CAMERA 证明微专家（跨矩阵）是更细冗余单元（ML IX·68）；Sub-MoE 的子空间合并是 training-free 且无蒸馏恢复（ML IV·86）。三者未打通。

**核心创新点**：
1. **微专家级蒸馏**：对 teacher/student MoE 层做联合 SVD，对齐共享 U 子空间，蒸馏每个微专家（如 V 分量的隐层激活），比整专家蒸馏吸收更充分；
2. **路由蒸馏 + 负载均衡**：继承 B-Distill 的蒙特卡洛覆盖采样与熵感知路由正则，学生路由器向 teacher 对齐同时避免负载坍缩；
3. **蒸馏→压缩闭环**：蒸馏完成后再接 CAMERA 式剪枝/量化，全链路训练-free 分析 + 训练恢复两步走。

**方法概要**：
- teacher：Mixtral-8×7B（INT4）或 DeepSeek-MoE-16B；student：2B 级小 MoE（如 OLMoE-1B，8 专家）；
- 蒸馏损失 = 微专家隐层对齐（在共享 U 子空间内）+ logit KL + 路由分布 KL + 覆盖均匀性正则；
- 每 k 步执行微专家贡献统计（类 CAMERA 的 5 分钟分析），把低贡献微专家并入共享 V 或降精度。

**数据集与基线**：UltraChat、OpenWebMath、Flan、MATH（合成 CoT）；评测 MMLU、GSM8K、HumanEval、BBH。基线：MoE→Dense KD（MiniLLM，arXiv:2306.08543）、MoE→MoE（B-Distill，ML V·63）、专家合并（Sub-MoE，arXiv:2506.23266）、专家剪枝（CAMERA，ML IX·68）、QLoRA 直接微调小 MoE。

**评测指标**：主指标=下游 acc + 激活参数/总参数比；消融=专家覆盖度（teacher 专家被采样比例）、路由负载均衡（熵、max load）、微专家对齐度、推理吞吐。

**算力与训练方案**：4×L40；teacher INT4（Mixtral 47B 总参 ~24GB）驻留 1–2 卡推理生成数据，student 2B MoE 在 2–3 卡 FSDP 蒸馏；预计 30–40 GPU·天。

**DeepSeek/Kimi API 用法**：DeepSeek-V4/Pro 合成高质量指令与 CoT teacher 响应（student 规模太小无法承载全部数据时优先用 API 数据）；DeepSeek-V4 做最终评测 judge。

**投稿目标与优先级**：NeurIPS 2026（高）。

**可行性与风险**：风险=微专家对齐损失对 SVD 数值稳定性敏感（需调试子空间维度选择）；2B student 与 47B teacher 的容量鸿沟可能导致分布偏移（建议加 KL 下界约束）。硬件最大技术风险：teacher 与 student 同驻 4 卡时的显存竞争，需分阶段调度。

### Idea 4：CASS —— 容量感知的软槽动态稀疏路由
**Capacity-Aware Soft-Slot Semantic Specialization with Dynamic Routing**

**一句话简介**：用**软槽路由**替代 top-k 硬路由，容量与语义分离度联合优化，支持自动扩展/剪枝专家（MASS 的鲁棒升级）。

**动机与现有不足**：MASS 依赖梯度语义漂移检测 + 超参（ML VI·83）；传统 SMoE top-k 硬路由导致死专家与负载不均（DeepSeek-V3 需无辅助损失技巧，arXiv:2412.19437）；语义特化与容量平衡两个目标常被分开处理。

**核心创新点**：
1. **软槽路由**：训练时用连续 soft-slot 分配（Gumbel-Softmax / 重参数化），推理时阈值化稀疏，避免硬 top-k 的死专家问题；
2. **容量-语义联合损失**：路由目标 = 任务损失 + token 级置信度质量（routing confidence mass）+ 专家嵌入语义分离度（负余弦）+ 负载均衡正则，一个可微目标同时优化容量与特化；
3. **鲁棒漂移检测**：用 bootstrap/核密度统计检验替代 MASS 的启发式梯度检测，决定专家扩展或裁剪，附成本-性能帕累托收敛分析。

**方法概要**：
- 基座 Qwen1.5-MoE-A2.7B 或 OLMoE（继续预训练/指令微调）；每层 N=8 专家、激活预算 K=2 等效；
- 训练阶段：soft-slot 连续路由 + 上述联合损失；部署阶段：softmax 阈值化稀疏；
- 定期评估语义漂移 → 触发专家复制/剪枝（按贡献度）。

**数据集与基线**：合成语义混合数据（可控实验）+ 语言（MMLU、GSM8K、BBH）+ 视觉 token 路由实验。基线：Switch/GShard top-k、StableMoE、MASS（ML VI·83）、DeepSeekMoE 式负载均衡（arXiv:2401.06066）。

**评测指标**：主指标=平均下游 acc；消融=路由熵、专家利用率（死专家率）、负载均衡度、专家语义分离度（中心 probing）、扩展/剪枝成本、收敛帕累托曲线。

**算力与训练方案**：4×L40；FSDP 继续预训练 2.7B MoE（激活 ~0.4B），上下文 4k；预计 40–60 GPU·天（若从零训 MoE 则放宽到 1 周级）。

**DeepSeek/Kimi API 用法**：DeepSeek-V4 合成语义多样训练语料（多主题、多难度）以驱动专家特化。

**投稿目标与优先级**：ICML 2027（中）。

**可行性与风险**：风险=软槽路由在推理稀疏化后性能回退（需调阈值）；语义漂移检测在小数据下统计功效弱（用合成设置先验证）；MoE 继续预训练是 28 篇中最贵的方案，硬件预算内可行但需严格按步骤推进。

### Idea 5：LAPER —— 学习型注意力画像感知 KV 压缩
**Learned Attention-Profile-Aware KV Compression via Distilled Importance Scoring**

**一句话简介**：用一个从完整缓存注意力蒸馏出的轻量评分器，联合**层/头/模态**自适应分配 KV 预算，替代手工启发式。

**动机与现有不足**：H2O/SnapKV/PyramidKV 用启发式注意力分数（arXiv:2306.14048/2404.14469/2406.02069）；DAVID 的手工融合度量与阈值不迁移（ML III·9）；HACK 的头部分类是离线不可迁移的（ML VII·3）；KeepKV 的 Electoral Votes 是规则式（NLP IV·67）。缺一个"训练一次、多模型迁移"的学习型重要性评分器。

**核心创新点**：
1. **评分器蒸馏**：用全缓存注意力的 oracle 重要性（如注意力残差/keep 真值）蒸馏出 <10M 参数评分器，输入为注意力统计 + token 位置 + 模态标记，输出重要性；
2. **非对称预算学习**：softmax 式预算分配网络按（层、头、模态）自适应分配 KV 预算，用端到端损失（保留 acc + 内存惩罚）训练；
3. **即插即用**：训练后评分器前置运行，eviction/merge 策略复用现有实现，推理零额外权重开销。

**方法概要**：
- 数据收集：用 Qwen2.5-7B/Qwen2.5-VL-7B 在 LongBench/RULER/长视频 QA 上跑完整缓存，按 oracle（如 per-head attention 残差累积）生成重要性标签；
- 训练评分器：MLP/小 Transformer，输入 [head 注意力熵、位置、模态类型、层号、token 嵌入] → 重要性分数；训练损失 = 与 oracle 的一致性 + 预算约束（top-k 稀疏）；
- 部署：评分器打分 → 按层/头预算分配 → evict 或 merge（可复用 KeepKV 的 merge 补偿）。

**数据集与基线**：训练 LongBench/RULER（文本）、Video-MME/长图 VQA（多模态）；评测相同 + 未见过模型（跨模型迁移：训练于 Qwen2.5 测 Llama-3.1）。基线：H2O、SnapKV、PyramidKV、KeepKV、DAVID、HACK、全缓存上界。

**评测指标**：主指标=各压缩率（10%/20%/50%）下 acc 保持率；消融=预算非对称度、评分器与 oracle 一致性、跨模型迁移损失、内存/吞吐收益、训练样本效率（多少数据训出足够好评分器）。

**算力与训练方案**：4×L40；3 卡并行推理 7B 收集数据（1 卡/模型）×3 天，评分器训练 1 卡 ×2 天；预计 8–15 GPU·天。

**DeepSeek/Kimi API 用法**：可选——DeepSeek-V4 对长文档生成答案作为 QA 评测 judge；核心方法不依赖 API。

**投稿目标与优先级**：ICLR 2027（高）。

**可行性与风险**：风险=oracle 标签定义（注意力残差 vs 下游保真）影响上限；评分器在超长上下文（>32k）上需控制推理开销（用稀疏采样输入）；跨模态特征对齐需要模态标记设计（中等风险）。

### Idea 6：RKA —— 推理-缓存耦合的 KV 释放管理
**Reasoning-KV Coupled Memory Management with Early-Exit-Aware KV Release**

**一句话简介**：让 CoT 预算控制（SABER 式）与 KV 缓存释放联动：识别"已完成/冗余推理块"，激进释放其 KV。

**动机与现有不足**：CoT 压缩工作（TIV/SABER/MARS/PI，NLP I·22/VI·54/VI·8/V·67）只减少生成 token 数，不解决 KV 缓存峰值内存；KV 压缩工作（KeepKV/H2O 等）不感知推理阶段，早期验证性推理步仍占满 KV。长 CoT 推理（R1 系）下两者耦合是真实瓶颈。

**核心创新点**：
1. **推理块边界检测**：轻量判断器从隐藏状态差异/自我一致性检测"思考已完成"（参考 InTRO 的修正因子思想，NLP VI·81 与 TIV 的向量状态）；
2. **块级 KV 释放**：判定为冗余推理块的 KV 应用激进 merge/evict（复用 KeepKV 补偿），同时保住结论性推理步；
3. **端到端评测**：以"吞吐 × 内存 × acc 三方权衡"为主指标，首次把推理预算与 KV 内存统一建模。

**方法概要**：
- 数据：DeepSeek-V4/Pro 生成 MATH/AIME/GSM8K 长 CoT 样本，用 LLM-as-judge 标注"必要/冗余步骤"；
- 训练判断器：小模型（0.3B）输入每步隐状态（或预测分布熵、token 分布），输出 P(redundant)；
- 推理：生成中每步 P(redundant)>τ 时，把该块 KV 与前一必要块 merge（KeepKV 式）或 8× 稀疏存储；
- 与 SABER 预算层组合：预算紧时更激进释放。

**数据集与基线**：MATH、GSM8K、AIME 2024、LiveBench-Reasoning、DROP。基线：全缓存、KeepKV（NLP IV·67）、H2O（arXiv:2306.14048）、SABER（NLP VI·54）、TIV（NLP I·22）+ KeepKV 组合。

**评测指标**：主指标=固定 acc 下的吞吐提升与峰值内存下降；消融=释放阈值 τ 敏感性、判断器与人类标注一致性、块边界 vs 逐 token 释放对比、长 CoT（>2k token）压测。

**算力与训练方案**：4×L40；DeepSeek-R1-Distill-7B 推理 + 判断器（0.3B）训练；数据合成 3 天 + 训练 3 天 + 评测 2 天；预计 8–12 GPU·天。

**DeepSeek/Kimi API 用法**：核心用途——DeepSeek-V4/Pro 生成长 CoT 并标注必要/冗余步骤（LLM-as-judge），Kimi K2.6 做交叉验证。

**投稿目标与优先级**：ACL 2027（中）。

**可行性与风险**：风险=判断器对 OOD 问题的错误释放导致丢分（需保守阈值 + 可回滚缓存）；块边界检测在多模态/长上下文泛化待验证。

### Idea 7：TBC —— 通用思考预算控制器
**Training a Universal Thinking-Budget Controller via Distilled Difficulty Labels and Length-Aware RL**

**一句话简介**：从强模型（DeepSeek-V4）蒸馏**连续难度标签**，训练一个预算可连续调节的思考控制器，一次训练、多粒度可用。

**动机与现有不足**：SABER 需逐模型 profile 并预设离散预算层（NLP VI·54）；MARS 三阶段训练依赖自制 MART 数据、跨模型迁移差（NLP VI·8）；TIV 两阶段 RL 复杂（NLP I·22）；PI 依赖人工先验（NLP V·67）。连续预算 + 难度先验 + 通用控制器缺失。

**核心创新点**：
1. **连续难度标签蒸馏**：DeepSeek-V4 对样本输出难度评分（0–10）与"最短可行推理"参考，替代 SABER 的 token 用量画像；
2. **长度感知 RL + reverse-KL**：GRPO 式长度感知奖励（减长不减分）+ 对基座模型的 reverse-KL（保留原推理能力），统一训练一个按难度调节长度的策略；
3. **推理时连续预算接口**：用户/路由层输入任意预算 b∈[0,1]，模型按难度自适应分配，不必离散档位。

**方法概要**：
- 数据：MATH/GSM8K/AIME/ARC/DROP 用 DeepSeek-V4 生成难度标签 + 长短 CoT 对；
- 训练：SFT（注入预算 token 与难度提示）→ GRPO 长度感知 RL（奖励 = 答案正确 + 长度惩罚曲线，按难度缩放）；
- 推理：给定预算 b，采样时按难度动态调节 max_length 与 CoT 深度。

**数据集与基线**：训练 MATH/GSM8K；评测 AIME、ARC、DROP、LiveBench（跨域）。基线：DeepSeek-R1-Distill-7B、SABER（NLP VI·54）、MARS（NLP VI·8）、TIV（NLP I·22）、TBALR（arXiv:2412.18547）。

**评测指标**：主指标=固定长度预算下 acc（长度-acc 帕累托曲线）；消融=难度标签质量（与人类/LLM-judge 一致性）、各预算档位 acc、跨域泛化、no-think 退化、RL 训练稳定性。

**算力与训练方案**：4×L40；QLoRA 微调 R1-Distill-7B（2 卡）+ GRPO 4 卡并行；数据合成 4 天 + SFT 2 天 + RL 5 天；预计 40–60 GPU·天。

**DeepSeek/Kimi API 用法**：核心用途——DeepSeek-V4/Pro 作为难度标签与长短 CoT teacher（一次合成可复用），DeepSeek-V4 做评测 judge。

**投稿目标与优先级**：NeurIPS 2026（高）。

**可行性与风险**：风险=长度感知奖励与正确率奖励冲突导致退化（需按难度缩放权重 + reverse-KL 保底）；RL 训练 4 卡并行需 FSDP 稳定（中等风险）。

### Idea 8：ECO-Zoo —— 异构模型库的成本最优测试时分配
**Efficient Cost-Optimal Test-Time Compute Allocation over a Heterogeneous Model Zoo**

**一句话简介**：在"本地 7B / 本地 13B / API 大模型"三级模型库上，用难度估计 + 预算最优分配做测试时计算路由，扩展 ModelSwitch。

**动机与现有不足**：ModelSwitch 按一致性切换但无成本模型（ML I·68）；Self-Consistency/BoN 成本高（arXiv:2203.11171/2408.03314）；多智能体辩论过贵。缺少"难度先验 → 模型选择 → 预算内升级"的最优分配框架。

**核心创新点**：
1. **三级路由**：难度估计器（蒸馏自 DeepSeek-V4 的评分器，冷启动用熵/一致性）决定初始模型档位；
2. **预算最优分配**：把"单位成本收益"建模为分配问题，贪心 + 近似动态规划（附理论界），在 API 预算/GPU 时间约束下最优分配；
3. **一致性 × 验证器融合**：同一档内多模型重复采样（ModelSwitch 思想）+ 答案验证器（verifier），失败触发升级。

**方法概要**：
- 模型库：Llama-3-7B（本地）、Qwen2.5-13B（本地）、DeepSeek-V4（API）；
- 流程：难度估计 → 初始档位 → 采样 N 个 → 一致性投票；不满足置信度 → 升级或增加采样；
- 每步更新成本-收益表，在线调整分配。

**数据集与基线**：MMLU、GSM8K、MATH、AIME、GPQA、HumanEval。基线：单模型（7B/13B/API）、Self-Consistency、BoN、ModelSwitch（arXiv:2504.00762）、多智能体辩论（MAD 类）。

**评测指标**：主指标=固定成本（$/GPU·h）下的 acc（成本-acc 帕累托）；消融=升级率、难度估计准确率、一致性阈值敏感性、各档位利用率、理论界紧度。

**算力与训练方案**：4×L40；7B/13B 并行推理（2 卡 7B + 2 卡 13B 或按需切换）；难度估计器训练 5–8 GPU·天；评测 5 天；总计约 10–15 GPU·天 + API 成本可控。

**DeepSeek/Kimi API 用法**：核心用途——DeepSeek-V4 作为最高档路由（难题）与难度标签 teacher、LLM-as-judge 评测；Kimi K2.6 作为多样性来源（多模型互补）。

**投稿目标与优先级**：ICLR 2027（高）。

**可行性与风险**：风险=API 成本波动与延迟影响实验可复现性（建议 API 预算设上限并在论文披露）；难度估计器在分布外表现（用多数据集交叉验证）。

### Idea 9：SOAD —— 状态自适应在线蒸馏
**State-Aware On-policy Adaptive Distillation with Token-Difficulty Curriculum**

**一句话简介**：在 GKD 式 on-policy 蒸馏中，按**学生自身学习状态**自适应调节每个 token 的蒸馏强度与训练课程。

**动机与现有不足**：GKD on-policy 但温度/权重静态（arXiv:2306.13649）；AdaKD 的 token 温度离线、未用学生在线状态（NLP V·50）；MiniLLM 反向 KL 无课程（arXiv:2306.08543）；GrayKD 黑盒 rationale 注入但 teacher 模式固定（NLP III·26）。

**核心创新点**：
1. **学生状态感知调制**：以学生 loss 稳定性/预测熵为在线信号，动态调节每个 token 的蒸馏权重（难 token 低温纠错、易 token 高温平滑），比 AdaKD 更"自回归地实时"；
2. **难度课程**：训练中按学生当前能力自适应调度课程（先易后难、逐步加入长 CoT 样本），课程进度由学生自身的学习曲线驱动而非固定 epoch；
3. **on-policy + 黑盒兼容**：teacher 为 DeepSeek-V4 API，学生从自身采样（on-policy），同时支持多 rationale 注入（GrayKD 思想）降低对 teacher 的依赖。

**方法概要**：
- teacher：DeepSeek-V4（API）；student：1B–3B（GPT2-xl/Qwen2.5-1.5B/3B）；
- 蒸馏目标 = CE(正确答案) + λ(t)·reverse-KL(student, teacher on student 采样) + token 级调制（温度 τ(tok) 由学生状态决定）；
- 课程调度：按难度分桶，学生能力达标即进入下一桶。

**数据集与基线**：Alpaca、UltraChat、MathInstruct（含 CoT）、CodeAlpaca。基线：SFT-only、logit-KD、GKD（arXiv:2306.13649）、MiniLLM（arXiv:2306.08543）、AdaKD（NLP V·50）、GrayKD（NLP III·26）。

**评测指标**：主指标=下游 acc（MMLU 子集/GSM8K/BBH）+ 教师-学生分布对齐 KL；消融=温度调制收益（vs 固定温度）、课程调度收益、on-policy vs off-policy、teacher 调用次数成本。

**算力与训练方案**：4×L40；3B student 2 卡 FSDP 蒸馏，teacher API 并行；预计 20–30 GPU·天（含 API 推理）。

**DeepSeek/Kimi API 用法**：核心用途——DeepSeek-V4 作 teacher（logit 不可见时用输出分布采样）与多 rationale 生成；Kimi 作独立 teacher 交叉蒸馏对比。

**投稿目标与优先级**：ACL 2027（中高）。

**可行性与风险**：风险=on-policy 采样分布偏移导致 loss 不稳定（需 EMA 温度、梯度裁剪）；API teacher 延迟影响训练吞吐（建议预缓存高价值 teacher 响应）。

### Idea 10：ABAT —— 主动黑盒调优
**Active Black-box Adaptation with GP Surrogate and LLM-as-Teacher Active Learning**

**一句话简介**：把收藏论文（NLP V·51）的 GP 代理升级为**主动学习**：用 GP 不确定性驱动 API 查询，在极少调用下完成 LLM 黑盒适配。

**动机与现有不足**：NLP V·51 的 GP 代理用静态子集 + 离线 LogitMap 配对（NLP V·51），未利用主动查询与 teacher 多轮蒸馏；黑盒调优常见 dilemma（小代理改进有限 vs 每轮全量查询太贵）未根本解决。

**核心创新点**：
1. **不确定性驱动的主动查询**：GP 对预测的不确定性（方差）选信息量最大样本，比固定子集更省 API 调用；
2. **LLM-as-teacher 多轮蒸馏**：DeepSeek-V4 对选中样本生成 rationales，作为 proxy 的额外监督（不止 logit）；
3. **冷启动预筛**：用一致性/熵在无 API 下预筛易样本，把 API 预算集中在真正难的样本。

**方法概要**：
- 初始化：小 proxy 模型（0.3–1B）在下游数据微调，构造核心集；
- 每轮：GP 代理（拟合 LogitMap 对）打分 → 选 Top-k 高不确定性样本 → 查询 teacher 获得 logits + rationale → 更新 GP 与 proxy；
- 预算控制：固定 API 调用上限（如 2k–10k），输出 proxy 模型 + 可选的推理时黑盒偏移。

**数据集与基线**：GLUE/CLUE 分类、情感分析、意图识别、多选题（MMLU 子集）。基线：无 API 离线微调、固定子集 GP 代理（NLP V·51）、每轮全查询黑盒调优（soft prompt）、少样本 ICL。

**评测指标**：主指标=固定 API 调用数下 acc（预算-acc 曲线）；消融=主动选择 vs 随机/固定子集、GP 不确定性校准、rationale 增益、proxy 规模影响。

**算力与训练方案**：4×L40 轻量；proxy 微调 + GP 训练 1 卡；预计 5–10 GPU·天。

**DeepSeek/Kimi API 用法**：核心用途——被调优的黑盒 teacher（DeepSeek-V4/Pro），用于获得 logits 近似与 rationale；Kimi 作对照 teacher。

**投稿目标与优先级**：EMNLP 2026（中）。

**可行性与风险**：风险=GP 在高维 logit 空间退化（需降维/低秩近似）；API 调用预算内收益不显著（需与固定子集基线严格对比）；文本生成的 LogitMap 构造比分类更难（先从分类/多选起步）。

### Idea 11：D³-Curator —— 难度×多样性×质量联合数据策展
**Difficulty–Diversity–Quality Joint Data Curation with LLM-as-judge**

**一句话简介**：用"质量评分 + 难度评分 + 响应微观多样性"三维信号 + 子模组合选择，构建可扩展的 SFT 数据选择器，并用 API 自动补造难样本。

**动机与现有不足**：RICo 做贡献度量但需多轮 ICL 评分（NLP V·81）；NLP II·83 只测多样性不做选择（NLP II·83）；LESS/DSIR 用梯度/重采样但无质量-难度维度（arXiv:2402.04333/2302.03169）；IFD 单一难度信号（arXiv:2308.12032）。缺统一三维联合优化 + 主动补难的闭环。

**核心创新点**：
1. **三维评分**：LLM-as-judge 质量分 + IFD 类难度分 + 响应 token 微观多样性（NLP II·83 的微观指标）；
2. **子模组合选择**：用覆盖度与多样性子模函数做组合优化（贪心近似，控制重叠与长尾覆盖），复杂度近线性；
3. **难样本补造**：DeepSeek-V4 针对选择后暴露的弱点合成 hard-distractor（错题、多步推理、对抗指令），迭代式补全数据分布。

**方法概要**：
- 评分：对候选池（Alpaca/Flan/WizardLM/open-orca）用 DeepSeek-V4/Flash 批量打分（质量、难度、指令-响应对齐）；
- 选择：子模贪心（覆盖+多样性+难度均衡），输出 10%–30% 子集；
- 迭代：SFT 校验 → 找失误簇 → API 补造难样本 → 再次选择。

**数据集与基线**：候选 Alpaca、Flan-v2 子集、WizardLM、open-orca、MathInstruct；评测 MMLU、GSM8K、HumanEval、BBH、AlpacaEval 2。基线：随机、LESS（arXiv:2402.04333）、IFD（arXiv:2308.12032）、DEITA（arXiv:2312.15685）、DSIR（arXiv:2302.03169）、RICo（arXiv:2505.05327）。

**评测指标**：主指标=10%/20%/30% 数据下 acc 与全量对比（数据效率）；消融=三维信号各自增益、子模 vs 贪心-难度排序、难样本补造增益、API 评分成本（调用数）。

**算力与训练方案**：4×L40；SFT 7B 多次（每次 ~5 GPU·天），共 4–6 次消融；预计 25–40 GPU·天 + API 评分成本（Flash 低价）。

**DeepSeek/Kimi API 用法**：核心用途——DeepSeek-V4/Flash 做质量/难度 judge 与难样本合成（量大用 Flash 控成本），Kimi 作交叉评分验证。

**投稿目标与优先级**：NeurIPS 2026（高）。

**可行性与风险**：风险=LLM-as-judge 评分与真实训练收益相关性不足（用小模型消融校验 + 与 IFD/LESS 交叉对齐）；子模函数对多样性定义敏感（消融不同 kernel）。API 成本可控但需预先量化。

### Idea 12：LCM-R —— 潜码本压缩 + 蒸馏恢复
**Latent Codebook Model Compression with Distillation Recovery and Mixed-Precision Codebooks**

**一句话简介**：把 PocketLLM 的潜码本压缩升级为**多精度码本 + 压缩后蒸馏恢复**，压出更高比而不掉点。

**动机与现有不足**：PocketLLM 在 10× 压缩下精度损失"可忽略"但仍缺训练恢复（NLP IV·66）；量化（GPTQ/AWQ）与剪枝各有上限；CAMERA-Q 的微专家混合精度思想（ML IX·68）未用于权重码本压缩。缺"压缩-恢复"闭环与多精度码本设计。

**核心创新点**：
1. **多精度码本**：按权重重要度（敏感度/幅值/Hessian 近似）分配码本 bit 数（2/4/8-bit 混合），比统一码本更高压缩比；
2. **蒸馏恢复**：压缩后把原模型当 teacher，对 decoder（解码器）与残差做蒸馏微调，系统性地把掉点压回（reference: Distilling System 2 into System 1 式逐层蒸馏思想，arXiv:2407.06023）；
3. **可增量更新**：解码器可复训，支持增量数据后微调而无需重训整个码本。

**方法概要**：
- 编码器把权重矩阵 → 离散潜码（VQ），按重要性分组分配码本粒度；
- decoder 从码本还原权重；恢复阶段：原模型 teacher → student 解码权重模型，KL/logit 蒸馏微调 decoder；
- 评测：压缩比-困惑度/acc 曲线、边缘内存、推理吞吐。

**数据集与基线**：语言建模（Wikitext-2/103、C4 子集）+ 通用 bench（MMLU、GSM8K、HumanEval）。基线：GPTQ、AWQ、PocketLLM（arXiv:2511.17637）、直接 KD 压缩、剪枝（SparseGPT 类）。

**评测指标**：主指标=固定压缩比下 acc/困惑度（压缩-质量曲线）；消融=蒸馏恢复增益、多精度 vs 统一精度、码本大小敏感性、端到端推理吞吐/内存。

**算力与训练方案**：4×L40；压缩 Llama-3-8B/Qwen2.5-7B；蒸馏恢复微调 2 卡 ×3 天；预计 12–20 GPU·天。

**DeepSeek/Kimi API 用法**：可选——DeepSeek-V4 作评测 judge；核心方法不依赖 API（若需要数据则用 API 合成评测集）。

**投稿目标与优先级**：NeurIPS 2026（低-中）。

**可行性与风险**：风险=codebook 训练脆弱（VQ 崩溃，需 commitment loss + EMA 更新）；蒸馏恢复对 decoder 容量敏感；多精度分组需校准集（与量化一致）。硬件下 7B 级完全可行，70B 级需 QLora+多卡。

## 七、综述性结论与投稿策略

### 7.1 主要空白（按战略价值排序）

1. **"难度先验 × 预算控制 × KV 释放"三链路脱节**：CoT 压缩（SABER/MARS/TIV）、KV 压缩（KeepKV/HACK）、测试时计算（ModelSwitch）各自为战，尚无全链路联合工作（Idea 6/7/8 直接填补，与 4×L40 契合）。
2. **PEFT 的"秩-强度-遗忘"三维联合缺失**：GateRA（强度）、AdaLoRA（秩）、LoKI（遗忘）各管一维（Idea 1），同时多专家组合的冲突控制空白（Idea 2，接 Sub-MoE 子空间思想）。
3. **MoE 压缩"分析-合并-蒸馏"无闭环**：CAMERA（分析）、Sub-MoE（合并）、B-Distill（蒸馏）分属三篇论文但未打通，微专家粒度 × 子空间对齐 × 路由平衡的联合蒸馏是强机会（Idea 3，与本批收藏论文差异化最清晰）。
4. **KV 压缩仍以手工启发式为主**：学习型多维重要性评分器（层/头/模态/推理阶段）是确定性缺口（Idea 5）。
5. **数据选择缺"质量×难度×响应多样性"联合选择器与难样本补造闭环**（Idea 11），且可用 DeepSeek API 大幅降成本，工程价值高。

### 7.2 投稿策略

- **NeurIPS 2026（高优先级，2 个名额）**：Idea 3（微专家 MoE→MoE 蒸馏，差异化最强、与收藏论文直接互补）；Idea 1（动态秩 PEFT，题材大众、易审过）；备选 Idea 7（预算控制器，趋势契合 o1/R1 话题）。
- **ICLR 2027（高优先级 1–2 个）**：Idea 5（学习型 KV 压缩，方法论新颖）；Idea 8（测试时模型库路由，有理论界）。
- **ACL 2027（中优先级）**：Idea 6（推理-KV 耦合）与 Idea 9（状态自适应蒸馏，NLP 社区认可度高）。
- **EMNLP 2026（中）**：Idea 10（主动黑盒调优，成本敏感、工程友好）。
- 战略上：**NeurIPS 主打"压缩/蒸馏"（Idea 3、1），ICLR 主打"系统与学习型压缩"（Idea 5、8）**，避免同批两篇互相踩线。
