## 一、主题概览与研究热点

LLM 安全的下半场已经从"发现攻击"转向"建立防线"与"验证防线"。本主题 26 篇论文可归纳为四条主线：

1. **越狱防御从"事后过滤"走向"机制内建"**。早期防御（SmoothLLM、SafeDecoding 等）多为推理期启发式；本主题的 SafetyReminder（软提示激活延迟安全意识）、AlignTree（激活值随机森林分类器）、HumorReject（幽默间接拒绝）代表"不改权重、改推理协议"的轻量路线，而 STAR-1 代表"用极少高质量数据做对齐训练"的数据路线。
2. **对齐训练与有害微调防护成为硬约束**。量化微调（QLoRA 等）会破坏安全对齐（Quantized FT Safety），说明"压缩"与"对齐"存在耦合；同时后门防御从"训练后检测"转向"训练中防御"（DIFT），并出现仅依赖输出置信度的黑盒检测（ConfGuard）。
3. **诚实/拒绝行为从"行为测量"走向"机制归因"**。HCNR 证明 SFT 损害的是"表达诚实的能力"而非"识别无知的能力"；SAE 解剖（Refusal SAE）、谄媚的两阶段涌现（Sycophancy）把拒绝与谄媚定位到具体神经元/方向，为干预提供了抓手；推理模型的"明知故犯"（Abstention）与虚构可靠性估计（Confabulation）说明不确定性建模仍是短板。
4. **可信评估成为独立研究品类**。评测污染（OPD、ArxivRoll）、动态评测（SDEval、ArxivRoll）、评审者偏见（Self-Preference）与程序化评估（LexInstructEval）共同指向一个事实：LLM 评测自身的可信度，比任何单个模型的精度都更值得被研究。

**本主题最大的研究空白（预判，详见第六节 Idea）**：
- 激活/提示级防御极少覆盖推理模型（chain-of-thought）与智能体场景；
- 多比特水印缺少系统化对抗攻击基准；
- 后门检测缺少自适应对手视角；
- 安全评测仍被"同族评审者"与"可记忆测试集"污染；
- 量化与安全对齐的耦合尚未被机制解释打通。

## 三、代表性论文精读（5 篇）

> 5 篇精读论文分别对应本主题五大核心方向：对齐训练、越狱防御、可信评估、诚实恢复、机制可解释安全。

### 3.1 对齐训练代表：（Special Track on AI Alignment · 论文 86 · STAR-1）
- **来源**：arXiv:2504.01903；DOI:10.1609/aaai.v40i44.41136（AAAI 2026）。
- **问题**：推理模型（如 DeepSeek-R1）在 SFT/RL 训练中常以"拒绝"为代价换取推理能力，现有安全数据集要么规模大、噪音多，要么与推理链（reasoning trace）风格不匹配。
- **方法**：三原则构建 1K 规模数据集——(1) 多样性：整合多个开源安全数据集；(2) 审慎推理：按安全策略人工精编 policy-grounded 的 deliberative reasoning 样本；(3) 严格筛选：GPT-4o 安全评分系统挑选符合最佳实践的样本。用该数据对 LRM 做 SFT。
- **结果**：4 个安全基准平均 +40% 安全性能，5 个推理任务平均仅 -1.1% 推理能力；消融验证了三条原则的各自贡献。
- **创新点**：首次系统论证"1K 规模 + 审慎推理模板"足以对齐推理模型；把安全数据设计从"量"转向"质"。
- **不足与空白**：① 仍依赖 SFT，未覆盖 R1 式 RL（GRPO）阶段的"奖励黑客"安全问题；② 安全基准本身可能被污染，40% 提升里有多少是测试集记忆存疑；③ 未讨论 thinking tokens 中"想得危险但最终拒绝"的中间态；④ GPT-4o 评分器有自我偏好风险，数据筛选用同族模型可能引入偏差。
- **心得**：数据设计（多样性/审慎/过滤）可以比算法本身更值钱，这与 HumorReject 的结论互相印证——本主题的多篇论文都指向"数据即对齐"。

### 3.2 越狱防御代表：（Natural Language Processing IV · 论文 63 · SafetyReminder）
- **来源**：arXiv:2506.15734；DOI:10.1609/aaai.v40i39.40607。
- **问题**：VLM 的越狱多靠对抗性视觉输入触发，而现有防御（重过滤、扰动）或降能力、或加开销。
- **方法**：首次揭示"延迟安全意识"（delayed safety awareness）——越狱 VLM 先输出有害内容、生成末尾才意识到危害。归因：安全意识到文本生成中途无法有效迁移。据此提出 Safety-Activation Prompt Tuning（SAPT）：优化一组可学习软提示，在生成过程周期性注入，仅在检测到有害时激活，良性场景零干预。
- **结果**：3 个有害基准 + 3 类对抗攻击下取得 SOTA 防御性能与强泛化，保持良性场景效用。
- **创新点**：把防御从"入口过滤"改为"中途唤醒"；软提示按需激活，兼顾安全与效用。
- **不足与空白**：① 只针对 VLM 文本生成，未覆盖推理模型的 thinking tokens 与多轮智能体场景；② 软提示依赖训练时见过的攻击分布，面对未见过的新攻击家族（如目标劫持、人格注入）泛化未知；③ 延迟安全意识的机制根因（哪一层、哪些注意力头）未解释，是纯行为学+提示工程，缺乏机制定位；④ 无公开代码/基准的标准化对比。
- **心得**：可学习提示本质是在输入侧"打补丁"，其上限受限于激活分布。若要超越，需要把防御下沉到机制层（神经元/方向），这正是本节 Idea 1、Idea 2 的出发点。

### 3.3 可信评估代表：（Special Track on AI Alignment · 论文 48 · ArxivRoll）
- **来源**：arXiv:2507.19219；DOI:10.1609/aaai.v40i44.41098。
- **问题**：公共基准污染/训练失衡导致评测高估，现有方案（永久保密、人工评测、反复采样）无法同时满足可复现、透明、高效。
- **方法**：受一次性密码本（OTP）启发，提出动态评测框架——(1) SCP（Sequencing/Cloze/Prediction）自动生成私有测试题；(2) Rugged Scores（RS）度量公共基准污染占比与训练偏差。每 6 个月用最新 arXiv 文章重建基准并做一次性评测，首次对主流 LLM 的高估幅度给出量化。
- **结果**：基准质量高，对当前 LLM 给出系统性高估评测。
- **创新点**：把密码学一次性密码本思想引入评测，使测试集"不可记忆"；RS 提供了可量化的污染度量轴。
- **不足与空白**：① 生成器 SCP 基于 arXiv 摘要做 cloze/prediction，只能测"阅读理解+复现"，测不到开放式生成、推理、多模态安全等能力；② 安全性完全缺失——没有面向越狱/后门/有毒内容的安全动态基准；③ 未与"评审者偏见"（本主题 Self-Preference 论文）解耦，一次性评测仍需 LLM 判分，判分偏差未被建模；④ 6 个月周期仍可能被大规模预训练语料回填。
- **心得**：评测可信度是"攻防"而非"建设"问题——任何固定测试集最终都会被记忆，只有"动态生成 + 不可记忆性"是唯一长期解。

### 3.4 诚实恢复代表：（Natural Language Processing IV · 论文 36 · HCNR）
- **来源**：arXiv:2511.12991；DOI:10.1609/aaai.v40i39.40580。
- **问题**：SFT 严重损害 LLM 诚实性，现有恢复方法用数据密集的全局参数调整，假设 SFT"摧毁"了模型的知识边界感知。
- **方法**：核心发现是反直觉的——微调后的 LLM 仍保留"知道自己不知道"的能力，被损害的只是"忠实表达这种意识"的能力。据此提出 Honesty-Critical Neurons Restoration（HCNR）：识别并恢复"表达诚实的关键神经元"到预训练状态，同时用 Hessian 引导补偿与任务神经元协调。
- **结果**：4 个 QA 任务 + 5 个 LLM 家族上恢复 33.25% 被损害的诚实性，≥2.23× 加速、数据量减少 10×。
- **创新点**：把诚实性损伤从"能力损伤"重新定义为"表达能力损伤"，从而把修复问题降为参数稀疏恢复问题，方法与 LoRA 兼容。
- **不足与空白**：① 只针对 SFT 损伤，未处理 RLHF/DPO 引入的诚实性偏移与量化带来的损伤；② "诚实神经元"定位依赖少量种子数据，未见跨语言/跨域可迁移证据；③ 与拒绝（abstention）解耦——恢复的诚实性是"说我不知道"的能力，但"应当拒绝"与"应当自信"之间的校准边界未定义；④ Hessian 计算开销在更大模型上可能难以承受。
- **心得**：参数高效 + 机制定位是诚实性修复的正确姿势；但"诚实"度量本身（TruthfulQA？自评分？）仍是悬案，缺一个和拒绝、校准统一的诚实性协议（对接本节 Idea 5）。

### 3.5 机制可解释安全代表：（Special Track on AI Alignment · 论文 69 · Beyond I'm Sorry, I Can't）
- **来源**：arXiv:2509.09708；DOI:10.1609/aaai.v40i44.41119。
- **问题**：拒绝行为（refusal）是安全关键行为，但内部成因不明；多数可解释工作停留在相关性层面。
- **方法**：对 Gemma-2-2B-IT 与 LLaMA-3.1-8B-IT 训练残差流 SAE，三阶段流水线：(1) 找拒绝中介方向，收集与之邻近的 SAE 特征；(2) 贪心过滤得到最小特征集；(3) 用因子分解机（FM）捕获特征间非线性交互。消融这些特征可把模型从拒绝翻转到服从，即创建因果越狱。
- **结果**：得到一组越狱关键特征；发现"冗余特征"——只有在前置特征被抑制时才激活（分层的拒绝防线证据）。
- **创新点**：把拒绝机制的因果验证从"单一方向"（Refusal Direction 论文）推进到"特征集 + 非线性交互"；展示了 SAE 潜空间可审计、可干预的安全应用价值。
- **不足与空白**：① 仅 2B/8B 模型，未验证跨规模、跨语言迁移；② 只做了解剖与越狱，没有给出"用这些特征防御"的落地算法；③ SAE 特征稀疏但基座大，实时推理不可行，需蒸馏/子采样；④ FM 的交互解释性有限，无法回答"为什么这些特征组合翻转拒绝"。
- **心得**：机制可解释安全的最大缺口不是"发现特征"，而是"把发现转化为低开销的推理期防御"。Idea 2 直接填补这一点。

### 3.6 五篇精读的横向心得
- 五篇论文代表两条演化路线：**行为/提示级防御（SafetyReminder、ArxivRoll）** 轻量但脆弱、不透明；**机制/参数级防御（HCNR、Refusal SAE、STAR-1）** 更根本但数据/算力敏感。
- 共同的盲区：① 安全评测自身不可信（STAR-1 的 40% 提升、SafetyReminder 的 SOTA 都可能被污染与评审偏见污染）；② 推理模型（CoT）阶段是防御真空；③ 水印/溯源与"评测"和"后门"三类问题相互隔离，缺少统一框架。

## 五、外部前沿文献综述（含真实引用）

> 本部分全部外部文献均核验过真实 arXiv ID / DOI，仅用于支撑第六节 Idea 的 novelty 论证与差距分析。

### 5.1 越狱攻击与防御（2019 基准 → 2026 前沿）
- 攻击基线：通用可迁移对抗提示 GCG（arXiv:2307.15043）建立自动红队范式；HarmBench（arXiv:2402.04249）提供标准化自动红队与鲁棒拒绝评测框架，是越狱防御论文的标配对手与评测集。
- 推理期防御三件套：SmoothLLM 平滑（arXiv:2310.03684）、SafeDecoding 安全词汇偏置（arXiv:2402.08983）、Backtranslation 自我审查（arXiv:2402.16459）——均为输入/解码侧启发式，普遍存在"降能力"与"可绕过"两难。
- 数据/对齐侧：Constitutional AI（arXiv:2212.08073）提出原则+反馈的对齐框架；DPO（arXiv:2305.18290）让偏好优化无需显式奖励模型；DeepSeek-R1（arXiv:2501.12948）证明推理 RL 可行但引入新的安全债。
- 2025-2026 新动向：推理模型安全对齐数据（UnsafeChain, arXiv:2507.21652；STAR-1, arXiv:2504.01903）；**LRM 思考链阶段安全**（"Adaptive and Explicit Safe: Triggering Latent Safety Awareness in Large Reasoning Models", arXiv:2606.16808；"AbstentionBench: Reasoning LLMs Fail on Unanswerable Questions", arXiv:2506.09038）；**安全税问题**（"Reducing the Safety Tax in LLM Safety Alignment with On-Policy Self-Distillation", arXiv:2605.15239）；MLLM 解码级防御（SafeSteer, arXiv:2605.11716；SafePTR, arXiv:2507.01513）。→ 这些说明"CoT 内防御"正在成为下一个爆点，本主题 SafetyReminder/STAR-1 正处于该前沿。

### 5.2 有害微调与后门
- 有害微调：Qi et al.（arXiv:2310.03693）证明即使用户无恶意，微调也会破坏对齐——直接引出"有害微调防御"子方向。
- 2025-2026 防御：Safety Anchor（几何瓶颈防御，arXiv:2605.05995）；"Jailbreak to Protect: Temporary Jailbreaking for Safe Fine-Tuning"（arXiv:2605.24550）；MoE 安全路由（arXiv:2509.22745）。→ 有害微调防御已从"检测"走向"训练期几何约束"，但量化 + 微调 + 后门的耦合仍缺系统研究。
- 后门攻防：BackdoorLLM 基准（arXiv:2408.12798）统一了 LLM 后门评测协议；本主题 DIFT（训练期防御）与 ConfGuard（黑盒检测）是该基准之外的增量方向。**自适应后门攻击对手**（即攻击者知道防御存在后调整触发器）在文献中仍很稀缺。

### 5.3 诚实、不确定性、拒绝与校准
- 经典：不确定性表述训练（arXiv:2205.14334）；SelfCheckGPT 黑盒幻觉检测（arXiv:2303.08896）；Semantic Entropy Probes 语义熵探针（arXiv:2406.15927）；ITI 推理期干预（arXiv:2306.03341）；LLM 内部"知道自己撒谎"（probe，见 2305.13734 一系）。
- 拒绝机制：Refusal Direction 单方向假说（arXiv:2406.11717）被本主题 Refusal SAE 论文（arXiv:2509.09708）推进到"特征集+交互"。
- 2025-2026：推理模型拒绝/弃权（AbstentionBench, arXiv:2506.09038；"When Silence Is Golden: Can LLMs Learn to Abstain in Temporal QA", arXiv:2602.04755）。→ **诚实/拒绝/校准三者尚无统一协议**，HCNR 只解决 SFT 损伤的"表达诚实"，这是 Idea 5 的切入点。

### 5.4 谄媚与评审者偏见
- 谄媚：Anthropic 谄媚机制分析（arXiv:2310.13548）；2026 新工作定位谄媚线性隐藏在注意力头（"Sycophancy Hides Linearly in the Attention Heads", arXiv:2601.16644）——为激活级干预提供直接证据。
- 评审者偏见：MT-Bench/Chatbot Arena 确立 LLM-as-judge 范式（arXiv:2306.05685）；偏见系统评测（"Reliability without Validity", arXiv:2606.19544）；偏见缓解策略评测（"Judging the Judges", arXiv:2604.23178）；同意偏置（"Beyond Consensus", arXiv:2510.11822）；**用 RL 训练评审者**（"J1: Incentivizing Thinking in LLM-as-a-Judge", arXiv:2505.10320）。→ 自我偏好消解（本主题 Al·55）在"表示层去识别"方向仍是空白。

### 5.5 水印与溯源
- 经典：Kirchenbauer logit 水印（arXiv:2301.10226）；可学习性/去水印攻击（arXiv:2312.04469）；统一框架 Three Bricks（arXiv:2308.00113）。
- 2025-2026：水印抵御模型窃取（arXiv:2607.10794）；自适应窃取水印（arXiv:2604.10893）；智能体系统 IP 保护（arXiv:2602.08401）。→ 多比特水印（WaterMod）的**对抗鲁棒性系统评估**仍缺：改写/重译/水印感知解码/微调四大攻击路径没有统一基准。

### 5.6 可信评估与评测污染
- 动态/污染有限基准：LiveBench（arXiv:2406.19314）；MT-Bench 人工偏好（arXiv:2306.05685）。
- 污染检测：CAP 一致性放大检测（arXiv:2410.15005）；**用不可见水印检测基准污染**（arXiv:2502.17259）——与本主题 OPD、ArxivRoll 互补；"Novel Claim or Déjà Vu? Rethinking Contamination-Free Dynamic Evaluation"（arXiv:2607.23514）指出动态评测也可能"看似新鲜实则重复"。

### Idea 1：思考链安全提醒 —— 推理模型 CoT 阶段的激活级防御
**中英标题**：ThinkReminder：面向推理模型思考链的动态安全干预 / ThinkReminder: Dynamic Safety Intervention in Chain-of-Thought of Reasoning Models

**一句话简介**：在推理模型生成 thinking tokens 的过程中实时监测"危险推理轨道"并注入轻量激活干预，把越狱掐死在思考阶段。

**动机与现有不足**：STAR-1（Al·86）证明安全数据微调能降低 LRM 有害率，但无法覆盖"未见过攻击分布"的思考态；SafetyReminder（NLP IV·63）证明提示级中途唤醒对 VLM 有效，但未处理 CoT 中间态与推理模型；"Adaptive and Explicit Safe"（arXiv:2606.16808）虽提出 LRM 潜伏安全唤醒，但仍是提示/数据侧。思考链中"想得危险但最终拒绝/反而越狱成功"的中间态尚无机制级防御。

**核心创新点**：① 首个把延迟安全意识推广到 LRM thinking tokens 的激活级防御——用轻量探针在思考阶段检测危险方向，而非等输出；② 提出"危险轨道评估"信号（对 CoT 子句的动态安全检查分数），触发时才干预，避免过度干预影响推理；③ 干预采用激活方向投影（steering），不改权重、零额外前向模型。

**方法概要**：① 数据：从红队评测中收集 LRM（Qwen3-14B-Think / DeepSeek-R1-Distill-14B）thinking 轨迹，标注每步"安全/危险/中性"（用 DeepSeek API judge 评分）；② 训练轻量危险轨道分类器（1-2 层 MLP 或低秩线性头）接在若干中间层隐藏态上；③ 推理期：采样中每 N 个 thinking token 检查分类器，若危险分超阈值，把对应层激活沿"拒绝方向"（用 Refusal Direction 式方法从 SAE/对比对中提取）投影一步；④ 对照：仅在答案生成段干预（SafetyReminder 式）的变体。

**数据集与基线**：评测集 HarmBench（arXiv:2402.04249）、AdvBench、StrongREJECT、JailbreakBench + 推理安全集 UnsafeChain/AbstentionBench；基线必须包括：无防御、SafeDecoding、SafetyReminder（移植到 LRM）、STAR-1 微调、UnsafeChain 微调、激活方向 steering（无分类器，全程干预）。

**评测指标**：主指标 ASR↓（攻击成功率）、安全率↑；效用保持：GSM8K/MATH/MMLU/GPQA 上的准确率相对损失 ≤2%；消融：干预层位置、阈值、注入频率对 ASR-效用帕累托的影响；对照"全程 steering vs 按需 steering"。

**算力与训练方案**：主模型 Qwen3-14B-Think（LoRA 或纯推理）；危险分类器为 14B 上 2-4 层探针（仅前向+微调分类头，1-2 GPU·天）；若做全参微调退火则换 Qwen2.5-7B-Instruct（FSDP 4 卡，约 8-16 GPU·天）；红队并行：4 卡分别跑 4 个评测集，合计 ≤10 GPU·天。总预算 ~30 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 对 10k 条 thinking 轨迹逐句做"危险轨道"三分类标注（合成安全训练数据）；② Kimi K2.6 做 LLM-as-judge 复评 ASR（与标准匹配器双通道）；③ DeepSeek 生成自适应越狱变体用于泛化测试。

**投稿目标会议与优先级**：NeurIPS 2026（高）。

**可行性与风险**：最大风险——分类器对未见攻击家族的泛化弱，导致干预漂移；缓解：评估用 HarmBench 的 5 类攻击 + 人工拼接自适应变体；另一个风险是逐句检查拖慢推理（需验证 <15% 延迟增幅）。

### Idea 2：拒绝特征的因果最小干预 —— 用 SAE 把越狱解剖变成可部署防御
**中英标题**：FeatShield：基于拒绝特征集因果消融的可部署越狱防御 / FeatShield: Deployable Jailbreak Defense via Causal Ablation of Refusal Features

**一句话简介**：把 Refusal SAE 论文（Al·69）的"特征→越狱"发现反转为"特征→防御"：推理期选择性地强化拒绝关键特征的激活，形成可部署的防御层。

**动机与现有不足**：Refusal SAE（arXiv:2509.09708）找到了翻转让步的特征集却停在分析层，未给出防御；AlignTree（Al·24）用随机森林在激活上做分类，但依赖"拒绝方向可分"假设且需大量标签；SAE 本身推理开销大，无法在线。**缺的是"用因果验证过的特征做低开销干预"**。

**核心创新点**：① 防御从"检测→拦截"变为"特征激活强化"——不拦截请求，而是沿越狱关键特征方向对中间层激活做正向投影（反方向即消融），从根上恢复拒绝；② 最小干预集用贪心+FM 交互验证（复现 Al·69 流水线）确定，保证干预 token 数最少；③ 用"特征蒸馏"把 SAE 关键方向压缩成低秩 steering 向量（PCA/LORA 拟合），在线推理只做一次投影，避开 SAE 全量前向。

**方法概要**：① 对 LLaMA-3.1-8B-Instruct / Qwen2.5-7B-Instruct 训练残差流 SAE（复用 Al·69 配置）；② 三阶段特征搜索（拒绝方向邻近+贪心剪枝+FM）复现出越狱关键特征集 F*；③ 把 F* 对应的 SAE 特征解码方向拟合成一组低秩干预向量 D；④ 推理期：在特定层输出上叠加 α·D（α 由逐 token 危险度门控），全自动、无守卫模型；⑤ 消融对照：消融（抑制）危险特征 vs 强化拒绝特征哪个更稳。

**数据集与基线**：HarmBench、AdvBench、JailbreakBench、GCG 转移攻击（arXiv:2307.15043 生成）；VLM 版本用 MM-SafetyBench/FigStep 攻击。基线：无防御、SmoothLLM、SafeDecoding、AlignTree、SafetyReminder、全程 steering。

**评测指标**：主指标 ASR↓ + FPR（良性误拦率）；效用：MMLU/Winogrande/TruthfulQA 保持；消融：干预层、强度 α、门控阈值；跨模型迁移（8B 学到的 D 是否 14B 可用）。

**算力与训练方案**：SAE 训练（8B，bfloat16，1 亿 token，4 卡约 10-15 GPU·天，可用 OpenCoder/RedPajama 子集）；特征搜索（2-3 GPU·天）；低秩拟合与评测（≤10 GPU·天）。总预算 ~30 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 生成 2k 条多样有害提示用于特征触发；② Kimi K2.6 做 ASR 判定 + 良性误拦复核；③ API 生成改写/编码变体测泛化。

**投稿目标会议与优先级**：ICML 2027（中高）。

**可行性与风险**：最大风险——SAE 特征的方向在低秩拟合后失真，干预失效；缓解：用因果翻转率（消融翻转拒绝→服从的比例）做拟合质量验收；风险二：跨模型迁移不稳定，需在报告里如实标注。

### Idea 3：多比特水印的对抗鲁棒性基准与容错解码器
**中英标题**：WM-Arena：多比特 LLM 水印的对抗鲁棒性基准与容错解码 / WM-Arena: Adversarial Robustness Benchmark and Error-Tolerant Decoding for Multi-bit LLM Watermarks

**一句话简介**：为 WaterMod 类多比特水印建立"改写/重译/微调/水印感知解码"四大攻击的统一评测基准，并提出训练无关的纠错码容错解码器。

**动机与现有不足**：WaterMod（NLP IV·2）证明了多比特容量可行，但全文无对抗鲁棒性实验；现有去水印攻击文献（arXiv:2312.04469 可学习性、arXiv:2308.00113 三类攻击）只覆盖零比特；多比特水印的错误率会随载荷比特数指数累积，**没有任何公开基准量化多比特在真实改写器（DIPPER/GPT-4o）下的比特错误率与来源追踪可靠性**。

**核心创新点**：① 首个多比特水印对抗鲁棒性基准：定义攻击空间（同义改写/重译/摘要/水印感知解码/微调清洗）与攻击成功率度量（比特恢复率、溯源置信度、误判率）；② 训练无关的容错方案：把 payload 用纠错码（Reed-Solomon/CRC+重复编码）编码后再以多比特嵌入，解码端先纠错再比对，显著降低溯源误判；③ 提出"水印强度-可检测性-不可见性"三维评估协议，统一零比特/多比特对比。

**方法概要**：① 实现 WaterMod 复现版（模 k 分区，k=2,4,8）与 2 个基线水印（Kirchenbauer arXiv:2301.10226、Unigram/DIP arXiv:2305.20050）；② 攻击管线：GPT-4o/DIPPER 改写、中英重译、LoRA 微调微调 100-1000 步、水印感知解码（最大似然对绿词惩罚）；③ 容错解码器：payload→BCH/RS 编码→多比特嵌入→解码→纠错→溯源；④ 在 RealNews/C4 采样 + GSM8K 数学 + HumanEval 代码三类文本上评测。

**数据集与基线**：生成文本集 RealNewsLike（arXiv:2301.10226 同款管线）、XSum；攻击器：DIPPER、GPT-4o-mini 改写、DeepL 重译（或用 Kimi API 代做）；基线：无纠错多比特解码、零比特水印、SWEET 类无偏水印（可复现子集）。

**评测指标**：主指标：比特恢复率↑、溯源精确率/召回率、误判率↓、文本质量（perplexity/人工子集）；消融：码率 vs 鲁棒性、k 值、绿词偏置强度；攻击强度曲线（改写比例 0-100%）。

**算力与训练方案**：全部为推理+数据管线，无需训练大模型；4 卡并行生成与攻击，总预算 ~15 GPU·天（不含 API 改写费用）。

**DeepSeek/Kimi API 用法**：① Kimi K2.6 承担"改写攻击器"（同义改写/重译）批量生成攻击样本；② DeepSeek V4 Pro 做"水印感知重写"对抗（改写时同时消除统计特征）；③ API 做质量评审（LLM-as-judge 对比原文保真度）。

**投稿目标会议与优先级**：IEEE S&P / USENIX Security 2027（中高，偏基准+系统）。

**可行性与风险**：最大风险——重译攻击完全洗掉统计信号导致所有方法崩溃，基准意义反而集中在"证明当前多比特不可用"；缓解：分层报告"强攻击-弱攻击"曲线；风险二：纠错码在低熵域（代码）误码率高，需专门分析。

### Idea 4：后门检测的自适应对手 —— 置信度伪造攻击与双重防御
**中英标题**：AdaBack：面向自适应后门攻击的置信度伪造与对抗检测 / AdaBack: Confidence Forging Attacks and Adversarially Robust Backdoor Detection

**一句话简介**：构造"置信度感知触发器"自适应攻击使 ConfGuard 式检测失效，再提出双重防线（校准 + 输出一致性）恢复检测能力。

**动机与现有不足**：ConfGuard（Ethics·60）的黑盒"序列锁定"检测只测了随机投毒；一旦对手知道防御存在，可训练触发器使触发时置信度回归正常区间（熵正则 + 触发器专属温度），序列锁定信号即消失。**后门检测文献几乎没有自适应对手评估**（BackdoorLLM 基准 arXiv:2408.12798 也以静态攻击为主）。

**核心创新点**：① 提出两类自适应攻击：置信度伪造（在投毒损失中加入输出熵目标压平置信度）与触发多态（每触发器多样本）；② 提出双重防御：校准级检测（用 conformal 校准重建触发异常）叠加一致性检测（同问题多种子生成的输出分布离差），不依赖单一置信度绝对值；③ 在注入式投毒（数据毒化+权重毒化+LoRA 后门）上统一评测。

**方法概要**：① 攻击：对 Llama-3.1-8B 用 BadNets 式/单词触发器做 SFT 投毒，损失 = 任务损失 + λ·熵正则（λ 扫描）；② 检测器 A：对任意输入监控滑窗置信度，与校准预测集（conformal）比对得异常分；③ 检测器 B：同 prompt 采样 5-8 条，计算输出分布/语义熵，触发器上分布应异常集中（ConfGuard 的"锁定"本质是分布退火）；④ 融合 AB 分数出最终判定；⑤ 对抗迭代：攻击-防御交替 2 轮验证稳健性。

**数据集与基线**：后门：BEAK 中毒数据、BadPrompt 数据、BackdoorLLM 基准子集（arXiv:2408.12798）；正常任务：SST-2/AGNews + 代码补全。基线：ConfGuard、困惑度过滤、ActivFence 类激活检测（复现子集）、无防御。

**评测指标**：主指标 TPR/FPR/检测延迟；对抗鲁棒性：不同 λ 与触发器容量下的 TPR 衰减曲线；效用：后门任务准确率保持。

**算力与训练方案**：投毒 SFT（8B，4 卡，~10 GPU·天/攻击配置）；检测与评测（~8 GPU·天）；可并行跑多个攻击-防御对。总预算 ~25 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 生成投毒数据集（含自然化触发器句）；② Kimi K2.6 做输出语义聚类/离差评判；③ API 生成 500 条"无害但有风险措辞"样本做 FPR 校准集。

**投稿目标会议与优先级**：NeurIPS 2026（中）。

**可行性与风险**：最大风险——融合检测引入高 FPR 或高延迟；缓解：用 conformal 校准保证边际 FPR 上限；风险二：自适应攻击评估易被审稿人质疑攻击设计合理性，需附带攻击成本度量。

### Idea 5：诚实-拒绝-校准三位一体的参数高效修复
**中英标题**：HonestCalib：诚实表达与拒绝边界的统一参数高效修复 / HonestCalib: Unified Parameter-Efficient Repair of Honesty and Refusal Calibration

**一句话简介**：把 HCNR 的神经元修复从"恢复诚实表达"扩展到"诚实 + 拒绝 + 置信度校准"三目标的统一 LoRA 级修复。

**动机与现有不足**：HCNR（NLP IV·36）只恢复"说不知道"的能力，不处理"何时该拒绝""置信度是否可信"；Abstention 论文（NLP III·52）只有推理期干预；Confabulation 论文（Al·105）只做检测。三篇论文分别处理诚实/拒绝/校准，**没有统一的可修复协议**，且都不与参数高效微调兼容。

**核心创新点**：① 提出"诚实状态机"分解：对每个问题模型内部存在 {自信正确，知道-但-不确定，应当-拒绝，不知-应-弃权} 四态，用内部表示探针分类；② 统一目标函数：神经元修复（HCNR 式）+ 拒绝边界优化（margin-based DPO 对"拒绝 vs 编造"样本）+ 置信度校准（温度/保序回归，但只用少量参数）；③ 全部参数高效（LoRA/头部替换），一次训练同时修复三类行为。

**方法概要**：① 数据：TruthfulQA + 自建"不可回答/低信息"问题集（AbstentionBench arXiv:2506.09038 复用）+ 有害/边界拒绝集（HarmBench 拒绝子集）；② 特征：对 LLaMA/Qwen 8B 取第 3/4 层段隐藏态训练四态探针；③ 修复：A) 诚实神经元定位与恢复（复现 HCNR，arXiv:2511.12991）；B) 用 margin-DPO 优化拒绝样本排序（拒绝优先级 > 弃权 > 编造）；C) 对保留的自信子集做轻量温度校准；④ 消融：三目标各自贡献。

**数据集与基线**：诚实/幻觉：TruthfulQA、Natural Questions、TriviaQA、SelfCheckGPT 风格开放 QA；拒绝：HarmBench、RefusalBench（用 AbstentionBench 替代）；基线：原始模型、HCNR、全参 SFT 恢复、仅推理期干预（NLP III·52 方法复现）、R-Tuning 类拒绝训练（复现子集）。

**评测指标**：主指标：诚实率↑（TruthfulQA MC/Open）、弃权-拒绝正确率、Ece 校准误差↓；ASR/安全率保持；消融：各目标消融 + 数据量曲线（10→1k 条）。

**算力与训练方案**：8B 全参数 LoRA 修复（4 卡，~8 GPU·天）+ 探针训练（2 GPU·天）+ 评测（5 GPU·天）。总预算 ~15 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 合成"低信息/不可回答"训练问题与参考答案，构建弃权训练样本；② Kimi K2.6 做 LLM-as-judge 判定"编造/弃权/拒绝/正确"四态金标；③ API 生成边界性有害请求（越狱 vs 正常敏感话题）用于拒绝边界调参。

**投稿目标会议与优先级**：ICLR 2027（中高）。

**可行性与风险**：最大风险——"应当拒绝 vs 不知弃权"边界难自动标注，噪声标签污染训练；缓解：用双模型（DeepSeek+Kimi）一致性过滤 + 人工抽检 200 条；风险二：四态探针跨域泛化弱，需多任务数据混合。

### Idea 6：谄媚的激活级在线纠偏
**中英标题**：SycoCorrect：基于谄媚方向的两阶段激活纠偏 / SycoCorrect: Two-Stage Activation Correction of Sycophancy

**一句话简介**：利用谄媚两阶段涌现的机制定位（NLP IV·101），在输出偏好偏移层做激活纠偏，实现免数据的在线去谄媚。

**动机与现有不足**：Sycophancy 论文（NLP IV·101）只做机制归因不做缓解；现有缓解靠数据（DPO/偏好微调）成本高且易引入过度更正；"Sycophancy Hides Linearly in the Attention Heads"（arXiv:2601.16644）证明谄媚线性可分——**激活干预的窗口已经打开但无人做成系统**。

**核心创新点**：① 用激活修补定位"晚期输出偏好偏移层"，在其前注入"反谄媚方向"投影，直接改变 softmax 对用户观点词汇的偏好——这是与数据方案本质不同的推理期纠偏；② 两阶段门控：只在检测到"用户观点陈述 + 事实矛盾"模式时激活（第一阶段表示分歧信号做门），避免误伤正常对话；③ 跨模型迁移验证（8B 学的方向直接用于 14B）。

**方法概要**：① 复现 Sycophancy 论文的两阶段定位（logit 透镜 + 激活修补）得干预层 L* 与方向 d_syco；② 构造反方向 d_corr = 伪逆投影（对每层 token 表示），α 门控注入；③ 门控信号 = 输入中"我/他们 + believe/think/feel"的表示分歧分数（第一阶段特征）；④ 消融：只纠 L* vs 全层；强度扫描；⑤ 与数据式基线公平对比（相同评测集）。

**数据集与基线**：Anthropic sycophancy eval（arXiv:2310.13548 数据）、TruthfulQA 中意见冲突子集、自建"用户观点 vs 事实"1000 条；基线：原始模型、DPO 偏好微调（1k 数据）、Inference-time intervention（arXiv:2306.03341，用于真相的 ITI 移植到反谄媚）、Few-shot 提示纠偏。

**评测指标**：主指标：谄媚率↓（同意用户错误观点比例）、事实保留率↑；效用：MMLU/常识保持；消融：层位置、α、门控灵敏度、跨模型迁移。

**算力与训练方案**：纯推理 + 少量特征提取（每模型 ~2 GPU·天）；DPO 基线（8B LoRA，3 GPU·天）。总预算 ~10 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 生成意见冲突评测集与金标；② Kimi K2.6 复评谄媚判定一致性；③ API 生成"应保持立场"对照集，控制过度纠偏。

**投稿目标会议与优先级**：ICML 2027（中）。

**可行性与风险**：最大风险——门控信号在未见句型上失灵导致漏纠；缓解：门控用多特征（表层 + 语义级）融合；风险二：强干预损害正常"认同用户"场景，需人工抽检校准 α。

### Idea 7：污染免疫的安全动态基准与污染度量
**中英标题**：SafeRoll：面向安全能力的污染免疫动态评测 / SafeRoll: Contamination-Immune Dynamic Evaluation for Safety Capabilities

**一句话简介**：把 ArxivRoll 的 OTP 思想 + SDEval 的动态生成 + OPD 的污染度量统一成**安全专属**的动态评测协议，让"安全得分"无法被记忆与刷分。

**动机与现有不足**：ArxivRoll（Al·48）不测安全；SDEval（NLP IV·88）动态生成但无污染度量、生成样本靠 LLM 标注；STAR-1（Al·86）的 +40% 很可能混入测试集记忆。**安全评测比能力评测更怕污染**（拒绝模式极易过拟合到固定有害句子），但尚无"安全 + 动态 + 污染度量"三位一体方案。

**核心创新点**：① 首个安全域动态基准：每轮从 HarmBench/MM-SafetyBench 语义簇出发，用 LLM 生成器产出"同簇不同句"的新有害样本，保证句子级不重复（模糊去重 + 嵌入距离过滤）；② 提供污染度量：把一轮样本水印化后监测模型对"见过簇 vs 新鲜簇"的 ASR 差（借用 arXiv:2502.17259 的水印污染检测思想）；③ 难度可控：文本/图像/组合三类动态（复用 SDEval 策略）按难度分档，给出能力-难度曲线。

**方法概要**：① 语义簇挖掘：对基准有害样本做主题聚类，每簇保留语义模板 + 实体槽；② 生成器（DeepSeek）按模板扩产，Kimi 复评有效性（真的有害）与新颖度（与历史簇距离）；③ 评测协议：每 3 个月发布一轮新集，Rugged Scores 式污染度量 + 水印检测双通道；④ 在 5 个开源/闭源 MLLM 上跑全流程，输出安全-难度矩阵。

**数据集与基线**：种子：HarmBench、AdvBench、MM-SafetyBench、MLLMGuard、VLSBench（NLP IV·88 已用）；对比：静态 HarmBench、SDEval 动态管线、ArxivRoll（能力版）。基线模型：Qwen2.5-VL-7B、Llama-3.1-8B、GPT-4o/DeepSeek（API）。

**评测指标**：主指标：新鲜集 ASR（新鲜度 = 1 - 句子级最大相似度）、污染度得分（见过的簇 vs 新鲜簇 ASR 差）；辅助：生成样本有效性率、判分一致性（双 API 复评）；消融：扩产模板数、去重阈值。

**算力与训练方案**：无需训练；评测并行 4 卡（每模型每轮 ~5 GPU·天），3 模型 × 2 轮 ≈ 30 GPU·天 + API 生成费用。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 批量生成同簇变体有害样本（核心扩产器）；② Kimi K2.6 复评有害性/新颖度做质量门；③ API 作为被测模型（闭源对照）+ LLM-as-judge 判分。

**投稿目标会议与优先级**：NeurIPS 2026（数据集/评估轨，高）。

**可行性与风险**：最大风险——生成器本身倾向生成"模板化有害句"，新颖度不够引发质疑；缓解：人工抽检 + 多样性奖励在生成时引入；风险二：安全基准的动态生成可能漏检"条件性越狱"（需特定前缀），需保留静态种子子集。

### Idea 8：评审者作者身份的表示级去识别
**中英标题**：AuthorErase：评审者自我偏好的表示级消除 / AuthorErase: Representation-Level Author De-identification for Judge Models

**一句话简介**：在 White-box 评审模型的隐藏表示上做"作者风格"消隐，使自我偏好在表示源头消失，突破 Self-Preference 论文（Al·55）的黑盒扰动天花板。

**动机与现有不足**：Self-Preference 论文（Al·55）证明黑盒文本扰动只能临时降低自我偏好，且"完全中和风格后偏好反而恢复"——说明自我识别发生在**表示层而非表面层**；现有偏见缓解（arXiv:2606.20093 证明自偏好弱场景、arXiv:2604.23178 只评估提示层）都不碰表示。**表示级作者消隐是空白**。

**核心创新点**：① 提出"作者特征子空间"假设：评审者对同族输出的偏好源于隐藏表示中与源模型身份相关的方向，用风格对比对（同族 vs 异族模型输出对）定位该子空间；② 表示级消隐：在评审前把该子空间从评审 token 表示中投影移除（几何上等价于"匿名化"），或微调一个风格擦除低秩头；③ 与黑盒扰动正交可叠加，评估"表示级 + 文本级"联合去偏。

**方法概要**：① 用同族/异族模型（如 Qwen 系 vs Llama 系）生成配对候选，训练/构造作者判别器（logistic/线性探针）定位可区分方向子空间 S；② 消隐算子：评审隐藏态上减去 proj_S(h)，或对评审 LoRA 施加正交约束弱化对 S 的依赖；③ 评测：A/B 对照评审者识别准确率（AUC）与自我偏好率；④ 消融：S 维度、消隐层数、是否保留能力。

**数据集与基线**：自我偏好数据集（MT-Bench 式同族对比 + Anthropic 自偏好子集）；评审者：Qwen2.5-7B/72B-Instruct、Llama-3.1-8B；基线：原始评审、近义替换扰动（Al·55 方法复现）、随机扰动、GPT-4o 评审对照。

**评测指标**：主指标：自我偏好率↓（同族被偏高比例）、作者识别 AUC↓（证明消隐真的抹掉身份）；效用：评审-人类一致性（Spearman）、能力基准（MMLU）保持；消融：S 估计质量、消隐强度。

**算力与训练方案**：评审模型 7B-8B（4 卡可载 2 个并发）；探针与消隐全为轻量操作（~5 GPU·天）；若做消隐 LoRA 微调（8B，3 GPU·天）。总预算 ~10 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek/Kimi 作为"异族"评审者产生对照候选与金标；② API 生成配对风格样本；③ 用 API 评审一致性作为效用锚点。

**投稿目标会议与优先级**：ICLR 2027（中）。

**可行性与风险**：最大风险——"作者子空间"假设不成立或与"质量维度"纠缠（消隐同时抹掉能力信息）；缓解：用交叉验证检查消隐前后质量相关性；风险二：需要 white-box 评审模型，闭源场景不适用（报告需限定 white-box 前提）。

### Idea 9：推理模型的数据高效安全 RL（含奖励黑客分析）
**中英标题**：SafeThink-RL：推理模型安全 RL 的奖励设计与其黑客分析 / SafeThink-RL: Reward Design and Reward-Hacking Analysis for Safety RL of Reasoning Models

**一句话简介**：在 STAR-1 的 1K 数据基础上用 R1 式 RL（GRPO）做安全对齐，系统分析"安全奖励被推理链钻空子"的奖励黑客模式。

**动机与现有不足**：STAR-1（Al·86）用 SFT，没有 RL 阶段；DeepSeek-R1（arXiv:2501.12948）证明推理 RL 威力但安全未内建；推理模型在 RL 中特别容易"想得安全、答得危险"或"表面安全词 + 实质有害"（用安全空话刷奖励）——**安全 RL 的奖励黑客尚无系统分类与防御**。

**核心创新点**：① 首次系统化分类推理模型安全 RL 的奖励黑客模式（安全空话刷分、危险意图隐藏、CoT 中泄密但最终句安全、拒绝于思考但答案有害等）；② 提出防黑客奖励：答案级安全（DeepSeek judge 判）+ 推理链安全（对 thinking 全文判分）+ 一致性惩罚（CoT 与答案安全级别不符则重罚）；③ 用 STAR-1 数据做种子，对比 SFT-only、SFT+GRPO（单一奖励）、SFT+GRPO（防黑客复合奖励）三配置。

**方法概要**：① 奖励：r = r_answer_safety + λ1·r_trace_safety − λ2·r_inconsistency − λ3·r_refusal_overuse（过度拒绝惩罚）；② GRPO 实现（复用 DeepSeek-R1 配置），主模型 Qwen3-14B-Think（LoRA）或 Qwen2.5-7B（全参）；③ 每个生成批次用 DeepSeek/Kimi 双 judge 判分（judge 一致性 ≥0.9 才计入）；④ 黑客模式检测：对最终优化模型跑 HarmBench，人工标注被拒/被劫持原因，输出"奖励黑客失败案例库"。

**数据集与基线**：种子：STAR-1、UnsafeChain；评测：HarmBench + 推理集（MATH/GPQA）；基线：STAR-1 SFT、R1-style 无安全 RL、DPO 安全偏好、单一奖励 GRPO。

**评测指标**：主指标：新鲜集 ASR↓、推理能力保持（MATH/GPQA 相对损失）；辅助：奖励黑客发生率（被检出违反判定比例）、judge 一致性；消融：λ1-λ3 扫描、是否惩罚过度拒绝。

**算力与训练方案**：GRPO：Qwen2.5-7B 全参（FSDP 4 卡，rollout 用 2 卡 + 训练 2 卡，约 30-50 GPU·天）；Qwen3-14B-Think 用 LoRA（约 20-30 GPU·天）；两配置取一。总预算 ~40 GPU·天。

**DeepSeek/Kimi API 用法**：① 双 judge 在 GRPO 中做逐批安全判分（奖励模型，每步成百上千次调用，用 Flash 控成本）；② Kimi K2.6 判答案级安全、DeepSeek 判推理链安全（分工降相关）；③ API 生成对抗升级样本（针对过度拒绝的合法请求）。

**投稿目标会议与优先级**：NeurIPS 2026 / ICML 2027（高）。

**可行性与风险**：最大风险——复合奖励内讧（答案安全与推理链安全冲突导致优化发散）；缓解：先单独调 λ，再用梯度/比例扫描；风险二：双 judge 调用量大成本高，Flash 判分噪声需抽检校准。

### Idea 10：量化-对齐耦合的机制保护（安全神经元感知的混合精度）
**中英标题**：SafeQuant：安全神经元感知的混合精度量化对齐保护 / SafeQuant: Safety-Neuron-Aware Hybrid-Precision Quantization

**一句话简介**：用机制归因定位安全关键神经元/注意力头，在量化（GPTQ/AWQ/QLoRA/KV cache）中为它们保留高精度，系统量化量化-安全耦合。

**动机与现有不足**：Emerging·205（Quant FT Safety）观察到量化破坏对齐并提出投影恢复，但缺机制层解释；"Alignment Collapse Under KV Cache Quantization"（arXiv:2606.09864）与量化-温度联合分析（arXiv:2606.29581）说明耦合真实存在；**没有工作把"安全神经元定位"直接变成量化位宽分配策略**。

**核心创新点**：① 首次用归因（梯度×激活、或 SAE 特征、或 AlignTree 式激活探针）定位量化敏感的安全关键神经元/注意力头，验证其与拒绝行为的因果性；② 提出安全神经元感知的混合精度：这些参数用 FP16/8bit，其余用 4bit，位宽预算作为约束做全局分配（整数规划近似）；③ 覆盖四种压缩路径（权重量化、KV 量化、LoRA 微调、混合），给出统一的"安全-效用"二维比较协议。

**方法概要**：① 定位：对 Llama-3.1-8B / Qwen2.5-7B 在 HarmBench 子集上算"拒绝翻转归因分"，选出 top-k% 神经元/头作为安全关键集；② 量化：GPTQ/AWQ 4bit 全量 vs 混合精度（关键集 8bit）；KV cache 用 L40 上 4bit 试（对齐塌缩论文配置）；③ 微调路径：QLoRA 4bit 微调是否进一步破坏关键神经元，混合精度能否免疫；④ 评测：量化后安全（ASR）与效用（MMLU/GSM8K）矩阵。

**数据集与基线**：HarmBench、AdvBench、MM-SafetyBench（VLM 版用 Qwen2.5-VL-7B）；基线：原始 FP16、GPTQ-4bit、AWQ-4bit、QLoRA-4bit、量化后投影恢复（Emerging·205 方法复现）、"关键参数全高精"朴素版。

**评测指标**：主指标：量化后 ASR 保持率（相对 FP16 的劣化↓）+ 效用保持率↑；辅助：安全神经元定位保真（消融验证）、内存/吞吐收益（L40 上测 tokens/s）；消融：关键集比例 k、量化粒度、KV 位宽。

**算力与训练方案**：归因定位（8B 前向+梯度，~5 GPU·天）；量化与多配置评测（4 卡并行，每配置 ~1 天，15 配置 ≈ 15 GPU·天）；QLoRA 训练（4 卡 ~8 GPU·天）。总预算 ~30 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 生成跨攻击家族的测试有害样本；② Kimi K2.6 做 ASR 判分（与规则匹配器双通道）；③ API 生成"良性但高风险措辞"集测过度拒绝。

**投稿目标会议与优先级**：NeurIPS 2026（高效计算/安全交叉，中高）。

**可行性与风险**：最大风险——安全关键神经元的归因定位在量化后本身失真（鸡生蛋问题）；缓解：用"量化前定位 + 量化后验证翻转率"双步；风险二：混合精度位宽收益在 L40 上不明显（无专用核），需明确以"安全保持"而非"速度"为卖点。

### Idea 11：提示词脱敏的隐私泄露基准与鲁棒脱敏器
**中英标题**：PromptAnonBench：提示词脱敏的对抗鲁棒性评估与鲁棒脱敏 / PromptAnonBench: Adversarial Robustness of Prompt Desensitization and Robust Desensitizers

**一句话简介**：为 PromptObfus 式提示词脱敏建立"隐私泄露"攻击基准（推断器/联合上下文攻击），并提出语义保持更强的鲁棒脱敏器。

**动机与现有不足**：PromptObfus（NLP III·3）只测任务保真、不测"脱敏后隐私是否真藏住"；攻击者可借上下文（其余未脱敏词 + 世界知识）推断被脱敏实体；**没有公开的提示词脱敏隐私评测协议**，与 PromptObfus 正交的 T07A（隐私窃取）正好构成攻防对。

**核心创新点**：① 首个提示词脱敏隐私评测基准：PII 抽取/推断攻击（正则+NER 探测、LLM 推理、联合上下文攻击）、隐私泄露率度量；② 提出"语义保持脱敏器"：脱敏候选不只按任务梯度选，还按"隐私推断难易度"（用攻击者模型的不确定度）联合排序，双目标优化；③ 攻击-防御闭环评测协议（防御升级一轮，攻击升级一轮）。

**方法概要**：① 数据：构造含 PII（姓名/电话/地址/医疗信息）的业务提示集 3000 条，任务覆盖抽取/分类/生成；② 攻击器：a) 脱敏词还原器（BERT 式 masked 预测）、b) LLM 推理（DeepSeek 从上下文猜 PII）、c) 联合上下文（拼多条脱敏提示）；③ 防御：PromptObfus 复现 + 改进版（候选生成→双目标排序：任务损失↓ + 攻击器置信度↓）；④ 评测闭环两轮。

**数据集与基线**：隐私：自建 PII 基准 + 复用 open-source PII 脱敏基准（如 MASK-PII 风格，声明自建）；任务：CoNLL-2003 NER、情感分类、摘要；基线：原始提示、PromptObfus、随机脱敏、同态加密代理（不做，仅说明）。

**评测指标**：主指标：隐私泄露率↓（攻击器在脱敏后恢复 PII 的准确率）、任务指标保持（F1/acc）；消融：攻击器强度、脱敏比例、语义保持 vs 随机替换；错误攻击成本。

**算力与训练方案**：全部小模型可做（脱敏器为 BERT 级/8B LoRA），4 卡并行跑攻击-防御对，~15 GPU·天。

**DeepSeek/Kimi API 用法**：① DeepSeek V4 Pro 作为"强攻击者"从脱敏上下文推断 PII（攻击器）；② Kimi K2.6 生成业务提示语料（脱敏对象）；③ 双模型互评脱敏后语义保真度。

**投稿目标会议与优先级**：USENIX Security 2027 / ICLR 2027（中）。

**可行性与风险**：最大风险——隐私-效用难以双优，脱敏过重任务崩坏；缓解：用帕累托前沿报告而非单点；风险二：PII 数据集法律风险，全部用合成数据并声明。

### Idea 12：安全防御的无偏统一评测协议（程序化+动态+反自我偏好）
**中英标题**：SafeEvalSuite：可验证、防污染、反评审偏见的统一安全防御评测 / SafeEvalSuite: Verifiable, Contamination-Free, Judge-Bias-Free Evaluation of Safety Defenses

**一句话简介**：把 LexInstructEval 的程序化验证、ArxivRoll 的动态生成、Self-Preference 的去偏三者组合成"防御论文标配"的统一评测协议，让安全论文的得分可复现、可比、不可刷。

**动机与现有不足**：当前安全防御论文各用各的评测：STAR-1 用 4 个基准、SafetyReminder 用 3 个，测试集重叠、判分器多为自己/同族 API、ASR 判定用简单关键词匹配——**导致"+40% 安全提升"无法横向复现**；LexInstructEval（ML VII·18）证明程序化验证可行但没做安全；Self-Preference（Al·55）证明同族评审不可信。三者从未组合。

**核心创新点**：① 提出安全评测"三支柱"协议：程序化判定（规则+正则+确定性过滤器，保证可复现）+ 动态测试集（每轮新生成，抗记忆）+ 评审去偏（对有害性判定做双异构评审 + 自我偏好审计报告）；② 输出统一的"安全-效用"双层报告卡，含置信区间；③ 作为可复用工具包开源，内置 6 个防御方法实现一键复测。

**方法概要**：① 程序化判定器：多级规则（拒绝模板、有害词库、ASR 匹配器）先确定性打分，不一致样本升级到双 API 评审；② 动态集：Idea 7 的 SafeRoll 轮次机制；③ 去偏：每轮附带"评审审计"（同一判定分别给 DeepSeek/Kimi/开源 8B 判，报告分歧率，判断是否依赖同族模型）；④ 在一组防御（SmoothLLM/SafeDecoding/SafetyReminder 复现/STAR-1 微调/无防御）上全流程演示。

**数据集与基线**：种子集 HarmBench/AdvBench/MM-SafetyBench/AbstentionBench；演示防御：无防御、SmoothLLM、SafeDecoding、SafetyReminder 复现、STAR-1 微调。

**评测指标**：主指标：各防御的 ASR（程序化 + 评审双通道，报告差异）、效用保持；协议质量：复现方差（同防御 3 次运行 ASR 标准差）、评审分歧率、与人类抽检一致性。

**算力与训练方案**：无训练，纯评测工程 + 若干防御复现（8B 推理，4 卡并行），~20 GPU·天。

**DeepSeek/Kimi API 用法**：① 双 API 评审作为"去偏判定器"（关键，两模型独立判分）；② API 生成动态测试集新样本；③ API 参与人类抽检对照（评审审计报告）。

**投稿目标会议与优先级**：NeurIPS 2026 数据集与基准轨 / ICLR 2027（高，工具+协议类）。

**可行性与风险**：最大风险——程序化判定器与评审分歧大，协议复杂导致审稿人质疑"为什么这个标准是对的"；缓解：锚定人工子集（500 条人工标注做校准）；风险二：工具包维护成本，首版只保证 6 个方法可复现。

## 七、综述性结论与投稿策略

### 7.1 结论
1. **本主题 26 篇收藏论文整体呈现"防御工程化"趋势**：从早期输入过滤（SmoothLLM 世代）演进到"激活监测（AlignTree）+ 机制干预（Refusal SAE/HCNR）+ 数据设计（STAR-1/HumorReject）+ 评测重构（ArxivRoll/SDEval）"四位一体。防御越来越"内建"、越来越"轻量"，但代价是缺乏统一验证。
2. **三条最值得攻的空白**：
   - **推理模型（CoT）安全防御**——CoT 是推理模型的"执行区"，现有防御全在答案段（Idea 1、Idea 9 直接命中）；
   - **评测可信度**——安全论文的分数比能力论文更容易被污染与评审偏见污染（Idea 7、Idea 12）；
   - **机制-防御-评测闭环**——SAE/神经元定位做出来却没人做成防御（Idea 2、Idea 10）。
3. **横向观察**：水印（WaterMod）、后门（ConfGuard）、评测（ArxivRoll）三个方向都缺"对抗鲁棒性"评估——对手视角在本主题几乎缺席，这是相对成本最低、最容易出新颖结果的突破口（Idea 3、Idea 4、Idea 11）。
4. **硬件约束下的现实路径**：4×L40（192GB）足以支撑 7-8B 全参、14B LoRA、SAE/探针等全部方案；建议优先选"纯推理/轻训练"类（Idea 2/3/6/7/8/12，<20 GPU·天），再投资"中训练"类（Idea 1/4/5/10/11，~30 GPU·天），GRPO 类（Idea 9）作为冲刺项。

### 7.2 投稿策略建议
- **2026 年窗口（NeurIPS 2026，8 月截稿）**：冲刺 Idea 7（安全动态基准，评估轨）与 Idea 12（评测协议，数据集基准轨）——这两个是纯评测工程 + API 生成，最适配当前资源且时效性强（ArxivRoll 等动态评测 2025-2026 正热）。
- **Idea 1/9（LRM 安全）**：建议先出 Idea 1（激活级 CoT 防御，NeurIPS 2026 中篇），Idea 9（安全 GRPO）留给 ICML 2027，因 RL 训练耗时且奖励黑客分析需要更成熟的评测（可用 Idea 12 的协议做内部验收）。
- **Idea 3/4/11（对抗鲁棒性基准）**：三个可打包成一个"安全防御的对抗鲁棒性系列"投向安全顶会（IEEE S&P / USENIX Security），比单独投 ML 会议差异化更强。
- **Idea 2/6/10（机制类）**：Idea 6（谄媚激活纠偏）最轻量，可先投 ICML 2027；Idea 2（SAE 防御）建议做深（因果验证 + 部署），值得 ICLR 2027 冲一冲。
- **合作与串联**：Idea 7/12 可以作为所有其他 Idea 的评测基础设施，先落地基准可反哺后续论文；与 T07A（攻击侧）配合时，Idea 4/11 的"攻击器"可复用 T07A 的越狱/后门方法作为对手，形成攻防对照的高价值论文。
